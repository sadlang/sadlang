# الميزة 24: نظام القدرات (Capability-Based Types)

**بسم الله الرحمن الرحيم**

**الأولوية**: 🟠 عالية — المرحلة 2
**المرجع**: س103، س115 من مواصفات BeeOS (أمان النواة والتواصل بين العمليات)
**التبعيات**: نظام الملكية (الميزة 01)، السمات والواجهات (الميزة 14)

---

## ١. الوصف

نظام القدرات (Capabilities) هو نموذج أمان يُستخدم في BeeOS بدلاً من نظام الصلاحيات التقليدي (ACL). الفكرة: كل عملية تمتلك **مفاتيح** (capabilities) تُثبت حقها في الوصول إلى مورد ما. المترجم يُتحقق من القدرات **وقت الترجمة** كلما أمكن.

### لماذا في المترجم؟

- **أمان وقت الترجمة**: إذا دالة تحتاج قدرة `قدرة_ذاكرة`، المترجم يرفض استدعاءها بدون تمريرها
- **عدم التزوير**: القدرات لا تُنشأ من العدم — تأتي فقط من النواة
- **التحويل لأسفل**: قدرة عامة تُشتق منها قدرة محدودة (لا العكس)

---

## ٢. المتطلبات

### ٢.١ نوع `قدرة<>` المدمج

```
// القدرات أنواع خاصة — لا يمكن إنشاؤها إلا من النواة
@غير_قابل_للنسخ
@غير_قابل_للتزوير
بنية قدرة<ق: وصف_قدرة> {
    معرّف: معرّف_قدرة,        // معرّف فريد
    صلاحيات: ق::الصلاحيات,    // الصلاحيات المحددة
    مصدر: معرّف_عملية,        // مَن أنشأها
}
```

### ٢.٢ تعريف أنواع القدرات

```
// وصف قدرة — سمة يُنفّذها كل نوع قدرة
سمة وصف_قدرة {
    نوع الصلاحيات;
    ثابت الاسم: &نص;
}

// أمثلة من BeeOS:
بنية قدرة_ذاكرة;
نفّذ وصف_قدرة لـ قدرة_ذاكرة {
    نوع الصلاحيات = صلاحيات_ذاكرة;
    ثابت الاسم: &نص = "ذاكرة";
}

بنية قدرة_ملفات;
نفّذ وصف_قدرة لـ قدرة_ملفات {
    نوع الصلاحيات = صلاحيات_ملفات;
    ثابت الاسم: &نص = "ملفات";
}

بنية قدرة_شبكة;
نفّذ وصف_قدرة لـ قدرة_شبكة {
    نوع الصلاحيات = صلاحيات_شبكة;
    ثابت الاسم: &نص = "شبكة";
}
```

### ٢.٣ استخدام القدرات في توقيعات الدوال

```
// هذه الدالة تتطلب قدرة ذاكرة — المترجم يفرض وجودها
دالة اطلب_صفحات(
    قدرة: &قدرة<قدرة_ذاكرة>,
    عدد: عدد_طبيعي
) → نتيجة<*متغير بايت, خطأ_ذاكرة> {
    // ...
}

// بدون القدرة — خطأ ترجمة:
// خطأ[م301]: الدالة `اطلب_صفحات` تتطلب قدرة<قدرة_ذاكرة>
// ← أضف القدرة كمعامل أو اطلبها من النواة
```

### ٢.٤ تضييق القدرات (Capability Attenuation)

```
// تحويل قدرة عامة إلى قدرة أضيق — مسموح
دالة ضيّق_قدرة_ذاكرة(
    عامة: &قدرة<قدرة_ذاكرة>
) → قدرة<قدرة_ذاكرة_قراءة_فقط> {
    // مسموح: تضييق (أقل صلاحيات)
    عامة.ضيّق()
}

// تحويل قدرة ضيقة إلى عامة — خطأ ترجمة:
// خطأ[م302]: لا يمكن توسيع قدرة — فقط التضييق مسموح
```

### ٢.٥ القدرات عبر IPC (BeeProtocol)

```
// إرسال قدرة مع رسالة IPC
دالة أرسل_قدرة(
    قناة: &قناة_نحل,
    قدرة: قدرة<قدرة_ملفات>,    // ← انقل الملكية
    رسالة: &رسالة_نحل
) → نتيجة<(), خطأ_ipc> {
    // القدرة تُنقل — المرسل يفقدها (نظام الملكية يضمن ذلك)
    قناة.أرسل(رسالة.مع_قدرة(قدرة))
}
```

## ٣. أمثلة من BeeOS

### ٣.١ نظام الملفات BeeFS

```
// فتح ملف يتطلب قدرة ملفات
دالة افتح(
    قدرة: &قدرة<قدرة_ملفات>,
    المسار: &مسار,
    الخيارات: خيارات_فتح
) → نتيجة<ملف, خطأ_نظام> {
    // التحقق من أن القدرة تسمح بالعملية المطلوبة
    تأكد!(قدرة.الصلاحيات.تسمح(الخيارات.إلى_صلاحية()))؟;
    // ...
}
```

### ٣.٢ استدعاء النظام

```
// استدعاء النظام يتطلب القدرة المناسبة
دالة استدعاء_نظام(
    قدرة: &قدرة<قدرة_نظام>,
    الرقم: عدد_طبيعي,
    المعاملات: &[عدد_طبيعي]
) → نتيجة<عدد_طبيعي, خطأ_نظام> {
    // ...
}
```

## ٤. ملاحظات تقنية

### ٤.١ ماذا يفعل المترجم؟

| الفحص | وقت الترجمة | وقت التشغيل |
|-------|-------------|-------------|
| وجود القدرة كمعامل | ✅ | — |
| نوع القدرة صحيح | ✅ | — |
| القدرة لم تُنقل (moved) | ✅ | — |
| القدرة صالحة (لم تنتهِ) | — | ✅ |
| القدرة مزورة | — | ✅ (بفحص التوقيع) |

### ٤.٢ تأثير على الأداء

- وقت الترجمة: **صفر overhead** — فحص أنواع فقط
- وقت التشغيل: فحص التوقيع مرة واحدة عند استلام القدرة عبر IPC
