**بسم الله الرحمن الرحيم**

**المرجع**: س104 من مواصفات BeeOS، المهمة T029
**التبعيات**: المؤشرات (الميزة 07)، كتل خطر (الميزة 08)

## ١. الوصف

العمليات الذرية هي عمليات على الذاكرة **لا يمكن مقاطعتها** — إما تكتمل بالكامل أو لا تحدث. هي أساس بناء **كل** آليات التزامن في نظام التشغيل (أقفال، spinlocks، قنوات، إلخ).

### لماذا هي حرجة؟

BeeOS يعمل على معالجات متعددة الأنوية (SMP — س118). بدون عمليات ذرية:
- لا يمكن بناء أقفال (mutexes)
- لا يمكن بناء قنوات رسائل (channels)
- لا يمكن بناء مُخصص ذاكرة آمن للخيوط
- لا يمكن بناء عدادات مرجعية (`مشترك<>`)

### القاعدة الذهبية في BeeOS (س104)

> **المترجم يفرض: لا ذاكرة مشتركة بدون رقصة — خطأ ترجمة لا تحذير**

هذا يعني أن المترجم يرفض مشاركة بيانات بين خيوط بدون استخدام آلية تزامن.

## ٢. المتطلبات التفصيلية

### ٢.١ الأنواع الذرية

```
ذرّي<ع8>          // عدد ذري 8-bit
ذرّي<ع16>         // عدد ذري 16-bit
ذرّي<ع32>         // عدد ذري 32-bit
ذرّي<ع64>         // عدد ذري 64-bit
ذرّي<منطقي>       // قيمة منطقية ذرية
ذرّي<*ثابت ن>     // مؤشر ذري
```

### ٢.٢ العمليات الذرية المطلوبة

| العملية | الوصف | تعليمة x86_64 |
|---------|-------|---------------|
| `حمّل(ترتيب)` | قراءة ذرية | `mov` + barrier |
| `خزّن(قيمة, ترتيب)` | كتابة ذرية | `mov` + barrier |
| `بادل(قيمة, ترتيب)` | قراءة + كتابة ذريتان | `xchg` |
| `قارن_وبادل(متوقع, جديد, ترتيب)` | CAS | `cmpxchg` |
| `أضف(قيمة, ترتيب)` | جمع ذري | `lock add` |
| `اطرح(قيمة, ترتيب)` | طرح ذري | `lock sub` |
| `و(قيمة, ترتيب)` | AND ذري | `lock and` |
| `أو(قيمة, ترتيب)` | OR ذري | `lock or` |
| `xor(قيمة, ترتيب)` | XOR ذري | `lock xor` |

### ٢.٣ ترتيب الذاكرة (Memory Ordering)

| الترتيب | الوصف | الاستخدام |
|---------|-------|----------|
| `مرخّي` (Relaxed) | لا ضمان ترتيب | عدادات فقط |
| `اكتساب` (Acquire) | القراءات بعده لا تُقدَّم | أخذ قفل |
| `إطلاق` (Release) | الكتابات قبله لا تُؤخَّر | تحرير قفل |
| `اكتساب_إطلاق` (AcqRel) | الاثنان معاً | CAS |
| `متسلسل` (SeqCst) | ترتيب كامل — الأبطأ | الافتراضي |

### ٢.٤ حواجز الذاكرة (Fences)

```
حاجز_ذاكرة(اكتساب)         // lfence
حاجز_ذاكرة(إطلاق)          // sfence
حاجز_ذاكرة(متسلسل)         // mfence
```

## ٣. البنية اللغوية المطلوبة

```
// إنشاء قيمة ذرية
دع عدّاد = ذرّي<ع64>::جديد(0)

// قراءة ذرية
دع القيمة = عدّاد.حمّل(متسلسل)

// كتابة ذرية
عدّاد.خزّن(42, متسلسل)

// جمع ذري (يُرجع القيمة القديمة)
دع القديم = عدّاد.أضف(1, مرخّي)

// مقارنة وتبادل (CAS)
دع نجح = عدّاد.قارن_وبادل(
    القيمة_المتوقعة,
    القيمة_الجديدة,
    اكتساب_إطلاق      // ترتيب عند النجاح
)

// بناء spinlock باستخدام ذريات
بنية اهتزازة {      // spinlock
    مقفل: ذرّي<منطقي>,
}

دالة اقفل(&ذات) {
    طالما ذات.مقفل.بادل(صح, اكتساب) {
        // انتظر — "اهتزي" (spin)
        تلميح_دوران()    // تعليمة `pause` على x86
    }
}

دالة افتح(&ذات) {
    ذات.مقفل.خزّن(خطأ, إطلاق)
}
```

## ٤. أمثلة عملية من BeeOS

### ٤.١ العداد المرجعي الذري (`مشترك<>`)

```
بنية مشترك<ن> {
    عدّاد: ذرّي<عدد_طبيعي>,
    قيمة: ن,
}

دالة انسخ(&ذات) → مشترك<ن> {
    ذات.عدّاد.أضف(1, مرخّي)
    // ... أنشئ نسخة تُشير لنفس البيانات
}

دالة أسقط(&متغير ذات) {
    إذا ذات.عدّاد.اطرح(1, إطلاق) == 1 {
        حاجز_ذاكرة(اكتساب)
        // نحن آخر مرجع — حرّر الذاكرة
        حرّر(ذات)
    }
}
```

### ٤.٢ حلقة بدون قفل (Lock-free Ring Buffer)

```
// حلقة الرحيق — BeeNectar Ring (مثل io_uring)
بنية حلقة_الرحيق<ن> {
    مخزن: [ن; 4096],
    رأس: ذرّي<ع32>,        // المنتج يكتب هنا
    ذيل: ذرّي<ع32>,        // المستهلك يقرأ هنا
}

دالة أرسل(&ذات, عنصر: ن) → منطقي {
    دع رأس = ذات.رأس.حمّل(مرخّي)
    دع ذيل = ذات.ذيل.حمّل(اكتساب)
    إذا رأس - ذيل >= 4096 { أعد خطأ }   // ممتلئة
    ذات.مخزن[رأس % 4096] = عنصر
    ذات.رأس.خزّن(رأس + 1, إطلاق)
    أعد صح
}
```

## ٦. ملاحظات تقنية

- العمليات الذرية يجب أن تُترجم مباشرة إلى تعليمات الآلة — لا استدعاء دوال
- `ذرّي<ع64>` على x86_64 يجب أن يكون محاذاً لـ 8 بايت تلقائياً
- يجب دعم `ذرّي<ع128>` لاحقاً عبر تعليمة `cmpxchg16b`
- التكامل مع نظام الملكية: `ذرّي<>` يُنفّذ سمة `مُشارَك` تلقائياً
