# الميزة 25: محسّن الأداء (Performance Optimizer)

**بسم الله الرحمن الرحيم**

**الأولوية**: 🟠 عالية — المرحلة 2
**المرجع**: س81 من مواصفات BeeOS (أداء يُنافس C/C++ مع أمان Rust)
**التبعيات**: التمثيل الوسيط BeeIR (الميزة 03)

---

## ١. الوصف

محسّن الأداء هو مجموعة تحويلات تعمل على BeeIR لتُنتج كوداً أسرع مع الحفاظ على صحة البرنامج. الهدف: أداء BeeOS يُنافس أنظمة مكتوبة بـ C/C++ — خصوصاً في:
- **النواة**: context switch < 1µs
- **نظام الملفات**: BeeFS throughput
- **التشفير**: ChaCha20 يُنافس OpenSSL
- **الشبكة**: BeeProtocol < 500ns لكل رسالة

## ٢. المتطلبات

### ٢.١ مستويات التحسين

```
ص ترجم --تحسين=0    // بدون تحسين — للتصحيح
ص ترجم --تحسين=1    // تحسينات أساسية — ترجمة سريعة
ص ترجم --تحسين=2    // تحسينات كاملة — إنتاج
ص ترجم --تحسين=3    // تحسينات عدوانية — سرعة قصوى
ص ترجم --تحسين=س    // تحسين حجم — أصغر ملف
```

### ٢.٢ تحسينات المستوى 1 (أساسية)

| التحسين | الوصف |
|---------|-------|
| إزالة الكود الميت | حذف كود لا يُنفّذ أبداً |
| طي الثوابت | `3 + 5` → `8` وقت الترجمة |
| نشر الثوابت | إذا `x = 5` ثم استبدل كل `x` بـ `5` |
| تبسيط التعبيرات | `x * 1` → `x`، `x + 0` → `x` |
| إزالة التعيينات المكررة | `x = 5; x = 7` → `x = 7` |

### ٢.٣ تحسينات المستوى 2 (كاملة)

| التحسين | الوصف |
|---------|-------|
| دمج الدوال (inlining) | دمج الدوال الصغيرة في المستدعي |
| تحريك كود الحلقات (LICM) | نقل حسابات ثابتة خارج الحلقة |
| تطوير الحلقات (unrolling) | نسخ جسم الحلقة عدة مرات |
| تخصيص السجلات | خوارزمية graph coloring |
| جدولة التعليمات | ترتيب أمثل لأنبوب المعالج (pipeline) |
| إزالة الفحوصات المكررة | إذا فُحص الحد مرة، لا يُفحص ثانية |
| تحويل الذيل (tail call) | تحويل الاستدعاء الذاتي الذيلي لحلقة |

### ٢.٤ تحسينات المستوى 3 (عدوانية)

| التحسين | الوصف |
|---------|-------|
| Vectorization | تحويل حلقات لتعليمات SIMD (SSE/AVX) |
| Devirtualization | تحويل استدعاء ديناميكي لمباشر إن أمكن |
| Interprocedural | تحسين عبر حدود الدوال |
| Profile-Guided (PGO) | تحسين بناءً على بيانات تشغيل فعلية |
| Link-Time (LTO) | تحسين عبر ملفات الترجمة عند الربط |

### ٢.٥ تلميحات المبرمج

```
// دمج دائماً — مهم للنواة
@ضمّن_دائماً
دالة قراءة_سجل_cr3() → ع64 {
    تراب { "mov {}, cr3" : "=r"(نتيجة) }
}

// لا تدمج أبداً — لأسباب تصحيح
@لا_تدمج
دالة عالج_مقاطعة(رقم: ع32) { ... }

// فرع نادر الحدوث — ضعه بعيداً
إذا @نادر(حدث_خطأ) {
    عالج_الخطأ()
}

// فرع متوقع — اجعله المسار الافتراضي
إذا @متوقع(الذاكرة_كافية) {
    خصّص()
}

// محاذاة دالة — للأداء في الحلقات الساخنة
@محاذاة(64)
دالة حلقة_ساخنة() { ... }

// لا تحسّن هذه الدالة (للتصحيح)
@بدون_تحسين
دالة تصحيح_ذاكرة() { ... }
```

### ٢.٦ التحسين الموجّه بالملف الشخصي (PGO)

```
// الخطوة 1: ترجمة مع أدوات القياس
ص ترجم --تحسين=2 --ملف-شخصي=أنشئ نواة.ص -خرج نواة_قياس

// الخطوة 2: تشغيل البرنامج (يُنشئ ملف بيانات)
./نواة_قياس    // يُنشئ: ملف_شخصي.بيانات

// الخطوة 3: إعادة الترجمة باستخدام البيانات
ص ترجم --تحسين=2 --ملف-شخصي=استخدم:ملف_شخصي.بيانات نواة.ص -خرج نواة
```

## ٣. تحسينات خاصة بنظام التشغيل

### ٣.١ تحسين context switch

```
// المترجم يعرف أن هذه الدالة تُستدعى في كل تبديل سياق
// فيُحسّنها بشكل خاص (لا function call overhead، register saving مُحسّن)
@مسار_ساخن
@ضمّن_دائماً
دالة بدّل_سياق(قديم: &متغير سياق, جديد: &سياق) {
    تراب {
        // حفظ/استعادة السجلات
        ...
    }
}
```

### ٣.٢ تحسين فحوصات الملكية

```
// المترجم يزيل فحوصات الملكية التي يُثبت عدم حاجتها
// مثال: إذا المتغير يُستخدم فقط في thread واحد
// فلا حاجة لـ atomic reference counting
```
