## ١. الوصف

نظام الملكية هو **القلب النابض** لإدارة الذاكرة في BeeOS. هو نظام يضمن أمان الذاكرة في وقت الترجمة (compile-time) بدون الحاجة إلى جامع قمامة (Garbage Collector)، مُستوحى من نظام ملكية Rust لكن بمصطلحات عربية أصيلة.

### لماذا نحتاجه؟

نظام التشغيل BeeOS **يرفض تماماً** استخدام جامع القمامة (GC) لأن:
- جامع القمامة يُسبب توقفات غير متوقعة (GC pauses) — وهذا مُدمّر لنواة نظام تشغيل تحتاج استجابة أقل من 1 ميكرو ثانية للمقاطعات
- نظام التشغيل يُدير الذاكرة الفيزيائية مباشرة — لا يوجد "وقت تشغيل" (runtime) يُدير الذاكرة عنه
- الأداء الحتمي (deterministic) مطلوب — يجب أن نعرف بالضبط متى تُحرَّر الذاكرة

### المفاهيم الأساسية

| المصطلح العربي | المكافئ في Rust | الشرح |
|---------------|----------------|-------|
| **مالك** (mālik) | owner | المتغير الذي يملك القيمة — مسؤول عن تحريرها |
| **مُعير** (mu'īr) | &mut / unique borrow | استعارة حصرية — يمكن القراءة والكتابة، لا أحد آخر يستطيع الوصول |
| **مُستعير** (musta'īr) | & / shared borrow | استعارة مشتركة — قراءة فقط، يمكن لعدة متغيرات الاستعارة |
| **وقف** (waqf) | 'static lifetime | عمر ثابت — القيمة تعيش طوال عمر البرنامج |
| **مشترك<>** | Arc<>/Rc<> | عداد مرجعي اختياري للحالات المعقدة |

## ٢. المتطلبات التفصيلية

### ٢.١ قواعد الملكية الأساسية

المترجم يجب أن يُطبّق هذه القواعد ويرفض الترجمة عند انتهاكها:

1. **كل قيمة لها مالك واحد فقط في أي لحظة**
2. **عند انتهاء نطاق المالك، تُحرَّر القيمة تلقائياً وحتمياً**
3. **الملكية يمكن نقلها (move) — المالك القديم يُصبح غير صالح**
4. **يمكن إعارة القيمة بدون نقل الملكية — إما إعارة حصرية أو مشتركة**
5. **لا يمكن وجود إعارة حصرية (مُعير) وأي إعارة أخرى في نفس الوقت**
6. **يمكن وجود عدة إعارات مشتركة (مُستعير) في نفس الوقت**

### ٢.٢ تحليل الأعمار (Lifetime Analysis)

المترجم يجب أن يتتبع عمر كل مرجع ويضمن أن:
- لا يوجد مرجع يُشير إلى ذاكرة مُحرَّرة (dangling reference)
- عمر المرجع لا يتجاوز عمر القيمة المُشار إليها
- يدعم تحديد الأعمار يدوياً عند الحاجة

### ٢.٣ التحرير الحتمي (Deterministic Deallocation)

- عند خروج المتغير من النطاق (scope)، يتم تحرير الذاكرة فوراً
- لا تأخير، لا GC، لا finalization queue
- يدعم تنفيذ دالة تنظيف مخصصة (مثل Drop في Rust) عند التحرير

### ٢.٤ العداد المرجعي الاختياري (`مشترك<>`)

- للحالات التي لا يمكن فيها تحديد مالك واحد (مثل: أشجار البيانات، الهياكل الدورية)
- عداد مرجعي ذري (atomic reference counting) آمن للاستخدام بين الخيوط
- يجب أن يكون **اختيارياً** — لا يُفرض على المبرمج

## ٣. البنية اللغوية المطلوبة

```
// تعريف مالك
دع س: عدد_صحيح = 42          // `س` مالك للقيمة 42

// نقل الملكية (move)
دع ص = س                      // الملكية انتقلت لـ `ص`
// اطبع(س)                    // ❌ خطأ ترجمة! `س` لم يعد صالحاً

// إعارة مشتركة (مُستعير)
دع م = &ص                     // `م` مُستعير — قراءة فقط
دع ن = &ص                     // ✅ يمكن — عدة مُستعيرين
// ص = 100                    // ❌ خطأ! لا يمكن التعديل أثناء الإعارة

// إعارة حصرية (مُعير)
دع ع = &متغير ص               // `ع` مُعير — قراءة وكتابة
// دع ف = &ص                  // ❌ خطأ! لا يمكن إعارة أخرى أثناء الإعارة الحصرية
*ع = 100                      // ✅ يمكن التعديل عبر المُعير

// عمر ثابت (وقف)
ثابت اسم_النظام: &وقف نص = "BeeOS"    // يعيش طوال عمر البرنامج

// عداد مرجعي
دع شجرة = مشترك<عقدة>::جديد(عقدة{...})
دع فرع = شجرة.انسخ()          // عداد المراجع يزيد
// عند خروج كليهما من النطاق → العداد يصل 0 → تحرير
```

## ٤. أمثلة عملية من BeeOS

### ٤.١ مُخصِّص ذاكرة النواة (BeeWax Allocator)

```
بنية مخازن_الشمع {
    أقراص: مالك<قائمة<قرص_شمع>>    // المخصص يملك قائمة الأقراص
    خلايا: مالك<قائمة<خلية_شمع>>    // ويملك قائمة الخلايا
}

دالة خصّص(&متغير ذات، حجم: عدد_طبيعي) → نتيجة<&متغير [بايت]، خطأ_ذاكرة> {
    // المتغير `ذات` يستعير ملكية المخصص حصرياً
    // القيمة المُرجَعة هي إعارة حصرية لكتلة الذاكرة المخصصة
    // ...
}
```

### ٤.٢ نظام العمليات (BeeLifecycle)

```
بنية عملية {
    معرّف: عدد_طبيعي
    اسم: مالك<نص>                    // العملية تملك اسمها
    خريطة_خلية: مالك<BeeCellMap>     // وتملك جدول صفحاتها
    نحلات: مالك<قائمة<نحلة>>        // وتملك خيوطها
}

// عند إنهاء العملية:
// 1. كل النحلات (الخيوط) تُحرَّر أولاً
// 2. ثم جدول الصفحات
// 3. ثم الاسم
// كل هذا تلقائي بفضل نظام الملكية — لا تسرب ذاكرة
```

### ٤.٣ نظام الملفات (BeeFS)

```
دالة اقرأ_ملف(مسار: &نص) → نتيجة<مالك<[بايت]>، خطأ> {
    دع واصف = افتح(مسار، قراءة)?          // `?` ينقل الخطأ للمُستدعي
    دع بيانات = واصف.اقرأ_الكل()?          // `بيانات` ملكية جديدة
    // `واصف` يُغلق تلقائياً هنا عند خروجه من النطاق
    أعد بيانات                              // نقل ملكية البيانات للمُستدعي
}
```

## ٥. معايير القبول

- [ ] المترجم يرفض كود يُحاول استخدام متغير بعد نقل ملكيته
- [ ] المترجم يرفض كود يُحاول التعديل أثناء وجود إعارة مشتركة
- [ ] المترجم يرفض كود يُحاول إنشاء إعارتين حصريتين لنفس القيمة
- [ ] المترجم يكشف مراجع مُعلَّقة (dangling references) في وقت الترجمة
- [ ] الذاكرة تُحرَّر حتمياً عند خروج المالك من النطاق
- [ ] دعم `مشترك<>` لعداد مرجعي ذري
- [ ] دعم تحديد الأعمار يدوياً للحالات المعقدة
- [ ] كل رسائل الخطأ المتعلقة بالملكية بالعربية الفصحى وواضحة
- [ ] الأداء: لا overhead في وقت التشغيل — كل التحقق في وقت الترجمة

## ٦. ملاحظات تقنية

- نظام الملكية يجب أن يكون **مدمجاً في قلب المترجم** — ليس مكتبة إضافية
- يجب أن يتكامل مع كتل `خطر {}` (الميزة 08) لتجاوز القواعد عند الحاجة
- يجب أن يتكامل مع العمليات الذرية (الميزة 09) لدعم الملكية بين الخيوط
- يجب أن يعمل بشكل صحيح في وضع النواة (الميزة 22) بدون مكتبة قياسية
