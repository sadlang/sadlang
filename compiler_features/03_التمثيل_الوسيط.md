## ١. الوصف

التمثيل الوسيط (Intermediate Representation — IR) هو **الجسر** بين كود لغة ص العالي المستوى وكود الآلة المنخفض المستوى. BeeIR هي طبقة وسيطة يُحوِّل المترجم كود ص إليها أولاً، ثم تُجرى عليها التحسينات، ثم تُحوَّل إلى كود الآلة النهائي.

### لماذا نحتاجها؟

1. **فصل الواجهة الأمامية عن الخلفية**: كود ص يُحوَّل إلى BeeIR مرة واحدة، ثم تُنتج عدة خلفيات (x86_64، ARM64) من نفس IR
2. **التحسينات**: التحسينات تُجرى على IR بشكل مستقل عن المعمارية المستهدفة
3. **الاستضافة الذاتية**: المترجم يُترجم نفسه — BeeIR يجعل هذا أسهل
4. **الهدف: أداء C/C++ مع أمان Rust**: هذا مطلب صريح في مواصفات BeeOS (س81)

### القرار المعماري الحاسم

BeeOS يتطلب **AOT فقط** (Ahead-Of-Time compilation) — **لا JIT في النواة**. هذا يعني أن BeeIR يجب أن تكون مُصمَّمة للترجمة الساكنة مسبقاً.

## ٢. المتطلبات التفصيلية

### ٢.١ بنية BeeIR

يجب أن تكون BeeIR لغة وسيطة مكتوبة الأنواع (typed IR) تدعم:

- **SSA (Static Single Assignment)**: كل متغير يُعيَّن مرة واحدة فقط — هذا يُسهّل التحسينات
- **كتل أساسية (Basic Blocks)**: الكود مُقسَّم إلى كتل بنقاط دخول وخروج واضحة
- **رسم تدفق التحكم (Control Flow Graph)**: للتحليل والتحسين
- **معلومات الأنواع**: الأنواع محفوظة في IR لدعم التحسينات المعتمدة على الأنواع
- **معلومات الملكية**: معلومات نظام الملكية محفوظة في IR لتحسينات التحرير

### ٢.٢ تحسينات المترجم المطلوبة

BeeOS يستهدف أداء C/C++ — لذلك يجب دعم هذه التحسينات على الأقل:

| التحسين | الوصف | الأهمية |
|---------|-------|---------|
| **تحليل تدفق البيانات** | تتبع كيف تتحرك القيم عبر البرنامج | أساسي |
| **إزالة الكود الميت** | حذف كود لا يؤثر على النتيجة | أساسي |
| **تضمين الدوال (Inlining)** | استبدال استدعاء دالة بجسمها | حرج للأداء |
| **تحسين الحلقات** | فك حلقات، نقل ثوابت خارج الحلقة | حرج للأداء |
| **إزالة التعبيرات الفرعية المشتركة (CSE)** | حساب التعبير مرة واحدة فقط | مهم |
| **نشر الثوابت (Constant Propagation)** | استبدال المتغيرات بقيمها الثابتة | مهم |
| **طي الثوابت (Constant Folding)** | حساب التعبيرات الثابتة في وقت الترجمة | مهم |
| **تحسين استدعاء الذيل (Tail Call)** | تحويل الاستدعاء الذيلي لقفزة | مهم للتكرار |
| **تحليل الاسم المستعار (Alias Analysis)** | معرفة هل مؤشران يُشيران لنفس الذاكرة | مهم |
| **التوجيه الآلي (Auto-vectorization)** | تحويل حلقات عددية لتعليمات SIMD | متقدم |

### ٢.٣ تحسينات وقت الربط (LTO — Link-Time Optimization)

- دعم LTO لتمكين التحسينات عبر حدود الملفات
- مهم جداً لأداء النواة حيث الدوال الصغيرة كثيرة
- يجب دعم LTO كامل وجزئي (Thin LTO)

## ٣. البنية اللغوية المطلوبة

لا توجد بنية لغوية مرئية للمبرمج — BeeIR هي طبقة داخلية في المترجم. لكن يجب دعم:

### ٣.١ تلميحات التحسين (Optimization Hints)

```
// تلميح بتضمين الدالة دائماً
@ضمّن_دائماً
دالة حجم_الصفحة() → عدد_طبيعي {
    أعد 4096
}

// تلميح بعدم تضمين الدالة (كبيرة جداً)
@لا_تضمّن
دالة عالج_الخطأ(خطأ: &خطأ_نظام) {
    // ...
}

// تلميح بأن هذا الفرع نادر (cold path)
إذا خطأ {
    @نادر
    عالج_الخطأ(خطأ)
}

// تلميح بمحاذاة الدالة لحدود ذاكرة (لأداء المقاطعات)
@محاذاة(4096)
خطر دالة معالج_المقاطعة_0() {
    // ...
}
```

### ٣.٢ مستويات التحسين

المترجم يجب أن يدعم مستويات تحسين متعددة:

```
// سطر الأوامر
ص ترجم --تحسين=0     // بدون تحسين — للتصحيح
ص ترجم --تحسين=1     // تحسينات أساسية
ص ترجم --تحسين=2     // تحسينات كاملة — الإنتاج
ص ترجم --تحسين=س     // تحسين للحجم (صغير)
ص ترجم --تحسين=3     // أقصى تحسين (قد يُبطئ الترجمة)
```

## ٤. أمثلة عملية من BeeOS

### ٤.١ تحسين دالة مكررة في النواة

```
// قبل التحسين:
دالة اقرأ_بايت(عنوان: عدد_طبيعي_64) → بايت {
    دع مؤشر = عنوان كـ *ثابت بايت
    أعد خطر { *مؤشر }
}

دالة اقرأ_سجل_الجهاز() → بايت {
    أعد اقرأ_بايت(0xFEE000B0)    // عنوان سجل APIC
}

// بعد التحسين (inlining + constant propagation):
// الدالة تُختصر إلى تعليمة واحدة: mov al, [0xFEE000B0]
```

### ٤.٢ تحسين حلقة التشفير

```
// المترجم يجب أن يُحسّن هذه الحلقة:
دالة xor_كتلة(بيانات: &متغير [بايت; 64], مفتاح: &[بايت; 64]) {
    لكل ي في 0..64 {
        بيانات[ي] ^= مفتاح[ي]
    }
}

// إلى تعليمات SIMD عبر auto-vectorization:
// vpxor ymm0, ymm0, [مفتاح]       — 32 بايت XOR دفعة واحدة
// vpxor ymm1, ymm1, [مفتاح+32]    — 32 بايت أخرى
```

## ٦. ملاحظات تقنية

- BeeIR يجب أن تكون **أصلية** — لا نريد LLVM IR لأن ذلك يخلق تبعية على مكتبة C++ ضخمة
- يمكن الاستلهام من LLVM IR أو Cranelift IR في التصميم، لكن الكتابة بلغة ص
- التحسينات يمكن إضافتها تدريجياً — الأساسيات أولاً ثم المتقدمة
- يجب أن تحمل BeeIR معلومات التصحيح (debug info) لدعم DWARF (الميزة 20)
