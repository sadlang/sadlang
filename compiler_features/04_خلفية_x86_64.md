# الميزة 04: خلفية إنتاج كود x86_64

**بسم الله الرحمن الرحيم**

**الأولوية**: 🔴 حرجة — المرحلة 1
**المرجع**: س81 من مواصفات BeeOS، المهمة T017، م-و-025
**التبعيات**: التمثيل الوسيط BeeIR (الميزة 03)

---

## ١. الوصف

خلفية x86_64 هي المكوّن المسؤول عن تحويل BeeIR إلى **كود آلة أصلي** (native machine code) لمعالجات x86_64 (Intel/AMD). هذا هو الهدف الأول والأساسي لمترجم لغة ص لبناء BeeOS.

### لماذا نحتاجها؟

BeeOS يستهدف **كود آلة أصلي مباشرة** — لا VM، لا bytecode، لا interpreter. هذا قرار معماري حاسم (س81) لأن:

- نظام التشغيل يعمل على المعالج مباشرة — لا يوجد "طبقة وسيطة" تحته
- الأداء المستهدف: مستوى C/C++ مع أمان Rust
- أول إقلاع bare metal يجب أن يحدث في أشهر 1-6 من المشروع

---

## ٢. المتطلبات التفصيلية

### ٢.١ إنتاج كود الآلة

المترجم يجب أن يُنتج:

- **ملفات كائنية (Object Files)**: بصيغة ELF أو صيغة `.نحلة` المخصصة
- **ملفات تنفيذية مباشرة**: kernel binary يمكنه الإقلاع على bare metal
- **مكتبات ثابتة (Static Libraries)**: `.a` أو ما يُكافئها
- **مكتبات مشتركة (Shared Libraries)**: `.شمع` — صيغة BeeOS المخصصة (س114)

### ٢.٢ اتفاقية الاستدعاء (Calling Convention)

يجب دعم:

- **اتفاقية BeeOS الأصلية**: اتفاقية استدعاء مخصصة مُحسَّنة لنواة BeeOS
- **اتفاقية System V AMD64 ABI**: للتوافقية مع كود C عند الحاجة
- **اتفاقية مقاطعات x86_64**: لمعالجات المقاطعات (يحفظ كل السجلات)

### ٢.٣ مجموعات التعليمات المدعومة

| المجموعة | الوصف | الأهمية |
|---------|-------|---------|
| **x86_64 أساسي** | التعليمات الأساسية (mov, add, jmp, call...) | إلزامي |
| **SSE2** | عمليات SIMD 128-bit (افتراضي في x86_64) | إلزامي |
| **SSE4.2** | CRC32 + مقارنة نصوص | مهم |
| **AVX/AVX2** | عمليات SIMD 256-bit | مهم للأداء |
| **AES-NI** | تسريع AES عتادي | مهم للتشفير |
| **POPCNT/LZCNT** | عد البتات | مهم للخوارزميات |
| **BMI1/BMI2** | معالجة بتات متقدمة | مفيد |
| **RDRAND/RDSEED** | أرقام عشوائية عتادية | مهم للتشفير |
| **TSC** | عدّاد دورات المعالج | مهم للتوقيت |

### ٢.٤ تعليمات النظام (System Instructions)

لبناء نظام تشغيل، يجب دعم إنتاج:

- `cli/sti` — تعطيل/تمكين المقاطعات
- `lgdt/lidt/lldt/ltr` — تحميل جداول النظام
- `mov crN` — سجلات التحكم
- `mov drN` — سجلات التصحيح
- `rdmsr/wrmsr` — سجلات النموذج
- `invlpg` — إبطال TLB
- `iretq` — عودة من مقاطعة
- `syscall/sysret` — انتقال نواة/مستخدم
- `hlt` — إيقاف المعالج
- `cpuid` — استعلام قدرات المعالج
- `in/out` — قراءة/كتابة منافذ I/O
- `wbinvd` — مسح ذاكرة التخزين المؤقت
- `mfence/sfence/lfence` — حواجز الذاكرة

### ٢.٥ تخصيص السجلات (Register Allocation)

مُخصص سجلات فعّال يدعم:
- 16 سجل عام (rax-r15)
- 16 سجل XMM/YMM (xmm0-xmm15)
- التعامل مع السجلات المحجوزة (rsp, rbp اختياري)
- تسرب إلى المكدس (spilling) عند نفاد السجلات
- تلوين الرسم البياني (Graph Coloring) أو خوارزمية خطية (Linear Scan)

### ٢.٦ الربط (Linking)

- ربط ثابت (static linking) — إلزامي للنواة
- ربط ديناميكي (dynamic linking) — لتطبيقات المستخدم
- دعم ربط مع ملفات `.تراب` (Assembly)
- دعم خرائط الربط (linker scripts) لتحديد عناوين الذاكرة في النواة

## ٣. أمثلة عملية من BeeOS

### ٣.١ إنتاج kernel binary

```
// أمر ترجمة النواة:
ص ترجم \
    --هدف=x86_64-نحلة-bare \
    --لا-مكتبة-قياسية \
    --خريطة-ربط=نواة/ربط.خريطة \
    --تحسين=2 \
    --مخرج=نواة.bin \
    نواة/الملكة/الرئيسية.ص
```

### ٣.٢ خريطة الربط للنواة

```
// ملف: نواة/ربط.خريطة
أقسام {
    .نص 0xFFFFFFFF80000000 : {    // النواة تبدأ في النصف الأعلى
        *(.نص.بداية)               // نقطة الدخول أولاً
        *(.نص)                     // كل الكود
    }
    .قراءة_فقط : {
        *(.قراءة_فقط)              // بيانات ثابتة
        *(.نصوص)                   // سلاسل نصية
    }
    .بيانات : {
        *(.بيانات)                 // بيانات متغيرة مُهيَّأة
    }
    .صفر : {
        *(.صفر)                    // بيانات غير مُهيَّأة (BSS)
    }
}
نقطة_الدخول = _بداية
```
