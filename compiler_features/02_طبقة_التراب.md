# الميزة 02: طبقة التراب — دعم Assembly المضمّن (BeeTurab)

**بسم الله الرحمن الرحيم**

**الأولوية**: 🔴 حرجة — المرحلة 1
**المرجع**: س83 من مواصفات BeeOS، المهمة T015
**التبعيات**: خلفية x86_64 (الميزة 04)

---

## ١. الوصف

طبقة التراب (BeeTurab) هي الأدنى في بنية نظام BeeOS — هي الطبقة الوحيدة التي يُسمح فيها بكتابة Assembly مباشرة. الاسم مُستوحى من أن التراب هو أدنى طبقات الأرض، وكذلك Assembly هي أدنى طبقات البرمجة.

### لماذا نحتاجها؟

هناك عمليات في نظام التشغيل **لا يمكن** كتابتها بأي لغة عالية المستوى:

1. **الإقلاع (Boot)**: أول تعليمات يُنفذها المعالج يجب أن تكون Assembly
2. **تبديل السياق (Context Switch)**: حفظ واستعادة سجلات المعالج يتطلب تعليمات Assembly مباشرة
3. **المقاطعات (Interrupts)**: معالجات المقاطعات تحتاج تعليمات خاصة (`iret`, `cli`, `sti`)
4. **الدخول/الخروج من النواة**: تعليمات `syscall`/`sysret` لا يمكن استدعاؤها من لغة عالية
5. **عمليات المعالج الخاصة**: مثل `rdmsr`, `wrmsr`, `cpuid`, `invlpg`, `hlt`
6. **عمليات التشفير العتادية**: `aesenc`, `aesenclast` لتسريع AES-NI

### مبدأ الحد الأدنى المطلق

دستور BeeOS (§2) ينص على أن Assembly يُستخدم **فقط** حيث لا بديل. لذلك المترجم يجب أن يوفر طريقة لكتابة Assembly المضمّن بشكل آمن ومحدود.

---

## ٢. المتطلبات التفصيلية

### ٢.١ كتلة `تراب نهاية` للـ Inline Assembly

المترجم يجب أن يدعم كتلة خاصة `تراب نهاية` تحتوي تعليمات Assembly:

- التعليمات داخل `تراب نهاية` تُمرَّر مباشرة لمُجمّع Assembly
- يجب دعم تمرير متغيرات لغة ص كمدخلات ومخرجات
- يجب تحديد السجلات المُستخدمة والمُتأثرة (clobbers)
- يجب أن يكون استخدام `تراب نهاية` داخل كتلة `خطر نهاية` إلزامياً

### ٢.٢ ملفات `.تراب` المعزولة

بالإضافة إلى inline assembly، يجب دعم ملفات Assembly كاملة بامتداد `.تراب`:

- تُترجم بشكل منفصل وتُربط مع كود لغة ص
- كل ملف `.تراب` يجب أن يكون مستقلاً ومعزولاً
- يمكن استدعاء دوال `.تراب` من كود ص عبر واجهة خارجية

### ٢.٣ قيود أمان إلزامية

- **كل سطر Assembly يجب أن يكون مُعلَّقاً بتعليق عربي** — المترجم يرفض assembly بدون تعليقات
- **لا يمكن استخدام `تراب ... نهاية` خارج كتلة `خطر ...  نهاية`** — خطأ ترجمة
- **تحذير عند تجاوز حد أسطر Assembly** — لتشجيع كتابة أكبر قدر بلغة ص

## ٣. البنية اللغوية المطلوبة

### ٣.١ Inline Assembly

```
# تعطيل المقاطعات
خطر 
    تراب 
        "cli"    # أوقفي المقاطعات
    نهاية
نهاية

# قراءة سجل CR3 (جدول الصفحات)
خطر 
    دع قيمة: عدد_طبيعي_64
    تراب 
        "mov نتيجةنهاية, cr3"    # انسخي سجل جدول الصفحات
        نتيجة = قيمة           # المخرج
    نهاية
نهاية

# كتابة في منفذ I/O
خطر 
    تراب 
        "out dx, al"          # أرسلي البايت إلى المنفذ
        مدخلات: dx = المنفذ, al = القيمة    # المدخلات
    نهاية
نهاية

# تعليمة CPUID
خطر 
    دع eax_نتيجة: عدد_طبيعي_32
    دع ebx_نتيجة: عدد_طبيعي_32
    تراب 
        "cpuid"               # استعلمي عن قدرات المعالج
        مخرجات: eax = eax_نتيجة, ebx = ebx_نتيجة
        مدخلات: eax = الوظيفة
        يُتلف: ecx, edx       # سجلات تتغير
    نهاية
نهاية
```

### ٣.٢ ملفات `.تراب`

```
# ملف: نواة/التراب/تبديل_سياق.تراب

# === تبديل سياق العملية ===
# هذه الدالة تحفظ سجلات العملية الحالية وتستعيد سجلات العملية التالية

.عام بدّل_السياق                    # اجعلي هذا الرمز عاماً
بدّل_السياق:
    push rbp                         # احفظي مؤشر الإطار
    push rbx                         # احفظي السجل الأساسي
    push r12                         # احفظي السجل 12
    push r13                         # احفظي السجل 13
    push r14                         # احفظي السجل 14
    push r15                         # احفظي السجل 15
    mov [rdi], rsp                   # احفظي مؤشر المكدس الحالي
    mov rsp, rsi                     # استعيدي مؤشر مكدس العملية التالية
    pop r15                          # استعيدي السجل 15
    pop r14                          # استعيدي السجل 14
    pop r13                          # استعيدي السجل 13
    pop r12                          # استعيدي السجل 12
    pop rbx                          # استعيدي السجل الأساسي
    pop rbp                          # استعيدي مؤشر الإطار
    ret                              # ارجعي للعملية التالية
```

### ٣.٣ استدعاء دوال `.تراب` من لغة ص

```
# الإعلان عن دالة Assembly خارجية
خارجي دالة بدّل_السياق(
    المكدس_الحالي: &متغير عدد_طبيعي_64,
    المكدس_التالي: عدد_طبيعي_64
)

# الاستخدام
خطر 
    بدّل_السياق(&متغير عمليتي.مكدس، العملية_التالية.مكدس)
نهاية
```

## ٤. أمثلة عملية من BeeOS

### ٤.١ معالج المقاطعات (BeeAlarm)

```
# ملف: نواة/الملكة/مقاطعات/جرس_الخلية.ص

#/ معالج مقاطعة المؤقت — الصرخة (top half)
#/ يجب أن يكتمل في أقل من 1 ميكرو ثانية
خطر دالة معالج_المؤقت() 
    # حفظ السجلات يتم في كود التراب قبل الوصول هنا
    
    تراب 
        "push rax"              # احفظي السجل المُتراكم
        "mov al, 0x20"          # جهّزي أمر نهاية المقاطعة
        "out 0x20, al"          # أرسلي EOI لمتحكم المقاطعات
        "pop rax"               # استعيدي السجل المُتراكم
    نهاية
    
    # باقي المنطق بلغة ص الآمنة
    المُجدوِل.علامة_مؤقت()
نهاية
```

### ٤.٢ تسريع AES-NI للتشفير (BeeVault)

```
#/ تشفير كتلة AES-128 باستخدام تعليمات العتاد
خطر دالة شفّر_aes_ni(
    بيانات: &متغير [بايت; 16],
    مفاتيح: &[بايت; 176]     # 11 مفتاح × 16 بايت
) 
    تراب 
        "movdqu xmm0, [بياناتنهاية]"     # حمّلي كتلة البيانات
        "movdqu xmm1, [مفاتيحنهاية]"     # حمّلي المفتاح الأول
        "pxor xmm0, xmm1"              # XOR مع المفتاح الأولي
        "aesenc xmm0, [مفاتيحنهاية+16]"  # الجولة 1
        "aesenc xmm0, [مفاتيحنهاية+32]"  # الجولة 2
        # ... الجولات 3-9
        "aesenclast xmm0, [مفاتيحنهاية+160]"  # الجولة الأخيرة
        "movdqu [بياناتنهاية], xmm0"      # خزّني النتيجة
        مدخلات: بيانات, مفاتيح
        يُتلف: xmm0, xmm1
    نهاية
نهاية
```

## ٦. ملاحظات تقنية

- كتلة `تراب نهاية` يجب أن تُترجم إلى inline assembly في الكود المُنتَج
- ملفات `.تراب` يجب أن تمر بمُجمّع Assembly (مثل NASM أو as) ثم تُربط مع الكود
- يجب التحقق من صحة أسماء السجلات والتعليمات في وقت الترجمة
- تبعية على الميزة 04 (خلفية x86_64) لمعرفة التعليمات المدعومة
- تبعية على الميزة 05 (خلفية ARM64) لدعم Assembly لـ AArch64 لاحقاً
