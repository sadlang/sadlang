---

## ١. الوصف

كتلة `خطر {}` (مثل `unsafe {}` في Rust) هي آلية تسمح بتجاوز ضمانات أمان المترجم عند الحاجة. في نظام التشغيل، هناك عمليات **لا يمكن** أن تكون آمنة بالتعريف — مثل الكتابة في عنوان ذاكرة ثابت أو تنفيذ تعليمات assembly. كتلة `خطر {}` تُحدد هذه المناطق بوضوح وتُلزم المبرمج بتدقيق إضافي.

### القيد في BeeOS

BeeOS يشترط **تدقيقاً إلزامياً** لكل كود `خطر {}`:
- مراجعة أمنية مزدوجة (حارسة + كشّافة) — س83
- تعليق عربي يشرح لماذا الكود غير آمن ضروري
- هدف: تقليل `خطر {}` للحد الأدنى المطلق

---

## ٢. المتطلبات التفصيلية

### ٢.١ ما يُسمح به داخل `خطر {}`

| العملية | مثال |
|---------|------|
| تفكيك مؤشر خام | `*مؤشر` |
| استدعاء دالة غير آمنة | `خطر دالة()` |
| الوصول لمتغير عام قابل للتغيير | `متغير_عام = 5` |
| كتلة تراب (assembly) | `تراب { "cli" }` |
| تحويل أنواع غير آمن | `قيمة كـ *متغير ن` |
| الوصول لحقول union | `اتحاد.حقل` |

### ٢.٢ دوال غير آمنة

```
// دالة كاملة مُعلَّنة كخطر — المستدعي يجب أن يكون في كتلة خطر
خطر دالة اكتب_في_منفذ(منفذ: ع16, قيمة: بايت) {
    تراب {
        "out dx, al"           // أرسلي البيانات إلى المنفذ
        مدخلات: dx = منفذ, al = قيمة
    }
}

// الاستدعاء يتطلب خطر
خطر {
    اكتب_في_منفذ(0x3F8, 0x41)     // كتابة 'A' في COM1
}
```

### ٢.٣ سمات غير آمنة (Unsafe Traits)

```
// سمة تتطلب تنفيذ آمن يدوي
خطر سمة مُرسَل {}     // يمكن إرسال القيمة بين الخيوط
خطر سمة مُشارَك {}     // يمكن مشاركة المرجع بين الخيوط

// التنفيذ يتطلب خطر
خطر نفّذ مُرسَل لـ مؤشر_ذري<ن> {}
```

## ٤. ملاحظات تقنية

- `خطر {}` لا تعني "الكود خاطئ" — بل تعني "المبرمج يتحمل مسؤولية صحته"
- المترجم يجب أن يستمر في تطبيق كل التحققات الممكنة داخل `خطر {}`
- فقط التحققات التي **لا يمكن** تطبيقها تُعلَّق (مثل تتبع الملكية عبر مؤشرات خام)
