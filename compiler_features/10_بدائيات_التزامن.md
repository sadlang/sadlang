## ١. الوصف

BeeOS يُعرّف بدائيات تزامن بأسماء عربية مُستوحاة من حياة النحل. المترجم يجب أن يفهم هذه المفاهيم ويفرض استخدامها — **لا ذاكرة مشتركة بدون رقصة** (خطأ ترجمة لا تحذير).

### أنواع الرقص (بدائيات التزامن)

| الاسم العربي | المكافئ | الوصف |
|-------------|---------|-------|
| **دوري** | Mutex | قفل حصري — نحلة واحدة تدخل |
| **اهتزي** | Spinlock | قفل دوّار — للعمليات القصيرة جداً |
| **نبّهي** | Condition Variable | إشارة انتظار — نحلة تنتظر حدثاً |
| **ذرّي** | Atomic | عمليات ذرية (الميزة 09) |
| **ملكي** | RWLock | قفل ملكي — قراءة متعددة أو كتابة واحدة |

## ٢. المتطلبات التفصيلية

### ٢.١ فرض التزامن في المترجم

```
// ❌ هذا الكود يُرفض — مشاركة بيانات بدون تزامن
بنية حالة_مشتركة {
    عدّاد: عدد_طبيعي,     // ❌ خطأ ترجمة: ليس آمناً للمشاركة بين الخيوط
}

// ✅ الطريقة الصحيحة
بنية حالة_مشتركة {
    عدّاد: دوري<عدد_طبيعي>,     // ✅ محمي بقفل
}

// أو
بنية حالة_مشتركة {
    عدّاد: ذرّي<عدد_طبيعي>,     // ✅ ذري
}
```

### ٢.٢ قناة الرسائل (Channel)

```
// قناة رسائل آمنة — البديل المُفضّل للذاكرة المشتركة
دع (مُرسِل، مُستقبِل) = قناة_جديدة<رسالة>()

// الإرسال
انطلقي {
    مُرسِل.أرسل(رسالة{ نوع: "بيانات", محتوى: بيانات })
}

// الاستقبال
دع رسالة = مُستقبِل.استقبل()    // ينتظر حتى تصل رسالة
```

### ٢.٣ كاشف الجمود (Deadlock Detector)

المترجم يجب أن يكشف بعض حالات الجمود في وقت الترجمة:
- قفلان يُؤخذان بترتيب مختلف في مسارات مختلفة
- خيط يُحاول أخذ قفل يملكه أصلاً

---

## ٣. معايير القبول

- [ ] المترجم يرفض مشاركة بيانات غير محمية بين خيوط (خطأ ترجمة)
- [ ] دعم `دوري<ن>` (Mutex)
- [ ] دعم `ملكي<ن>` (RWLock)
- [ ] دعم قنوات رسائل `قناة<ن>`
- [ ] دعم `انطلقي {}` لإنشاء خيط (نحلة)
- [ ] تحذير عند اكتشاف جمود محتمل
- [ ] سمات `مُرسَل` و `مُشارَك` تُفرض تلقائياً

---

## ٤. ملاحظات تقنية

- بدائيات التزامن يمكن أن تكون **مكتبة** وليست في المترجم مباشرة
- لكن **فرض التزامن** (رفض مشاركة بيانات غير محمية) يجب أن يكون في المترجم
- القنوات والأقفال يمكن بناؤها بلغة ص فوق العمليات الذرية (الميزة 09)
