# الميزة 11: الأنواع المعممة (Generics)

**بسم الله الرحمن الرحيم**

**الأولوية**: 🔴 حرجة — المرحلة 1
**المرجع**: عقود BeeOS API (`contracts/bee-api.md`)، نموذج البيانات
**التبعيات**: لا تبعيات

---

## ١. الوصف

الأنواع المعممة (Generics) تسمح بكتابة كود يعمل مع **أي نوع** بدون تكرار. هذا أساسي لـ BeeOS الذي يستخدم أنواعاً معممة في كل مكان: `قائمة<عملية>`، `نتيجة<بيانات، خطأ>`، `ذرّي<ع64>`، `قناة<رسالة>`.

### لماذا هي حرجة؟

بالنظر إلى عقود API لـ BeeOS، **كل** واجهة تقريباً تستخدم أنواعاً معممة:

```
ارقصي<ن>(قناة: قناة<ن>، رسالة: ن) → نتيجة<()، خطأ>
قناة_جديدة<ن>() → (مُرسل<ن>، مُستقبل<ن>)
حالة<ن>(قيمة_أولية: ن) → (ن، دالة(ن))
إعداد<ن>(مسار: نص) → نتيجة<ن، خطأ>
```

بدون Generics، سنحتاج كتابة نسخة منفصلة لكل نوع — مستحيل عملياً.

---

## ٢. المتطلبات التفصيلية

### ٢.١ دوال معممة

```
// دالة تعمل مع أي نوع
دالة بادل<ن>(أ: &متغير ن, ب: &متغير ن) {
    دع مؤقت = أ
    أ = ب
    ب = مؤقت
}

// دالة معممة مع قيد (constraint)
دالة الأكبر<ن: قابل_للمقارنة>(أ: ن, ب: ن) → ن {
    إذا أ > ب { أعد أ } وإلا { أعد ب }
}
```

### ٢.٢ بنيات معممة

```
// قائمة معممة
بنية قائمة<ن> {
    عناصر: مالك<[ن]>,
    عدد: عدد_طبيعي,
}

// خريطة معممة
بنية خريطة<م, ق> {
    أزواج: قائمة<(م, ق)>,
}

// اختياري معمم
تعداد اختياري<ن> {
    بعض(ن),
    لا_شيء,
}
```

### ٢.٣ قيود الأنواع (Type Constraints)

```
// النوع يجب أن يدعم سمة معينة
دالة اطبع<ن: قابل_للعرض>(قيمة: ن) {
    اطبع(قيمة.إلى_نص())
}

// عدة قيود
دالة خزّن_في_خريطة<م: قابل_للتجزئة + قابل_للمقارنة, ق>(
    خريطة: &متغير خريطة<م, ق>,
    مفتاح: م,
    قيمة: ق
) {
    // ...
}

// قيد حجم ثابت (مطلوب للنواة)
دالة انسخ_ذاكرة<ن: حجم_ثابت>(المصدر: &ن, الهدف: &متغير ن) {
    // حجم النوع معروف في وقت الترجمة
}
```

### ٢.٤ Monomorphization (التخصيص)

المترجم يجب أن يُنشئ نسخة متخصصة من الكود المعمم لكل نوع فعلي يُستخدم:

```
// الكود الأصلي:
دالة أضف<ن: عددي>(أ: ن, ب: ن) → ن { أعد أ + ب }

// الاستدعاءات:
أضف(1_ع32, 2_ع32)
أضف(1.0_حم64, 2.0_حم64)

// المترجم يُنشئ:
دالة أضف_ع32(أ: ع32, ب: ع32) → ع32 { أعد أ + ب }
دالة أضف_حم64(أ: حم64, ب: حم64) → حم64 { أعد أ + ب }
```

هذا يضمن **صفر overhead** في وقت التشغيل — الأداء مماثل لكتابة الكود يدوياً لكل نوع.

## ٣. أمثلة عملية من BeeOS

### ٣.١ نظام الملفات

```
// من عقود BeeOS API
افتح(مسار: نص, وضع: وضع_ملف) → نتيجة<واصف_ملف, خطأ>
اقرأ(واصف: واصف_ملف, حجم: عدد_طبيعي) → نتيجة<[بايت], خطأ>
```

### ٣.٢ الخيوط

```
// إنشاء قناة معممة
دع (مُرسِل, مُستقبِل) = قناة_جديدة<حزمة_شبكة>()

// الإرسال
مُرسِل.أرسل(حزمة)

// الاستقبال
دع حزمة: حزمة_شبكة = مُستقبِل.استقبل()?
```

## ٤. معايير القبول

- [ ] دعم دوال معممة `دالة اسم<ن>(...)`
- [ ] دعم بنيات معممة `بنية اسم<ن> { ... }`
- [ ] دعم تعدادات معممة `تعداد اسم<ن> { ... }`
- [ ] دعم قيود الأنواع `<ن: سمة>` و `<ن: سمة1 + سمة2>`
- [ ] Monomorphization — صفر overhead في وقت التشغيل
- [ ] استنتاج الأنواع — المترجم يستنتج النوع من السياق عند الإمكان
- [ ] رسائل خطأ واضحة بالعربية عند عدم تطابق الأنواع
- [ ] دعم أنواع معممة متعددة `بنية خريطة<م, ق>`
- [ ] دعم قيم افتراضية للأنواع المعممة (اختياري)

---

## ٥. ملاحظات تقنية

- Monomorphization يُنتج كوداً أسرع لكن ملفاً تنفيذياً أكبر
- يمكن دعم type erasure كخيار لتقليل الحجم (لتطبيقات المستخدم)
- لكن النواة تحتاج monomorphization دائماً لأقصى أداء
- يجب أن يتكامل مع نظام الملكية — `مالك<قائمة<ن>>` يعمل بشكل صحيح
