# البنية المعمارية للمكتبة الرسومية
# Graphics Library Architecture

---

## 🏛️ نظرة عامة

### الفلسفة المعمارية

المكتبة الرسومية للغة ص تتبع معمارية متعددة الطبقات (Layered Architecture) مع فصل واضح للمسؤوليات وواجهات محددة بين الطبقات.

```
المبادئ الأساسية:
1. Separation of Concerns (فصل المسؤوليات)
2. Abstraction (التجريد)
3. Modularity (النمطية)
4. Extensibility (قابلية التوسع)
5. Performance (الأداء)
6. Cross-platform (عبور المنصات)
```

---

## 📐 الطبقات المعمارية

### نظرة شاملة

```
┌─────────────────────────────────────────────────┐
│          طبقة لغة ص (Sad Language API)          │  ← المستخدم النهائي
├─────────────────────────────────────────────────┤
│       مكتبة الرسومات (Graphics Library)         │  ← واجهة عالية المستوى
├─────────────────────────────────────────────────┤
│     طبقة التجريد (Abstraction Layer)            │  ← توحيد المنصات
├─────────────────────────────────────────────────┤
│      محركات الأساس (Base Engines)              │  ← SDL2, OpenGL, etc
├─────────────────────────────────────────────────┤
│      نظام التشغيل (Operating System)            │  ← Windows, Linux, macOS
└─────────────────────────────────────────────────┘
```

## 🔷 الطبقة 1: طبقة لغة ص (Sad Language API)

### الغرض
توفير واجهة برمجية عربية نظيفة وسهلة الاستخدام للمطورين.

### المكونات

#### 1. FFI Bridge (جسر الاستدعاء الأجنبي)
```
المسؤوليات:
- تحويل أنواع بيانات لغة ص إلى C/C++
- تحويل أنواع C/C++ إلى لغة ص
- معالجة الأخطاء والاستثناءات
- إدارة الذاكرة عبر الحدود
- callback handling

التقنيات:
- C ABI للتوافق
- جداول وظائف مُصدَّرة
- object handles (مقابض الكائنات)
- reference counting أو GC integration
```

**مثال على الربط**:
```cpp
// C++ side
extern "C" {
    WindowHandle* sad_window_create(const char* title, int width, int height) {
        return new WindowHandle(new Window(title, width, height));
    }
    
    void sad_window_set_title(WindowHandle* handle, const char* title) {
        handle->window->setTitle(title);
    }
    
    void sad_window_destroy(WindowHandle* handle) {
        delete handle->window;
        delete handle;
    }
}
```

```
// Sad language side (pseudo-code)
صنف نافذة {
    _handle: مؤشر
    
    دالة منشئ(العنوان: نص، العرض: رقم، الارتفاع: رقم) {
        هذا._handle = __ffi_call("sad_window_create"، العنوان، العرض، الارتفاع)
    }
    
    دالة اضبط_العنوان(العنوان: نص) {
        __ffi_call("sad_window_set_title"، هذا._handle، العنوان)
    }
    
    دالة تدمير() {
        __ffi_call("sad_window_destroy"، هذا._handle)
    }
}
```

#### 2. High-Level Wrappers
```
الغرض: تغليف API منخفض المستوى بواجهة عربية صديقة

الميزات:
- أسماء عربية واضحة
- معاملات افتراضية منطقية
- معالجة أخطاء شاملة
- التحقق من الصحة (validation)
- رسائل خطأ مفيدة بالعربية

الأنماط المستخدمة:
- Builder pattern (للإنشاء المعقد)
- Facade pattern (للتبسيط)
- Adapter pattern (للتوافق)
```

#### 3. Type System Integration
```
تكامل مع نظام الأنواع في لغة ص:

أنواع أساسية:
- رقم → float/double
- رقم_صحيح → int
- نص → string
- منطقي → bool
- قائمة → array
- قاموس → map/dict

أنواع رسومية:
- لون → Color (RGBA)
- نقطة → Point (x, y)
- حجم → Size (width, height)
- مستطيل → Rect (x, y, w, h)
- متجه2د → Vector2
- متجه3د → Vector3
- مصفوفة → Matrix

أنواع معقدة:
- نافذة → Window*
- راسم → Renderer*
- صورة → Texture*
- خط → Font*
- صوت → Sound*
```

### أنماط التصميم المستخدمة

#### 1. Singleton Pattern
```
الاستخدام:
- WindowManager (مدير نوافذ واحد)
- InputManager (مدير إدخال واحد)
- AudioMixer (خلاط صوت واحد)
- ResourceCache (ذاكرة تخزين موارد واحدة)

السبب: مورد مشترك يجب أن يكون له نسخة واحدة فقط

المثال:
class WindowManager {
private:
    static WindowManager* instance;
    WindowManager() {}
    
public:
    static WindowManager* getInstance() {
        if (!instance) {
            instance = new WindowManager();
        }
        return instance;
    }
    
    Window* createWindow(...) { ... }
};
```

#### 2. Factory Pattern
```
الاستخدام:
- إنشاء كائنات مختلفة حسب المنصة
- إنشاء shaders
- إنشاء textures

المثال:
class RendererFactory {
public:
    static IRenderer* create(RendererType type) {
        switch(type) {
            case OPENGL:
                return new OpenGLRenderer();
            case DIRECTX:
                return new DirectXRenderer();
            case VULKAN:
                return new VulkanRenderer();
        }
    }
};
```

#### 3. Observer Pattern
```
الاستخدام:
- نظام الأحداث
- callbacks
- event listeners

المثال:
class Window {
    std::vector<IWindowListener*> listeners;
    
public:
    void addListener(IWindowListener* listener) {
        listeners.push_back(listener);
    }
    
    void notifyResize(int width, int height) {
        for (auto listener : listeners) {
            listener->onResize(width, height);
        }
    }
};
```

#### 4. Strategy Pattern
```
الاستخدام:
- خوارزميات رسم مختلفة
- طرق معالجة مختلفة

المثال:
interface IRenderStrategy {
    void render(RenderData data);
};

class ImmediateRenderer : public IRenderStrategy { ... };
class BatchRenderer : public IRenderStrategy { ... };

class Renderer {
    IRenderStrategy* strategy;
    
public:
    void setStrategy(IRenderStrategy* s) { strategy = s; }
    void render(RenderData data) { strategy->render(data); }
};
```

#### 5. Object Pool Pattern
```
الاستخدام:
- إعادة استخدام كائنات متكررة الإنشاء/الحذف
- particles
- temporary objects

المثال:
template<typename T>
class ObjectPool {
    std::vector<T*> available;
    std::vector<T*> inUse;
    
public:
    T* acquire() {
        if (available.empty()) {
            return new T();
        }
        T* obj = available.back();
        available.pop_back();
        inUse.push_back(obj);
        return obj;
    }
    
    void release(T* obj) {
        auto it = std::find(inUse.begin(), inUse.end(), obj);
        if (it != inUse.end()) {
            inUse.erase(it);
            available.push_back(obj);
            obj->reset();  // إعادة تهيئة
        }
    }
};
```

## 🔷 الطبقة 3: طبقة التجريد (Abstraction Layer)

### الغرض
توحيد الاختلافات بين المنصات والتقنيات المختلفة.

### المكونات

#### 1. Platform Abstraction
```
الغرض: إخفاء تفاصيل نظام التشغيل

interface IPlatform {
    // Window management
    virtual WindowHandle createWindow(...) = 0;
    virtual void destroyWindow(WindowHandle) = 0;
    
    // File system
    virtual bool fileExists(const char* path) = 0;
    virtual std::vector<uint8_t> readFile(const char* path) = 0;
    
    // Time
    virtual double getTime() = 0;
    virtual void sleep(int ms) = 0;
    
    // Threading
    virtual ThreadHandle createThread(...) = 0;
};

التنفيذات:
- WindowsPlatform
- LinuxPlatform
- MacOSPlatform
```

#### 2. Rendering Backend Abstraction
```
الغرض: دعم محركات رسم مختلفة

interface IRenderBackend {
    // Initialization
    virtual bool initialize() = 0;
    virtual void shutdown() = 0;
    
    // Frame
    virtual void beginFrame() = 0;
    virtual void endFrame() = 0;
    
    // Drawing
    virtual void draw(Geometry geo, Material mat) = 0;
    virtual void drawIndexed(...) = 0;
    
    // Resources
    virtual TextureHandle createTexture(...) = 0;
    virtual BufferHandle createBuffer(...) = 0;
    virtual ShaderHandle createShader(...) = 0;
    
    // State
    virtual void setViewport(...) = 0;
    virtual void setScissor(...) = 0;
    virtual void setClearColor(...) = 0;
};

التنفيذات:
- OpenGLBackend
- VulkanBackend (مستقبلاً)
- DirectX12Backend (مستقبلاً)
```

#### 3. Audio Backend Abstraction
```
interface IAudioBackend {
    virtual bool initialize() = 0;
    virtual void shutdown() = 0;
    
    virtual SoundHandle loadSound(const char* path) = 0;
    virtual void playSound(SoundHandle, float volume, ...) = 0;
    virtual void stopSound(SoundHandle) = 0;
    
    virtual void setMasterVolume(float volume) = 0;
};

التنفيذات:
- OpenALBackend
- SDL_AudioBackend
```

## 🔷 الطبقة 4: محركات الأساس (Base Engines)

### الغرض
مكتبات خارجية وأنظمة منخفضة المستوى.

### المكتبات المستخدمة

#### 1. SDL2 (Simple DirectMedia Layer)
```
الاستخدام:
- إدارة النوافذ
- معالجة الأحداث
- OpenGL context creation
- Audio (كبديل)
- Input handling

المزايا:
- عبور المنصات
- مجتمع كبير
- مستقر وموثوق
- مفتوح المصدر
```

#### 2. OpenGL
```
الاستخدام:
- Rendering 2D/3D
- Shaders
- Textures
- Frame buffers

الإصدارات المدعومة:
- OpenGL 3.3+ (core profile)
- OpenGL 4.6 (للميزات المتقدمة)
- OpenGL ES (للموبايل مستقبلاً)
```

#### 3. GLEW/GLAD
```
الاستخدام:
- تحميل OpenGL extensions
- التوافق عبر المنصات

المفضل: GLAD (أخف وأحدث)
```

#### 4. FreeType
```
الاستخدام:
- تحميل الخطوط
- rendering glyphs
- دعم Unicode كامل
- دعم TrueType, OpenType

المزايا:
- دعم ممتاز للعربية
- جودة عالية
- مفتوح المصدر
```

#### 5. stb Libraries
```
stb_image:
- تحميل الصور (PNG, JPEG, BMP, ...)
- header-only
- سهل التكامل

stb_image_write:
- حفظ الصور

stb_truetype (بديل لـ FreeType):
- أخف ولكن أقل ميزات
```

#### 6. OpenAL (أو miniaudio)
```
OpenAL:
- audio 3D
- أكثر قوة
- صعب قليلاً

miniaudio:
- header-only
- أسهل تكامل
- يكفي لمعظم الحالات
```

#### 7. GLM (OpenGL Mathematics)
```
الاستخدام:
- رياضيات الرسومات
- vectors, matrices
- transformations
- camera math

المزايا:
- مطابق لـ GLSL
- header-only
- performance ممتاز
```

## 🔄 تدفق البيانات (Data Flow)

### مثال: رسم مربع

```
1. كود لغة ص:
   راسم.ارسم_مربع(100، 100، 50، 50)
   
2. FFI Bridge:
   sad_renderer_draw_rect(renderer_handle, 100, 100, 50, 50)
   
3. Graphics Library (Renderer2D):
   renderer->drawRect(Rect(100, 100, 50, 50))
   ↓
   // تحويل لـ geometry
   vertices = createRectVertices(...)
   ↓
   // إضافة لـ batch
   batch->addRect(vertices, currentColor, currentTransform)
   
4. Abstraction Layer (RenderBackend):
   backend->draw(vertices, material)
   
5. Base Engine (OpenGL):
   glBindBuffer(...)
   glBufferData(...)
   glDrawArrays(GL_TRIANGLES, ...)
   
6. OS/Driver:
   تنفيذ الرسم على GPU
```

## 💾 إدارة الموارد (Resource Management)

### استراتيجية التخزين المؤقت

```
ResourceManager (Singleton):
  ├── TextureCache
  │   └── Map<string, Texture*>
  ├── FontCache
  │   └── Map<string, Font*>
  ├── ShaderCache
  │   └── Map<string, Shader*>
  ├── ModelCache
  │   └── Map<string, Model*>
  └── SoundCache
      └── Map<string, Sound*>

ميزات:
- Reference counting
- Lazy loading
- Auto-unload (LRU)
- Async loading (threading)
- Hot reloading (للتطوير)
```

### دورة حياة المورد

```
1. Request (طلب)
   resource = ResourceManager::load("texture.png")
   
2. Check Cache (فحص التخزين)
   if (cache.has("texture.png"))
       return cache.get("texture.png")  // موجود
   
3. Load (تحميل)
   data = loadFromDisk("texture.png")
   resource = createResource(data)
   
4. Store (تخزين)
   cache.put("texture.png", resource)
   resource.refCount++
   
5. Use (استخدام)
   // ...
   
6. Release (تحرير)
   resource.refCount--
   if (resource.refCount == 0)
       cache.markForUnload(resource)
   
7. Unload (تفريغ)
   // عند نقص الذاكرة أو بعد مدة
   cache.unloadUnused()
```

## 🧵 Multi-threading Architecture

### استراتيجية الخيوط

```
Main Thread (الخيط الرئيسي):
- Game/App logic
- Rendering commands
- Input processing
- Present frame

Render Thread (خيط الرسم) - اختياري:
- OpenGL calls
- GPU commands
- Buffer uploads

Asset Loading Thread(s):
- File I/O
- Texture decompression
- Model parsing
- Audio loading

Physics Thread (مرحلة متقدمة):
- Physics simulation
- Collision detection

Audio Thread:
- Audio mixing
- Effects processing
- Streaming
```

### التزامن (Synchronization)

```
تقنيات:
- Command buffers (للرسم)
- Lock-free queues (لتمرير البيانات)
- Atomic operations (للأعلام والعدادات)
- Mutex (عند الضرورة فقط)
- Condition variables (للانتظار)

مثال:
// Main thread
commandBuffer.addDrawCommand(...)
commandBuffer.submit()

// Render thread
while (running) {
    auto commands = commandBuffer.fetch()
    for (auto cmd : commands) {
        executeCommand(cmd)
    }
}
```

## 📊 معايير الأداء

### أهداف الأداء

```
2D Rendering:
- 10,000+ sprites @ 60 FPS
- 1,000+ draw calls/frame
- < 16ms frame time

3D Rendering:
- 100,000+ triangles @ 60 FPS
- 50+ draw calls
- 10+ dynamic lights

Memory:
- Base: < 50 MB
- With assets: < 200 MB
- Leak-free (zero leaks)

Startup:
- < 1 second (simple app)
- < 5 seconds (complex app)
```
