# المرحلة 1.1: المترجم الأساسي (LLVM Backend)

## 🎯 الهدف الاستراتيجي

**تحويل لغة ص من مفسر بطيء إلى مترجم سريع جداً**

### النتيجة المتوقعة
- سرعة تنفيذ **100x-1000x** أسرع من الوضع الحالي
- أداء مماثل أو أفضل من C++ في معظم الحالات
- دعم JIT و AOT compilation
- تحسينات compiler قوية

### المدة الزمنية
**8-10 أسابيع** (شهرين)

---

## 📊 التحليل الفني الشامل

### الوضع الحالي

#### مشاكل المفسر الحالي
```
المشكلة 1: البطء الشديد
├─ تفسير كل سطر في runtime
├─ لا caching للتعليمات
├─ لا optimizations
└─ النتيجة: ~100x أبطأ من C++

المشكلة 2: استهلاك ذاكرة عالي
├─ AST كامل في الذاكرة
├─ لا تحرير للموارد غير المستخدمة
└─ النتيجة: 10x ذاكرة أكثر من اللازم

المشكلة 3: محدودية الوظائف
├─ لا inline functions
├─ لا loop unrolling
├─ لا dead code elimination
└─ النتيجة: كود غير محسّن
```

### الحل: LLVM Backend

#### لماذا LLVM؟
```
✅ المميزات:
├─ محرك تحسين قوي جداً (100+ optimizations)
├─ دعم JIT و AOT
├─ دعم multiple platforms (x86, ARM, RISC-V)
├─ مستخدم من Apple, Google, Mozilla
├─ توثيق ممتاز ومجتمع كبير
└─ مجاني ومفتوح المصدر

❌ التحديات:
├─ منحنى تعلم حاد
├─ API معقد
├─ debugging صعب
└─ وقت compilation أطول قليلاً
```

#### البدائل المرفوضة
```
❌ GCC Backend: صعب التكامل، API قديم
❌ كتابة مترجم خاص: سنوات من العمل
❌ Cranelift: جديد جداً، أقل نضجاً
✅ LLVM: الخيار الأمثل
```

## 🏗️ البنية المعمارية

### المراحل الأساسية

```
كود لغة ص (.s)
    ↓
┌─────────────────┐
│     Lexer       │ ← موجود حالياً
│  (Tokenizer)    │
└────────┬────────┘
         ↓
┌─────────────────┐
│     Parser      │ ← موجود حالياً
│   (AST Build)   │
└────────┬────────┘
         ↓
┌─────────────────┐
│  Type Checker   │ ← **جديد** ⚠️
│  (Validation)   │
└────────┬────────┘
         ↓
┌─────────────────┐
│ LLVM IR Gen     │ ← **جديد** ⚠️ (المحور الرئيسي)
│ (Code Gen)      │
└────────┬────────┘
         ↓
┌─────────────────┐
│ LLVM Optimizer  │ ← LLVM يوفره
│ (Optimize)      │
└────────┬────────┘
         ↓
┌─────────────────┐
│ Machine Code    │ ← LLVM يوفره
│ (Native Binary) │
└─────────────────┘
```

#### 1. Type Checker (مدقق الأنواع)
```
الوظيفة:
├─ التحقق من صحة الأنواع قبل التوليد
├─ Type inference للمتغيرات
├─ معالجة generics و templates
└─ تحويل AST إلى Typed AST

الملفات المطلوبة:
├─ include/compiler/type_checker.h
├─ src/compiler/type_checker.cpp
├─ include/compiler/typed_ast.h
└─ src/compiler/typed_ast.cpp
```

#### 2. LLVM IR Generator (مولد LLVM IR)
```
الوظيفة:
├─ تحويل Typed AST إلى LLVM IR
├─ معالجة الدوال والأصناف
├─ إدارة الذاكرة (malloc/free أو GC)
└─ معالجة control flow

الملفات المطلوبة:
├─ include/compiler/llvm_generator.h
├─ src/compiler/llvm_generator.cpp
├─ include/compiler/llvm_context.h
└─ src/compiler/llvm_context.cpp
```

#### 3. Optimization Pass Manager
```
الوظيفة:
├─ تطبيق optimizations على LLVM IR
├─ إدارة optimization levels (-O0, -O1, -O2, -O3)
├─ custom optimizations للعربية
└─ profiling-guided optimization

الملفات المطلوبة:
├─ include/compiler/optimizer.h
├─ src/compiler/optimizer.cpp
├─ include/compiler/optimization_passes.h
└─ src/compiler/optimization_passes.cpp
```

#### 4. JIT Compiler
```
الوظيفة:
├─ تشغيل فوري مع compilation
├─ hot path detection
├─ dynamic recompilation
└─ caching النتائج

الملفات المطلوبة:
├─ include/compiler/jit_engine.h
├─ src/compiler/jit_engine.cpp
├─ include/compiler/jit_cache.h
└─ src/compiler/jit_cache.cpp
```

### الأسبوع 5-6: LLVM IR Generation الأساسي

#### المهام
```
1. تحويل الأنواع
   ├─ رقم → i32 أو i64
   ├─ عشري → double
   ├─ نص → i8* (pointer)
   ├─ منطقي → i1
   └─ مصفوفة → struct

2. تحويل العبارات
   ├─ Literals → constants
   ├─ Variables → load/store
   ├─ Binary ops → add, sub, mul, div
   └─ Comparisons → icmp, fcmp

3. تحويل التحكم
   ├─ if → br, label
   ├─ while → br, phi
   ├─ for → optimized loop
   └─ return → ret
```

#### مثال توضيحي
```
كود لغة ص:
───────────
دالة رقم جمع(رقم س، رقم ص) {
    إرجاع س + ص
}

LLVM IR:
─────────
define i32 @جمع(i32 %س، i32 %ص) {
entry:
  %result = add i32 %س، %ص
  ret i32 %result
}

Assembly (x86-64):
───────────────────
جمع:
  add edi, esi    ; س + ص
  mov eax, edi    ; result
  ret
```

#### معايير النجاح
```
✅ دوال بسيطة تترجم بنجاح
✅ عمليات حسابية صحيحة
✅ control flow يعمل
```
