## 📋 نظرة عامة

### الهدف الرئيسي
تحويل لغة ص من **Dynamic Typing فقط** إلى **Optional Static Typing** مع دعم كامل لـ:
- Type Inference (استنتاج الأنواع التلقائي)
- Generics (الأنواع العامة)
- Union Types (أنواع الاتحاد)
- Type Checking في وقت الترجمة
- الحفاظ على Dynamic Typing كخيار

### لماذا نحتاج هذا؟
```
❌ المشكلة الحالية:
   ├─ جميع المتغيرات dynamic (بطيئة، غير آمنة)
   ├─ لا يوجد type safety في وقت الترجمة
   ├─ أخطاء Type تظهر في Runtime فقط
   └─ لا يمكن للمترجم تحسين الكود بشكل فعال

✅ بعد نظام الأنواع:
   ├─ Type safety في وقت الترجمة (اكتشاف الأخطاء مبكراً)
   ├─ Performance أفضل (تحسينات المترجم)
   ├─ IDE support أفضل (autocomplete, refactoring)
   ├─ Code أكثر وضوحاً وأماناً
   └─ مرونة كاملة (dynamic عند الحاجة)
```

## 🎯 الأهداف التفصيلية

### 1. Type Annotations (تعليقات الأنواع)
```s
# ✅ دعم تحديد الأنواع اختيارياً
دالة جمع(أ: رقم، ب: رقم) -> رقم {
    إرجاع أ + ب
}

# ✅ أنواع متغيرات محلية
متغير العمر: رقم = 25
متغير الاسم: نص = "أحمد"

# ✅ أنواع الأصناف والخصائص
صنف شخص {
    الاسم: نص
    العمر: رقم
    البريد: نص?  # نوع اختياري (nullable)
}
```

### 2. Type Inference (استنتاج الأنواع)
```s
# ✅ استنتاج تلقائي من القيمة
متغير عدد = 42           # => رقم
متغير نص = "مرحبا"       # => نص
متغير قائمة = [1, 2, 3] # => مصفوفة<رقم>

# ✅ استنتاج من استخدام المتغير
دالة مربع(س) {  # يستنتج س: رقم من س * س
    إرجاع س * س
}
```

### 3. Generics (الأنواع العامة)
```s
# ✅ دوال عامة
دالة عكس<T>(قائمة: مصفوفة<T>) -> مصفوفة<T> {
    # ...
}

# ✅ أصناف عامة
صنف صندوق<T> {
    متغير القيمة: T
    
    دالة احصل() -> T {
        إرجاع هذا.القيمة
    }
}

# ✅ استخدام
متغير صندوق_أرقام = صندوق<رقم>(42)
متغير صندوق_نصوص = صندوق<نص>("مرحبا")
```

### 4. Union Types (أنواع الاتحاد)
```s
# ✅ متغير يمكن أن يكون عدة أنواع
متغير نتيجة: رقم | نص | خطأ

# ✅ دالة تُرجع أنواع متعددة
دالة اقسم(أ: رقم، ب: رقم) -> رقم | نص {
    إذا (ب == 0) {
        إرجاع "لا يمكن القسمة على صفر"
    }
    إرجاع أ / ب
}
```

### 5. Type Guards (حراس الأنواع)
```s
# ✅ التحقق من النوع
دالة معالجة(قيمة: رقم | نص) {
    إذا (قيمة نوع رقم) {
        # هنا compiler يعرف أن قيمة: رقم
        اطبع(قيمة * 2)
    } وإلا {
        # هنا compiler يعرف أن قيمة: نص
        اطبع(قيمة.طول())
    }
}
```

### 6. Type Aliases (أسماء مستعارة)
```s
# ✅ تعريف أسماء جديدة للأنواع
نوع معرف = رقم
نوع بريد_إلكتروني = نص
نوع استجابة = {نجاح: منطقي، بيانات: أي}

# ✅ استخدام
متغير المعرف: معرف = 12345
متغير البريد: بريد_إلكتروني = "user@example.com"
```

## 🔧 تفاصيل التنفيذ

### 1. Type Representation

#### Base Type Class
```cpp
// type.h
class Type {
public:
    enum class Kind {
        PRIMITIVE,  // رقم، نص، منطقي
        GENERIC,    // T, U, etc.
        UNION,      // A | B | C
        FUNCTION,   // (A, B) -> C
        CLASS,      // User-defined class
        ARRAY,      // مصفوفة<T>
        MAP,        // خريطة<K, V>
        OPTIONAL    // T?
    };
    
    virtual Kind getKind() const = 0;
    virtual std::string toString() const = 0;
    virtual bool isCompatible(const Type* other) const = 0;
    virtual bool isSubtype(const Type* other) const = 0;
    virtual ~Type() = default;
};
```

#### Primitive Type
```cpp
// primitive_type.h
class PrimitiveType : public Type {
public:
    enum class PrimitiveKind {
        INT,     // رقم
        FLOAT,   // عشري
        STRING,  // نص
        BOOL,    // منطقي
        VOID,    // فراغ
        NULL_TYPE // لاشيء
    };
    
    explicit PrimitiveType(PrimitiveKind kind);
    Kind getKind() const override { return Kind::PRIMITIVE; }
    std::string toString() const override;
    bool isCompatible(const Type* other) const override;
};
```

#### Generic Type
```cpp
// generic_type.h
class GenericType : public Type {
    std::string name_;              // "Array", "Map", etc.
    std::vector<Type*> parameters_; // [T, U, ...]
    
public:
    GenericType(std::string name, std::vector<Type*> params);
    Kind getKind() const override { return Kind::GENERIC; }
    std::string toString() const override;
    bool isCompatible(const Type* other) const override;
};
```

### 2. Type Checker Algorithm

#### Visitor Pattern
```cpp
// type_checker.h
class TypeChecker : public ASTVisitor {
    TypeEnvironment* env_;
    TypeInferencer* inferencer_;
    
public:
    // زيارة التعبيرات
    Type* visitLiteralExpr(LiteralExpr* expr) override;
    Type* visitBinaryExpr(BinaryExpr* expr) override;
    Type* visitCallExpr(CallExpr* expr) override;
    
    // زيارة الجمل
    void visitFunctionDecl(FunctionDecl* decl) override;
    void visitVariableDecl(VariableDecl* decl) override;
    void visitIfStmt(IfStmt* stmt) override;
    
    // الدوال المساعدة
    void checkCompatibility(Type* expected, Type* actual);
    Type* inferType(Expr* expr);
};
```

#### Type Inference Example
```cpp
// type_inferencer.cpp
Type* TypeInferencer::inferFromBinaryOp(BinaryExpr* expr) {
    Type* leftType = infer(expr->left);
    Type* rightType = infer(expr->right);
    
    if (expr->op == "+") {
        if (leftType->is<IntType>() && rightType->is<IntType>()) {
            return Type::Int();
        }
        if (leftType->is<StringType>() || rightType->is<StringType>()) {
            return Type::String();
        }
        reportError("Incompatible types for +");
    }
    
    // المزيد من العمليات...
}
```

### 3. Constraint Solving

#### Constraint System
```cpp
// constraint_solver.h
struct Constraint {
    Type* left;
    Type* right;
    enum class Kind { EQUAL, SUBTYPE } kind;
};

class ConstraintSolver {
    std::vector<Constraint> constraints_;
    
public:
    void addConstraint(Type* left, Type* right, Constraint::Kind kind);
    bool solve();

};
```

## 🚨 التحديات المتوقعة

### 1. التحدي: Type Inference Complexity
**الوصف:** Hindley-Milner معقد للغة ديناميكية

**الحل:**
- ابدأ بـ simple inference
- أضف advanced features تدريجياً
- استخدم constraint-based approach

### 2. التحدي: Generic Type Instantiation
**الوصف:** إنشاء concrete types من generics

**الحل:**
```cpp
// Monomorphization: توليد نسخة لكل نوع
auto arrayInt = instantiate(arrayGeneric, {Type::Int()});
auto arrayStr = instantiate(arrayGeneric, {Type::String()});
```

### 3. التحدي: Union Type Checking
**الوصف:** التحقق من تطابق Union Types معقد

**الحل:**
```cpp
bool UnionType::isCompatible(const Type* other) const {
    // other يجب أن يكون متوافق مع أحد أعضاء الاتحاد
    for (auto member : members_) {
        if (other->isCompatible(member)) {
            return true;
        }
    }
    return false;
}
```

### 4. التحدي: Backwards Compatibility
**الوصف:** يجب أن يعمل الكود القديم (بدون type annotations)

**الحل:**
- Type annotations اختيارية 100%
- إذا لم يوجد annotation، استخدم Dynamic Type
- Gradual typing approach

```s
        إرجاع "محتوى الملف"
    } اصطد (خطأ) {
        إرجاع خطأ.جديد("فشل فتح الملف")
    }
}

# ✅ معالجة مع type guard
متغير نتيجة = قراءة_من_ملف("data.txt")

إذا (نتيجة نوع نص) {
    # هنا compiler يعرف أن نتيجة: نص
    اطبع("نجح: " + نتيجة)
} وإلا {
    # هنا compiler يعرف أن نتيجة: خطأ
    اطبع("فشل: " + نتيجة.الرسالة())
}
```

### مثال 4: Type Inference
```s
# ملف: examples/type_system/04_inference.s

# ✅ استنتاج تلقائي
دالة ضعف(س) {  # يستنتج: س: رقم، الإرجاع: رقم
    إرجاع س * 2
}

# ✅ استنتاج من السياق
متغير قائمة = [1, 2, 3]  # يستنتج: مصفوفة<رقم>

دالة معالجة_قائمة(ق) {  # يستنتج: ق: مصفوفة<رقم>
    لكل (عنصر في ق) {  # يستنتج: عنصر: رقم
        اطبع(عنصر * 2)
    }
}

معالجة_قائمة(قائمة)
```

### Gradual Typing Strategy
لغة ص تدعم **Gradual Typing**:
- يمكنك كتابة كود بدون types (dynamic)
- يمكنك إضافة types تدريجياً
- يمكنك خلط dynamic و static في نفس الملف
- لا يوجد "all or nothing"

### IDE Integration (تحضيراً)

- Autocomplete (اقتراحات تلقائية)

- Error Highlighting (تظليل الأخطاء)
