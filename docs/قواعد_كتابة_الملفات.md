# معايير هندسة ملفات المشروع — الإصدار المتقدم
# (Sad Language Project — Elite Engineering Standards)

> **المستوى:** صارم — لا استثناءات بدون موافقة كتابية مع مبرر تقني
> **النطاق:** كل ملف في المشروع (`*.cpp`, `*.h`, `*.hpp`, `CMakeLists.txt`, `*.cmake`)
> **التحديث:** يونيو 2025 — الإصدار 2.0
> **المرجعية:** هذه المعايير تتفوق على أي اتفاق شفهي سابق

---

## الفلسفة الحاكمة — القوانين الخمسة

> 1. **قانون الوحدانية:** كل ملف مسؤولية واحدة. لا يوجد ملف "يفعل أشياء متعددة".
> 2. **قانون القرائية:** مطور جديد يفهم أي ملف خلال 10 دقائق — وإلا الملف معيب.
> 3. **قانون التنبؤ:** من اسم الملف ومساره، تستطيع التنبؤ بمحتواه بدقة 90%.
> 4. **قانون العزل:** تعديل ملف واحد لا يفرض تعديل أكثر من 3 ملفات أخرى.
> 5. **قانون العدم:** لا كود ميت، لا تعليقات ميتة، لا ملفات يتيمة، لا imports غير مستخدمة.

## §1.2 أسماء الرموز — جدول حاسم

| الرمز | الصيغة | مثال صحيح | مثال خاطئ |
|---|---|---|---|
| أصناف | `PascalCase` | `ParserCore`, `SIRBuilder` | `parser_core`, `sirBuilder` |
| نطاقات | `PascalCase` مبتدئة بـ `Sad::` | `Sad::Parser`, `Sad::Compiler::SIR` | `sad::parser`, `parser` |
| تعدادات | `PascalCase` | `TokenType`, `ValueType` | `token_type`, `TOKEN_TYPE` |
| عناصر التعداد | `UPPER_SNAKE_CASE` | `KEYWORD_FUNCTION`, `SLOT_EMPTY` | `KeywordFunction` |
| دوال عضوية | `camelCase` | `parseExpression()`, `buildSIR()` | `ParseExpression()`, `parse_expression()` |
| دوال حرة | `camelCase` | `formatError()`, `hashString()` | `format_error()` |
| متغيرات محلية | `camelCase` | `currentToken`, `lineCount` | `CurrentToken`, `line_count` |
| أعضاء صنف | `camelCase` + لاحقة `_` | `tokens_`, `current_`, `position_` | `tokens`, `m_tokens`, `_tokens` |
| ثوابت | `UPPER_SNAKE_CASE` | `MAX_BUFFER_SIZE`, `DEFAULT_CAPACITY` | `maxBufferSize` |
| ماكروز C | `SAD_UPPER_SNAKE` مع بادئة `SAD_` | `SAD_ASSERT`, `SAD_LOG_DEBUG` | `ASSERT`, `LOG` |
| معاملات قالب | حرف كبير أو `PascalCase` | `T`, `Container`, `ValueType` | `t`, `container` |
| بادئة bool | `is`, `has`, `can`, `should` | `isEmpty()`, `hasValue()` | `empty()`, `value()` |

## §1.3 أسماء ملفات الرؤوس

| القاعدة | التفصيل |
|---|---|
| **H1:** الرأس يطابق اسم ملف التنفيذ | `parser_oop.h` ↔ `parser_oop.cpp` |
| **H2:** رأس تصريحات أمامية: لاحقة `_fwd` | `parser_fwd.h` |
| **H3:** `.h` للرؤوس العامة (C-compatible أو declarations فقط) | `parser_core.h` |
| **H4:** `.hpp` لرؤوس بتنفيذ (templates, inline) | `generics_parser.hpp` |
| **H5:** `#ifndef` + `#define` إلزامي (لا pragma once) | `#ifndef SAD_PARSER_CORE_H` |
| **H6:** Guard يتبع المسار الكامل مع بادئة `SAD_` | `SAD_SHARED_PARSER_CORE_H` |
| **H7:** كل header يكون self-contained (يُمكن تضمينه وحده) | لا يعتمد على include سبقه |

## §2.4 استراتيجية التقسيم — 5 خطوات

عند تقسيم ملف كبير:

```
الخطوة 1: رسم خريطة المسؤوليات
   ├── حدد كل "مجموعة دوال مترابطة"
   ├── كل مجموعة = ملف مرشح
   └── مجموعة أقل من 80 سطراً → لا تستحق ملفاً مستقلاً

الخطوة 2: التحقق من التبعيات
   ├── هل المجموعة تعتمد على أعضاء خاصة؟ → تبقى في نفس الملف
   ├── هل المجموعة مستقلة؟ → ملف جديد
   └── هل هناك تبعية دائرية؟ → أنشئ header وسيط

الخطوة 3: التسمية
   ├── الملف الجديد = <بادئة_المكون>_<وصف_المجموعة>.cpp
   └── لا أرقام، لا "part"، لا "misc"

الخطوة 4: النقل
   ├── انقل الدوال
   ├── حدّث CMake (كل الملفات!)
   ├── حدّث #include
   └── ابنِ

الخطوة 5: التحقق
   ├── sad.exe يبني ✅
   ├── sadc.exe يبني ✅
   ├── الاختبارات تعمل ✅
   └── لا warnings جديدة ✅
```

#### مثال عملي — تقسيم `sir_builder_helpers.cpp` (4,953 سطر)

```
# التحليل:
# - سطور 1-800:    عمليات الخرائط (hash table, insert, lookup, delete)
# - سطور 801-1300:  عمليات النصوص (concat, substr, compare, format)
# - سطور 1301-1900: عمليات المصفوفات (create, push, pop, sort, filter)
# - سطور 1901-2700: بناء Lambda/Closures (capture, env, apply)
# - سطور 2701-3400: عمليات الفهرسة والوصول (index, member, method call)
# - سطور 3401-4953: مساعدات عامة (type conversion, error handling, utility)

# النتيجة:
sir_builder_map_ops.cpp          (~800 سطر)
sir_builder_string_ops.cpp       (~500 سطر)
sir_builder_array_ops.cpp        (~600 سطر)
sir_builder_closures.cpp         (~800 سطر)

sir_builder_helpers.cpp          (~1,553 سطر → يحتاج تقسيم ثانٍ لاحقاً)
```

```

   3أ. دوال خاصة
```

# الباب السابع: قواعد `#include` (Include Discipline)

## §7.1 قواعد صارمة

| # | القاعدة | التفصيل |
|---|---|---|
| I1 | **Self-first** | أول include في `.cpp` هو الـ header المقابل له |
| I2 | **4 أقسام مفصولة** | (1) self, (2) مشروع, (3) مكتبة قياسية, (4) خارجية |
| I3 | **أبجدي داخل كل قسم** | `#include "ast.h"` قبل `#include "value.h"` |
| I4 | **لا include غير مستخدم** | حذف فوري |
| I5 | **Forward declaration أولاً** في headers | `class ASTNode;` بدلاً من `#include "ast_node.h"` |
| I6 | **لا مسارات نسبية** | `#include "parser_core.h"` ✅ — `#include "../include/parser_core.h"` ❌ |
| I7 | **لا include تبعي** | كل header يكون self-contained |
| I8 | **`<>` للخارجي** | `#include <string>`, `#include <nlohmann/json.hpp>` |
| I9 | **`""` للداخلي** | `#include "parser_core.h"` |
| I10 | **حد أقصى 12 include مشروع** في `.cpp` | أكثر = الملف يفعل أشياء كثيرة |
| I11 | **حد أقصى 5 include مشروع** في `.h` | أكثر = واجهة واسعة جداً |

| # | القاعدة | التفصيل |
|---|---|---|
| H1 | **Zero warnings** | الكود يجب أن يُبنى بدون أي تحذير مع `-Wall -Wextra` |
