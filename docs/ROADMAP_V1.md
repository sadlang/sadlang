>
> **الجمهور المستهدف:** المطورون الذين يريدون استبدال الإنجليزية بالعربية في عالم البرمجة.
>
> **الإستراتيجية:** لا نشر قبل الاستقرار التام — v1.0 كامل ومستقر.
>
> **تاريخ الإعداد:** مارس 2026

### 0.1 إصلاح إدارة النطاقات والمتغيرات (الأسبوع 1-2)

| # | المهمة | الملفات المتأثرة | الأولوية |
|---|--------|-----------------|---------|
| 0.1.1 | **إصلاح `متغير x = x + 1` داخل `بينما`** — المفسر يُنشئ متغيرًا جديدًا بدل التحديث | `variable_manager.cpp`, `scope_manager.cpp` | P0 |
| 0.1.2 | **جعل `constVariables_` scope-aware** — حاليًا مجموعة مسطحة (flat set) تتعارض بين النطاقات | `variable_manager.cpp` | P0 |
| 0.1.3 | **إصلاح إعادة التعريف مقابل التحديث** — توضيح: `متغير x = 5` (تعريف) مقابل `x = 5` (تحديث) | `variable_manager.cpp`, `statement_executor.cpp` | P0 |
| 0.1.4 | **اختبارات شاملة للنطاقات** — تغطية: نطاقات متداخلة، shadowing، دوال داخل دوال، closures | `tests/` | P0 |

**تفاصيل تقنية:**
```
المشكلة الجذرية: define() يبحث عن متغير بنفس الاسم في النطاقات الأب ويُحدّثه،
لكن عند كتابة "متغير x = x + 1"، Parser ينتج VarDecl (تعريف جديد) وليس 
Assignment (تحديث). يجب التفريق:
  - "متغير x = ..." → دائمًا تعريف جديد في النطاق الحالي
  - "x = ..." → بحث في سلسلة النطاقات ثم تحديث
ملاحظة: الكود الحالي يحاول منع التظليل لكنه يكسر التحديث أيضًا.
```

```

  1. OBJECT type → shared_ptr<ObjectInstance> → يمرر بالمرجع ✓ 
  2. MAP type مع __class__ → ينسخ الخريطة → التغييرات تضيع ✗
  يجب توحيد المسار: جميع الكائنات تكون OBJECT type مع shared_ptr.
```

## تصميم البنية للتوسع والشمولية

### مبادئ التصميم المعماري

```
┌──────────────────────────────────────────────────────────────┐
│                      الطبقة العليا                            │
│   أدوات (LSP, pkg, fmt, repl) │ تطبيقات │ مكتبات خارجية     │
├──────────────────────────────────────────────────────────────┤
│                    المكتبة القياسية                           │
│   core │ io │ math │ string │ network │ graphics │ ...       │
├──────────────────────────────────────────────────────────────┤
│                   طبقة التنفيذ                               │
│   المفسر (interpreter)  │  المترجم (sadc/LLVM)  │  VM       │
├──────────────────────────────────────────────────────────────┤
│                   النواة المشتركة (shared)                   │
│   Lexer │ Parser │ AST │ Types (Value) │ Errors │ Modules   │
├──────────────────────────────────────────────────────────────┤
│                  البنية التحتية (infra)                      │
│   UTF-8 │ Unicode │ Position │ SourceManager │ Allocator    │
└──────────────────────────────────────────────────────────────┘
```

### قواعد القابلية للتوسع

| القاعدة | الوصف | التطبيق |
|---------|-------|--------|
| **1. فصل النواة عن الامتدادات** | النواة المشتركة لا تعتمد على المفسر أو المترجم | Shared ← Interpreter, Shared ← Compiler (لا اعتمادات معكوسة) |
| **2. نظام مكتبات قابل للتوصيل** | أي مكتبة يمكن إضافتها/إزالتها بدون تأثير على النواة | `استورد مكتبة` يحمّل ديناميكيًا |
| **3. أنواع قابلة للتوسع** | نظام أنواع يسمح بإضافة أنواع مخصصة | Trait-based type system |
| **4. Backend-agnostic** | نفس الـ AST يُنفّذ عبر: مفسر، LLVM، VM، WASM | Backend interface واحدة |
| **5. أدوات مستقلة** | كل أداة (LSP, pkg, fmt) مكتبة مستقلة | لا تعتمد على بعضها |
| **6. استيراد متدرّج** | `core` دائمًا متوفر، الباقي يُستورد عند الحاجة | لا تحميل زائد |

### خارطة الميزات المؤجلة (ما بعد v1.0)

| الميزة | الأولوية | الهدف |
|--------|---------|------|
