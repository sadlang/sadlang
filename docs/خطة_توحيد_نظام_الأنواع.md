## المشكلة الحالية: 5 أنظمة أنواع منفصلة

### المشاكل الناتجة:

| # | المشكلة | التأثير |
|---|---------|---------|
| 1 | **تكرار الأنواع** — INTEGER موجود في 5 أماكن بأسماء مختلفة | صيانة مضاعفة، احتمال عدم تطابق |
| 2 | **لا ربط رسمي** — التحويل بين الأنظمة يدوي عبر switch | أخطاء عند إضافة نوع جديد |
| 3 | **TypeChecker معطل** — `enableTypeCheck = false` افتراضياً | المستخدم لا يرى أخطاء أنواع |
| 4 | **26 ملف في compiler_new/types/** لا يستخدمها المفسر | كود ميت فعلياً للمفسر |
| 5 | **type_nodes.h** (UNION, OPTIONAL, FUNCTION types) غير متصل بالParser | ميزات متقدمة معطلة |
| 6 | **parseGenericType()** يقرأ `<رقم>` لكن لا يخزنها | Generics بلا فائدة عملية |
| 7 | **لا رفض runtime** — `متغير رقم س = "نص"` يعمل بدون خطأ | اللغة تتصرف كـ dynamically-typed |

### التعداد الموحد `SadTypeKind`:

```cpp
enum class SadTypeKind {
    // ═══ أنواع بدائية ═══
    Void,           // فراغ / لاشيء
    Integer,        // رقم صحيح (int64)
    Float,          // عشري (double)
    Boolean,        // منطقي
    String,         // نص
    Byte,           // بايت
    
    // ═══ أنواع مركبة (بارامترية) ═══
    Array,          // مصفوفة<T>
    Map,            // خريطة<K, V>
    Tuple,          // (T1, T2, ...)
    
    // ═══ أنواع كائنية ═══
    Class,          // صنف
    Struct,         // بنية
    Enum,           // تعداد
    Trait,          // سمة
    
    // ═══ أنواع وظيفية ═══
    Function,       // (Params) -> Return
    Closure,        // إغلاق (دالة + سياق)
    
    // ═══ أنواع متقدمة ═══
    Union,          // T1 | T2
    Optional,       // T?
    Generic,        // معامل نوع (T)
    TypeAlias,      // اسم مستعار
    
    // ═══ أنواع مراجع (للمترجم) ═══
    Reference,      // &T
    MutableRef,     // &متغير T
    
    // ═══ أنواع خاصة ═══
    Any,            // أي (يقبل كل شيء)
    Never,          // أبداً (لا يُرجع)
    Unknown,        // غير محدد (يُستنتج لاحقاً)
    Error,          // خطأ (داخلي)
    
    // ═══ أنواع async ═══
    Future,         // مستقبل<T>
    Generator,      // مولّد<T>
};
```

### واجهة `SadType` الأساسية:

```cpp
class SadType : public std::enable_shared_from_this<SadType> {
public:
    virtual ~SadType() = default;
    
    // ═══ الهوية ═══
    SadTypeKind getKind() const;
    
    // ═══ الأسماء ═══
    virtual std::string arabicName() const = 0;   // "رقم", "مصفوفة<نص>"
    virtual std::string englishName() const = 0;   // "Integer", "Array<String>"
    virtual std::string toString() const = 0;      // تمثيل مختصر
    
    // ═══ علاقات الأنواع ═══
    virtual bool equals(const SadType* other) const = 0;
    virtual bool isAssignableTo(const SadType* target) const;
    virtual bool isSubtypeOf(const SadType* parent) const;
    bool coercesTo(const SadType* target) const;   // تحويل ضمني
    
    // ═══ فحوصات سريعة ═══
    bool isPrimitive() const;
    bool isNumeric() const;
    bool isComposite() const;
    bool isCallable() const;
    bool isNullable() const;
    
    // ═══ تحويلات (Lowering) ═══
    ValueType toValueType() const;               // → runtime
    Data::DataType toDataType() const;           // → legacy AST (حذف لاحقاً)
    
    // ═══ Factory methods ═══
    static SadTypePtr fromValueType(ValueType vt);
    static SadTypePtr fromDataType(Data::DataType dt);  // backward compat
    static SadTypePtr fromArabicName(const std::string& name);
    
    // ═══ حجم ومحاذاة (للمترجم) ═══
    virtual size_t sizeInBytes() const;
    virtual size_t alignment() const;
};
```

## خطة الترحيل (Migration Plan)

### المرحلة 1: إنشاء النظام الموحد (أسبوع)
1. إنشاء `shared/types/include/sad_type.h` و الأصناف الفرعية
2. إنشاء `SadTypeRegistry` كـ singleton
3. إنشاء دوال التحويل: `fromDataType()`, `fromValueType()`, `toDataType()`, `toValueType()`
4. **لا تعديل** على أي كود موجود — فقط إضافات

### المرحلة 2: ربط Parser بالنظام الموحد (أسبوع)
1. تعديل `Parameter` ليحمل `SadTypePtr` بالإضافة إلى `DataType`
2. تعديل `parseType()` ليُرجع `SadTypePtr`
3. تعديل `parseGenericType()` لتخزين المعاملات فعلياً في `SadArrayType.elementType`
4. ربط `type_nodes.h` بالنظام الموحد

### المرحلة 3: تفعيل التحقق في المفسر (أسبوع)
1. نقل `TypeChecker` من `compiler_new/` إلى `shared/`
2. تفعيل `enableTypeCheck = true` افتراضياً (وضع تحذيرات فقط أولاً)
3. إضافة runtime type validation في `statement_executor.cpp`

### المرحلة 4: دمج Generics والسمات (أسبوعان)
1. نقل `generics.h`, `trait_system.h` من `compiler_new/` إلى `shared/`
2. ربطها بالـ Parser والمفسر
3. تفعيل Generic instantiation في المفسر

### المرحلة 5: حذف الأنظمة القديمة (أسبوع)
1. إزالة `DataType` enum واستبداله كلياً بـ `SadTypePtr`
2. تبسيط `SIRBuilder::astTypeToSIRType()` ليستخدم `SadType::toLLVMType()`
3. حذف 26 ملف مكرر من `compiler_new/include/types/`

## المميزات

### 1. توحيد المصدر (Single Source of Truth)
- **قبل:** إضافة نوع جديد (مثل `Set`) تتطلب تعديل 5 أماكن
- **بعد:** إضافة صنف `SadSetType` واحد يعمل في كل مكان

### 2. فحص أنواع فعلي
- **قبل:** `متغير رقم س = "نص"` ← يعمل بدون خطأ!
- **بعد:** ← خطأ: "لا يمكن تعيين 'نص' لمتغير من نوع 'رقم'"

### 3. أنواع بارامترية حقيقية
- **قبل:** `مصفوفة<رقم>` ← يُقرأ ويُهمل
- **بعد:** `مصفوفة<رقم>` ← `SadArrayType(elementType: Integer)` → يُفحص

### 4. Union و Optional types
- **قبل:** غير ممكن عملياً
- **بعد:** `متغير قيمة: رقم | نص = 42` ← يعمل!

### 5. استنتاج أنواع عبر البرنامج
- **قبل:** `TypeInferencer` موجود فقط في المترجم
- **بعد:** يعمل في المفسر أيضاً

### 6. أداء أفضل
- Type Interning يمنع إنشاء نسخ مكررة من نفس النوع
- مقارنة الأنواع بالمؤشر بدلاً من المحتوى

### 7. رسائل خطأ أفضل
- كل نوع يحمل `arabicName()` و `englishName()`
- رسائل خطأ مثل: "توقع 'رقم' لكن وُجد 'نص' في السطر 15"

### 8. توافق عكسي كامل
- `fromDataType()` و `toDataType()` تضمن عمل الكود القديم
- `ValueType` لا يتغير — الـ runtime يبقى كما هو

## العيوب والمخاطر

### 1. حجم التغيير كبير
- **الخطر:** تعديل Parser + Interpreter + Compiler معاً
- **التخفيف:** الترحيل تدريجي — كل مرحلة مستقلة ويمكن اختبارها

### 2. كسر التوافق المحتمل
- **الخطر:** برامج `.ص` موجودة قد تتوقف عن العمل إذا فُعّل فحص الأنواع
- **التخفيف:** 
  - البدء بوضع "تحذيرات فقط" (لا أخطاء)
  - إضافة خيار `--strict-types` للفحص الصارم
  - الوضع الافتراضي: تحذيرات → بعد 6 أشهر أخطاء

### 3. تعقيد إضافي في الصيانة
- **الخطر:** نظام أنواع غني = مزيد من الكود
- **التخفيف:** النظام الجديد **يحل محل** 5 أنظمة — إجمالي الكود سيقل

### 4. أداء التحليل (Parsing)
- **الخطر:** إنشاء `SadTypePtr` (shared_ptr) لكل نوع يُحلل — تكلفة heap
- **التخفيف:** Type Interning يخزّن الأنواع البدائية مسبقاً (لا heap جديد لـ `رقم`)

### 5. تبعية دائرية محتملة
- **الخطر:** `shared/types/` يعتمد على `shared/ast/` والعكس
- **التخفيف:** `SadType` لا يعتمد على AST — استخدام forward declarations

### 6. تأخير الميزات الجديدة
- **الخطر:** العمل على التوحيد يؤخر إضافة ميزات لغوية جديدة
- **التخفيف:** المرحلة 1 و 2 أسبوعان فقط — بعدها يصبح إضافة ميزات أسهل

## مقارنة: الحالة الحالية vs النظام الموحد

| السيناريو | الحالة الحالية | بعد التوحيد |
|-----------|---------------|-------------|
| إضافة نوع `Set` | تعديل 5 enums + 4 switch statements | إضافة `SadSetType` واحد |
| `متغير رقم س = "نص"` | يعمل بصمت! | خطأ/تحذير واضح |
| `مصفوفة<رقم>` فحص | `parseGenericType()` يهمل المعاملات | فحص عناصر المصفوفة |
| `دالة رقم جمع(أ, ب)` | نوع الإرجاع يُخزن كـ `DataType` فقط | يُفحص مع return الفعلي |
| `سمة قابل_للطباعة` | Parser يحلل، المفسر يتجاهل | يُفحص ويُنفّذ |
| `قالب<نوع ت> دالة` | Parser يحلل، لا تنفيذ | instantiation فعلي |
| رسائل خطأ الأنواع | غير موجودة في المفسر | "توقع 'رقم' وُجد 'نص'" |

## الخلاصة

توحيد نظام الأنواع هو **أهم تحسين بنيوي** يمكن عمله في المشروع حالياً:
- يحول لغة ص من لغة ديناميكية بحتة إلى لغة **تدريجية الأنواع** (Gradual Typing)
- يقلل الكود المكرر ويسهّل الصيانة
- يفتح الباب لميزات متقدمة (Generics, Traits, Type Inference) تعمل فعلاً
- الثمن: ~5 أسابيع عمل مع مخاطر محسوبة وقابلة للتخفيف

### التوصية:
البدء بالمرحلة 1 فوراً (إنشاء `SadType` بدون تعديل أي كود موجود) لتقييم الجدوى.
