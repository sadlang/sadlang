# خارطة طريق تطوير نظام الرسومات — لغة ص (SadUI)

## مسار الكود من لغة ص حتى العرض على المنصة

### المسار الكامل (Pipeline)

```
كود لغة ص (.ص)
    │
    ▼
┌─────────────────────────────────────┐
│  1. المحلل المعجمي (LexerCore)      │  shared/lexer/
│     كود نصي → رموز (Tokens)         │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│  2. المحلل النحوي (ParserCore)      │  shared/parser/
│     → UIParser لتحليل عناصر UI     │  shared/parser/src/ui_parser.cpp
│     رموز → شجرة AST               │
│     (ViewDefinition + UINode Tree)  │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│  3. المفسر (InterpreterCore)        │  interpreter_new/
│     → يسجل دوال واجهات المدمجة     │  interpreter_new/src/ui/
│     → يبني شجرة Widget من Value    │
│     → ينشئ UIBridge               │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│  4. جسر الواجهة (UIBridge)          │  interpreter_new/src/ui/ui_bridge.h
│     Value Tree → IRNode Tree       │
│     convertToIR() → شجرة IR       │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│  5. باني IR (IRBuilder)             │  sad_ui/core/
│     UINode → IRNode                │
│     + RenderingHint (Native/Canvas) │
│     + IRProperty + IREvent         │
│     + التحسينات (حذف فارغ، دمج)   │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│  6. محرك التخطيط (Layout Engine)    │  sad_ui/core/src/layout.cpp
│     IRNode + constraints           │
│     → LayoutResult (x, y, w, h)   │
│     Flexbox-style + RTL            │
└───────────────┬─────────────────────┘
                │
                ▼
┌─────────────────────────────────────┐
│  7. التوجيه الهجين (HybridRouter)   │  sad_ui/core/src/hybrid_routing.cpp

│     حسب المنصة + نوع العنصر       │

                │
    ┌───────────┼───────────┬────────────┬────────────┬──────────────┐
    │           │           │            │            │              │
    ▼           ▼           ▼            ▼            ▼              ▼
┌────────┐ ┌────────┐ ┌─────────┐ ┌─────────┐ ┌─────────┐ ┌──────────────┐
│Desktop │ │  Web   │ │ Android │ │   iOS   │ │  macOS  │ │ Freestanding │
│ SDL2+  │ │HTML/CSS│ │Compose  │ │SwiftUI  │ │ AppKit  │ │  Framebuffer │

└────────┘ └────────┘ └─────────┘ └─────────┘ └─────────┘ └──────────────┘
```

## المرحلة 1: UIParser — من كود ص إلى شجرة UINode

### الملفات:
- `shared/parser/src/ui_parser.cpp` — محلل UI
- `sad_ui/core/include/sad_ui/node.h` — تعريف UINode

### كيف يعمل:
```sad
# المطور يكتب هذا:
استورد واجهات

دالة رئيسية()
    _محرك_واجهات(
        عمود(
            نص("مرحباً")
                .حجم_خط(24)
                .لون(.أحمر),
            زر("اضغط هنا")
                .عند_النقر(لامدا() اطبع("تم!") نهاية)
        )
    )
نهاية
```

### ما يحدث:
1. `UIParser::parseUIBody()` يحلل النص ويُنشئ شجرة `UINode`
2. كل عنصر (نص، زر، عمود) يصبح `UINode` بنوع محدد (`UINodeType::Text`, `Button`, `Column`)
3. المعدّلات (`.حجم_خط()`, `.لون()`) تصبح `Modifier` على العقدة
4. الأبناء (children) تُبنى كشجرة متداخلة

### الشجرة الناتجة:
```
UINode(Column)
├── UINode(Text, args=["مرحباً"])
│   ├── Modifier(FontSize, 24)
│   └── Modifier(ForegroundColor, Red)
└── UINode(Button, args=["اضغط هنا"])
    └── Modifier(OnTap, lambda)
```

## المرحلة 2: UIBridge — من Value إلى IR

### الملفات:
- `interpreter_new/src/ui/ui_bridge.h` — header UIBridge
- `interpreter_new/src/ui/ui_bridge.cpp` — التنفيذ
- `interpreter_new/src/ui/ui_builtins.cpp` — تسجيل الدوال

### كيف يعمل:
1. المفسر يُنفذ `_محرك_واجهات(widget)` → يستدعي `UIBridge::run()`
2. `run()` يستدعي `convertToIR(rootWidget)` لتحويل شجرة Value إلى شجرة IRNode
3. `convertNodeToIR()` يحوّل كل عقدة تكرارياً:
   - نوع العنصر → `UINodeType`
   - الخصائص → `IRProperty`
   - الأحداث → `IREvent` مع `registerHandler()`
   - الأبناء → `IRNode::children`

### النتيجة:
```
IRNode(Text)
├── IRProperty("text", "مرحباً")
├── IRProperty("fontSize", 24.0)
├── IRProperty("color", "#FF0000")
└── hint = RenderingHint::Canvas
```

## المرحلة 3: IRBuilder + Layout + Routing

### الملفات:
- `sad_ui/core/include/sad_ui/ir_builder.h` — باني IR
- `sad_ui/core/src/ir_builder.cpp`
- `sad_ui/core/src/layout.cpp` — محرك التخطيط
- `sad_ui/core/src/hybrid_routing.cpp` — التوجيه الذكي

### خطوات:
1. **IRBuilder** يحوّل UINode → IRNode مع:
   - `processModifiers()` — تحويل Modifier → IRProperty
   - `determineRenderingHint()` — تحديد Native/Canvas/Hybrid
   - `processStateBindings()` — ربط الحالة التفاعلية
   - `optimizeTree()` — حذف عقد فارغة ودمج

2. **Layout Engine** يحسب:
   - الأبعاد (width, height) لكل عقدة
   - المواضع (x, y) — Flexbox-style
   - اتجاه RTL تلقائياً
   - `LayoutResult` لكل عقدة

3. **HybridRouter** يُحدد لكل عنصر:

| العنصر | Desktop | Android | iOS | Web |
|--------|---------|---------|-----|-----|
| Text | Canvas | Native | Native | Canvas |
| Button | Canvas | Native | Native | Canvas |
| TextField | SDL2 | Native | Native | Canvas |
| Image | Canvas | Canvas | Canvas | Canvas |
| Custom | Canvas | Canvas | Canvas | Canvas |

## المرحلة 4: العرض على المنصة

### Desktop (الأكثر اكتمالاً)
**الملفات:**
- `sad_ui/backends/desktop/src/renderer.cpp` — المُصيّر الرئيسي
- `sad_ui/backends/desktop/src/renderer_canvas.cpp` — رسم Canvas
- `sad_ui/backends/desktop/src/renderer_draw.cpp` — دوال الرسم
- `sad_ui/backends/desktop/src/window.cpp` — إدارة نافذة SDL2
- `sad_ui/backends/desktop/src/text_editing.cpp` — تحرير النص
- `sad_ui/backends/desktop/src/system_bridge.cpp` — جسر النظام

**المسار:**
```
IRNode + LayoutResult → DesktopRenderer.render() → SDL2/OpenGL → الشاشة
```

**دورة الحياة:**
1. `Window::create()` — إنشاء نافذة SDL2
2. `Renderer::initialize()` — تهيئة OpenGL
3. حلقة الأحداث:
   - معالجة أحداث SDL2 (فأرة، لوحة مفاتيح)
   - `Renderer::beginFrame()` — مسح الشاشة
   - `Renderer::render(irRoot, layout)` — رسم الشجرة
   - `Renderer::endFrame()` — عرض الإطار
4. `UIBridge::updateTimers()` — مؤقتات
5. `UIBridge::updateAnimations()` — رسوم متحركة

**API الرسم الأساسي (PlatformRenderer — 16 دالة مجردة):**
- `drawFilledRect()`, `drawRoundedRect()`, `drawRectOutline()`
- `drawText()`, `measureText()`
- `drawImage()`, `drawCircle()`, `drawCircleOutline()`
- `drawLine()`, `drawLinearGradient()`
- `setClipRect()`, `clearClipRect()`
- `beginFrame()`, `endFrame()`
- `loadFont()`, `initialize()`, `shutdown()`

## خارطة الطريق — الخطوات القادمة

### الأولوية 1: تثبيت Desktop + Web (قريب المدى)

#### 1.1 اختبار شامل لـ Desktop

- [ ] اختبار RTL مع نصوص مختلطة عربي/إنجليزي
- [ ] اختبار الأداء مع 1000+ عنصر
- [ ] اختبار Hot Reload مع تغييرات UI متعددة
- [ ] إصلاح أي مشاكل في scroll والقص (clipping)

#### 1.2 تثبيت Web Codegen
- [ ] اختبار الـ HTML المُولّد في متصفحات حقيقية (Chrome, Firefox, Safari)
- [ ] اختبار الأحداث التفاعلية (نقر، إدخال، تمرير)
- [ ] إضافة Service Worker للعمل offline
- [ ] إضافة PWA manifest

#### 1.3 بناء WASM
- [ ] ربط Desktop Renderer مع Emscripten
- [ ] اختبار الأداء في المتصفح عبر WASM
- [ ] مقارنة أداء WASM مقابل HTML Codegen

### الأولوية 2: تفعيل منصة موبايل واحدة (متوسط المدى)

#### 2.1 Android — الخيار الأسهل للبدء
- [ ] استكمال `ComposeCodegen` — تحويل IR إلى Kotlin/Compose

- [ ] بناء native module يُغلّف المُصيّر

#### 2.2 iOS (بعد Android)
- [ ] استكمال `SwiftUICodegen` — تحويل IR إلى SwiftUI
- [ ] تنفيذ `iOSRenderer` — Metal/CoreGraphics
- [ ] تنفيذ `SystemBridge`

### الأولوية 3: تحسينات معمارية (بعيد المدى)

#### 3.1 تقسيم UIBridge
UIBridge يحتوي حالياً على 40 نظام فرعي في class واحد (~800 سطر header).
- [ ] استخراج أنظمة مستقلة: `AudioSystem`, `StorageSystem`, `NavigationSystem`
- [ ] كل نظام يُطبق واجهة مجردة + تنفيذ لكل منصة
- [ ] UIBridge يصبح فقط منسّق (Coordinator)

#### 3.2 Tree Diffing (المقارنة الذكية)
- [ ] تطوير خوارزمية مقارنة أشجار IR (مثل React Reconciler)
- [ ] إعادة رسم العناصر المتغيرة فقط بدلاً من الشجرة كاملة
- [ ] تحسين كبير في الأداء مع واجهات معقدة

#### 3.3 Accessibility
- [ ] ربط نظام الوصولية بالمنصات الأصلية
- [ ] التعامل مع قارئات الشاشة (Screen Readers)
- [ ] دعم لوحة المفاتيح الكامل

#### 3.4 نظام سمات متقدم
- [ ] سمات ديناميكية (فاتح/داكن/مخصص)
- [ ] ألوان وخطوط مُخصصة لكل سمة
- [ ] تبديل السمة في وقت التشغيل بسلاسة

### الأولوية 4: المترجم (sadc)

#### 4.1 دعم UI في المترجم
- [ ] تحويل شجرة IR إلى SIR → LLVM IR → Assembly

## ملف نظام الاستيراد المؤثر

### كيف يصل كود ص إلى نظام UI:

```sad
استورد واجهات    # ← يُفعّل وحدة "واجهات" في BuiltinModuleRegistry
```

**المسار الداخلي:**
1. `visitImportStmt("واجهات")` في `statement_executor_modules.cpp`
2. → `BuiltinModuleRegistry::loadModule("واجهات")` — تحميل كسول
3. → يُسجل دوال: `_محرك_واجهات`, `نص`, `زر`, `عمود`, `صف`, `صورة`, `حالة`, `عيّن_حالة`, ...
4. → المسجل في `interpreter_new/src/ui/ui_builtins.cpp`
5. عندما يستدعي المطور `_محرك_واجهات(widget)`:
   - يُنشأ `UIBridge`
   - يُمرر الـ widget الجذري
   - يبدأ حلقة الأحداث

### الدوال المسجلة (وحدة واجهات — 40+ دالة):

**بناء العناصر:**
`نص()`, `زر()`, `عمود()`, `صف()`, `صورة()`, `حاوية()`, `مربع()`,
`شريط_تمرير()`, `شريط_تقدم()`, `مفتاح_تبديل()`, `حقل_ادخال()`, `قائمة()`

**الحالة والتفاعل:**
`حالة()`, `عيّن_حالة()`, `احصل_حالة()`, `راقب()`, `محسوب()`

**التنقل:**
`انتقل_الى()`, `ارجع()`, `صفحة_رئيسية()`, `استبدل_صفحة()`

**الأنظمة الفرعية (40 نظام):**
`مؤقت()`, `فاصل_زمني()`, `انسخ()`, `الصق()`, `تنبيه()`, `تأكيد()`,
`خزّن()`, `استرجع()`, `شاشة_كاملة()`, `لقطة_شاشة()`, ... إلخ
