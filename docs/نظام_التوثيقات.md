# نظام التوثيقات في لغة ص — `--docs`

> دليل شامل لنظام استخراج التوثيق المدمج في كل من المفسر `sad` والمترجم `sadc`.
> لا يحتاج النظام إلى أي أداة خارجية — التوثيق يُستخرج مباشرة من شجرة AST.

---

## 1. نظرة عامة

نظام التوثيقات يقرأ التعليقات التوثيقية المرفقة بالتصريحات (دوال، أصناف، تعدادات، بُنى، سمات، ماكروز، عقود ذكية، خاصيات `احصل`/`عيّن`، طرق امتداد، دوال async، مولّدات) ويُنتج Markdown / JSON / HTML / PDF بشكل تلقائي.

### لماذا هو دقيق؟
بخلاف أدوات المسح النصي، النظام يستخدم **نفس مسار اللغة**:

```
ملف .ص  →  Lexer  →  Parser  →  AST  →  DocsExtractor  →  {Markdown, JSON, HTML, PDF}
```

أي تعليق توثيقي يُسجَّل في حقل `docComment` على عقدة AST نفسها، فلا يُنسب لخطأ.

### صيغ التصدير المدعومة
| الصيغة | العلم | الوصف |
|---|---|---|
| Markdown | `--docs` (افتراضي) | مرجع نصي، مناسب لـ GitHub |
| JSON | `--docs-format=json` | بنية مُهيكلة للأدوات |
| HTML | `--docs-format=html` | صفحة مستقلة + Mermaid + CSS داكن |
| PDF | `--docs-format=pdf` | يستخدم Edge/Chrome/wkhtmltopdf headless |

## 2. كتابة التوثيق في كود لغة ص

### أنواع التعليقات التوثيقية
| الصياغة | الاستخدام |
|---|---|
| `## نص` | توثيق سطر واحد (يقع مباشرة قبل التصريح) |
| `## سطر 1`<br>`## سطر 2` | توثيق متعدد الأسطر (يُجمَّع بـ `\n`) |
| `#** ... **#` | كتلة توثيق متعددة الأسطر |

> **مهم:** التعليقات `#` و `#* *#` العادية لا تُلتقط — فقط `##` و `#** **#` تُعتبر توثيقاً.

### الوسوم المدعومة
كل وسم يبدأ بـ `@` على سطره الخاص. الوسوم العربية والإنجليزية تعمل بنفس النتيجة:

| عربي | إنجليزي | الغرض |
|---|---|---|
| `@معطى` | `@param` / `@parameter` | وصف معامل |
| `@أرجع` | `@return` / `@returns` | وصف القيمة المرجعة |
| `@استثناء` | `@throws` / `@exception` | استثناء محتمل |
| `@انظر` | `@see` | مرجع ذو صلة |
| `@منذ` | `@since` | نسخة الإضافة |
| `@مهمل` | `@deprecated` | علامة إهمال |
| `@مؤلف` | `@author` | المؤلف |
| `@ملاحظة` | `@note` | ملاحظة |
| `@تحذير` | `@warning` | تحذير |
| `@مثال` | `@example` | مثال استخدام |
| `@نسخة` | `@version` | إصدار العنصر |
| `@نوع` | `@type` | نوع المتغير/الخاصية |
| `@تعقيد` | `@complexity` | تعقيد زمني/مكاني |
| `@آمن_خيوط` | `@threadsafe` | أمان التزامن |
| `@تجريبي` | `@experimental` | ميزة قد تتغير |
| `@رخصة` | `@license` | رخصة الكود |
| `@رابط` | `@link` | روابط مرجعية |
| `@افتراضي` | `@default` | القيمة الافتراضية |

### كتل الأمثلة داخل التوثيق
أي كتلة بين ` ``` ` (أو ` ```ص ` أو ` ```sad `) تُجمَّع كمثال. يمكن استخدامها مع أو بدون وسم `@مثال`.

## 3. أوامر سطر الأوامر

كل من `sad.exe` و `sadc.exe` يدعمان نفس الأوامر بنفس المخرجات بايت-بايت.

| الأمر | الوصف |
|---|---|
| `sad --docs ملف.ص` | طباعة التوثيق إلى stdout |
| `sad --وثّق ملف.ص` | المرادف العربي |
| `sad --docs-out=out.md ملف.ص` | كتابة إلى ملف |
| `sad --docs-format=md\|json\|html\|pdf ملف.ص` | اختيار صيغة التصدير |
| `sad --docs-project=<مجلد>` | توثيق مشروع كامل تكرارياً |
| `sad --docs-project=<مجلد> --docs-project-name="اسمي"` | تخصيص عنوان المشروع |
| `sad --docs-exclude=internal.ص,private/` | استثناء ملفات/مجلدات في وضع المشروع |

### وضع الملف المفرد
```powershell
.\build\bin\Debug\sad.exe --docs-out=رياضيات.md stdlib\رياضيات.ص
```

### وضع المشروع
```powershell
.\build\bin\Release\sadc.exe --docs-project=stdlib `
                              --docs-out=stdlib_docs.md `
                              --docs-project-name="المكتبة القياسية للغة ص"
```

> **بناء `sadc`:** يجب أن يُبنى في **Release** فقط.

## 4. أنواع التصريحات المدعومة

| النوع | الكلمة المفتاحية | الشارة |
|---|---|---|
| دالة | `دالة` | `دالة / function` |
| دالة async | `دالة غير_متزامن` | `async function` |
| مولّد | `مولد دالة` | `generator` |
| ماكرو | `ماكرو` | `macro` (يدعم معاملات متغيرة `...اسم`) |
| عقد ذكي | `عقد` | `smart contract` (مع `يتطلب` و `يضمن`) |
| امتداد | `امتداد <اسم_صنف>` | `extension` |
| صنف | `صنف` | `class` |
| تعداد | `تعداد` | `enum` |
| بنية | `بنية` | `struct` |
| سمة | `سمة` | `trait` |
| طريقة | `دالة` داخل `صنف` | `method` |
| حقل | `متغير` داخل `صنف` | `field` |
| باني | `باني` | `constructor` |
| خاصية | `خاصية` مع `احصل`/`عيّن` | `property` |
| قيد نوع | `حيث ت: <سمة>` | يظهر تحت توقيع الدالة |
| تصدير | `صدّر دالة/صنف...` | يُفك التغليف ويُوثَّق التصريح الداخلي |
| متغير عام | `متغير` في النطاق العلوي | `variable` |
| ثابت | `ثابت` في النطاق العلوي | `constant` |

### قاعدة الأصناف
الصنف يُعرض إذا:
- لديه توثيق `##` خاص به، **أو**
- يحوي عضواً واحداً على الأقل موثَّقاً.

## 5. الميزات المتقدمة

### 5.1 جدول المحتويات التلقائي (TOC)
كل ملف Markdown يحتوي على قسم `📑 جدول المحتويات` يسرد جميع التصاريح المُوثقة برموز ملونة (🔧 دالة، 🏛 صنف، 📊 تعداد، 🧱 بنية، 🎭 سمة، 📦 متغير، 🔒 ثابت).

### 5.2 جدول إحصائيات
في رأس كل ملف توثيق:

| النوع / Kind | العدد / Count |
|---|---:|
| 🔧 دوال | 12 |
| 🏛 أصناف | 5 |
| 🔒 ثوابت | 8 |

### 5.3 رسوم Mermaid التلقائية
في صيغة HTML و PDF، يولّد النظام رسم class diagram تلقائياً:
- وراثة فردية ومتعددة
- أعضاء الصنف (متغيرات + دوال) إذا كانت موثَّقة
- في وضع المشروع: مخطط شامل لكل الأصناف عبر الملفات
- قابل للطي عبر `<details open>`
- يدعم الوضع الداكن تلقائياً

### 5.4 الروابط المتقاطعة (Cross-references)
كل تصريح يحصل على معرّف HTML قابل للربط (`<a id="cls-اسم">`)، مما يسمح بالربط:
- من جدول المحتويات إلى التصريح
- بين الأصناف والوراثة
- بين الدوال داخل نفس الملف

### 5.5 تصدير PDF بدقة عالية
استخدام Microsoft Edge headless مع `--virtual-time-budget=10000` لضمان تنفيذ JavaScript الخاص بـ Mermaid قبل تصدير PDF.

### 5.6 تطابق sad ⇄ sadc بايت-بايت
ضمان كامل أن المفسر والمترجم يُنتجان نفس التوثيق لكل صيغة (بعد توحيد فواصل الأسطر) — مُتحقَّق عبر **72 اختباراً**.

## 6. الاختبارات المزدوجة

نظام شامل للتأكد من تطابق sad↔sadc:
- **الموقع:** [`tests/doc_gen_dual_execution/`](../tests/doc_gen_dual_execution/)
- **18 ملف اختبار** يغطي كل ميزة (basic، classes، inheritance، traits، enums، namespace، export، macros، async، extension، smart contract، properties، generators، constraints، إلخ)
- **2 مشروع متعدد الملفات** (`app/`, `zoo/`) مع اختبار `--docs-exclude=`
- **4 صيغ × 18 = 72 اختبار**, **معدل النجاح: 72/72 ✓**

### التشغيل
```powershell
# اختبار سريع بدون PDF
python tests/doc_gen_dual_execution/runner.py --skip-pdf

# اختبار كامل مع PDF
python tests/doc_gen_dual_execution/runner.py
```

### CTest
```powershell
cmake -S . -B build -DBUILD_TESTS=ON
ctest --test-dir build -C Debug -R DocGenDual_Fast
ctest --test-dir build -C Debug -R DocGenDual_Full
```

### قواعد المقارنة
| الصيغة | معيار التطابق |
|---|---|
| Markdown / JSON / HTML | بايت-بايت بعد توحيد CRLF→LF |
| PDF | فرق ≤ 5 KB (مسموح بفروقات metadata من Edge) |

## 7. البنية الداخلية (للمطورين)

### الملفات الرئيسية

| الملف | الدور |
|---|---|
| [shared/ast/include/doc_comment.h](../shared/ast/include/doc_comment.h) | بنى `DocComment`, `DocParam`, `DocException` ومحلل `DocCommentParser` |
| [shared/ast/include/docs_extractor.h](../shared/ast/include/docs_extractor.h) | `Sad::AST::DocsExtractor` — يُولّد جميع الصيغ |
| [shared/ast/include/pdf_exporter.h](../shared/ast/include/pdf_exporter.h) | تصدير PDF عبر Edge/Chrome/wkhtmltopdf |
| [tools/compiler/main_simple.cpp](../tools/compiler/main_simple.cpp) | معالجة `--docs` في المفسر `sad` |
| [tools/compiler/compiler_driver_cli.cpp](../tools/compiler/compiler_driver_cli.cpp) | تحليل أعلام التوثيق في `sadc` |
| [tools/compiler/compiler_driver_frontend.cpp](../tools/compiler/compiler_driver_frontend.cpp) | early-return يستدعي `Lexer→Parser→DocsExtractor` |
| [cmake/doc_gen_dual_tests.cmake](../cmake/doc_gen_dual_tests.cmake) | تكامل CTest |

### مسار التقاط التعليق (Parser)

1. `LexerCore` يُنتج رمز `DOC_COMMENT` لكل سطر `##` أو كتلة `#** **#`.
2. `ParserCore` يجمع الرموز المتتالية في `pendingDocComment_` (مفصولة بـ `\n`).
3. عند بدء parsing لأي تصريح، تُستدعى `consumePendingDocComment()` لنقل النص إلى `ASTNode::docComment`.
4. **مهم:** كل دوال OOP (`parseFieldDeclaration`, `parseMethodDeclaration`, `parseConstructorDeclaration`) تستدعي هذه الدالة في بدايتها.

### تكامل LSP
نفس `DocCommentParser` يُستخدم في خادم LSP لتقديم Markdown غني عند تمرير المؤشر فوق المُعرّفات. أي تحسين في `DocCommentParser` يستفيد منه LSP و `--docs` معاً.

## 9. حدود معروفة

- التعليقات `#` و `#* *#` العادية تُحذف ولا تظهر في التوثيق — هذا متعمَّد.
- ترتيب التصريحات في المخرج يتبع ترتيب ظهورها في الملف المصدري.
- في وضع المشروع، الملفات تُرتَّب أبجدياً حسب المسار.
- بناء Debug لـ `sadc` يفشل (رموز LLVM) — استخدم Release.
