# مراحل إنتاج الكود في لغة ص

## نظرة عامة

عندما تكتب برنامجاً بلغة ص، يمر هذا البرنامج بعدة مراحل قبل أن يتم تنفيذه. كل مرحلة تقوم بمهمة محددة، وتُعد مخرجاتها مدخلات للمرحلة التالية. هذا الفصل يشرح بالتفصيل كل مرحلة من مراحل إنتاج الكود، من النص المصدري الخام حتى الكود القابل للتنفيذ.

## المرحلة الأولى: التحليل المعجمي (Lexical Analysis)

### ما هو التحليل المعجمي؟

التحليل المعجمي هو أول مرحلة في معالجة الكود المصدري. يقرأ المحلل المعجمي (Lexer) النص حرفاً بحرف ويحوله إلى سلسلة من الرموز (Tokens). كل رمز يمثل وحدة لغوية واحدة: كلمة مفتاحية، معرف، رقم، عامل، نص، إلخ.

### كيف يعمل؟

```cpp
// من lexer_core.cpp
LexerCore::LexerCore(const std::string& source)
    : source_(source)
    , current_(0)
    , line_(1)
    , column_(1)
{
    // تهيئة جدول الكلمات المفتاحية
    KeywordTable::initialize();
}

char LexerCore::peek() const {
    if (isAtEnd()) return '\0';
    return source_[current_];
}

char LexerCore::advance() {
    char c = source_[current_++];
    if (c == '\n') {
        line_++;
        column_ = 1;
    } else {
        column_++;
    }
    return c;
}
```

### مثال على التحليل المعجمي

الكود:
```
متغير س = 42 + 3
```

الرموز الناتجة:
```
[KEYWORD: متغير] [IDENTIFIER: س] [ASSIGN: =] [NUMBER: 42] [PLUS: +] [NUMBER: 3]
```

### أنواع الرموز

| النوع | الوصف | أمثلة |
|-------|-------|-------|
| KEYWORD | كلمات مفتاحية | متغير، دالة، إذا |
| IDENTIFIER | معرفات | س، اسم، حساب |
| NUMBER | أرقام | 42، 3.14، 0xFF |
| STRING | نصوص | "مرحباً" |
| OPERATOR | عوامل | +، -، *، / |
| PUNCTUATION | علامات الترقيم | (، )، {، } |

## المرحلة الثانية: التحليل النحوي (Parsing)

### ما هو التحليل النحوي؟

التحليل النحوي يأخذ سلسلة الرموز من المرحلة السابقة ويبني منها شجرة الصيغة المجردة (Abstract Syntax Tree - AST). هذه الشجرة تمثل البنية المنطقية للبرنامج.

### كيف يعمل؟

المحلل النحوي يستخدم قواعد اللغة لتحديد كيفية تجميع الرموز. على سبيل المثال:

```
تعبير → تعبير + حد | حد
حد → حد * عامل | عامل
عامل → رقم | معرف | (تعبير)
```

### مثال على الشجرة

الكود:
```
متغير س = 42 + 3 * 2
```

الشجرة:
```
VarDecl
├── name: "س"
└── initializer: BinaryExpr
    ├── op: +
    ├── left: Literal(42)
    └── right: BinaryExpr
        ├── op: *
        ├── left: Literal(3)
        └── right: Literal(2)
```

لاحظ أن الضرب له أولوية أعلى من الجمع، لذا `3 * 2` في فرع منفصل.

## المرحلة الثالثة: التحليل الدلالي (Semantic Analysis)

### ما هو التحليل الدلالي؟

بعد بناء الشجرة، نحتاج للتأكد من أن البرنامج له معنى. التحليل الدلالي يفحص:

- **التحقق من الأنواع:** هل يمكن جمع هذين القيمتين؟
- **فحص النطاق:** هل المتغير معرّف قبل استخدامه؟
- **التحقق من التوقيعات:** هل استدعاء الدالة يطابق تعريفها؟

### أمثلة على الأخطاء الدلالية

```
متغير س = "نص" + 5          // خطأ: لا يمكن جمع نص ورقم
اطبع(ص)                     // خطأ: ص غير معرّف
دالة مثال(أ، ب) { }
مثال(1)                      // خطأ: الدالة تحتاج معاملين
```

## المرحلة الرابعة: التمثيل الوسيط (Intermediate Representation)

### ما هو SIR؟

SIR (Sad Intermediate Representation) هو تمثيل وسيط بين AST وكود الآلة. أقرب للآلة من AST لكن أعلى مستوى من LLVM IR.

### مكونات SIR

```
SIRModule
├── Functions
│   └── SIRFunction
│       ├── BasicBlocks
│       │   └── SIRBasicBlock
│       │       └── Instructions
│       │           └── SIRInstruction
│       └── Parameters
└── GlobalVariables
```

### مثال على SIR

الكود:
```
دالة مثال(س) {
    إذا (س > 0) {
        أرجع س * 2
    }
    أرجع 0
}
```

SIR:
```
function @مثال(%س: i64) -> i64 {
entry:
    %cmp = icmp sgt i64 %س, 0
    br %cmp, then, else

then:
    %mul = mul i64 %س, 2
    ret i64 %mul

else:
    ret i64 0
}
```

## المرحلة الخامسة: التحسين (Optimization)

### لماذا التحسين؟

الكود المكتوب بشرياً نادراً ما يكون الأمثل. المحسن يطبق تحويلات لتحسين الأداء دون تغيير سلوك البرنامج.

### أنواع التحسينات

**إزالة الكود الميت:**
```
// قبل
متغير س = 5
متغير ص = 10    // لم يُستخدم
أرجع س

// بعد
متغير س = 5
أرجع س
```

**طي الثوابت:**
```
// قبل
متغير س = 3 + 5 * 2

// بعد
متغير س = 13
```

**إنتشار الثوابت:**
```
// قبل
متغير س = 10
متغير ص = س + 5

// بعد
متغير س = 10
متغير ص = 15
```

**تحسين الحلقات:**
```
// قبل
لكل ع من 0 إلى 1000 {
    متغير ن = حساب_ثابت()  // لا يعتمد على ع
    اطبع(ع + ن)
}

// بعد
متغير ن = حساب_ثابت()
لكل ع من 0 إلى 1000 {
    اطبع(ع + ن)
}
```

## المرحلة السادسة: توليد الكود (Code Generation)

### المسار الأول: البايت كود

البايت كود محمول ويعمل على الآلة الافتراضية:

```
; مثال على بايت كود
PUSH_CONST 0    ; ادفع 42
PUSH_CONST 1    ; ادفع 3
ADD             ; اجمع
STORE_LOCAL 0   ; خزّن في س
```

### المسار الثاني: LLVM IR

للأداء الأقصى، نولد LLVM IR:

```llvm
define i64 @main() {
entry:
    %س = alloca i64
    store i64 45, i64* %س
    %val = load i64, i64* %س
    ret i64 %val
}
```

### المسار الثالث: كود الآلة

LLVM يحول IR إلى كود آلة أصلي:

```asm
main:
    push    rbp
    mov     rbp, rsp
    mov     QWORD PTR [rbp-8], 45
    mov     rax, QWORD PTR [rbp-8]
    pop     rbp
    ret
```

## الخلاصة

إنتاج الكود في لغة ص هو عملية متعددة المراحل، كل مرحلة تبني على ما قبلها. من التحليل المعجمي الذي يفهم الحروف، إلى التحليل النحوي الذي يفهم البنية، إلى التحليل الدلالي الذي يفهم المعنى، إلى التحسين الذي يحسن الأداء، وأخيراً توليد الكود الذي ينتج برنامجاً قابلاً للتنفيذ. هذه المراحل مصممة بعناية لإنتاج كود سريع وصحيح مع الحفاظ على رسائل خطأ واضحة ومفيدة.
