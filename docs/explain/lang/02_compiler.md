# المترجم (Compiler)

## ما هو المترجم؟

المترجم (Compiler) هو المكون الأساسي في لغة ص المسؤول عن تحويل الكود المصدري المكتوب بالعربية أو الإنجليزية إلى كود آلة يمكن تنفيذه مباشرة على المعالج. على عكس المفسر الذي يقرأ وينفذ الكود سطراً بسطر، فإن المترجم يقوم بتحليل البرنامج بالكامل أولاً، ثم يطبق تحسينات متعددة، وأخيراً ينتج ملفاً تنفيذياً مستقلاً يمكن تشغيله دون الحاجة لوجود بيئة اللغة.

يتميز المترجم في لغة ص بأنه يستخدم بنية LLVM القوية كخلفية لتوليد الكود، مما يعني أن البرامج المترجمة تحصل على نفس مستوى التحسينات والأداء الذي تحصل عليه لغات مثل C++ و Rust و Swift. هذا الاختيار المعماري يجعل لغة ص قادرة على إنتاج برامج عالية الأداء تنافس أسرع اللغات المترجمة في العالم.

## بنية المترجم

يتواجد المترجم في المجلد `compiler_new/` ويتكون من عدة طبقات متتالية:

```
compiler_new/
├── src/
│   ├── frontend/      # الواجهة الأمامية (SIR Builder)
│   ├── middle/        # التمثيل الوسيط
│   ├── optimizer/     # محسنات الكود
│   ├── backend/       # الواجهة الخلفية (LLVM)
│   │   └── llvm/      # توليد كود LLVM IR
│   ├── bytecode/      # توليد البايت كود
│   ├── jit/           # التجميع الفوري
│   └── types/         # نظام الأنواع المتقدم
└── include/           # ملفات الرأس
```

## مراحل الترجمة

### المرحلة الأولى: بناء التمثيل الوسيط (SIR - Sad Intermediate Representation)

بعد أن يقوم المحلل النحوي ببناء شجرة AST، تبدأ أول مرحلة في المترجم وهي تحويل AST إلى تمثيل وسيط يسمى SIR. هذا التمثيل الوسيط مصمم خصيصاً للغة ص ويحتفظ بمعلومات الأنواع والنطاقات بشكل صريح. يتكون SIR من وحدات (Modules) تحتوي على دوال، وكل دالة تتكون من كتل أساسية (Basic Blocks)، وكل كتلة تحتوي على تعليمات (Instructions).

التعليمات في SIR تشمل العمليات الحسابية والمنطقية، عمليات الذاكرة (التحميل والتخزين)، استدعاءات الدوال، وتعليمات التحكم في التدفق. هذا التمثيل أقرب للآلة من AST ولكنه أعلى مستوى من LLVM IR، مما يسمح بتطبيق تحسينات خاصة بلغة ص.

### المرحلة الثانية: التحسين (Optimization)

محسن الكود هو أحد أهم مكونات المترجم. يقوم بتحليل الكود وتطبيق مجموعة من التحسينات لتحسين الأداء وتقليل حجم الكود. التحسينات تشمل:

**إزالة الكود الميت (Dead Code Elimination):** يكتشف المحسن الكود الذي لن يتم تنفيذه أبداً (مثل الكود بعد return) والمتغيرات التي لا تُستخدم، ويقوم بإزالتها. هذا يقلل حجم البرنامج ويحسن استخدام الذاكرة المؤقتة (Cache).

**طي الثوابت (Constant Folding):** إذا كان هناك تعبير يتكون من ثوابت فقط مثل `3 + 5`، يقوم المحسن بحساب النتيجة `8` في وقت الترجمة بدلاً من تركها لوقت التشغيل.

**إنتشار الثوابت (Constant Propagation):** إذا تم تعيين متغير لقيمة ثابتة ولم يتغير بعدها، يتم استبدال استخدامات المتغير بالقيمة الثابتة مباشرة.

**تحسين الحلقات (Loop Optimization):** يشمل نقل الحسابات الثابتة خارج الحلقة، وتوسيع الحلقات الصغيرة (Loop Unrolling)، وتحسين الفهرسة.

### المرحلة الثالثة: توليد LLVM IR

بعد التحسين، يتم تحويل SIR المُحسَّن إلى LLVM IR. هذه المرحلة تتم بواسطة مولد الكود (LLVMCodeGen) الذي يقوم بالتالي:

**ربط الأنواع (Type Mapping):** تحويل أنواع لغة ص إلى أنواع LLVM المقابلة. على سبيل المثال، `رقم` يصبح `i64` و `عشري` يصبح `double`.

**توليد التعليمات:** كل تعليمة SIR تتحول إلى تعليمة أو أكثر من تعليمات LLVM IR.

**إدارة الذاكرة:** توليد الكود اللازم للتعامل مع الكائنات على الكومة (Heap) وربطها بجامع القمامة.

```cpp
// مثال من llvm_codegen.cpp
```

### المرحلة الرابعة: تحسينات LLVM

بعد توليد LLVM IR، يتم تمريره عبر مجموعة تحسينات LLVM القوية. هذه التحسينات تشمل:

- **تحسينات على مستوى الدالة:** Inlining، Tail Call Optimization
- **تحسينات على مستوى الوحدة:** Link-Time Optimization (LTO)، Dead Global Elimination
- **تحسينات خاصة بالمعمارية:** استخدام تعليمات SIMD، تحسين استخدام المسجلات

يمكن التحكم في مستوى التحسين عبر الخيارات O0 (بدون تحسين)، O1 (تحسينات أساسية)، O2 (تحسينات متوسطة)، O3 (تحسينات قصوى).

### المرحلة الخامسة: توليد كود الآلة

المرحلة الأخيرة هي تحويل LLVM IR إلى كود آلة أصلي للمعمارية المستهدفة. LLVM يدعم العديد من المعماريات:

- **x86_64:** لأجهزة الكمبيوتر الشخصية (Windows, Linux, macOS)
- **ARM64:** للهواتف والأجهزة المحمولة وأجهزة Mac الحديثة
- **WebAssembly:** للتشغيل في المتصفحات

## نظام الأنواع المتقدم

يتميز مترجم لغة ص بنظام أنواع متطور يدعم:

**أنواع الاتحاد (Union Types):** تسمح لمتغير واحد بحمل قيم من أنواع مختلفة. مثل `رقم | نص` الذي يمكن أن يكون رقماً أو نصاً.

**الأنواع الاختيارية (Optional Types):** تمثل قيمة قد تكون موجودة أو لا. مثل `نص?` الذي يمكن أن يكون نصاً أو `عدم`.

**الأنواع العامة (Generic Types):** تسمح بكتابة كود يعمل مع أنواع مختلفة. مثل `قائمة<ن>` التي تعمل مع أي نوع.

**حراس الأنواع (Type Guards):** تسمح بتضييق نوع المتغير داخل شرط معين.

## البايت كود

بالإضافة إلى توليد كود الآلة، يمكن للمترجم توليد بايت كود محمول يمكن تنفيذه على الآلة الافتراضية. البايت كود يتكون من:

**تجمع الثوابت (Constant Pool):** يحتوي على جميع الثوابت المستخدمة في البرنامج (أرقام، نصوص).

**جدول الدوال:** معلومات عن كل دالة في البرنامج.

**الكود:** سلسلة من تعليمات البايت كود.

```cpp
// مثال من bytecode.cpp
uint32_t ConstantPool::addInteger(int64_t value) {
    // تحقق من وجود القيمة مسبقاً
    auto it = intMap_.find(value);
    if (it != intMap_.end()) {
        return it->second;
    }
    
    // أضف قيمة جديدة
    uint32_t index = static_cast<uint32_t>(constants_.size());
    constants_.push_back(VM::Value::Int(value));
    intMap_[value] = index;
    return index;
}
```

## استخدام المترجم

لترجمة برنامج بلغة ص:

```bash
# ترجمة مع تحسينات
sad compile --optimize -o برنامجي برنامجي.s

# ترجمة لـ Release
sad compile --release -o برنامجي برنامجي.s

# توليد بايت كود
sad compile --bytecode -o برنامجي.sbc برنامجي.s
```

## الخلاصة

المترجم في لغة ص هو نظام متكامل ومتطور يحول الكود العربي إلى برامج أصلية عالية الأداء. من خلال استخدام LLVM كخلفية، نضمن أن البرامج المكتوبة بلغة ص تحصل على نفس مستوى التحسينات والأداء الذي تحصل عليه أشهر لغات البرمجة في العالم. المترجم يدعم نظام أنواع متقدم، ومحسنات متعددة المستويات، ويمكنه استهداف منصات متعددة.
