# الآلة الافتراضية (Virtual Machine - VM)

## ما هي الآلة الافتراضية؟

الآلة الافتراضية (Virtual Machine) في لغة ص هي برنامج يحاكي معالجاً حاسوبياً متخصصاً لتنفيذ البايت كود. بدلاً من تنفيذ الكود مباشرة على المعالج الفعلي، يتم تشغيله على هذه الآلة المحاكاة. الآلة الافتراضية تقرأ تعليمات البايت كود واحدة تلو الأخرى وتنفذها، تماماً كما يقرأ المعالج الفعلي تعليمات كود الآلة.

الهدف من استخدام آلة افتراضية هو تحقيق قابلية النقل (Portability) - برنامج واحد مترجم إلى بايت كود يمكن تشغيله على أي نظام تشغيل لديه الآلة الافتراضية. هذا النهج مشابه لما تفعله Java مع JVM و Python مع CPython. الفرق أن لغة ص توفر أيضاً خيار الترجمة المباشرة إلى كود آلة للحصول على أعلى أداء.

## بنية الآلة الافتراضية

تتواجد الآلة الافتراضية في المجلد `runtime_new/src/vm/` وتتكون من:

```
runtime_new/src/vm/
├── vm.cpp              # التنفيذ الرئيسي للآلة
├── vm_gc.cpp           # تكامل جامع القمامة
├── vm_helpers.cpp      # دوال مساعدة
└── vm_opcodes.cpp      # تنفيذ أكواد العمليات
```

## مكونات الآلة الافتراضية

### المكدس (Stack)

الآلة الافتراضية في لغة ص تعتمد على المكدس (Stack-based VM). جميع العمليات تتم عبر وضع القيم على المكدس وسحبها منه. على سبيل المثال، لجمع رقمين:

1. ادفع الرقم الأول على المكدس
2. ادفع الرقم الثاني على المكدس
3. نفذ عملية الجمع (تسحب الرقمين وتدفع النتيجة)

```cpp
// من vm.cpp - تهيئة المكدس
VirtualMachine::VirtualMachine()
    : config_()
    , stats_()
    , module_(nullptr)
    , code_(nullptr)
    , ip_(0)                    // مؤشر التعليمات
    , objects_(nullptr)
    , bytesAllocated_(0)
    , nextGC_(config_.initialHeapSize)
    , hasError_(false) {
    
    stack_.reserve(config_.maxStackSize);
    frames_.reserve(config_.maxCallDepth);
}
```

### إطارات الاستدعاء (Call Frames)

عند استدعاء دالة، يتم إنشاء إطار استدعاء جديد يحتوي على:
- عنوان العودة (Return Address)
- المتغيرات المحلية للدالة
- مؤشر قاعدة المكدس للدالة

```cpp
struct CallFrame {
    const FunctionInfo* function;   // معلومات الدالة
    const uint8_t* ip;              // مؤشر التعليمات
    size_t stackBase;               // قاعدة المكدس
};
```

### المتغيرات العامة (Globals)

المتغيرات العامة تُخزَّن في مصفوفة منفصلة يمكن الوصول إليها من أي مكان في البرنامج:

```cpp
void VirtualMachine::loadModule(const Bytecode::BytecodeModule* module) {
    module_ = module;
    code_ = module->getCode().data();
    ip_ = module->getEntryPoint();
    
    // تهيئة المتغيرات العامة
    const auto& globalInfos = module->getGlobals();
    globals_.resize(globalInfos.size());
    for (size_t i = 0; i < globalInfos.size(); ++i) {
        globals_[i] = globalInfos[i].initialValue;
    }
}
```

## أكواد العمليات (Opcodes)

البايت كود يتكون من سلسلة من أكواد العمليات، كل منها يمثل عملية محددة:

### عمليات المكدس
- **PUSH_CONST:** ادفع ثابتاً من تجمع الثوابت
- **POP:** أزل القيمة العلوية من المكدس
- **DUP:** نسخ القيمة العلوية
- **SWAP:** تبديل القيمتين العلويتين

### العمليات الحسابية
- **ADD:** جمع
- **SUB:** طرح
- **MUL:** ضرب
- **DIV:** قسمة
- **MOD:** باقي القسمة
- **NEG:** سالب

### العمليات المنطقية
- **AND:** و منطقي
- **OR:** أو منطقي
- **NOT:** نفي منطقي

### عمليات المقارنة
- **EQ:** يساوي
- **NE:** لا يساوي
- **LT:** أصغر من
- **LE:** أصغر من أو يساوي
- **GT:** أكبر من
- **GE:** أكبر من أو يساوي

### عمليات التحكم في التدفق
- **JUMP:** قفز غير مشروط
- **JUMP_IF_FALSE:** قفز إذا كانت القيمة خاطئة
- **CALL:** استدعاء دالة
- **RETURN:** عودة من دالة

### عمليات الذاكرة
- **LOAD_LOCAL:** تحميل متغير محلي
- **STORE_LOCAL:** تخزين في متغير محلي
- **LOAD_GLOBAL:** تحميل متغير عام
- **STORE_GLOBAL:** تخزين في متغير عام

## حلقة التنفيذ الرئيسية

الآلة الافتراضية تعمل عبر حلقة تنفيذ بسيطة:

```cpp
VMResult VirtualMachine::execute() {
    while (true) {
        // قراءة كود العملية التالي
        Opcode op = static_cast<Opcode>(*ip_++);
        
        switch (op) {
            case Opcode::PUSH_CONST: {
                uint32_t index = readU32();
                stack_.push_back(module_->getConstant(index));
                break;
            }
            
            case Opcode::ADD: {
                Value b = stack_.back(); stack_.pop_back();
                Value a = stack_.back(); stack_.pop_back();
                stack_.push_back(a + b);
                break;
            }
            
            case Opcode::JUMP_IF_FALSE: {
                uint32_t offset = readU32();
                Value condition = stack_.back(); stack_.pop_back();
                if (!condition.toBoolean()) {
                    ip_ = code_ + offset;
                }
                break;
            }
            
            case Opcode::CALL: {
                uint16_t argCount = readU16();
                // ... تنفيذ الاستدعاء
                break;
            }
            
            case Opcode::RETURN: {
                // ... معالجة العودة
                if (frames_.empty()) {
                    return VMResult::Success;
                }
                break;
            }
            
            case Opcode::HALT:
                return VMResult::Success;
                
            // ... المزيد من العمليات
        }
    }
}
```

## تكامل جامع القمامة

الآلة الافتراضية متكاملة مع جامع القمامة لإدارة الذاكرة تلقائياً:

```cpp
// عند تخصيص كائن جديد
Object* VirtualMachine::allocateObject(ObjectType type, size_t size) {
    // التحقق من الحاجة لجمع القمامة
    if (bytesAllocated_ + size > nextGC_) {
        collectGarbage();
    }
    
    Object* obj = static_cast<Object*>(malloc(size));
    obj->type = type;
    obj->isMarked = false;
    obj->next = objects_;
    objects_ = obj;
    
    bytesAllocated_ += size;
    return obj;
}
```

## التعامل مع Endianness

لضمان قابلية النقل، الآلة الافتراضية تتعامل مع ترتيب البايتات:

```cpp
// دوال تحويل ترتيب البايتات
inline uint16_t swap_uint16(uint16_t val) {
    return (val << 8) | (val >> 8);
}

inline uint32_t swap_uint32(uint32_t val) {
    val = ((val << 8) & 0xFF00FF00) | ((val >> 8) & 0xFF00FF);
    return (val << 16) | (val >> 16);
}
```

## إعدادات الآلة الافتراضية

يمكن تخصيص سلوك الآلة الافتراضية عبر الإعدادات:

```cpp
struct VMConfig {
    size_t maxStackSize = 1024;       // حجم المكدس الأقصى
    size_t maxCallDepth = 256;        // عمق الاستدعاء الأقصى
    size_t initialHeapSize = 1024*1024;  // حجم الكومة الابتدائي
    bool enableDebug = false;          // تفعيل وضع التصحيح
    bool enableGC = true;              // تفعيل جامع القمامة
};
```

## وضع التصحيح (Debug Mode)

في وضع التصحيح، الآلة الافتراضية تطبع معلومات مفصلة:

```cpp
if (config_.enableDebug) {
```

## الأداء مقارنة بالمفسر

الآلة الافتراضية أسرع من المفسر لعدة أسباب:

1. **لا تحليل:** البايت كود جاهز للتنفيذ
2. **تمثيل مدمج:** التعليمات بايت واحد أو بضعة بايتات
3. **قفزات مباشرة:** لا حاجة لتتبع شجرة AST
4. **تحسينات المترجم:** البايت كود مُحسَّن مسبقاً

## متى تستخدم الآلة الافتراضية؟

- **التوزيع:** توزيع برنامج واحد لجميع الأنظمة
- **الأمان:** البايت كود أصعب في الهندسة العكسية
- **الموارد المحدودة:** عندما لا يمكن ترجمة لكود آلة
- **التطوير المختلط:** تشغيل سريع أثناء التطوير

## الخلاصة

الآلة الافتراضية في لغة ص توفر طريقة متوسطة بين التفسير المباشر والترجمة الكاملة. تحقق أداءً جيداً مع الحفاظ على قابلية النقل. التكامل مع جامع القمامة يجعل إدارة الذاكرة شفافة للمبرمج. الخيار بين الآلة الافتراضية والكود المترجم يعتمد على متطلبات المشروع من حيث الأداء وقابلية النقل.
