# الأنواع الاتحادية (Union Types)
## دليل شامل للمبرمجين

---

## 🎯 ما هي الأنواع الاتحادية؟

**الأنواع الاتحادية (Union Types)** هي ميزة قوية تسمح لمتغير أو دالة بقبول قيم من أنواع مختلفة متعددة. بمعنى آخر، النوع الاتحادي هو "إما هذا أو ذاك" - قيمة يمكن أن تكون من النوع A **أو** النوع B **أو** النوع C.

تخيل أن لديك دالة تُرجع إما رقماً (في حالة النجاح) أو رسالة خطأ نصية (في حالة الفشل). بدلاً من إنشاء نوع wrapper معقد، يمكنك ببساطة استخدام:

```sad
دالة اقسم(أ: رقم، ب: رقم) -> رقم | نص {
    إذا (ب == 0) {
        ارجع "خطأ: القسمة على صفر!"
    }
    ارجع أ / ب
}
```

هنا، `رقم | نص` هو نوع اتحادي يعني "إما رقم أو نص".

الأنواع الاتحادية تحل مشكلة أساسية: كيف نعبّر عن قيمة يمكن أن تكون من أنواع متعددة بطريقة آمنة ومعبّرة؟ قبل Union Types، كان المبرمجون يستخدمون:
1. **Any/Object**: نوع عام يقبل أي شيء (غير آمن)
2. **Wrapper classes**: أصناف wrapper معقدة
3. **Error codes**: رموز أخطاء مع قيم منفصلة

Union Types تقدم حلاً أنيقاً: نوع واحد يمثل بدائل متعددة بشكل صريح وآمن.

## 📚 المفاهيم الأساسية

### 1. صيغة Union Type

في لغة ص، نستخدم الرمز `|` للتعبير عن Union:

```sad
# نوع بسيط
متغير القيمة: رقم | نص

# نوع معقد
متغير البيانات: رقم | نص | منطقي | لاشيء

# في تعريف الدوال
دالة معالج(الإدخال: رقم | نص) -> منطقي

# في الأنواع المُعرّفة
نوع النتيجة = رقم | خطأ
نوع الخطأ = نص | رمز_خطأ
```

### 2. Alternatives (البدائل)

كل نوع في Union يسمى "alternative" (بديل). في `رقم | نص | منطقي`، لدينا 3 بدائل.

خصائص البدائل:
- **مُرتبة**: `رقم | نص` و `نص | رقم` هما نفس النوع (يتم ترتيبهم تلقائياً)
- **فريدة**: `رقم | رقم | نص` يُبسط إلى `رقم | نص`
- **مُسطحة**: `رقم | (نص | منطقي)` يُبسط إلى `رقم | نص | منطقي`

### 3. Type Narrowing (تضييق النوع)

عند استخدام قيمة من نوع اتحادي، يجب عليك "تضييق" النوع لمعرفة البديل الفعلي:

```sad
متغير القيمة: رقم | نص = حصل_على_قيمة()

إذا (القيمة نوع رقم) {
    # هنا، المترجم يعرف أن القيمة من النوع رقم
    اطبع(القيمة * 2)
} وإلا {
    # هنا، المترجم يعرف أن القيمة من النوع نص
    اطبع(القيمة.طول())
}
```

### 4. Optional Types (الأنواع الاختيارية)

النوع الاختياري هو syntactic sugar لـ Union مع `لاشيء`:

```sad
# هذان متساويان:
متغير الاسم: نص?
متغير الاسم: نص | لاشيء

# كلاهما يعني: "إما نص أو لا شيء"
```

Optional Types شائعة جداً لتمثيل قيم قد تكون موجودة أو غير موجودة.

## 🎓 لماذا نحتاج الأنواع الاتحادية؟

### المشكلة: التعبير عن البدائل

تخيل دالة تبحث عن عنصر في قائمة. إذا وجدت العنصر، تُرجعه. إذا لم تجده، ماذا تُرجع؟

**الحل السيئ 1: استخدام null/undefined**
```sad
دالة ابحث(القائمة: رقم[]، الهدف: رقم) -> رقم {
    لكل عنصر في القائمة {
        إذا (عنصر == الهدف) {
            ارجع عنصر
        }
    }
    ارجع لاشيء  # ❌ خطأ: نوع الإرجاع رقم، لكن نُرجع لاشيء
}
```

**الحل السيئ 2: استخدام قيمة خاصة**
```sad
دالة ابحث(القائمة: رقم[]، الهدف: رقم) -> رقم {
    لكل عنصر في القائمة {
        إذا (عنصر == الهدف) {
            ارجع عنصر
        }
    }
    ارجع -1  # ❌ ماذا لو كان -1 قيمة صحيحة في القائمة؟
}
```

**الحل السيئ 3: استخدام Any**
```sad
دالة ابحث(القائمة: رقم[]، الهدف: رقم) -> أي {
    لكل عنصر في القائمة {
        إذا (عنصر == الهدف) {
            ارجع عنصر
        }
    }
    ارجع لاشيء  # ❌ فقدنا أمان الأنواع
}
```

### الحل الصحيح: Union Types

```sad
دالة ابحث(القائمة: رقم[]، الهدف: رقم) -> رقم | لاشيء {
    لكل عنصر في القائمة {
        إذا (عنصر == الهدف) {
            ارجع عنصر
        }
    }
    ارجع لاشيء  # ✅ واضح وآمن
}

# الاستخدام:
متغير النتيجة = ابحث([1، 2، 3، 4، 5]، 3)

إذا (النتيجة != لاشيء) {
    اطبع("وُجد: " + النتيجة)
} وإلا {
    اطبع("لم يُوجد")
}
```

**الفوائد:**
- ✅ واضح: النوع يُعبر عن النية بوضوح
- ✅ آمن: المترجم يجبرك على معالجة كلا الحالتين
- ✅ موثق ذاتياً: أي شخص يقرأ الكود يفهم الاحتمالات

## 💡 أمثلة عملية

### المثال الأول: نوع النتيجة (Result Type)

واحد من أشهر استخدامات Union Types هو تمثيل عمليات قد تنجح أو تفشل:

```sad
# تعريف نوع النتيجة
نوع النتيجة<T، E> = نجاح<T> | فشل<E>

# صنف النجاح
صنف نجاح<T> {
    عام متغير القيمة: T
    
    دالة جديد(قيمة: T) {
        هذا.القيمة = قيمة
    }
}

# صنف الفشل
صنف فشل<E> {
    عام متغير الخطأ: E
    
    دالة جديد(خطأ: E) {
        هذا.الخطأ = خطأ
    }
}

# دالة تُرجع النتيجة
دالة اقرأ_ملف(المسار: نص) -> النتيجة<نص، نص> {
    إذا (!ملف_موجود(المسار)) {
        ارجع فشل<نص>.جديد("الملف غير موجود: " + المسار)
    }
    
    محاولة {
        متغير المحتوى = قراءة_الملف(المسار)
        ارجع نجاح<نص>.جديد(المحتوى)
    } استثناء (خطأ) {
        ارجع فشل<نص>.جديد("خطأ في القراءة: " + خطأ.الرسالة())
    }
}

# الاستخدام:
متغير النتيجة = اقرأ_ملف("data.txt")

طابق النتيجة {
    نجاح(محتوى) => {
        اطبع("المحتوى: " + محتوى.القيمة)
    }
    فشل(خطأ) => {
        اطبع("خطأ: " + خطأ.الخطأ)
    }
}

# أو باستخدام if
إذا (النتيجة نوع نجاح) {
    متغير المحتوى = (النتيجة كـ نجاح<نص>).القيمة
    اطبع("المحتوى: " + المحتوى)
} وإلا {
    متغير رسالة_الخطأ = (النتيجة كـ فشل<نص>).الخطأ
    اطبع("خطأ: " + رسالة_الخطأ)
}
```

**لماذا هذا أفضل من الاستثناءات؟**
- ✅ الأخطاء جزء من signature الدالة
- ✅ إجباري: المترجم يجبرك على معالجة الأخطاء
- ✅ أسرع: لا overhead للاستثناءات
- ✅ أكثر وضوحاً: يظهر في النوع

### المثال الثاني: قيمة JSON (JSON Value)

JSON يدعم أنواع متعددة من القيم. Union Types مثالية لتمثيل هذا:

```sad
# تعريف أنواع JSON
نوع قيمة_JSON = 
    | رقم
    | نص
    | منطقي
    | لاشيء
    | مصفوفة_JSON
    | كائن_JSON

نوع مصفوفة_JSON = قائمة<قيمة_JSON>
نوع كائن_JSON = قاموس<نص، قيمة_JSON>

# دالة لتحويل قيمة JSON إلى نص
دالة إلى_نص_JSON(القيمة: قيمة_JSON) -> نص {
    # استخدام pattern matching لمعالجة كل نوع
    طابق القيمة {
        رقم(ع) => ارجع ع.إلى_نص()
        
        نص(ن) => ارجع "\"" + ن + "\""
        
        منطقي(م) => ارجع إذا (م) "true" وإلا "false"
        
        لاشيء => ارجع "null"
        
        مصفوفة_JSON(م) => {
            متغير عناصر: نص[] = []
            لكل عنصر في م {
                عناصر.أضف(إلى_نص_JSON(عنصر))
            }
            ارجع "[" + عناصر.اربط("، ") + "]"
        }
        
        كائن_JSON(ك) => {
            متغير أزواج: نص[] = []
            لكل (مفتاح، قيمة) في ك {
                متغير زوج = "\"" + مفتاح + "\": " + إلى_نص_JSON(قيمة)
                أزواج.أضف(زوج)
            }
            ارجع "{" + أزواج.اربط("، ") + "}"
        }
    }
}

# الاستخدام:

# JSON بسيط
متغير رقم: قيمة_JSON = 42
متغير نص: قيمة_JSON = "مرحباً"
متغير منطقي: قيمة_JSON = صحيح

اطبع(إلى_نص_JSON(رقم))     # "42"
اطبع(إلى_نص_JSON(نص))      # "\"مرحباً\""
اطبع(إلى_نص_JSON(منطقي))   # "true"

# JSON مصفوفة
متغير مصفوفة: قيمة_JSON = [1، 2، 3، "أربعة"]
اطبع(إلى_نص_JSON(مصفوفة))  # "[1، 2، 3، \"أربعة\"]"

# JSON كائن
متغير كائن: قيمة_JSON = {
    "الاسم": "أحمد"،
    "العمر": 25،
    "نشط": صحيح،
    "الهوايات": ["قراءة"، "برمجة"، "رياضة"]
}
اطبع(إلى_نص_JSON(كائن))
# {"الاسم": "أحمد"، "العمر": 25، "نشط": true، "الهوايات": ["قراءة"، "برمجة"، "رياضة"]}

# JSON متداخل معقد
متغير بيانات: قيمة_JSON = {
    "المستخدمون": [
        {"الاسم": "أحمد"، "العمر": 25}،
        {"الاسم": "فاطمة"، "العمر": 30}
    ]،
    "العدد_الكلي": 2،
    "نشط": صحيح
}
اطبع(إلى_نص_JSON(بيانات))
```

**الفوائد:**
- ✅ نوع واحد يمثل جميع قيم JSON الممكنة
- ✅ المترجم يضمن معالجة جميع الحالات
- ✅ Type-safe: لا يمكن وضع قيمة غير JSON
- ✅ سهولة في الصيانة والتوسع

## 🔧 عمليات Union (Set Operations)

الأنواع الاتحادية تدعم عمليات المجموعات:

### 1. Union (الاتحاد) - ∪

دمج نوعين اتحاديين:

```sad
# A = رقم | نص
# B = نص | منطقي
# A ∪ B = رقم | نص | منطقي

دالة unionOf<A، B>(قيمة: A | B) -> A | B {
    ارجع قيمة
}
```

### 2. Intersection (التقاطع) - ∩

الأنواع المشتركة بين اتحادين:

```sad
# A = رقم | نص | منطقي
# B = نص | منطقي | عشري
# A ∩ B = نص | منطقي
```

### 3. Difference (الفرق) - −

إزالة أنواع من اتحاد (مفيد لـ Type Narrowing):

```sad
# A = رقم | نص | منطقي
# A − نص = رقم | منطقي

إذا (القيمة نوع نص) {
    # معالجة نص
} وإلا {
    # هنا النوع هو: رقم | منطقي
    # (تم إزالة نص من الاتحاد)
}
```

## 🔧 التنفيذ في لغة ص

في لغة ص، تم تنفيذ Union Types في **Phase 1.3.5.0** بشكل كامل:

### 1. UnionType Class
```cpp
class UnionType : public Type {
    TypeList alternatives_;
    
    // عمليات المجموعات
    UnionTypePtr intersection(const UnionTypePtr& other);
    UnionTypePtr unionWith(const UnionTypePtr& other);
    UnionTypePtr difference(const TypePtr& type);
    
    // التبسيط
    UnionTypePtr simplify();  // إزالة التكرار، التسطيح
    
    // علاقات الأنواع
    bool isAssignableTo(const Type* other);
    bool isSubtypeOf(const Type* other);
};
```

### 2. OptionalType Class
```cpp
class OptionalType : public UnionType {
    TypePtr innerType_;
    
    // T? = T | null
    OptionalType(TypePtr innerType);
    
    TypePtr getInnerType();
    bool containsNull();
};
```


## 📖 مصطلحات ذات صلة

### Tagged Union
Union type حيث كل بديل له "tag" لتمييزه في runtime. في لغة ص، كل union هو tagged union.

### Discriminated Union
نفس Tagged Union - union حيث يمكن التمييز بين البدائل.

### Sum Type
مصطلح من نظرية الأنواع: `A | B` هو "مجموع" A و B.

### Product Type
عكس Sum Type: tuple أو struct هو "ضرب" الأنواع.

### Exhaustiveness Checking
التحقق من أن جميع بدائل Union قد تمت معالجتها في pattern matching.

## 🎯 الخلاصة

الأنواع الاتحادية (Union Types) هي ميزة قوية تسمح بـ:
- ✅ **تعبير واضح**: البدائل ظاهرة في النوع
- ✅ **أمان**: المترجم يجبرك على معالجة جميع الحالات
- ✅ **مرونة**: نوع واحد يمثل بدائل متعددة
- ✅ **موثق ذاتياً**: النوع يشرح نفسه

في لغة ص، Union Types مُنفذة بالكامل مع:
- Union syntax (`A | B`)
- Optional types (`T?`)
- Set operations
- Type narrowing
- Pattern matching (قيد التنفيذ)

Union Types هي أساس للبرمجة الآمنة والمعبرة، وتُستخدم في:
- معالجة الأخطاء (Result types)
- تمثيل البيانات المتنوعة (JSON، XML)
- State machines
- Parser results
- وأكثر بكثير!
