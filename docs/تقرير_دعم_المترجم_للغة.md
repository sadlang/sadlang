# تقرير شامل: نسبة دعم المترجم (sadc) لقواعد لغة ص

**التاريخ:** 9 أبريل 2026 (محدّث: يوليو 2026)  
**الهدف:** تحليل شامل لمقارنة تغطية المترجم (sadc) مقابل المفسر (sad) لكل قواعد وميزات لغة ص  
**الأدوات:** sadc (LLVM backend) | sad (tree-walking interpreter)

---

## الملخص التنفيذي

| المقياس | القيمة |
|---------|--------|
| إجمالي عقد AST | **98** |
| مدعوم كاملاً في SIR builder | **89** (91%) |
| مدعوم جزئياً | **9** (9%) |
| غير مدعوم كلياً | **0** (0%) |
| نسبة التغطية الإجمالية في SIR | **~91%** |
| نسبة التغطية الفعلية (SIR → LLVM → تنفيذي) | **~80-85%** |

> **ملاحظة مهمة:** نسبة 91% تعكس تغطية **بناء SIR من AST** فقط. النسبة الفعلية أقل لأن بعض الميزات تُبنى في SIR لكن لا تُترجم بشكل كامل إلى LLVM IR أو تفشل في وقت التشغيل.

## III. تفصيل الميزات المتقدمة

### 1. Async/Await — تقييم: ⚠️ 50%
```
AST Parsing:  ✅ (AwaitExpr, AsyncFuncDecl)
SIR Builder:  ⚠️ (flagging فقط — لا state machine)
LLVM Codegen: ❌ (لا coroutine lowering)
المفسر:        ✅ (يعمل كـ synchronous)
```
**المشكلة:** لا يوجد تحويل الدوال غير المتزامنة إلى state machines أو coroutines في LLVM. الدوال المعلّمة بـ `غير_متزامن` تُترجم كدوال عادية.

### 2. القوالب (Generics/Templates) — تقييم: ⚠️ 60%
```
AST Parsing:  ✅ (TemplateFunctionDecl, TemplateClassDecl)
SIR Builder:  ⚠️ (monomorphization أساسي في sir_builder_templates.cpp)
LLVM Codegen: ⚠️ (يعمل للحالات البسيطة فقط)
المفسر:        ⚠️ (دعم جزئي)
```
**المشكلة:** Monomorphization يعمل لحالات بسيطة لكن ليس كاملاً. لا يدعم:
- قيود أنواع معقدة (where clauses)
- أنواع مرتبطة (associated types)
- تخصيص القوالب (template specialization)

### 3. الماكروز — تقييم: ⚠️ 50%
```
AST Parsing:  ✅ (MacroDecl, MacroCallExpr!)
SIR Builder:  ⚠️ (تسجيل + expansion بسيط عبر دوال مؤقتة)
LLVM Codegen: ❌ (الماكروز المعقدة لا تُترجم)
المفسر:        ✅ (expansion كامل مع hygiene)
```
**المشكلة:** في SIR builder، الماكروز تُحول إلى دوال مؤقتة (`__macro_NAME_N`) مع استدعاء مباشر. هذا يعمل للماكروز البسيطة لكن لا يدعم:
- ماكروز إجرائية
- ماكروز مع كتل كود كمعاملات
- Variadic expansion المعقد

### 4. المولدات (Generators) — تقييم: ⚠️ 50%
```
AST Parsing:  ✅ (GeneratorExpr, YieldStmt)
SIR Builder:  ⚠️ (yield → STORE فقط)
LLVM Codegen: ❌ (لا coroutine/iterator protocol)
المفسر:        ✅ (كامل مع lazy evaluation)
```
**المشكلة:** لا يوجد بروتوكول iterator/generator في LLVM backend. `أنتج` يُترجم كـ STORE عادي بدون حفظ الحالة.

### 5. تنفيذ وقت الترجمة (@وقت_الترجمة) — تقييم: ⚠️ 40%
```
AST Parsing:  ✅ (ComptimeBlockStmt)
SIR Builder:  ⚠️ (يُبنى كجمل عادية)
LLVM Codegen: ❌ (لا constant folding خاص)
المفسر:        ⚠️ (ينفذ عادياً في وقت التشغيل)
```
**المشكلة:** لا يوجد CTFE (Compile-Time Function Evaluation). الكتل تُعامل كأنها جمل عادية.

### 6. Goroutines والقنوات — تقييم: ✅ ~90%
```
AST Parsing:  ✅ (GoStmt, SelectStmt, ChannelOps)
SIR Builder:  ✅ (كامل مع GOROUTINE_SPAWN, CHANNEL_*)
LLVM Codegen: ⚠️ (runtime functions لكن بدون lightweight scheduling)
المفسر:        ✅ (كامل مع GoroutineManager, SadChannel)
```
**ملاحظة:** يعمل بشكل جيد عبر runtime functions. الفجوة الوحيدة هي أن LLVM يستخدم OS threads بدلاً من goroutines خفيفة.

## VIII. نقاط الضعف الرئيسية

### 1. ❌ Async/Await — **أولوية عالية**
- لا يوجد coroutine lowering
- الدوال غير المتزامنة تُترجم كدوال عادية
- **التأثير:** تطبيقات الشبكة والـ I/O غير المتزامن لن تعمل بالمترجم

### 2. ❌ المولدات — **أولوية عالية**
- `أنتج` لا تنتج قيماً بشكل lazy
- لا يوجد بروتوكول iterator
- **التأثير:** أي كود يستخدم مولدات لن يعمل بالمترجم

### 3. ⚠️ القوالب — **أولوية متوسطة**
- Monomorphization أساسي فقط
- لا قيود أنواع معقدة
- **التأثير:** الأكواد المعممة قد تفشل في حالات متقدمة

### 4. ⚠️ الماكروز — **أولوية منخفضة**
- Expansion بسيط عبر دوال مؤقتة
- لا ماكروز إجرائية
- **التأثير:** محدود — معظم الأكواد لا تستخدم ماكروز معقدة

### 5. ⚠️ نظام الملكية — **أولوية منخفضة**
- Opcodes الملكية (BORROW, DROP, CLONE, etc.) غير مُترجمة إلى LLVM IR
- تُستخدم GC بدلاً منها
- **التأثير:** لا بأس عملياً — GC يعمل جيداً

## X. التوصيات للتطوير المستقبلي

### أولوية قصوى (تأثير كبير)
1. **إكمال Async/Await** — تحويل إلى LLVM coroutines أو state machines
2. **إكمال المولدات** — بناء بروتوكول iterator في LLVM backend

### أولوية متوسطة
3. **تحسين القوالب** — monomorphization كامل مع where clauses

### أولوية منخفضة
4. **توسيع الماكروز** — دعم expansion أكثر تعقيداً
5. **تنفيذ وقت الترجمة** — CTFE عبر مفسر مدمج في المترجم
6. **Lightweight goroutines** — استبدال OS threads بـ userspace scheduler

## XI. الخلاصة

المترجم (sadc) يغطي **91% من عقد AST** على مستوى SIR builder، و**~80-85%** على مستوى التنفيذي الفعلي. الأساسيات (جمل، تعابير، OOP، مطابقة أنماط، defer، goroutines) تعمل بالكامل. عمليات المصفوفات (slice، append، remove، فهارس سالبة، فحص حدود) مكتملة وآمنة. الفجوات الرئيسية في: **Async/Await**، **المولدات**، و**القوالب المتقدمة**.

بالمقارنة، المفسر (sad) يدعم **~98%** من ميزات اللغة بشكل فعال. لذا **نسبة دعم المترجم أضعف بـ 18-23% تقريباً** مقارنة بالمفسر، لكن الفجوة تتركز في ميزات متقدمة محددة وليس في الأساسيات.

| المقياس | المترجم (sadc) | المفسر (sad) |
|---------|----------------|-------------|
| تغطية AST | 91% | ~98% |
| التنفيذ الفعلي | ~75-80% | ~98% |
| الأساسيات | ✅ 100% | ✅ 100% |
| الميزات المتقدمة | ⚠️ ~50% | ✅ ~90% |
| الأداء | **أسرع بكثير** (native code) | أبطأ (tree-walking) |
