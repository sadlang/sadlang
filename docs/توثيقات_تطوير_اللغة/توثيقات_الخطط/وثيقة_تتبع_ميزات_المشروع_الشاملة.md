### أ) نظام الكيوبت (Qubit Type) — T452

**الهدف:** تمكين المطورين من كتابة **خوارزميات الحوسبة الكمومية** بالعربية عبر محاكاة كلاسيكية على CPU عادي.

**هام:** لغة ص **لا تتحكم في جهاز كمومي حقيقي** — بل تُجري **محاكاة رياضية** دقيقة للكيوبتات. الكيوبت في الذاكرة هو زوج أعداد مركبة `(α, β)` يمثل `α|0⟩ + β|1⟩`.

**الفوائد العملية:**
- الباحثون يكتبون خوارزميات مثل Shor/Grover بالعربية
- الطلاب يتعلمون الحوسبة الكمومية بأمثلة تنفيذية
- المحاكاة تعمل على أي جهاز دون hardware خاص

**مثال الاستخدام المستهدف:**
```sad
من كمومي استورد كيوبت، هادامارد، قس، تشابك

متغير كب = كيوبت::صفر()       # |0⟩
هادامارد(كب)                   # (|0⟩+|1⟩)/√2
متغير نتيجة = قس(كب)           # 0 أو 1 بنسبة 50%
اطبع_سطر("النتيجة: " + نتيجة)

# التشابك الكمومي (Entanglement)
متغير كب1 = كيوبت::صفر()
متغير كب2 = كيوبت::صفر()
هادامارد(كب1)
تشابك(كب1، كب2)               # حالة بيل: (|00⟩+|11⟩)/√2
```

**حالة التنفيذ:**

| المكوّن | الحالة | ملاحظة |
|--------|--------|---------|
| `QubitState (α,β)` | ✅ مكتمل | normalize, probability0/1 |
| `QubitType class` | 📦 | **مُؤرشَف** (Fix #5) في `archived/experimental_types/qubit_type.cpp` |
| حالات أساسية (Zero/One/Plus/Minus) | ✅ مكتمل | تعريفات رياضية دقيقة |

| `stdlib/كمومي.ص` | ❌ غير موجود | يحتاج إنشاءً |

**ما ينقص للتفعيل:**

### ج) توليد EVM (Ethereum VM) — T352

**الهدف:** تمكين كتابة **عقود ذكية لـ Ethereum** بالعربية — لغة ص كبديل عربي لـ Solidity.

**القيمة التنافسية:**

| Solidity | لغة ص + EVM |
|---------|-------------|
| إنجليزية فقط | **عربية كاملة** |
| نظام أنواع بسيط | 35+ نوع + Generics |
| لا borrow checker | **أمان الذاكرة مُدقَّق** |
| لا pattern matching | **مطابقة أنماط كاملة** |

**مثال العقد الذكي العربي المستهدف:**
```sad
عقد محفظة_عربية
    متغير عام رصيد: خريطة[نص، رقم]

    دالة عام إيداع(مبلغ: رقم)
        يتطلب مبلغ > 0
        هذا.رصيد[المُرسِل()] += مبلغ
        أصدر_حدث("إيداع"، المُرسِل()، مبلغ)
    نهاية

    دالة عام سحب(مبلغ: رقم)
        يتطلب هذا.رصيد[المُرسِل()] >= مبلغ
        هذا.رصيد[المُرسِل()] -= مبلغ
        حوّل(المُرسِل()، مبلغ)
    نهاية
نهاية
```

**يعمل على:** Ethereum + Polygon + BSC + أي شبكة EVM-compatible

**حالة التنفيذ:**

| المكوّن | الحالة | ملاحظة |

### 13.2 تفاصيل التشفير (المُحدَّثة)

#### AES-256-GCM (aes_gcm.cpp)
| الميزة | الحالة |
|--------|--------|
| T-tables (fallback برمجي) | ✅ |
| **AES-NI** (تسريع عتادي — CPUID auto-detect) | ✅ |
| **PCLMULQDQ** (GHASH acceleration) | ✅ |
| CSPRNG — BCryptGenRandom (Windows) | ✅ |
| CSPRNG — /dev/urandom (Linux) | ✅ |

#### X25519 + Double Ratchet (x25519.cpp)
| الميزة | الحالة |
|--------|--------|
| Curve25519 field arithmetic ذاتي (بدون libsodium) | ✅ |
| p = 2^255 - 19 حسابات دقيقة | ✅ |
| MSVC: `_umul128` intrinsic لـ 128-bit | ✅ |
| **Double Ratchet** (Signal Protocol — نفس WhatsApp) | ✅ |
| `DoubleRatchetSession` class | ✅ |

#### messaging.cpp — E2EE طرف-لطرف
- صيغة الرسالة: `[id:8][type:1][sender:32][recipient:32][timestamp:8][payload_len:4][payload:N][sig_len:2][sig:M]`
- يستخدم: AES-GCM + HMAC-SHA256 + SHA256 + X25519
- يدعم: جلسات فردية + جلسات مجموعات مشفرة

#### DHT (dht_engine.cpp + routing_table.cpp) — Kademlia الكامل
- **4 عمليات**: PING + STORE + FIND_NODE + FIND_VALUE
- **بحث تكراري** مع α=3 (المعيار في Kademlia)
- **256 K-Bucket** مع LRU eviction (لكل 256-bit Node ID)
- Thread-safe: mutex لكل Bucket
- RPC غير متزامن: `send_and_wait()` مع `condition_variable` + callbacks
- Background `recv_thread` لاستقبال الرسائل

### 13.2 البنية التقنية

```
SadNet Architecture:
┌─────────────────────────────────────────────────────────┐
│ Application Layer    ← stdlib/شبكة + bindings           │
├─────────────────────────────────────────────────────────┤
│ Protocol Layer       ← messaging + streaming + CDN      │
├─────────────────────────────────────────────────────────┤
│ P2P Layer            ← DHT + identity + discovery       │
│                      ← routing + nat + trust            │
├─────────────────────────────────────────────────────────┤
│ Security Layer       ← X25519 (ECDH) + AES-GCM + SHA256 │
├─────────────────────────────────────────────────────────┤
│ Transport Layer      ← TCP/UDP + DNS + core             │
├─────────────────────────────────────────────────────────┤
│ Kernel Layer         ← freestanding (بدون OS)           │
└─────────────────────────────────────────────────────────┘
```

> **ما ينقص:** ربط DHT بالـ discovery فعلياً + اختبار X25519 handshake + CLI للاختبار

## §20 — نظام وقت التشغيل: ObjectInstance + ClassType + FunctionRef

> **المصدر:** `shared/types/include/` — 3 ملفات جوهرية للمفسر
>
> هذه الملفات تُشكّل **جوهر نظام OOP في وقت التشغيل** — كل عملية `جديد` أو استدعاء طريقة تمر بهذه المكونات.

---

### 20.1 ClassType — تعريف الصنف في وقت التشغيل

**الملف:** `shared/types/include/class_type.h`

**الوظيفة:** يُخزّن معلومات الصنف الكاملة (حقول + طرق + باني + هدام + وراثة)

| البنية الداخلية | الوصف |
|----------------|-------|
| `struct ClassField` | حقل الصنف: `name`, `type` (DataType), `visibility`, `isStatic`, `defaultValue` |
| `struct ClassMethod` | طريقة: `name`, `returnType`, `params`, `body`, `isStatic`, `isVirtual`, `isAbstract` |
| `class ClassType : public Type` | الصنف الرئيسي (سطر 251) |

**أبرز خصائص ClassType:**
- `std::vector<ClassField> fields` — قائمة الحقول
- `std::vector<ClassMethod> methods` — قائمة الطرق
- `addField()` / `addMethod()` — لإضافة حقل/طريقة
- `createInstance()` — إنشاء `ObjectInstance` جديد
- الخصائص الثابتة (`isStatic`) تُخزَّن في `ClassType` مباشرةً (لا في الكائن)

---

### 20.2 ObjectInstance — نسخة الصنف في وقت التشغيل

**الملف:** `shared/types/include/object_instance.h`

**الوظيفة:** يُمثّل كائناً فعلياً من صنف — ما ينتجه `جديد` أو `صنف()` في لغة ص

| العنصر | الوصف |
|--------|-------|
| `ClassType* classType` | مؤشر للصنف الأصلي (قد يكون nullptr للكائنات الداخلية) |
| `unordered_map<string, Value> fields` | حقول الكائن بقيمها الفعلية |
| `Value* getField(name)` | قراءة حقل |
| `bool setField(name, value)` | كتابة حقل + إشعار المراقب |
| `void initializeFields()` | تهيئة الحقول بقيمها الافتراضية (بما في ذلك الوراثة) |
| `string getClassName()` | اسم الصنف (من `classType->name` أو `fields["__class__"]`) |
| `bool isInstanceOf(name)` | فحص الوراثة |
| Observer callback | `onFieldChanged_` — يُستدعى عند تغيير أي حقل (للـ UI Reactive) |

**الفرق بين ClassType و ObjectInstance:**
- `ClassType` = القالب (مثل تعريف `صنف شخص`)
- `ObjectInstance` = النسخة (مثل `متغير أحمد = شخص("أحمد", 25)`)

**الكائنات الداخلية:** `classType = nullptr` في بعض الكائنات الداخلية مثل القنوات (channels) — يُعرَّف الاسم عبر `fields["__class__"]`.

---

### 20.3 FunctionRef — مرجع الدالة في وقت التشغيل

**الملف:** `shared/types/include/function_ref.h`

**الوظيفة:** يُخزّن مرجعاً لدالة قابلة للاستدعاء — يُستخدم عند تمرير الدوال كقيم

| `FunctionRefKind` | العربي | الوصف |
|------------------|--------|-------|
| `USER_DEFINED` | مُعرَّفة بالمستخدم | دالة بكلمة `دالة` |
| `LAMBDA` | لامبدا | دالة مجهولة `لامدا` |
| `METHOD` | طريقة | طريقة داخل صنف |

**أبرز حقول FunctionRef:**
- `displayName` — اسم الدالة كما كتبه المستخدم
- `registeredName` — الاسم الفعلي في `FunctionManager` (قد يختلف للامبدا)
- `parameterNames` — أسماء المعاملات
- `arity` — عدد المعاملات
- `isLambda()` — هل لامبدا؟

**سلسلة الاستدعاء:** `Value(FunctionRefPtr)` في variant → `FunctionManager::call()` في المفسر

---

### 20.4 علاقة المكونات الثلاثة

```
ClassType (القالب)
    ↓ createInstance()
ObjectInstance (النسخة) ←── classType* ──→ ClassType
    ↓ fields["دالة"] = Value(FunctionRefPtr)
FunctionRef (مرجع الدالة) → FunctionManager::call()
```

> **ملاحظة أمان الخيوط:** `ObjectInstance` يُمرَّر كـ `shared_ptr<ObjectInstance>` — عدة goroutines يمكن أن تشير لنفس الكائن. تعديل الحقول غير محمي بـ mutex افتراضياً — المستخدم مسؤول عن التزامن.

### 21.4 النموذج المرجعي: AstToSirLowering

**الملف:** `compiler/src/sir/ast_to_sir.cpp` (884 سطر)

هذا الملف **نموذج توثيقي** يشرح مفهوم التحويل بشكل مبسط:

| الفئة | الوصف |
|-------|-------|
| `AstNodeKind` | تعداد 22 نوع عقدة (Program, Function, VarDecl, If, While, ...) |

| `AstToSirLowering` | المحول المبسط: lower() → lowerFunction() → lowerBlock() → lowerStatement() → lowerExpression() |

**تحولات التعبير في النموذج:**
- `IntLiteral` → `Alloc(sirInt32())` — ⚠️ يُؤكد مشكلة i32

### 22.1 المحرك الرئيسي: TypeInferencer (Hindley-Milner)

**الملف:** `type_inferencer.cpp` (440 سطر)

**الخوارزمية:** Hindley-Milner Algorithm W (Damas & Milner 1982)

| الفئة | الوصف |
|-------|-------|
| `TypeEnvironment` | بيئة الأنواع: `bind(name, type)` + `lookup(name)` + `createChild()` — بنية متداخلة |
| `InferenceContext` | سياق الاستنتاج: `environment_` + `typeVarCounter_` |
| `InferenceResult` | نتيجة: `success + type + substitution` أو `success=false + errorMessage` |
| `TypeInferencer` | المحرك: `inferExpression(expr*)` + `inferExpression(expr*, env)` |

**مسار الاستنتاج:**
```
TypeInferencer::inferExpression(expr*)
    → inferExpression(expr, globalEnv_)
    → [Validation] تحقق من null
    → [Lookup] بحث في TypeEnvironment (متداخل مع الأب)
    → [Substitution] تطبيق الاستبدالات
    → InferenceResult::makeSuccess(type, subst)
    أو InferenceResult::makeFailure(errorMsg)
```

### 23.1 فئة SIRFrontendOptimizer الرئيسية

```
SIRFrontendOptimizer()
    → addPass(ConstantFoldingFrontendPass)      ← ممر 1
    → addPass(DeadCodeEliminationFrontendPass)   ← ممر 2
    → addPass(FunctionInliningFrontendPass)      ← ممر 3
    → addPass(CommonSubexpressionEliminationPass) ← ممر 4
    → addPass(LoopSimplificationFrontendPass)    ← ممر 5

optimizeModule(SIRModule&):
    1. يشغّل FunctionInlining على مستوى الوحدة (module-level)
    2. يشغّل كل الممرات الأخرى على كل دالة بشكل تكراري (حتى maxIterations_)
    3. يُنهي عندما لا يتغير شيء (Fixed-point iteration)

optimizeFunction(SIRFunction&):
    → تكرار حتى maxIterations_ أو حتى عدم وجود تغيير
    → لكل ممر مُفعَّل: pass->runOnFunction(func)
    → تحديث إحصاء FrontendOptStats
```

**`enablePass(name, bool)`** — تفعيل/تعطيل ممر بالاسم

---

### 23.2 الممر 1: طيّ الثوابت (Constant Folding)

**الفئة:** `ConstantFoldingFrontendPass`

**الوظيفة:** يُحسب نتيجة العمليات الحسابية/المنطقية/المقارنة التي معاملاها ثوابت في وقت الترجمة

**مثال:**
```
قبل:  %0 = ADD_I64 3, 5        → بعد:  %0 = CONSTANT 8
قبل:  %1 = EQ 10, 10           → بعد:  %1 = CONSTANT true
```

**العمليات المدعومة:** حسابية (`isArithmeticOp`) + مقارنة (`isComparisonOp`) + بتية (`isBitwiseOp`)

**الدوال:**
- `isConstant(op, constants)` — هل هذا ثابت معروف؟
- `resolveConstant(op, constants)` — استرجاع قيمة الثابت
- `foldInstruction(inst, constants)` — تجربة طيّ تعليمة واحدة
- `runOnFunction(func)` — تطبيق على دالة كاملة

---

### 23.3 الممر 2: حذف الكود الميت (Dead Code Elimination)

**الفئة:** `DeadCodeEliminationFrontendPass`

**الوظيفة:** يحذف التعليمات التي نتائجها لا تُستخدم أبداً

**آلية العمل:**
1. `collectUsedRegisters(func)` — جمع كل السجلات المستخدمة
2. لكل تعليمة: إذا لم تكن نتيجتها مستخدمة **ولم يكن لها آثار جانبية** → تحذف

**`hasSideEffects(inst)`** — التعليمات ذات الآثار الجانبية لا تُحذف حتى لو نتيجتها غير مستخدمة:
- استدعاءات دوال (`CALL`, `BUILTIN_PRINT`, ...)
- تعليمات الذاكرة (`STORE`, `ALLOC`, ...)
- التحكم (`BR`, `RET`, ...)
- I/O وOS وخيوط

> يُطابق نفس النمط في `middle optimizer/dead_code_elimination_pass.cpp`

---

### 23.4 الممر 3: تضمين الدوال (Function Inlining)

**الفئة:** `FunctionInliningFrontendPass`

**الوظيفة:** يستبدل استدعاء دالة صغيرة بتعليماتها مباشرةً (يُلغي overhead الاستدعاء)

**شروط التضمين (`shouldInline`):**
- حجم الدالة ≤ `maxInlineSize_` تعليمة
- الدالة تحتوي ≤ 2 basic block (بدون تحكم معقد)
- لا تُضمَّن الدوال العودية (Recursive)

**آلية التضمين (`inlineCallSite`):**
1. ربط أسماء المعاملات بالوسائط الفعلية (`paramMap`)
2. توليد بادئة فريدة للسجلات (`_inl0_`, `_inl1_`, ...)
3. استبدال `RET` بـ `MOVE` إلى نتيجة الاستدعاء
4. إعادة تسمية السجلات مع الحفاظ على أسماء المتغيرات العالمية

**ملاحظة:** يعمل على **مستوى الوحدة** (`runOnModule`) لأنه يحتاج قراءة الدوال الأخرى

---

### 23.5 الممر 4: إزالة التعبيرات المتكررة (CSE)

**الفئة:** `CommonSubexpressionEliminationPass`

**الوظيفة:** إذا حُسب نفس التعبير مرتين، يستخدم النتيجة الأولى

**مثال:**
```
قبل:  %a = MUL %x, %y    %b = MUL %x, %y
بعد:  %a = MUL %x, %y    %b = %a           (المرة الثانية تُحذف)
```

**آلية التنفيذ:**
- `ExprKey = {opcode, operandNames[]}` — مفتاح التعبير
- `ExprKeyHash` — hash مخصص
- `isPureOperation(opcode)` — يطبق CSE فقط على العمليات النقية (بدون آثار جانبية)
- خريطة `exprMap: ExprKey → resultName` داخل كل basic block

---

### 23.6 الممر 5: تبسيط الحلقات (Loop Simplification)

**الفئة:** `LoopSimplificationFrontendPass`

**ثلاث تحسينات:**

| الدالة | الوصف |
|--------|-------|
| `simplifyBranches(func)` | تحويل `BR_COND(ثابت, then, else)` إلى `BR(then)` أو `BR(else)` مباشرةً |
| `removeEmptyBlocks(func)` | حذف basic blocks تحتوي فقط على `BR` غير مشروط + إعادة توجيه الروابط |
| `mergeLinearBlocks(func)` | دمج basic block مع تاليه إذا كان الانتقال بينهما مباشراً وحصرياً |

**تسلسل التشغيل:** simplifyBranches → removeEmptyBlocks → mergeLinearBlocks

### 24.1 فئة LlvmIrGenerator — المحوّل النصي

**المبدأ:** يُنتج LLVM IR **كنص** (text) بدلاً من استخدام LLVM C++ API مباشرةً. النص يُمرَّر لاحقاً إلى `llc` أو `lli`.

```cpp
class LlvmIrGenerator {
    std::ostringstream output_;     // IR المُولَّد
    size_t tempCounter_;            // عداد القيم المؤقتة
    size_t stringCounter_;          // عداد ثوابت النصوص
    std::map<ValueId, SadTypePtr> valueTypes_;  // نوع كل ValueId

    std::string generate(const SirModule&);     // نقطة الدخول
};
```

**تسلسل `generate()`:**
1. `emitHeader()` — Target datalayout + target triple
2. `emitTypeDefinitions()` — تعريف `%String` و `%Array`
3. `emitExternalDeclarations()` — دوال الـ runtime + UI
4. لكل دالة → `emitFunction()` → `emitBlock()` → `emitInstruction()`

### 24.2 الهدف والتعريفات المدمجة

### 24.4 التعليمات القياسية المدعومة

**عمليات الملكية (Ownership):**
| تعليمة SIR | LLVM IR المُولَّد |
|-----------|-----------------|
| `Alloc(T)` | `%r = alloca T` |
| `Borrow(%v)` | `%r = bitcast T* %v to T*` |
| `Move/Copy(%v)` | `%r = load T, T* %v` |
| `Drop(%v)` | `; drop %v` (comment — no-op للأنواع البسيطة) |
| `Clone(%v)` | `%r = load T, T* %v` |
| `Deref(%ref)` | `%r = load T, T* %ref` |
| `EndBorrow` | `; end borrow` (comment) |

**عمليات الذاكرة:**
| تعليمة | LLVM IR |
|--------|---------|
| `Load(%ptr)` | `%r = load T, T* %ptr` |
| `Store(%ptr, %v)` | `store T %v, T* %ptr` |

**عمليات حسابية:** `add/sub/mul/sdiv/srem` ← تتحوّل تلقائياً إلى `fadd/fsub/fmul/fdiv/frem` للأنواع العشرية

**المقارنة:** `icmp eq/ne/slt/sle/sgt/sge` أو `fcmp oeq/one/olt/ole/ogt/oge` للعشريات

**التحكم:**
- `Jump(block)` → `br label %bbN`
- `Branch(cond, then, else)` → `br i1 %cond, label %bbT, label %bbF`
- `Return(v)` → `ret T %v` / `Return()` → `ret void`
- `Call(f, args...)` → `call T @f(T1 %a1, ...)`

### 25.1 ast_to_sir.cpp — النموذج التوثيقي للتحويل

#### 25.1.1 AstNodeKind — عقد AST المُعرَّفة

|-------|---------|

#### 25.1.2 ScopeManager — إدارة النطاقات

```cpp
class ScopeManager {
    pushScope(BlockId)              // فتح نطاق جديد
    popScope() → vector<ValueId>    // إغلاق النطاق وإرجاع المتغيرات (للـ Drop)
    addVariable(name, id, type, mut)
    lookupVariable(name) → ScopeVariable*
    markMoved(name)                 // تعليم المتغير كـ "منقول"
    currentDepth() → int
};

struct ScopeVariable {
    string name;
    ValueId valueId;
    SadTypePtr type;
    bool isMutable;
    bool isMoved;  // هل نُقل؟
    int scopeDepth;
};
```

#### 25.1.3 AstToSirLowering — مُحول AST إلى SIR

**الفئة الرئيسية** — تُبيّن منطق التحويل:

| الدالة | الوصف |
|--------|-------|
| `lower(program)` | تحويل برنامج كامل → `SirModule` |
| `lowerFunction(funcNode)` | تحويل دالة + إدراج Drop تلقائي لمتغيرات النطاق |
| `lowerBlock(block)` | تحويل كتلة + إدراج Drop عند الخروج (LIFO) |
| `lowerStatement(stmt)` | dispatch حسب نوع العبارة |
| `lowerVarDecl(varDecl)` | `Alloc` + `Store` + تسجيل في `ScopeManager` |
| `lowerAssignment(assign)` | `Store` للمتغير المستهدف |
| `lowerIf(ifStmt)` | ثلاث كتل: `إذا_صح` + `إذا_خطأ` + `بعد_إذا` |
| `lowerWhile(whileStmt)` | ثلاث كتل: `طالما_شرط` + `طالما_جسم` + `بعد_طالما` |
| `lowerReturn(ret)` | `Return()` أو `Return(val)` |
| `lowerCall(call)` | تحويل المعاملات + إصدار `Call` |
| `lowerExpression(expr)` | dispatch حسب نوع التعبير |
| `lowerBinaryOp(binOp)` | يدعم `+/-/*////%/==/!=/</<=/>/>=` والعربية |
| `lowerUnaryOp(unary)` | يدعم `-` و `!` و `ليس` |
| `lowerBorrow(node, isMut)` | `Borrow` أو `BorrowMut` |
| `lowerMove(node)` | `Move` + `markMoved()` |
| `lowerFieldAccess(access)` | `Project` |
| `lowerIdentifier(ident)` | `Load` من `ScopeManager` |

**آلية Drop التلقائي (LIFO):**
```
عند popScope():
    for var in reversed(vars):
        emit(Drop(var.id))
```
يضمن تنظيف المتغيرات بترتيب عكسي (الأخير ينظَّف أولاً).

**العمليات الثنائية المدعومة (ثنائية اللغة):**
```
"+"  أو "جمع"           → Add
"-"  أو "طرح"           → Sub
"*"  أو "ضرب"           → Mul
"/"  أو "قسمة"          → Div
"//" أو "قسمة_صحيحة"   → FloorDiv
"%"  أو "باقي"          → Mod
"==" أو "يساوي"         → Eq
"!=" أو "لا_يساوي"      → Ne
"<"  أو "أقل"           → Lt
"<=" أو "أقل_أو_يساوي" → Le
">"  أو "أكبر"          → Gt
">=" أو "أكبر_أو_يساوي"→ Ge
"و"  أو "&&"            → And
"أو" أو "||"            → Or
```

**واجهة C الخارجية:**

```
القاعدة 1: كل قيمة لها مالك واحد فقط
القاعدة 2: عند النقل، المالك القديم يفقد الملكية (isMoved = true)
القاعدة 3: الاستعارة (&) لا تنقل الملكية
القاعدة 4: لا يمكن استخدام قيمة بعد نقلها

مثال:
    متغير س = 10          → س: Owned
    متغير ص = &س          → س: Owned، ص: Borrowed
    متغير ع = انقل س      → س: Moved (غير صالح)، ع: Owned
    اطبع(س)               → ❌ UseAfterMove!
```

**الحالات في `OwnershipState`** (من `sir_types.h`):
`Owned` | `Borrowed` | `MutBorrowed` | `Moved` | `Dropped` | `Uninitialized`

### 25.4 sir_borrow_check.cpp — فحص الاستعارات

**الهدف:** التحقق من صحة الاستعارات وفق قواعد دلالات الاستعارة.

#### 25.4.1 BorrowErrorKind — أنواع أخطاء الاستعارة

| الخطأ | الوصف |
|-------|-------|
| `SharedAndMut` | استعارة ثابتة ومتغيرة معاً لنفس القيمة |
| `MultipleMut` | أكثر من استعارة متغيرة لنفس القيمة |
| `BorrowOutlivesSource` | الاستعارة تعيش أطول من المصدر |
| `DanglingReference` | مرجع معلق (المصدر حُرر) |
| `UseAfterMove` | استخدام بعد النقل (مشترك مع ownership_analysis) |
| `UseAfterFree` | استخدام بعد التحرير |
| `MutateImmutable` | محاولة تعديل قيمة ثابتة |
| `MutateThroughSharedRef` | تعديل عبر مرجع ثابت |

#### 25.4.2 BorrowError — هيكل الخطأ

```cpp
struct BorrowError {
    BorrowErrorKind kind;
    SourceLocation location;
    string message;
    vector<SourceLocation> relatedLocations;  // مواقع الاستعارات المتعارضة

    string kindName() const;  // اسم النوع بالعربية
};
```

#### 25.4.3 قواعد الاستعارة

```
القاعدة 1: يمكن وجود عدة استعارات ثابتة (&) معاً
القاعدة 2: يُسمح باستعارة متغيرة واحدة فقط (&متغير)
القاعدة 3: لا يمكن الجمع: ثابتة + متغيرة → SharedAndMut
القاعدة 4: الاستعارة لا تعيش أطول من المصدر → BorrowOutlivesSource

مثال صحيح:
    متغير س = 10
    متغير أ = &س       ✅ استعارة ثابتة
    متغير ب = &س       ✅ استعارة ثابتة ثانية (مسموح)

مثال خاطئ:
    متغير س = 10
    متغير أ = &س       استعارة ثابتة
    متغير ب = &متغير س ❌ SharedAndMut!
```

### 26.5 نظام الإغلاق (Closure) في SIRBuilder

**الإغلاق = دالة تلتقط متغيرات من النطاق الأب**

```cpp
struct CaptureInfo {
    string varName;      // اسم المتغير (مثال: "عداد")
    string registerName; // سجل SIR (%5)
    SadTypeKind type;    // النوع
};
```

**آلية الالتقاط:**
1. `collectFreeVarsStmt()` — يجمع المتغيرات الحرة عبر AST traversal
2. `lookupVariable()` — يتحقق من وجود كل متغير في النطاق الحالي
3. إنشاء `__env` struct يحمل جميع القيم الملتقطة
4. الدالة الناتجة تأخذ `__env*` كأول معامل
5. `closureCaptures_[lambdaName]` يُخزن التقاطات لاستخدامها في `buildDeferredClosure()`

**`buildDeferredClosure(stmt)`:** يُنشئ إغلاقاً من جملة مباشرة (لدعم `defer { ... }`)
