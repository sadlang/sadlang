# نظام الأنواع في لغة ص — مسار النوع، طبقاته، وأنظمته الداخلية

> **الغرض:** وثيقة مرجعية تشرح **كيف يمثَّل النوع ويتحرّك** في لغة ص: مساره عبر
> الطبقات المعتمدة، الرسم البصريّ لطبقات تمثيل النوع، والأنظمة الداخلية المكوِّنة له.
>
> **القاعدة الذهبية:** نظام **نوع** واحد موحَّد (`SadTypeKind`)، لكن **تنفيذ** له
> عوالم متعدّدة (المفسّر ≠ الثنائيّ المُترجَم). تعدّد تمثيلات *القيمة* ليس ازدواجًا
> في *النوع* — بل فصلٌ سليمٌ بين عالَمَي تنفيذ.
>
> **الحالة:** ما بعد توحيد الأنواع (RFC sadlang/rfcs#8، المسار أ). أُزيلت السقالة
> الانتقالية بالكامل — راجع [§9 ملحق: ما أُزيل](#9-ملحق-ما-أُزيل).

## 1. الخريطة الكلّية

```
                          ┌───────────────────────────────┐
                          │   مصدر الحقيقة (Source of Truth)│
                          │   language-truth/types.yaml    │
                          └───────────────┬───────────────┘
                                          │ توليد آليّ
                                          ▼
                          ┌───────────────────────────────┐
                          │  sad_type_kind_generated.h      │
                          │  enum SadTypeKind  (52 قيمة)    │
                          └───────────────┬───────────────┘
                                          │ يُبنى فوقه
                ┌─────────────────────────┴─────────────────────────┐
                ▼                                                     ▼
   ┌──────────────────────────┐                      ┌──────────────────────────┐
   │  عالَم المفسّر  (sad-run)  │                      │  عالَم المترجم (sad-build) │
   │  C++ — Sad::Data/Types    │                      │  C++ — Sad::TypeSystem     │
   │                           │                      │                            │
   │  • SadType (هرمية)        │                      │  • استدلال Hindley-Milner  │
   │  • SadTypeRegistry        │   ── النوع مشترك ──▶  │  • توحيد + قيود + generics  │
   │  • Value (قيمة التشغيل)   │      (SadTypeKind)    │  • SIR types → LLVM IR     │
   └──────────────────────────┘                      └─────────────┬────────────┘
                                                                    │ يولّد ثنائيًّا
                                                                    ▼
                                                      ┌──────────────────────────┐
                                                      │  عالَم الثنائيّ الناتج     │
                                                      │  C runtime (llvm_runtime) │
                                                      │  • struct SadValue        │
                                                      └──────────────────────────┘
```

**ثلاث طبقات معتمدة للنوع، وعالَمان للقيمة:**
- النوع يُعرَّف مرّة (`SadTypeKind`) ويُستهلك في كلّ مكان.
- القيمة تُمثَّل بـ`Value` (C++) داخل المفسّر، وبـ`SadValue` (struct C) داخل الثنائيّ
  المُترجَم — لأن المفسّر والثنائيّ بيئتا تنفيذ مختلفتان جذريًّا.

## 2. الأنظمة الداخلية لنظام الأنواع

نظام الأنواع ليس كتلة واحدة، بل **أربعة أنظمة داخلية** متمايزة الأدوار:

| # | النظام الداخليّ | الدور | الموضع | الفضاء |
|---|---|---|---|---|
| ① | **نظام النوع الموحَّد** | تعريف النوع وتمثيله الغنيّ (هرمية + سجلّ + interning) | `shared/types/` | `Sad::Types` |
| ② | **نظام قيمة المفسّر** | حمل القيمة الحيّة أثناء `sad-run` | `shared/types/` | `Sad::Data` |
| ③ | **نظام الاستدلال الثابت** | فحص/استنتاج الأنواع وقت الترجمة (HM) | `compiler/.../types/` | `Sad::TypeSystem` |
| ④ | **نظام قيمة الثنائيّ** | قيمة وقت تشغيل البرنامج المُترجَم | `compiler/.../llvm_runtime.*` | C ABI |

### ① نظام النوع الموحَّد — `Sad::Types`

```
   SadTypeKind (enum, 52 قيمة)  ◀── "أيّ نوع؟" (وسم خفيف)
        │
        │ يُلَفّ في
        ▼
   SadType (هرمية 17 صنفًا)      ◀── النوع الغنيّ (نوع العنصر، المعاملات، الاختياريّة…)
        │
        │ تُنشأ وتُختزن عبر
        ▼
   SadTypeRegistry (Singleton)   ◀── إنشاء مركزيّ + interning (مقارنة == بالمؤشّر)
```

- **الملفّ:** `shared/types/include/sad_type_system.h`
- يخدم **المفسّر والمترجم معًا** — مصدر تمثيل النوع الوحيد.

### ② نظام قيمة المفسّر — `Sad::Data`

```
   class Value {
       SadTypeKind  type_;     // الوسم السريع
       SadTypePtr   sadType_;  // النوع الغنيّ الكامل (يعتمد ①)
       variant      data_;     // البيانات الفعلية
   }
        │ يتعاون مع
        ├─ ObjectInstance  (كائن صنف حيّ، يُمرَّر بمرجع)
        └─ FunctionRef     (مرجع دالة قابل للاستدعاء)
```

- **الملفّات:** `value.h`، `object_instance.h`، `class_type.h`، `function_ref.h`، `generator.h`
- كل قيمة تتحرّك في المفسّر هي `Value` (≈5700 موضع استعمال).

### ③ نظام الاستدلال الثابت — `Sad::TypeSystem`

```
   Type Inferencer (Hindley-Milner)
        ├─ Type Variables      (متغيّرات نوع طازجة)
        ├─ Unification         (توحيد القيود)
        ├─ Substitution        (تعويض الحلول)
        ├─ Constraint Solver   (حلّ القيود)
        ├─ Generics            (توليد نُسخ generic)
        └─ Trait System        (حلّ السمات)
```

- **الملفّات:** `compiler/include/types/` (`type_inferencer.h`، `unification.h`،
  `substitution.h`، `constraint_solver.h`، `generics.h`، `trait_system.h`، …)
- يعمل **قبل** توليد الكود؛ يحفر معلومات النوع في SIR. لا وجود له في المفسّر.

### ④ نظام قيمة الثنائيّ — C ABI

```
   typedef struct SadValue {
       SadValueType  tag;    // تعداد C منفصل
       union { ... } data;   // البيانات في الثنائيّ الناتج
   } SadValue;
```

- **الملفّ:** `compiler/include/backend/llvm/llvm_runtime.h`
- ما يجري فعليًّا حين تشغّل `.exe` مُترجَمًا. **لا علاقة له بصنف `Value` (C++)** سوى
  تشابُه الغرض — كيان مستقلّ في عالَم مختلف.

## 3. مسار النوع حسب الطبقات المعتمدة

النوع يولد في المصدر ويتدفّق عبر طبقات ثابتة حتى التنفيذ. المسار يتفرّع عند الطبقة 5
بحسب أداة التشغيل:

```
   ┌────────────────────────────────────────────────────────────────────┐
   │  طبقات مشتركة (المفسّر والمترجم)                                    │
   └────────────────────────────────────────────────────────────────────┘

   (1) مصدر .ص                 دالة ف(س: رقم) ...
        │
        ▼
   (2) Lexer                   سلسلة رموز (tokens)
        │
        ▼
   (3) Parser → AST            عُقد AST تحمل SadTypeKind مباشرة
        │                       (لا تمثيل وسيط — DataType محذوف)
        ▼
   (4) Type Checker            توحيد على SadTypeKind
        │                       (فحص الإسناد، التوافق، الوراثة)
        │
        ├──────────────────────────────┬──────────────────────────────┐
        ▼                              ▼                                │
   ┌─────────────────────┐   ┌──────────────────────────────────────┐ │
   │  (5أ) مسار المفسّر    │   │  (5ب) مسار المترجم                    │ │
   │  ─────────────       │   │  ─────────────                       │ │
   │  تقييم الشجرة         │   │  استدلال Hindley-Milner (③)          │ │
   │       │              │   │       │                              │ │
   │       ▼              │   │       ▼                              │ │
   │  Value (②)           │   │  SIR types (sir_types.h)             │ │
   │  type_ + sadType_    │   │       │                              │ │
   │  + data_             │   │       ▼                              │ │
   │       │              │   │  LLVM IR                             │ │
   │       ▼              │   │       │                              │ │
   │  تنفيذ مباشر          │   │       ▼                              │ │
   │  (نوع() يقرأ sadType_)│   │  ثنائيّ native → SadValue (④)         │ │
   └─────────────────────┘   └──────────────────────────────────────┘ │
                                                                        │
   فرض أمان null للمفسّر يحدث في طبقة statement_executor (الطبقة 5أ) ◀───┘
```

**ملخّص الطبقات المعتمدة:**

| الطبقة | المُدخَل | المُخرَج | المسؤول |
|:---:|---|---|---|
| 1 | نصّ `.ص` | أحرف | — |
| 2 | أحرف | رموز (tokens) | Lexer |
| 3 | رموز | AST (يحمل `SadTypeKind`) | Parser |
| 4 | AST | AST مُتحقَّق منه | Type Checker (دلاليّ) |
| 5أ | AST | `Value` ← تنفيذ | المفسّر (`Sad::Data`) |
| 5ب | AST | SIR → LLVM → ثنائيّ → `SadValue` | المترجم (`Sad::TypeSystem`) |

## 4. طبقات تمثيل النوع نفسه

داخل النظام ①، النوع يُمثَّل بثلاث طبقات متصاعدة الغنى:

```
   الطبقة A — SadTypeKind (تعداد)
   ─────────────────────────────
   أخفّ تمثيل: "أيّ صنف نوع؟"
   Void · Integer · Float · String · Boolean · Array · Map · Tuple ·
   Class · Struct · Enum · Trait · Function · Closure · Optional ·
   Result · Union · Generic · Future · Generator · Null · Any · …  (52)

                    │  "Array" وحده لا يكفي — مصفوفة لماذا؟
                    ▼
   الطبقة B — هرمية SadType (17 صنفًا)
   ─────────────────────────────
   النوع الغنيّ: يحمل البنية الكاملة
        SadType (الأساس)
        ├─ SadPrimitiveType   (كل البدائيات والعددية)
        ├─ SadArrayType       (+ نوع العنصر:  مصفوفة<رقم>)
        ├─ SadMapType         (+ نوع المفتاح/القيمة)
        ├─ SadTupleType       (+ أنواع العناصر)
        ├─ SadFunctionType    (+ المعاملات/الراجع)
        ├─ SadClassType / SadEnumType / SadTraitType
        ├─ SadUnionType / SadOptionalType / SadResultType
        ├─ SadGenericType / SadReferenceType
        ├─ SadFutureType / SadGeneratorType
        └─ SadSpecialType     (Any/Never/Unknown/Error)

                    │  كثرة الإنشاء ⇒ تكرار وتكلفة مقارنة
                    ▼
   الطبقة C — SadTypeRegistry (Singleton + interning)
   ─────────────────────────────
   إنشاء مركزيّ + اختزان: مصفوفة<رقم> تُنشأ مرّة وتُعاد
   ⇒ مقارنة المؤشّر  ==  صحيحة للأنواع المتماثلة بنيويًّا
```

> **مثال حيّ:** `[1، 2، 3]` نوعه الطبقة A = `Array`؛ الطبقة B = `SadArrayType`
> عنصره `Integer` (أي `مصفوفة<رقم>`)؛ الطبقة C تضمن أن كل `مصفوفة<رقم>` تشير
> إلى الكائن المختزن نفسه.

## 5. تمثيل القيمة عبر العالَمَين (التمييز الحاسم)

```
                 ┌──────────────────────────────────────────────┐
                 │  السؤال: "القيمة 42 كيف تُمثَّل وقت التشغيل؟"  │
                 └──────────────────────────────────────────────┘
                          │                           │
            في المفسّر (C++)                  في الثنائيّ المُترجَم (C)
                  ▼                                   ▼
   ┌───────────────────────────┐        ┌───────────────────────────┐
   │ Value {                   │        │ SadValue {                │
   │   type_  = Integer        │        │   tag  = SAD_TYPE_INT     │
   │   sadType_ = SadType(Int) │        │   data.i = 42             │
   │   data_  = 42             │        │ }                         │
   │ }                         │        │  (struct C في الثنائيّ)    │
   │  (صنف C++ في sad-run)     │        └───────────────────────────┘
   └───────────────────────────┘
```

| | `Value` (②) | `SadValue` (④) |
|---|---|---|
| العالَم | المفسّر (sad-run) | الثنائيّ المُترجَم |
| اللغة | صنف C++ | struct C |
| يحمل النوع كـ | `SadTypeKind` + `SadTypePtr` | `tag` (تعداد C) |
| الملفّ | `shared/types/value.h` | `compiler/.../llvm_runtime.h` |

> لا يلتقيان في الذاكرة أبدًا — برنامجٌ يُشغَّل بالمفسّر لا يلمس `SadValue`،
> وثنائيٌّ مُترجَم لا يلمس `Value`. الاسمان متشابهان، الكيانان منفصلان.

## 6. ValueType — قشرة توافق **مُزالة**

> ⛔ أُزيل `namespace Sad::Data::ValueType` (RFC sadlang/rfcs#8). كان أسماءً مستعارة
> `constexpr` تشير إلى `SadTypeKind` — لا نظامًا ولا تخزينًا. المحور الوحيد الآن
> `Types::SadTypeKind` مباشرة.

رُحّل كل مستهلكيه بخريطة التسمية التالية (ليست بادئة واحدة — فيها إعادة تسمية):

```
   ValueType::VOID     →  SadTypeKind::Void
   ValueType::INTEGER  →  SadTypeKind::Integer
   ValueType::DOUBLE   →  SadTypeKind::Float    ◀ اسم مختلف
   ValueType::OBJECT   →  SadTypeKind::Class    ◀ اسم مختلف
   ValueType::STRING/BOOLEAN/ARRAY/MAP/TUPLE/FUNCTION/Null  →  المقابِل في SadTypeKind
```

> ملاحظة: يوجد `ValueType` آخران لا صلة لهما بهذا: تعداد `enum class ValueType` في
> `sad_ui` (نظام الواجهات)، و`ValueType` في stdlib القديمة غير المُجمَّعة
> (`*_builtins.cpp`، أعضاء `NUMBER`/`NULL_TYPE`) — كلاهما خارج هذا النظام.

## 9. ملحق: ما أُزيل

لئلّا يبحث القارئ عمّا لم يعد موجودًا — أُزيلت هذه السقالة الانتقالية ولا تعد جزءًا من النظام:

| المُزال | كان | حُذف في |
|---|---|---|
| `DataType` (enum, 14 قيمة) | تمثيل نوع الـAST القديم | S-TS-P2.5b |
| `enum Data::ValueType` | نظام نوع تشغيل ثانٍ | استُبدل بثوابت توافق (P2.5) |
| `namespace Data::ValueType` (ثوابت توافق) | أسماء مستعارة لـ`SadTypeKind` | RFC#8 |
| `type_bridge.{h,cpp}` | جسر تحويل `SadType↔Value` | RFC#8 المسار أ |
| `sad_value.h` (`Sad::Types::SadValue`) | حاوية قيمة بديلة مهجورة (ADR-01) | RFC#8 المسار أ |

> الباقي الوحيد المسمّى `SadValue` هو **struct الـC في `llvm_runtime`** (النظام ④) —
> كيان حيّ مستقلّ، ليس له صلة بصنف ADR-01 المحذوف.
