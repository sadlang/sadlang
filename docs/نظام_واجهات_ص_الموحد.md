# نظام واجهات ص الموحد — SadUI
## الرؤية الثورية: اكتب مرة، انشر في كل مكان

## ملخص تنفيذي

هذا المقترح يصف نظامًا ثوريًا لبناء واجهات المستخدم في لغة ص، حيث يكتب المطور كود واحد بالعربية ثم يُترجَم أصليًا (Native) إلى:
- **سطح المكتب** (Windows / Linux / macOS) — عبر SDL2/Raylib مباشرة
- **أندرويد** — عبر توليد Kotlin + Jetpack Compose
- **iOS** — عبر توليد Swift + SwiftUI
- **الويب** — عبر توليد HTML/CSS/JS (مرحلة لاحقة)

> **الفلسفة**: لا نرسم بكسلات على كل منصة (كما يفعل Flutter)، بل نولّد كود **أصلي حقيقي** لكل منصة يستخدم مكوناتها الأصلية.

### ما ينقص ❌

| المكون | الأهمية | التفاصيل |
|--------|---------|----------|
| **خط أنابيب البناء الموحد** | 🔴 حرج | لا يوجد أمر واحد يأخذ `.ص` وينتج `.apk` أو `.exe` |
| **طبقة التجريد الموحدة (SadUI IR)** | 🔴 حرج | لا يوجد تمثيل وسيط موحد بين الباحث النحوي ومولدات الكود |
| **ربط الحالة بالواجهة** | 🟡 مهم | النظام التفاعلي (signals) موجود في C++ لكن غير مربوط بمولدات الكود |

| **اختبار التوافق** | 🟠 متوسط | لا توجد اختبارات تتحقق أن الواجهة متطابقة بين المنصات |
| **Hot Reload** | 🟢 تحسين | إعادة تحميل ساخنة أثناء التطوير |

## المكون الجوهري: SadUI IR — التمثيل الوسيط الموحد

### لماذا نحتاج SadUI IR؟

حاليًا `ui_parser.cpp` ينتج `UINode` AST مباشرة، ثم كل مولد (`android_compose.cpp`, `ios_swiftui.cpp`) يفسرها بطريقته. المشكلة:

1. **لا يوجد توحيد للأنماط** — كل مولد يفسّر `.بحجم(24)` بطريقة مختلفة
2. **لا يوجد ربط الحالة** — `إشارة()` و`محسوب()` لا يُترجمان تلقائيًا
3. **لا يوجد تحقق مسبق** — الأخطاء تظهر بعد التوليد لا قبله

### هيكل SadUI IR

```cpp
namespace Sad::UI::IR {

// ═══════════════════════════════════════════════════════
// عقدة الواجهة الموحدة
// ═══════════════════════════════════════════════════════
struct UINodeIR {
    // الهوية
    int id;
    UIWidgetType type;              // نوع المكون (109 نوع)
    std::string name;               // اسم معرّف (اختياري)
    
    // الخصائص المشتركة
    StyleIR style;                  // الأنماط الموحدة
    std::vector<UINodeIR> children; // الأبناء
    
    // الربط التفاعلي
    std::optional<StateBinding> binding;     // ربط بإشارة
    std::vector<EventHandler> handlers;      // معالجات الأحداث
    
    // التخطيط
    LayoutConstraints constraints;  // قيود التخطيط
    Alignment alignment;            // المحاذاة
    
    // التنقل
    std::optional<NavigationAction> navAction; // إجراء تنقل
};

// ═══════════════════════════════════════════════════════
// الأنماط الموحدة — تُترجم لكل منصة
// ═══════════════════════════════════════════════════════
struct StyleIR {
    // الألوان
    std::optional<Color> backgroundColor;
    std::optional<Color> textColor;
    std::optional<Color> borderColor;
    
    // الخطوط
    std::optional<float> fontSize;
    std::optional<FontWeight> fontWeight;
    std::optional<TextAlign> textAlign;
    
    // التباعد
    EdgeInsets padding;
    EdgeInsets margin;
    float spacing = 0;
    
    // الحدود
    float borderRadius = 0;
    float borderWidth = 0;
    
    // الأبعاد
    Dimension width;    // ثابت، مرن، أو نسبي
    Dimension height;
    
    // التأثيرات
    std::optional<Shadow> shadow;
    float opacity = 1.0f;
    
    // RTL
    bool isRTL = true;  // افتراضي: عربي
};

// ═══════════════════════════════════════════════════════
// ربط الحالة — يُحوّل لكل منصة
// ═══════════════════════════════════════════════════════
struct StateBinding {
    std::string stateKey;           // مفتاح الحالة
    BindingType type;               // نوع الربط
    // BindingType::Signal → Compose: remember/mutableStateOf
    //                     → SwiftUI: @State / @Published
    //                     → SDL2: sad::state::setState
    
    std::optional<std::string> computedExpr;  // تعبير محسوب
};

// ═══════════════════════════════════════════════════════
// معالج حدث
// ═══════════════════════════════════════════════════════
struct EventHandler {
    EventType event;                // نقر، تغير_نص، تغير_قيمة...
    std::string handlerName;        // اسم الدالة المعالجة
    std::vector<std::string> args;  // الوسائط
};

} // namespace Sad::UI::IR
```

### ماذا يحدث عند الترجمة لكل منصة؟

#### → سطح المكتب (SDL2):
```
UINodeIR → sad::ui::widget_column(), widget_card(), ...
        → SDL2 رسم مباشر مع الثيمة المحلية
        → ملف تنفيذي .exe واحد
```

#### → أندرويد (Jetpack Compose):
```kotlin
// الكود المُولَّد تلقائيًا — لا يحتاج المطور رؤيته
@Composable
fun TaskScreen() {
    val tasks = remember { mutableStateListOf(
        Task("شراء حليب", false),
        Task("مذاكرة", true)
    )}
    val remaining by remember { derivedStateOf { tasks.count { !it.completed } } }
    
    Scaffold(
        topBar = {
            TopAppBar(
                title = { Text("مهامي 📝") },
                actions = {
                    IconButton(onClick = { navController.navigate("search") }) {
                        Text("🔍")
                    }
                }
            )
        },
        floatingActionButton = {
            FloatingActionButton(onClick = { navController.navigate("add") }) {
                Text("➕")
            }
        }
    ) { padding ->
        Column(Modifier.padding(padding)) {
            // إحصائيات
            Row(
                Modifier.fillMaxWidth().padding(16.dp),
                horizontalArrangement = Arrangement.SpaceBetween
            ) {
                Text("المهام المتبقية: $remaining", fontSize = 18.sp)
                CircularProgressIndicator(
                    progress = remaining.toFloat() / tasks.size,
                    modifier = Modifier.size(40.dp)
                )
            }
            // القائمة
            LazyColumn {
                itemsIndexed(tasks) { index, task ->
                    Card(Modifier.padding(4.dp)) {
                        Row(Modifier.padding(12.dp)) {
                            Checkbox(
                                checked = task.completed,
                                onCheckedChange = { tasks[index] = task.copy(completed = it) }
                            )
                            Text(
                                task.title,
                                fontSize = 16.sp,
                                textDecoration = if (task.completed) 
                                    TextDecoration.LineThrough else TextDecoration.None,
                                modifier = Modifier.weight(1f)
                            )
                            IconButton(onClick = { tasks.removeAt(index) }) {
                                Text("🗑️")
                            }
                        }
                    }
                }
            }
        }
    }
}
```

```swift
                    }
                    .padding(12)
                }
            }
            .navigationTitle("مهامي 📝")
            .toolbar {
                Button("🔍") { /* navigate to search */ }
            }
        }
        .environment(\.layoutDirection, .rightToLeft)
    }
}
```

## خطوات التنفيذ — خريطة طريق مرحلية

### المرحلة 1: توحيد SadUI IR (الأساس) — 3 أسابيع

```
📁 compiler_new/src/ui/
├── sad_ui_ir.h              ← تعريف هياكل SadUI IR
├── sad_ui_ir_builder.cpp    ← تحويل UINode AST → SadUI IR
├── sad_ui_ir_validator.cpp  ← التحقق من صحة الشجرة
├── sad_ui_ir_optimizer.cpp  ← تحسين (حذف عقد زائدة، دمج أنماط)
└── sad_ui_ir_printer.cpp    ← طباعة للتشخيص
```

**المهام:**
1. تعريف `UINodeIR`, `StyleIR`, `StateBinding`, `EventHandler` (الهياكل أعلاه)
2. بناء `SadUIIRBuilder` الذي يأخذ UINode AST الحالي ويحوله لـ SadUI IR
3. ربط نظام الحالة (`إشارة`, `محسوب`) بـ `StateBinding`
4. ربط نظام التنقل (`انتقل_إلى`, `ارجع_للخلف`) بـ `NavigationAction`
5. كتابة مدقق يتحقق أن جميع المكونات مدعومة على المنصة المستهدفة

### المرحلة 2: تطوير مولد سطح المكتب (MVP) — 2 أسابيع

```
📁 compiler_new/src/backend/desktop/
├── desktop_backend.h        ← واجهة مولد سطح المكتب
├── desktop_sdl2_gen.cpp     ← توليد كود C++ يستدعي sad_ui_framework
└── desktop_linker.cpp       ← ربط مع SDL2 وتوليد .exe
```

**المهام:**
1. تحويل SadUI IR → استدعاءات `sad::ui::widget_*` الموجودة
2. توليد ملف `main.cpp` يبني الشجرة ويشغل حلقة SDL2
3. ربط مع `sad_ui_api.cpp` و `sad_ui_layout_render.cpp` الموجودين
4. دعم Hot Reload: مراقبة تغييرات `.ص` وإعادة بناء الشجرة

### المرحلة 3: تطوير مولد أندرويد (الهدف الأول) — 4 أسابيع

```
📁 compiler_new/src/backend/android/
├── android_backend.h          ← واجهة مولد أندرويد
```

## لماذا هذا النظام ثوري؟

### 1. ليس مثل Flutter — أفضل منه
- Flutter يرسم كل شيء بنفسه (Skia) → **المكونات لا تبدو أصلية**
- نظام ص يولد **كود أصلي حقيقي** → `Compose` على أندرويد، `SwiftUI` على iOS → **المكونات أصلية 100%**

### 2. ليس مثل React Native — أسرع منه
- React Native يستخدم JavaScript bridge → **بطيء**
- نظام ص يُترجم **مباشرة لنيتف** → لا bridge، لا overhead

### 3. ليس مثل MAUI/Xamarin — أبسط منه
- MAUI يحتاج C# ومايكروسوفت → تعقيد كبير
- نظام ص يحتاج **ملف واحد بالعربية** → أبسط بكثير

### 4. أول نظام واجهات عربي أصلي
- **RTL من اليوم الأول** — ليس إضافة لاحقة
- **كلمات مفتاحية عربية** — `سقالة`, `عمود`, `زر`, `إشارة`
- **توثيق عربي** — كل شيء موثق بالعربية

### 5. نظام مكونات ضخم (109+ مكون)
- أكبر مكتبة مكونات Flutter-like في لغة عربية
- مكونات إسلامية أصلية (تقويم هجري، أوقات صلاة، اتجاه القبلة)
- مكونات ثورية (20 مكون مبتكر لا مثيل لها)
