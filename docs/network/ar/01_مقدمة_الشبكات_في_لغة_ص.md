## 📚 ما هي برمجة الشبكات؟

برمجة الشبكات هي فن وعلم كتابة برامج تتواصل مع برامج أخرى عبر شبكات الكمبيوتر. في عالمنا المعاصر، كل تطبيق تقريباً يحتاج إلى التواصل عبر الشبكة - من تطبيقات الدردشة البسيطة إلى أنظمة البنوك المعقدة، ومن متصفحات الويب إلى ألعاب الإنترنت متعددة اللاعبين. لغة ص الآن تمنحك القدرة الكاملة على بناء هذه التطبيقات بلغة عربية بحتة!

في هذا الدليل الشامل، سنستكشف معاً عالم برمجة الشبكات من الصفر، بدءاً من المفاهيم الأساسية وصولاً إلى بناء تطبيقات حقيقية. سواء كنت مبتدئاً في البرمجة أو مطوراً متمرساً تتعلم لغة ص، فهذا الدليل مصمم لك.

## 🎯 لماذا تحتاج لتعلم برمجة الشبكات؟

### التطبيقات العملية اللامحدودة

برمجة الشبكات تفتح أمامك عالماً من الإمكانيات. تخيل أنك تستطيع بناء:

**تطبيقات الدردشة والتواصل:** يمكنك بناء تطبيق دردشة كامل يتيح للمستخدمين إرسال الرسائل النصية والصور والملفات في الوقت الفعلي. تخيل أن تبني نسختك الخاصة من واتساب أو تيليجرام باستخدام لغة عربية بحتة! كل ما تحتاجه هو فهم كيفية إرسال واستقبال البيانات عبر الشبكة، وستكون قادراً على بناء نظام دردشة متكامل يدعم المحادثات الفردية والجماعية.

**خوادم الويب وواجهات API:** هل تريد بناء موقع إلكتروني أو خدمة ويب؟ برمجة الشبكات هي الأساس. يمكنك بناء خادم ويب كامل يستقبل طلبات HTTP من المتصفحات ويرد عليها بصفحات HTML أو بيانات JSON. يمكنك إنشاء واجهات برمجية (APIs) تسمح لتطبيقات أخرى بالتفاعل مع خدمتك، تماماً مثل Twitter API أو Google Maps API.

**أنظمة الألعاب متعددة اللاعبين:** الألعاب الحديثة تعتمد بشكل كبير على الشبكات. سواء كنت تبني لعبة استراتيجية بطيئة الوتيرة أو لعبة إطلاق نار سريعة، ستحتاج لفهم كيفية مزامنة حالة اللعبة بين اللاعبين المختلفين عبر الإنترنت. مع لغة ص، يمكنك بناء بنية الشبكة الأساسية للعبتك بسهولة.

**أنظمة إنترنت الأشياء (IoT):** في عصر الأجهزة الذكية، كل شيء متصل بالإنترنت. من الثلاجات الذكية إلى أنظمة الأمان المنزلية، كل هذه الأجهزة تحتاج للتواصل عبر الشبكة. يمكنك استخدام لغة ص لبرمجة هذه الأجهزة وجعلها تتواصل مع بعضها البعض أو مع خوادم سحابية.

**أدوات المراقبة والإدارة:** الشركات تحتاج لمراقبة خوادمها وأنظمتها باستمرار. يمكنك بناء أدوات مراقبة تجمع البيانات من خوادم متعددة وتعرضها في لوحة تحكم مركزية. تخيل أن تبني نظاماً يراقب صحة 100 خادم في وقت واحد ويرسل تنبيهات عند حدوث مشاكل.

### المهارة الأساسية في عالم البرمجة الحديث

برمجة الشبكات ليست مجرد مهارة إضافية - إنها أساسية في البرمجة الحديثة. معظم الوظائف البرمجية اليوم تتطلب فهماً على الأقل للمفاهيم الأساسية للشبكات. حتى لو لم تعمل مباشرة على تطوير تطبيقات الشبكات، ستحتاج لفهم كيفية عمل APIs، وكيفية التعامل مع الطلبات والاستجابات، وكيفية معالجة الأخطاء الشبكية.

في السوق العربي خاصة، هناك نقص كبير في المطورين القادرين على بناء أنظمة شبكية قوية. بتعلمك برمجة الشبكات في لغة ص، أنت لا تتعلم مهارة تقنية فقط، بل تكتسب القدرة على بناء حلول محلية بلغة عربية، مما يفتح أمامك فرصاً كبيرة في سوق العمل.

## 🏗️ المفاهيم الأساسية

قبل أن نبدأ في كتابة الكود، دعنا نفهم المفاهيم الأساسية التي تبنى عليها كل برمجة الشبكات:

### ما هو المقبس (Socket)؟

المقبس (Socket) هو المفهوم الأساسي والأهم في برمجة الشبكات. فكر في المقبس كنقطة اتصال أو "مأخذ كهربائي" للبيانات. تماماً كما تحتاج لتوصيل قابس الكهرباء في المأخذ للحصول على الطاقة، تحتاج برامجك لإنشاء مقابس للاتصال بالشبكة وإرسال واستقبال البيانات.

المقبس في لغة ص هو كائن برمجي يمثل طرفاً في اتصال شبكي. كل اتصال شبكي يتطلب مقبسين على الأقل: واحد على جهازك وواحد على الجهاز الآخر الذي تتواصل معه. عندما تفتح متصفحك وتزور موقعاً إلكترونياً، متصفحك ينشئ مقبساً على جهازك، ويتصل بمقبس آخر على خادم الموقع. البيانات تتدفق بين هذين المقبسين في الاتجاهين.

في لغة ص، توفر لك المكتبة نوعين رئيسيين من المقابس: مقابس TCP ومقابس UDP. كل نوع له خصائصه واستخداماته التي سنشرحها بالتفصيل.

### عناوين IP والمنافذ

لكي يتمكن جهازان من التواصل عبر الشبكة، كل منهما يحتاج لعنوان فريد. هذا العنوان يتكون من جزأين أساسيين:

**عنوان IP (Internet Protocol Address):** هذا هو العنوان الفريد لجهاز الكمبيوتر على الشبكة. إنه يشبه عنوان منزلك في العالم الحقيقي. عناوين IP تأتي في نسختين:
- IPv4: تستخدم أرقاماً مكونة من أربعة أجزاء، مثل `192.168.1.100`. هذا هو النظام القديم الذي لا يزال مستخدماً بكثرة.
- IPv6: تستخدم أرقاماً أطول وأكثر تعقيداً مثل `2001:0db8:85a3::8a2e:0370:7334`. هذا النظام الجديد وُضع لحل مشكلة نفاد عناوين IPv4.

لغة ص تدعم كلا النوعين بشكل كامل، ويمكنك التبديل بينهما بسلاسة.

**رقم المنفذ (Port Number):** إذا كان عنوان IP يشبه عنوان المبنى، فرقم المنفذ يشبه رقم الشقة. جهاز كمبيوتر واحد يمكن أن يشغل عدة تطبيقات شبكية في نفس الوقت - متصفح ويب، برنامج بريد إلكتروني، لعبة أونلاين، إلخ. كل تطبيق يستخدم منفذاً مختلفاً. أرقام المنافذ تتراوح من 0 إلى 65535، وبعضها محجوز لخدمات معينة:
- المنفذ 80: خدمة HTTP (مواقع الويب)
- المنفذ 443: خدمة HTTPS (مواقع الويب المشفرة)
- المنفذ 25: خدمة SMTP (البريد الإلكتروني)
- المنفذ 22: خدمة SSH (الاتصال الآمن بالخوادم)

عندما تبني تطبيقك، غالباً ستستخدم أرقام منافذ أكبر من 1024 لتجنب التعارض مع الخدمات النظامية.

### نموذج العميل والخادم (Client-Server Model)

معظم التطبيقات الشبكية تعمل وفق نموذج العميل-الخادم. هذا نموذج بسيط لكنه قوي جداً:

**الخادم (Server):** هو البرنامج الذي يعمل باستمرار في انتظار طلبات الاتصال. تخيله كمطعم ينتظر الزبائن. الخادم يفتح منفذاً معيناً على عنوان IP محدد ويبقى "يستمع" (listening) لأي طلبات قادمة. عندما يصل طلب اتصال، الخادم "يقبله" (accepts) ويبدأ في خدمة ذلك العميل.

في لغة ص، إنشاء خادم بسيط جداً. كل ما عليك فعله هو إنشاء مقبس TCP، وإخباره أن يستمع على منفذ معين، ثم البدء في قبول الاتصالات:

```sad
استخدم شبكة

دالة رئيسية() 
    #إنشاء خادم يستمع على المنفذ 8080
    خادم = شبكة.انشئ_خادم_tcp(8080)
    اطبع("الخادم يستمع على المنفذ 8080")
    
    #الانتظار لاتصال عميل
    عميل = خادم.اقبل()
    اطبع("عميل جديد اتصل!")
نهاية
```

**العميل (Client):** هو البرنامج الذي يبدأ الاتصال بالخادم. تخيله كزبون يدخل المطعم. العميل يعرف عنوان IP ورقم منفذ الخادم، ويطلب الاتصال به. إذا قبل الخادم، يتم إنشاء قناة اتصال بينهما.

إنشاء عميل أيضاً بسيط:

```sad
استخدم شبكة

دالة رئيسية() 
    #الاتصال بخادم على نفس الجهاز (127.0.0.1) منفذ 8080
    عميل = شبكة.اتصل_tcp("127.0.0.1", 8080)
    اطبع("تم الاتصال بالخادم!")
نهاية
```

هذا النموذج يستخدم في كل مكان - متصفحك هو عميل يتصل بخوادم المواقع، تطبيق البريد الإلكتروني الخاص بك هو عميل يتصل بخادم البريد، وحتى الألعاب الأونلاين غالباً تستخدم هذا النموذج حيث جهازك (العميل) يتصل بخادم اللعبة.

## 📡 بروتوكولا TCP و UDP

في عالم الشبكات، هناك طريقتان رئيسيتان لإرسال البيانات: TCP و UDP. فهم الفرق بينهما أساسي لاختيار الأداة المناسبة لتطبيقك.

### TCP (Transmission Control Protocol) - بروتوكول التحكم في النقل

TCP هو البروتوكول الأكثر استخداماً وموثوقية. فكر فيه كخدمة بريد مسجل مضمونة الوصول:

**الموثوقية التامة:** TCP يضمن أن كل بايت ترسله سيصل للطرف الآخر بنفس الترتيب الذي أرسلته به. إذا فُقدت حزمة بيانات في الطريق (بسبب مشكلة في الشبكة مثلاً)، TCP سيكتشف ذلك تلقائياً ويعيد إرسالها. هذا يجعل TCP مثالياً للتطبيقات التي لا تحتمل فقدان البيانات مثل:
- نقل الملفات: عند تحميل أو رفع ملف، لا يمكنك تحمل فقدان حتى بايت واحد
- تطبيقات الدردشة: لا تريد أن تفقد بعض الرسائل
- متصفحات الويب: صفحات HTML يجب أن تصل كاملة
- البريد الإلكتروني: الرسائل يجب أن تصل كاملة

**الاتصال الموجه (Connection-Oriented):** قبل إرسال أي بيانات عبر TCP، يجب إنشاء "اتصال" بين العميل والخادم. هذا الاتصال يشبه المكالمة الهاتفية - تتصل أولاً، ثم تتحدث، ثم تقفل الخط. الاتصال يضمن أن الطرفين جاهزان للتواصل ويتفقان على معلومات الاتصال.

**التحكم في التدفق:** TCP ذكي - يكتشف مدى سرعة الشبكة ويعدل سرعة الإرسال تلقائياً. إذا كانت الشبكة بطيئة، يبطئ الإرسال. إذا كانت سريعة، يسرّع. هذا يضمن استخدام الشبكة بكفاءة دون إغراقها.

**الترتيب المضمون:** الحزم قد تصل بترتيب خاطئ عبر الإنترنت (لأنها تأخذ مسارات مختلفة)، لكن TCP يعيد ترتيبها تلقائياً قبل تسليمها لتطبيقك. أنت دائماً تستقبل البيانات بنفس الترتيب الذي أُرسلت به.

**العيب الرئيسي:** كل هذه الميزات تأتي بثمن - TCP أبطأ قليلاً من UDP بسبب كل عمليات التحقق والتأكيد. أيضاً، الحاجة لإنشاء اتصال قبل الإرسال تضيف تأخيراً بسيطاً في البداية.

**مثال عملي في لغة ص:**
```sad
استخدم شبكة

دالة رئيسية() 
    #خادم TCP بسيط يردد ما يستقبله
    خادم = شبكة.انشئ_خادم_tcp(8080)
    اطبع("خادم TCP يعمل...")
    
    بينما (صحيح )
        عميل = خادم.اقبل()
        رسالة = عميل.استقبل()
        اطبع("استقبلت: " + رسالة)
        عميل.ارسل(رسالة) #   رد بنفس الرسالة
    نهاية
نهاية
```

### UDP (User Datagram Protocol) - بروتوكول حزم بيانات المستخدم

UDP هو البروتوكول الأسرع ولكن الأقل موثوقية. فكر فيه كإرسال بطاقات بريدية عادية:

**السرعة والبساطة:** UDP لا يضمن وصول البيانات، ولا يهتم بالترتيب، ولا يعيد إرسال الحزم المفقودة. قد تبدو هذه عيوباً، لكنها في الواقع ميزات لبعض التطبيقات! لأن UDP لا يقوم بكل عمليات التحقق التي يقوم بها TCP، فهو أسرع بكثير ويستهلك موارد أقل.

**عديم الاتصال (Connectionless):** UDP لا يحتاج لإنشاء اتصال قبل الإرسال. ترسل الحزمة مباشرة للعنوان المطلوب. هذا يجعله مثالياً للرسائل القصيرة السريعة.

**الاستخدامات المثالية:**
- **البث المباشر للفيديو والصوت:** إذا فقدت إطاراً واحداً من الفيديو، لا مشكلة! الإطار التالي سيصل بعد جزء من الثانية. من الأفضل فقدان بعض الإطارات بدلاً من توقف الفيديو لإعادة إرسال البيانات المفقودة.
- **الألعاب الأونلاين:** في لعبة إطلاق نار سريعة، موقع اللاعب منذ ثانية لا يهم - المهم موقعه الحالي. UDP يرسل تحديثات سريعة باستمرار، وإذا فُقد تحديث، التحديث التالي سيصل قريباً.
- **خدمات DNS:** عند كتابة عنوان موقع، جهازك يرسل طلب UDP قصير لخادم DNS للحصول على عنوان IP. الطلب صغير جداً والسرعة أهم من الضمان.
- **البث الجماعي (Broadcast/Multicast):** إرسال نفس البيانات لعدة مستقبلين في نفس الوقت.

**مثال عملي في لغة ص:**
```sad
استخدم شبكة

دالة رئيسية() {
    // خادم UDP يستقبل ويرد
    خادم = شبكة.انشئ_مقبس_udp()
    خادم.اربط(9090)
    اطبع("خادم UDP يعمل...")
    
    بينما صحيح {
        (بيانات، مرسل) = خادم.استقبل_من()
        اطبع("استقبلت من " + مرسل.عنوان() + ": " + بيانات)
        خادم.ارسل_الى("استلمت!", مرسل)
    }
}
```

### متى تستخدم TCP ومتى تستخدم UDP؟

القاعدة البسيطة:
- **استخدم TCP** عندما تحتاج لضمان وصول كل البيانات بالترتيب الصحيح
- **استخدم UDP** عندما تحتاج للسرعة ويمكنك تحمل فقدان بعض البيانات

## 🚀 أول برنامج شبكي لك في لغة ص!

الآن دعنا نبني أول تطبيق شبكي حقيقي. سنبني برنامج "صدى" (Echo) بسيط - الخادم يستقبل رسائل من العميل ويعيد إرسالها.

### خادم الصدى TCP

هذا الخادم ينتظر اتصالات من العملاء، يستقبل رسائلهم، ويعيد إرسال نفس الرسائل:

```sad
استخدم شبكة
استخدم نص

دالة رئيسية() {
    // إنشاء خادم على المنفذ 8080
    خادم = شبكة.انشئ_خادم_tcp(8080)
    
    إذا خادم == باطل {
        اطبع("فشل إنشاء الخادم!")
        ارجع 1
    }
    
    اطبع("✅ خادم الصدى يعمل على المنفذ 8080")
    اطبع("في انتظار اتصالات العملاء...")
    اطبع("يمكنك إيقاف الخادم بالضغط على Ctrl+C")
    اطبع("")
    
    // حلقة لا نهائية لقبول اتصالات متعددة
    عدد_الاتصالات = 0
    
    بينما صحيح {
        // انتظار عميل جديد
        عميل = خادم.اقبل()
        عدد_الاتصالات = عدد_الاتصالات + 1
        
        اطبع("🔗 عميل جديد اتصل! (إجمالي الاتصالات: " + عدد_الاتصالات + ")")
        اطبع("   العنوان: " + عميل.عنوان_البعيد())
        
        // معالجة رسائل العميل
        بينما صحيح {
            // استقبال رسالة (حتى 4096 بايت)
            رسالة = عميل.استقبل(4096)
            
            // إذا كانت الرسالة فارغة، العميل قطع الاتصال
            إذا رسالة.طول() == 0 {
                اطبع("❌ العميل قطع الاتصال")
                اطبع("")
                اكسر
            }
            
            // عرض الرسالة المستقبلة
            رسالة_نصية = نص.من_بايتات(رسالة)
            اطبع("📨 استقبلت: " + رسالة_نصية)
            
            // إعادة إرسال نفس الرسالة
            عميل.ارسل_الكل(رسالة)
            اطبع("📤 أعدت إرسال: " + رسالة_نصية)
        }
        
        // إغلاق اتصال العميل
        عميل.اغلق()
    }
}
```

### عميل الصدى TCP

هذا العميل يتصل بالخادم، يرسل رسائل، ويستقبل الردود:

```sad
استخدم شبكة
استخدم إدخال_إخراج

دالة رئيسية() {
    اطبع("🔌 جاري الاتصال بخادم الصدى...")
    
    // الاتصال بالخادم على نفس الجهاز (127.0.0.1)
    عميل = شبكة.اتصل_tcp("127.0.0.1", 8080)
    
    إذا عميل == باطل {
        اطبع("❌ فشل الاتصال! تأكد من تشغيل الخادم.")
        ارجع 1
    }
    
    اطبع("✅ تم الاتصال بالخادم!")
    اطبع("اكتب رسالة واضغط Enter لإرسالها")
    اطبع("اكتب 'خروج' للإنهاء")
    اطبع("")
    
    // حلقة لإرسال واستقبال الرسائل
    بينما صحيح {
        // قراءة رسالة من المستخدم
        اطبع("أنت: ", نهاية="")
        رسالة = إدخال_إخراج.اقرأ_سطر()
        
        // التحقق من أمر الخروج
        إذا رسالة == "خروج" {
            اطبع("👋 إنهاء الاتصال...")
            اكسر
        }
        
        // إرسال الرسالة
        عميل.ارسل_الكل(رسالة)
        
        // استقبال الرد
        رد = عميل.استقبل(4096)
        رد_نصي = نص.من_بايتات(رد)
        
        اطبع("الخادم: " + رد_نصي)
        اطبع("")
    }
    
    // إغلاق الاتصال
    عميل.اغلق()
    اطبع("✅ تم قطع الاتصال بنجاح")
}
```

### كيفية تجربة البرنامج

1. **احفظ كود الخادم** في ملف اسمه `خادم_الصدى.ص`
2. **احفظ كود العميل** في ملف اسمه `عميل_الصدى.ص`
3. **شغل الخادم أولاً** في نافذة Terminal:
   ```bash
   sad خادم_الصدى.ص
   ```
4. **شغل العميل** في نافذة Terminal أخرى:
   ```bash
   sad عميل_الصدى.ص
   ```
5. **ابدأ في كتابة رسائل** في نافذة العميل وشاهدها ترتد!

## 🎓 ما تعلمناه حتى الآن
