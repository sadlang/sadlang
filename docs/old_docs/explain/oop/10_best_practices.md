# أفضل الممارسات في البرمجة الكائنية - لغة ص

## مقدمة

بعد أن تعلمنا مفاهيم البرمجة الكائنية الأساسية، حان الوقت لنتعلم كيف نطبقها بشكل صحيح وفعّال. هذا القسم يُقدّم مجموعة من أفضل الممارسات والنصائح التي ستُساعدك على كتابة كود نظيف وقابل للصيانة.

## 1. مبدأ المسؤولية الواحدة

**كل صنف يجب أن يكون له مسؤولية واحدة فقط**

### ❌ مثال سيء: صنف يفعل كل شيء

```
صنف موظف_سيء
    نص الاسم
    عشري الراتب
    
    باني(نص اسم، عشري راتب)
        الاسم = اسم
        الراتب = راتب
    نهاية
    
    # حساب الراتب - مسؤولية 1
    دالة عشري حساب_الراتب()
        ارجع الراتب
    نهاية
    
    # طباعة التقرير - مسؤولية 2
    دالة طباعة_تقرير()
        اطبع_سطر("تقرير الموظف...")
    نهاية
    
    # حفظ في قاعدة البيانات - مسؤولية 3
    دالة حفظ()
        اطبع_سطر("حفظ في قاعدة البيانات...")
    نهاية
    
    # إرسال بريد - مسؤولية 4
    دالة إرسال_بريد()
        اطبع_سطر("إرسال بريد...")
    نهاية
نهاية
```

### ✅ مثال جيد: فصل المسؤوليات

```
صنف موظف
    نص الاسم
    عشري الراتب
    
    باني(نص اسم، عشري راتب)
        الاسم = اسم
        الراتب = راتب
    نهاية
    
    دالة نص اسم()
        ارجع الاسم
    نهاية
    
    دالة عشري راتب()
        ارجع الراتب
    نهاية
نهاية

صنف حاسبة_رواتب
    دالة عشري حساب_الراتب_الشهري(موظف م)
        ارجع م.راتب()
    نهاية
    
    دالة عشري حساب_الراتب_السنوي(موظف م)
        ارجع م.راتب() * 12
    نهاية
نهاية

صنف طابعة_تقارير
    دالة طباعة_تقرير_موظف(موظف م)
        اطبع_سطر("تقرير الموظف: " + م.اسم())
        اطبع_سطر("الراتب: " + م.راتب())
    نهاية
نهاية
```

## 2. تفضيل التركيب على الوراثة

**استخدم التركيب (composition) عندما يكون ذلك منطقياً**

### ❌ وراثة غير منطقية

```
# خاطئ: السيارة ليست "نوعاً من" المحرك
صنف سيارة يرث محرك
    # ...
نهاية
```

### ✅ التركيب المنطقي

```
صنف محرك
    رقم القوة
    نص النوع
    
    باني(رقم قوة، نص نوع)
        القوة = قوة
        النوع = نوع
    نهاية
    
    دالة تشغيل()
        اطبع_سطر("المحرك يعمل...")
    نهاية
    
    دالة إيقاف()
        اطبع_سطر("المحرك توقف...")
    نهاية
نهاية

صنف سيارة
    نص الماركة
    محرك المحرك  # السيارة "تحتوي على" محرك
    
    باني(نص ماركة، محرك م)
        الماركة = ماركة
        المحرك = م
    نهاية
    
    دالة تشغيل()
        اطبع_سطر("تشغيل السيارة...")
        المحرك.تشغيل()
    نهاية
    
    دالة إيقاف()
        المحرك.إيقاف()
        اطبع_سطر("السيارة توقفت")
    نهاية
نهاية

دالة رئيسية()
    محرك م = جديد محرك(200، "بنزين")
    سيارة س = جديد سيارة("تويوتا"، م)
    
    س.تشغيل()
    س.إيقاف()
    
    ارجع 0
نهاية
```

## 5. التحقق من صحة البيانات في الباني

### ❌ بدون تحقق

```
صنف عمر_سيء
    رقم القيمة
    
    باني(رقم قيمة)
        القيمة = قيمة  # ماذا لو كان سالباً؟
    نهاية
نهاية
```

### ✅ مع تحقق

```
صنف عمر
    رقم القيمة
    
    باني(رقم قيمة)
        إذا قيمة < 0
            اطبع_سطر("خطأ: العمر لا يمكن أن يكون سالباً")
            القيمة = 0
        وإلا
            إذا قيمة > 150
                اطبع_سطر("خطأ: العمر غير واقعي")
                القيمة = 0
            وإلا
                القيمة = قيمة
            نهاية
        نهاية
    نهاية
نهاية
```

## 6. تصميم للتوسعة

### ✅ صنف أساسي قابل للتوسعة

```

    نهاية
نهاية

صنف جمع يرث عملية_حسابية
    دالة عشري تنفيذ(عشري أ، عشري ب)
        ارجع أ + ب
    نهاية
    
    دالة نص الاسم()
        ارجع "جمع"
    نهاية
نهاية

صنف طرح يرث عملية_حسابية

        ارجع أ - ب
    نهاية
    
    دالة نص الاسم()
        ارجع "طرح"
    نهاية
نهاية

صنف ضرب يرث عملية_حسابية
    دالة عشري تنفيذ(عشري أ، عشري ب)
        ارجع أ * ب
    نهاية
    
    دالة نص الاسم()
        ارجع "ضرب"
    نهاية
نهاية

صنف قسمة يرث عملية_حسابية

            اطبع_سطر("خطأ: القسمة على صفر!")
            ارجع 0

        ارجع أ / ب
    نهاية
    
    دالة نص الاسم()
        ارجع "قسمة"

    طرح عملية2 = جديد طرح()

## 7. استخدام دوال مساعدة

```

## ملخص أفضل الممارسات

| الممارسة | الوصف |
|----------|-------|
| المسؤولية الواحدة | كل صنف يفعل شيئاً واحداً |
| التركيب على الوراثة | استخدم "يحتوي على" بدلاً من "هو نوع من" عند اللزوم |
| أسماء واضحة | اختر أسماء وصفية للأصناف والدوال والمتغيرات |
| أصناف صغيرة | تجنب الأصناف الضخمة |
| التحقق | تحقق من البيانات في الباني ودوال التعديل |
| التوسعة | صمم للتوسعة المستقبلية |
| دوال مساعدة | قسّم الدوال الكبيرة |
| تعليقات مفيدة | علّق على "لماذا" وليس "ماذا" |
| لا تكرار | أعد استخدام الكود بدلاً من تكراره |
| ثوابت | استخدم ثوابت بدلاً من الأرقام السحرية |

## الخلاصة

اتباع أفضل الممارسات يُحسّن جودة كودك بشكل كبير. الكود النظيف أسهل في القراءة والصيانة والتوسعة. تذكّر أن الهدف ليس فقط كتابة كود يعمل، بل كتابة كود يمكن للآخرين (وأنت في المستقبل) فهمه وتعديله بسهولة.
