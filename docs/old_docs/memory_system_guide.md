## مقدمة

نظام ذاكرة ص الذكية هو نظام مبتكر يجمع بين سهولة لغات مثل Python و JavaScript
وأمان وأداء لغات مثل Rust. الفكرة الأساسية:

> **ابدأ بسرعة، انتقل للأداء عند الحاجة**

### لماذا نظام مزدوج؟

| المشكلة | الحل في لغة ص |
|---------|---------------|
| Rust صعب للمبتدئين | وضع التطوير مع GC تلقائي |
| Python/JS بطيء | وضع الإنتاج مع ملكية صارمة |
| التحويل بين اللغات صعب | نفس الكود، أوضاع مختلفة |

## فلسفة التصميم

### المبدأ الأول: لا تُرهِق المبرمج

```
┌─────────────────────────────────────────────────────────────┐
│                    رحلة مبرمج لغة ص                         │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  المبتدئ ──────► المتوسط ──────► المتقدم ──────► الخبير     │
│     │              │               │              │         │
│     ▼              ▼               ▼              ▼         │
│   تطوير         مختلط          إنتاج         إنتاج+        │
│   (GC)        (GC+ملكية)      (ملكية)     (unsafe)        │
│                                                             │
│  لا تفكير    ←  تعلم تدريجي  ←  إتقان  ←  تحكم كامل       │
│  في الذاكرة     في الملكية      الملكية    بالذاكرة        │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### المبدأ الثاني: رسائل تعليمية

بدلاً من رسائل الخطأ المُربكة، يُقدم المترجم شروحات تعليمية:

```
❌ الطريقة التقليدية (Rust):
   error[E0382]: borrow of moved value: `x`

✅ طريقة لغة ص:
   خطأ: لا يمكن استخدام 'س' بعد نقله
   
   💡 شرح:
   المتغير 'س' تم نقل ملكيته للدالة 'معالجة()'.
   بعد النقل، لم تعد تملك الوصول للقيمة الأصلية.
   
   🔧 الحلول الممكنة:
   1. استخدم .انسخ() لإنشاء نسخة
   2. مرر بالمرجع باستخدام &س
   3. استخدم عم<> للملكية المشتركة
```

## أوضاع الذاكرة

### 1. وضع التطوير (Development Mode)

**الاستخدام:** للتجريب السريع والتعلم

```bash
sadc --تطوير برنامجي.s
# أو
sadc --dev برنامجي.s
```

**الخصائص:**
- ✅ جامع قمامة تلقائي (Reference Counting)
- ✅ لا حاجة للتفكير في الملكية
- ✅ اقتراحات لتحسين الكود
- ⚠️ أداء أقل من وضع الإنتاج

**مثال:**
```س
# في وضع التطوير، كل شيء يعمل "سحرياً"
دالة رئيسية()
    قائمة = مصفوفة<رقم>()
    قائمة.أضف(1)
    قائمة.أضف(2)
    
    # لا مشكلة - GC يتعامل مع الذاكرة
    معالجة(قائمة)
    اطبع(قائمة)  # لا يزال يعمل!
نهاية
```

---

### 2. وضع الإنتاج (Production Mode)

**الاستخدام:** للإصدارات النهائية والأداء العالي

```bash
sadc --إنتاج برنامجي.s
# أو
sadc --prod برنامجي.s
```

**الخصائص:**
- ✅ أقصى أداء (كـ Rust/C++)
- ✅ أمان كامل في وقت الترجمة
- ✅ لا overhead من GC
- ⚠️ يتطلب فهم الملكية

**مثال:**
```س
# في وضع الإنتاج، يجب التفكير في الملكية
دالة رئيسية()
    قائمة = مصفوفة<رقم>()
    قائمة.أضف(1)
    
    # خطأ! قائمة انتقلت لـ معالجة
    معالجة(قائمة)
    # اطبع(قائمة)  ← خطأ ترجمة!
    
    # الحل 1: مرر بالمرجع
    معالجة(&قائمة)
    اطبع(قائمة)  # ✓ يعمل
    
    # الحل 2: انسخ
    معالجة(قائمة.انسخ())
    اطبع(قائمة)  # ✓ يعمل
نهاية
```

---

### 3. الوضع المختلط (Hybrid Mode)

**الاستخدام:** للمشاريع الكبيرة مع أجزاء حرجة للأداء

```bash
sadc --مختلط برنامجي.s
# أو
sadc --hybrid برنامجي.s
```

**الخصائص:**
- ✅ GC للكود العادي
- ✅ ملكية صارمة للأجزاء الموسومة
- ✅ تحكم دقيق

**مثال:**
```س
# الكود العادي يستخدم GC
دالة معالجة_واجهة(بيانات)
    # GC يتعامل مع الذاكرة
    عرض(بيانات)
نهاية

# الأجزاء الحرجة تستخدم ملكية
#[ملكية]
دالة معالجة_صوت(عينات: &مصفوفة<عش32>) -> مصفوفة<عش32>
    # هنا يجب الالتزام بقواعد الملكية
    نتيجة = مصفوفة<عش32>::بسعة(عينات.طول())
    لكل (عينة في عينات)
        نتيجة.أضف(عينة * 2.0)
    نهاية
    ارجع نتيجة
نهاية
```

---

### 4. وضع التعلم (Learning Mode)

**الاستخدام:** لتعلم مفاهيم الملكية تدريجياً

```bash
sadc --تعلم برنامجي.s
# أو
sadc --learn برنامجي.s
```

**الخصائص:**
- ✅ يعمل كوضع التطوير
- ✅ يُظهر اقتراحات الملكية
- ✅ شروحات تعليمية مفصلة
- ✅ مثالي للانتقال التدريجي

## استخدام الأوضاع

### من سطر الأوامر

```bash
# الأعلام الأساسية
sadc --تطوير program.s      # Development mode
sadc --إنتاج program.s       # Production mode
sadc --مختلط program.s       # Hybrid mode
sadc --تعلم program.s        # Learning mode

# خيارات متقدمة
sadc --gc=refcount program.s          # عدّ مراجع
sadc --gc=atomic program.s            # عدّ ذري (متزامن)
sadc --gc=tracing program.s           # Mark & Sweep
sadc --gc=none program.s              # بدون GC

sadc --ملكية=off program.s            # إيقاف فحص الملكية
sadc --ملكية=warnings program.s       # تحذيرات فقط
sadc --ملكية=strict program.s         # صارم
sadc --ملكية=ultra program.s          # صارم جداً (كـ Rust)

# دمج الخيارات
sadc --تطوير --اقتراحات program.s     # تطوير + اقتراحات
sadc --إنتاج --gc=none program.s      # إنتاج بدون GC
```

### من الكود (سمات)

```س
# تحديد الوضع لملف كامل
#[وضع_ذاكرة: تطوير]

# تحديد الوضع لدالة معينة
#[ملكية]
دالة حرجة()
    # ...
نهاية

# تحديد الوضع لصنف
#[gc]
صنف واجهة_مستخدم
    # ...
نهاية
```

### من متغيرات البيئة

```bash
# Windows
set SAD_MEMORY_MODE=dev
set SAD_GC_STRATEGY=refcount

# Linux/macOS
export SAD_MEMORY_MODE=prod

```

### من ملف التكوين (sad.config)


## المؤشرات الذكية

### عم<T> (Reference Counted - Rc)

**الاستخدام:** للملكية المشتركة في خيط واحد

```س
استورد عم من "ص/ذاكرة"

# إنشاء
قائمة = عم<مصفوفة<رقم>>::أنشئ()

# المشاركة (يزيد العداد)
نسخة = قائمة.شارك()

# الاستخدام
اطبع(قائمة.قيمة().طول())

# العداد
اطبع("عدد المراجع:", قائمة.عدد())

# التحقق من التفرد
إذا (قائمة.فريد())
    اطبع("أنت المالك الوحيد")
نهاية
```

**متى تستخدم عم<>؟**
- ✅ بيانات مشتركة بين أجزاء البرنامج
- ✅ هياكل بيانات مثل الأشجار والرسوم
- ✅ ذاكرة مؤقتة (cache)
- ❌ لا تستخدم مع خيوط متعددة

---

### عم_ذري<T> (Atomic Reference Counted - Arc)

**الاستخدام:** للملكية المشتركة بين خيوط متعددة

```س
استورد عم_ذري من "ص/ذاكرة"
استورد خيط من "ص/متزامن"

# إنشاء
بيانات = عم_ذري<مصفوفة<رقم>>::أنشئ()

# المشاركة بين خيوط
خيط.أنشئ(دالة()
    نسخة = بيانات.شارك()
    # استخدام آمن في خيط منفصل
نهاية)
```

**متى تستخدم عم_ذري<>؟**
- ✅ بيانات مشتركة بين خيوط
- ✅ حالة عامة للتطبيق
- ⚠️ أبطأ قليلاً من عم<> بسبب الذرية

---

### مرجع_ضعيف<T> (Weak Reference)

**الاستخدام:** لكسر دورات المراجع

```س
استورد عم، مرجع_ضعيف من "ص/ذاكرة"

صنف عقدة
    قيمة: رقم
    أبناء: مصفوفة<عم<عقدة>>        # ملكية قوية
    أب: مرجع_ضعيف<عقدة>           # مرجع ضعيف (لا يملك)
نهاية

# إنشاء شجرة
جذر = عم<عقدة>::أنشئ(قيمة: 1)
ابن = عم<عقدة>::أنشئ(قيمة: 2)

# ربط (الأب يملك الابن)
جذر.قيمة().أبناء.أضف(ابن.شارك())

# ربط عكسي (الابن لا يملك الأب)
ابن.قيمة().أب = جذر.ضعيف()

# استخدام المرجع الضعيف
إذا (أب_قوي = ابن.قيمة().أب.قوِّ())
    اطبع("الأب موجود:", أب_قوي.قيمة().قيمة)
وإلا
    اطبع("الأب تم حذفه")
نهاية
```

**متى تستخدم مرجع_ضعيف<>؟**
- ✅ مراجع عكسية (ابن → أب)
- ✅ ذاكرة مؤقتة (cache) قد تُحذف
- ✅ مراقبون (observers)
- ✅ كسر أي دورة مراجع

## كاشف الدورات

### ما هي دورة المراجع؟

```
     ┌──────────────────────────────────────┐
     │          دورة مراجع قوية            │
     │                                      │
     │    ┌───┐      ┌───┐      ┌───┐      │
     │    │ أ │ ───► │ ب │ ───► │ ج │      │
     │    └───┘      └───┘      └───┘      │
     │      ▲                      │       │
     │      │                      │       │
     │      └──────────────────────┘       │
     │                                      │
     │  المشكلة: لا يمكن تحرير أي كائن!    │
     │  عداد كل كائن لن يصل للصفر أبداً    │
     └──────────────────────────────────────┘
```

### استخدام الكاشف

```س
استورد كاشف_دورات من "ص/ذاكرة/تشخيص"

# تفعيل الكشف
كاشف = كاشف_دورات()

# تحليل ملف
دورات = كاشف.حلل_ملف("برنامجي.s")

# عرض التقرير
إذا (دورات.ليست_فارغة())
    اطبع("⚠️ تم اكتشاف دورات مراجع!")
    لكل (دورة في دورات)
        اطبع(دورة.للنص_العربي())
    نهاية
وإلا
    اطبع("✅ لا توجد دورات")
نهاية
```

```

╚═══════════════════════════════════════════════════════════════════════════════╝

  📊 الإحصائيات:
  ─────────────
    • الكائنات المحللة:    25
    • المراجع المحللة:     42
    • الدورات المكتشفة:    1
    • دورات مشكلة:        1
    • دورات آمنة:         0

  ⚠️ الدورات المكتشفة:
  ─────────────────────

  ┌─── دورة #1 🔴 مشكلة ───
  │
  │  المسار: عقدة_أ → عقدة_ب → عقدة_ج → عقدة_أ
  │
  │  الطول: 3 عقد
```

## مُقترِح الملكية

### ما هو؟

نظام ذكي يحلل كودك المكتوب بوضع التطوير ويقترح كيفية تحويله لنظام الملكية.

### تفعيل الاقتراحات

```bash
sadc --تطوير --اقتراحات برنامجي.s
# أو
sadc --تعلم برنامجي.s  # مفعّل افتراضياً
```

### أنواع الاقتراحات

#### 1. استخدام المؤشرات الذكية

```س
# الكود الأصلي
شخص = جديد شخص("أحمد")

# الاقتراح:
# 💡 استخدم عم<شخص> بدلاً من جديد
# 
#   // قبل:
#   شخص = جديد شخص("أحمد")
#   
#   // بعد:
#   شخص = عم<شخص>::أنشئ("أحمد")
#
# 📚 شرح:
# استخدام 'جديد' مباشرة قد يسبب تسرب ذاكرة
# عم<> يضمن تحرير الذاكرة تلقائياً
```

#### 2. تجنب المراجع المعلقة

```س
# الكود الأصلي
دالة خطرة() -> &نص
    محلي = "مرحباً"
    ارجع &محلي  # ⚠️ خطر!
نهاية

# الاقتراح:
# ⚠️ تحذير: إرجاع مرجع لمتغير محلي!
#
# 📚 شرح:
# المتغير 'محلي' سيُحذف عند انتهاء الدالة
# المرجع المُرجَع سيصبح معلقاً (dangling)
#
# 🔧 الحلول:
# 1. أرجع قيمة بدلاً من مرجع: -> نص
# 2. أرجع نسخة: ارجع محلي.انسخ()
# 3. استخدم عم<>: ارجع عم<نص>::أنشئ(محلي)
```

#### 3. اكتشاف الدورات المحتملة

```س
# الكود الأصلي
صنف عقدة
    التالي: عم<عقدة>
    السابق: عم<عقدة>  # ⚠️ دورة محتملة!
نهاية

# الاقتراح:
# 🔄 تحذير: دورة مراجع محتملة!
#
# 📚 شرح:
# إذا كانت عقدة A تشير لعقدة B والعكس،
# لن يُحرَّر أي منهما!
#
# 🔧 الحل:
# استخدم مرجع_ضعيف<> لأحد الاتجاهين:
#   السابق: مرجع_ضعيف<عقدة>
```

## أمثلة عملية

### مثال 1: قائمة مرتبطة

```س
# stdlib/collections/linked_list.s

استورد عم، مرجع_ضعيف من "ص/ذاكرة"

# عقدة في القائمة
صنف عقدة<T>
    قيمة: T
    التالي: اختياري<عم<عقدة<T>>>
    السابق: اختياري<مرجع_ضعيف<عقدة<T>>>  # ضعيف لتجنب الدورات
نهاية

# القائمة المرتبطة
صنف قائمة_مرتبطة<T>
    _رأس: اختياري<عم<عقدة<T>>>
    _ذيل: اختياري<مرجع_ضعيف<عقدة<T>>>
    _طول: رقم
    
    دالة أنشئ() -> قائمة_مرتبطة<T>
        ارجع قائمة_مرتبطة<T>(
            _رأس: لاشيء(),
            _ذيل: لاشيء(),
            _طول: 0
        )
    نهاية
    
    دالة أضف_نهاية(&ذاتي، قيمة: T)
        عقدة_جديدة = عم<عقدة<T>>::أنشئ(
            قيمة: قيمة،
            التالي: لاشيء()،
            السابق: لاشيء()
        )
        
        إذا (ذاتي._ذيل.موجود())
            # ربط بالعقدة السابقة
            ذيل_قوي = ذاتي._ذيل.قيمة().قوِّ()
            إذا (ذيل_قوي.موجود())
                ذيل_قوي.قيمة().قيمة().التالي = بعض(عقدة_جديدة.شارك())
                عقدة_جديدة.قيمة().السابق = بعض(ذيل_قوي.قيمة().ضعيف())
            نهاية
        وإلا
            # القائمة فارغة
            ذاتي._رأس = بعض(عقدة_جديدة.شارك())
        نهاية
        
        ذاتي._ذيل = بعض(عقدة_جديدة.ضعيف())
        ذاتي._طول += 1
    نهاية
    
    دالة طول(&ذاتي) -> رقم
        ارجع ذاتي._طول
    نهاية
نهاية

# الاستخدام
دالة رئيسية()
    قائمة = قائمة_مرتبطة<رقم>::أنشئ()
    قائمة.أضف_نهاية(1)
    قائمة.أضف_نهاية(2)
    قائمة.أضف_نهاية(3)
    
    اطبع("الطول:", قائمة.طول())  # 3
نهاية
```

### مثال 2: ذاكرة مؤقتة (Cache)

```س
# stdlib/cache/lru_cache.s

استورد عم، مرجع_ضعيف من "ص/ذاكرة"
استورد قاموس من "ص/مجموعات"

# ذاكرة مؤقتة LRU
صنف ذاكرة_مؤقتة<K، V>
    _سعة: رقم
    _بيانات: قاموس<K، عم<V>>
    _ترتيب: مصفوفة<K>
    
    دالة أنشئ(سعة: رقم) -> ذاكرة_مؤقتة<K، V>
        ارجع ذاكرة_مؤقتة<K، V>(
            _سعة: سعة،
            _بيانات: قاموس<K، عم<V>>::جديد()،
            _ترتيب: مصفوفة<K>()
        )
    نهاية
    
    دالة ضع(&ذاتي، مفتاح: K، قيمة: V)
        # إذا موجود، حدّث الترتيب
        إذا (ذاتي._بيانات.يحتوي(مفتاح))
            ذاتي._حدث_ترتيب(مفتاح)
            ذاتي._بيانات[مفتاح] = عم<V>::أنشئ(قيمة)
            ارجع
        نهاية
        
        # إذا ممتلئ، احذف الأقدم
        إذا (ذاتي._ترتيب.طول() >= ذاتي._سعة)
            أقدم = ذاتي._ترتيب.أزل_أول()
            ذاتي._بيانات.أزل(أقدم)
        نهاية
        
        # أضف الجديد
        ذاتي._بيانات[مفتاح] = عم<V>::أنشئ(قيمة)
        ذاتي._ترتيب.أضف(مفتاح)
    نهاية
    
    دالة جلب(&ذاتي، مفتاح: K) -> اختياري<&V>
        إذا (ذاتي._بيانات.يحتوي(مفتاح))
            ذاتي._حدث_ترتيب(مفتاح)
            ارجع بعض(&ذاتي._بيانات[مفتاح].قيمة())
        نهاية
        ارجع لاشيء()
    نهاية
    
    دالة _حدث_ترتيب(&ذاتي، مفتاح: K)
        ذاتي._ترتيب.أزل_قيمة(مفتاح)
        ذاتي._ترتيب.أضف(مفتاح)
    نهاية
نهاية

# الاستخدام
دالة رئيسية()
    ذاكرة = ذاكرة_مؤقتة<نص، رقم>::أنشئ(سعة: 100)
    
    ذاكرة.ضع("أحمد"، 25)
    ذاكرة.ضع("سارة"، 30)
    
    إذا (عمر = ذاكرة.جلب("أحمد"))
        اطبع("عمر أحمد:", عمر.قيمة())
    نهاية
نهاية
```

### مثال 3: شجرة ثنائية

```س
# stdlib/trees/binary_tree.s

استورد عم، مرجع_ضعيف من "ص/ذاكرة"

# عقدة الشجرة
صنف عقدة_شجرة<T>
    قيمة: T
    يسار: اختياري<عم<عقدة_شجرة<T>>>
    يمين: اختياري<عم<عقدة_شجرة<T>>>
    أب: اختياري<مرجع_ضعيف<عقدة_شجرة<T>>>  # ضعيف!
نهاية

# الشجرة الثنائية
صنف شجرة_ثنائية<T>
    _جذر: اختياري<عم<عقدة_شجرة<T>>>
    
    دالة أنشئ() -> شجرة_ثنائية<T>
        ارجع شجرة_ثنائية<T>(_جذر: لاشيء())
    نهاية
    
    دالة أدخل(&ذاتي، قيمة: T)
        عقدة = عم<عقدة_شجرة<T>>::أنشئ(
            قيمة: قيمة،
            يسار: لاشيء()،
            يمين: لاشيء()،
            أب: لاشيء()
        )
        
        إذا (ذاتي._جذر.فارغ())
            ذاتي._جذر = بعض(عقدة)
            ارجع
        نهاية
        
        ذاتي._أدخل_في(ذاتي._جذر.قيمة()، عقدة)
    نهاية
    
    دالة _أدخل_في(&ذاتي، أب: عم<عقدة_شجرة<T>>، عقدة: عم<عقدة_شجرة<T>>)
        إذا (عقدة.قيمة().قيمة < أب.قيمة().قيمة)
            إذا (أب.قيمة().يسار.موجود())
                ذاتي._أدخل_في(أب.قيمة().يسار.قيمة()، عقدة)
            وإلا
                عقدة.قيمة().أب = بعض(أب.ضعيف())
                أب.قيمة().يسار = بعض(عقدة)
            نهاية
        وإلا
            إذا (أب.قيمة().يمين.موجود())
                ذاتي._أدخل_في(أب.قيمة().يمين.قيمة()، عقدة)
            وإلا
                عقدة.قيمة().أب = بعض(أب.ضعيف())
                أب.قيمة().يمين = بعض(عقدة)
            نهاية
        نهاية
    نهاية
    
    دالة اطبع_مرتب(&ذاتي)
        إذا (ذاتي._جذر.موجود())
            ذاتي._اطبع_مرتب_من(ذاتي._جذر.قيمة())
        نهاية
    نهاية
    
    دالة _اطبع_مرتب_من(&ذاتي، عقدة: عم<عقدة_شجرة<T>>)
        إذا (عقدة.قيمة().يسار.موجود())
            ذاتي._اطبع_مرتب_من(عقدة.قيمة().يسار.قيمة())
        نهاية
        
        اطبع(عقدة.قيمة().قيمة)
        
        إذا (عقدة.قيمة().يمين.موجود())
            ذاتي._اطبع_مرتب_من(عقدة.قيمة().يمين.قيمة())
        نهاية
    نهاية
نهاية
```

## أفضل الممارسات

### ✅ افعل

1. **ابدأ بوضع التطوير**
   ```bash
   sadc --تطوير برنامجي.s
   ```

2. **استخدم --تعلم للانتقال التدريجي**
   ```bash
   sadc --تعلم --اقتراحات برنامجي.s
   ```

3. **استخدم عم<> للملكية المشتركة**
   ```س
   بيانات = عم<T>::أنشئ(...)
   ```

4. **استخدم مرجع_ضعيف<> للمراجع العكسية**
   ```س
   أب: مرجع_ضعيف<عقدة>
   ```

5. **مرر بالمرجع للقراءة فقط**
   ```س
   دالة معالجة(بيانات: &مصفوفة<رقم>)
   ```

6. **استخدم اختياري<> بدلاً من null**
   ```س
   نتيجة: اختياري<مستخدم>
   ```

7. **استخدم نتيجة<> للأخطاء**
   ```س
   نتيجة: نتيجة<بيانات، خطأ>
   ```

### ❌ لا تفعل

1. **لا تستخدم جديد مباشرة في الإنتاج**
   ```س
   # ❌ خطأ
   كائن = جديد صنفي()
   
   # ✅ صحيح
   كائن = عم<صنفي>::أنشئ()
   ```

2. **لا ترجع مرجعاً لمتغير محلي**
   ```س
   # ❌ خطأ
   دالة خطرة() -> &نص
       محلي = "مرحباً"
       ارجع &محلي
   نهاية
   ```

3. **لا تستخدم عم<> بين خيوط**
   ```س
   # ❌ خطأ - عم<> ليس آمناً للخيوط
   خيط.أنشئ(دالة()
       اطبع(بيانات_عم.قيمة())
   نهاية)
   
   # ✅ صحيح - استخدم عم_ذري<>
   خيط.أنشئ(دالة()
       اطبع(بيانات_ذري.قيمة())
   نهاية)
   ```

4. **لا تُهمل تحذيرات الدورات**
   ```س
   # ⚠️ إذا رأيت تحذير دورة، أصلحه!
   ```

## الأسئلة الشائعة

### س: متى أستخدم وضع التطوير مقابل الإنتاج؟

**ج:** 
- **التطوير**: للتجريب، النماذج الأولية، التعلم، السكربتات السريعة
- **الإنتاج**: للإصدارات النهائية، الأنظمة الحرجة، الأداء العالي

### س: هل وضع التطوير بطيء جداً؟

**ج:** لا! الفرق عادةً 10-30% فقط. لمعظم التطبيقات هذا مقبول تماماً.
استخدم الإنتاج فقط عندما تحتاج أقصى أداء.

### س: هل يمكن خلط الوضعين في مشروع واحد؟

**ج:** نعم! استخدم الوضع المختلط:
```س
# كود عادي (GC)
دالة واجهة() ...

# كود حرج (ملكية)
#[ملكية]
دالة معالجة_صوت() ...
```

### س: كيف أتعلم نظام الملكية؟

**ج:**
1. ابدأ بوضع التعلم: `sadc --تعلم`
2. اقرأ الاقتراحات والشروحات
3. حاول تطبيق الاقتراحات يدوياً
4. انتقل تدريجياً للإنتاج

### س: ما الفرق بين عم<> و عم_ذري<>؟

**ج:**
- `عم<>`: أسرع، لخيط واحد فقط
- `عم_ذري<>`: آمن للخيوط، أبطأ قليلاً

### س: متى أستخدم مرجع_ضعيف<>؟

**ج:** عندما تحتاج مرجعاً لا "يملك" الكائن:
- مراجع عكسية (ابن → أب)
- ذاكرة مؤقتة قد تُحذف
- مراقبون ومستمعون
