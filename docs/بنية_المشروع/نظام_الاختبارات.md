# نظام الاختبارات — `tests/`

> **الدور:** اختبارات شاملة للغة ص (وحدة, تكامل, أداء, dual execution)  
> **عدد المجلدات:** 50+  
> **الأدوات:** C++ (CTest), Python 3 (runner.py), `.ص` scripts

---

## نظرة عامة

```
tests/
├── comprehensive/         ← ~25 ملف C++ شامل (900+ اختبار)
├── dual_execution/        ← ⚡ اختبارات مفسر + مترجم (الأهم)
├── interpreter_tests/     ← اختبارات المفسر
├── compiler/              ← اختبارات المترجم
├── parser_tests/          ← اختبارات المحلل النحوي

├── oop/                   ← اختبارات OOP
├── stdlib/                ← اختبارات المكتبة القياسية
├── ...                    ← 40+ مجلد آخر
```

## أهم أنواع الاختبارات

### 1. اختبارات التنفيذ المزدوج — `dual_execution/` ⚡

> **الهدف:** تشغيل نفس الكود في المفسر والمترجم والتأكد أن النتيجة متطابقة

| الملف/المجلد | الدور |
|-------------|------|


## كيفية إضافة اختبار جديد

### اختبار تنفيذ مزدوج (الأسهل):
1. أنشئ ملف `.ص` في `tests/dual_execution/core/` (أو `oop/` أو `advanced/`)
2. أضف تعليق `# المخرج المتوقع:` في أول الملف
3. شغّل `python runner.py`

### اختبار C++ شامل:
1. أنشئ ملف `.cpp` في `tests/comprehensive/`
2. أضف إلى `cmake/tests_comprehensive.cmake`
3. ابنِ وشغّل بـ CTest

## ⚠️ ملاحظات

1. **الاختبارات معطّلة افتراضياً** — فعّلها بـ `-DBUILD_TESTS=ON`
2. **`parser_tests` و `oop_tests` معطلة** — لا تتسبب في تراجع
3. **`dual_execution/runner.py`** هو الأداة الأساسية للتحقق من تطابق المفسر والمترجم
4. **19 اختبار تنفيذ مزدوج ناجح حالياً**
5. **~900 اختبار شامل** في `comprehensive/`
