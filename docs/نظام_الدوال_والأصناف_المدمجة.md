# نظام الدوال والأصناف المدمجة في مفسر لغة ص

> مرجع للمطورين: كيفية تسجيل دوال مدمجة جديدة، إنشاء كائنات برمجياً، وفهم بنية نظام OOP الداخلي.

---

## 1. تسجيل دالة مدمجة جديدة (Builtin Function)

### الآلية الأساسية

الدوال المدمجة تُسجَّل عبر `FunctionManager::registerBuiltinFunction()` المُعرَّفة في:
- **التصريح:** `interpreter_new/include/managers/function_manager.h` (سطر ~379)
- **التنفيذ:** `interpreter_new/src/managers/function_manager.cpp` (سطر ~492)

```cpp
void FunctionManager::registerBuiltinFunction(
    const std::string& name,
    const std::function<std::shared_ptr<Value>(const std::vector<std::shared_ptr<Value>>&)>& func);
```

### خطوات إضافة دالة مدمجة

1. **اختر ملف التسجيل المناسب** (أو أنشئ واحداً جديداً):
   - الدوال الأساسية (اطبع، طول، أضف): `builtin_registry_part1.cpp`
   - الرياضيات المتقدمة: `builtin_registry_part6.cpp`
   - التزامن والقنوات: `builtin_registry_part8.cpp`
   - نظام الملفات: `builtin_registry_part7.cpp`
   - UI والرسوميات: `interpreter_new/src/ui/ui_core_builtins.cpp`

2. **عرّف لامدا بالتوقيع المطلوب:**
   ```cpp
   auto my_func = [](const std::vector<std::shared_ptr<Data::Value>>& args)
       -> std::shared_ptr<Data::Value>
   {
       // التحقق من عدد المعاملات
       if (args.empty()) {
           throw std::runtime_error("الدالة تحتاج معاملاً واحداً على الأقل");
       }
       
       // معالجة المعاملات
       std::string input = args[0]->toString();
       
       // إرجاع النتيجة
       return std::make_shared<Data::Value>(input.length());
   };
   ```

3. **سجّل الدالة بأسماء متعددة (عربي + إنجليزي):**
   ```cpp
   interpreter.getFunctionManager().registerBuiltinFunction("طول_النص", my_func);
   interpreter.getFunctionManager().registerBuiltinFunction("str_length", my_func);
   ```

4. **إذا كانت الدالة في وحدة:** سجّلها في دالة `registerBuiltinsPartN()` وأضف `extern` لها في `builtin_registry.cpp`.

### مثال كامل (من `builtin_registry_part1.cpp`)

```cpp
void registerBuiltinsPart1(Interpreter& interpreter) {
    // دالة الطباعة
    auto print_func = [](const std::vector<std::shared_ptr<Data::Value>>& args) {
        return BuiltinFunctions::print(args);
    };
    interpreter.getFunctionManager().registerBuiltinFunction("اطبع", print_func);
    interpreter.getFunctionManager().registerBuiltinFunction("print", print_func);
    
    // دالة الطول
    auto len_func = [](const std::vector<std::shared_ptr<Data::Value>>& args) {
        return BuiltinFunctions::length(args);
    };
    interpreter.getFunctionManager().registerBuiltinFunction("طول", len_func);
    interpreter.getFunctionManager().registerBuiltinFunction("length", len_func);
    interpreter.getFunctionManager().registerBuiltinFunction("len", len_func);
}
```

### نظام التحميل الكسول (Lazy Loading)

بدلاً من تسجيل ~2500 دالة عند البدء، يستخدم المفسر `BuiltinModuleRegistry` (في `interpreter_new/include/core/builtin_module_registry.h`):

| الوحدة | الأجزاء | متى تُحمَّل |
|--------|---------|------------|
| أساسي (Core) | Parts 1, 2, 6, 7, 8, 10, 39, 40 | تلقائياً عند البدء |
| نظام_ملفات | Part 7-8 | عند `استورد نظام_ملفات` |
| رسوميات | Part 9, 22 | عند `استورد رسوميات` |
| نظام_منخفض | Parts 19-21 | عند `استورد نظام_منخفض` |
| usb | Part 23 | عند `استورد usb` |
| محرك | Parts 29-34 | عند `استورد محرك` |

لتسجيل وحدة جديدة:
```cpp
BuiltinModuleRegistry::getInstance().registerModule({
    .name = "اسم_الوحدة",
    .aliases = {"alias1", "alias2"},
    .description = "وصف الوحدة",
    .registrar = [](Interpreter& interp) { registerBuiltinsPartN(interp); }
});
```

## 2. إنشاء كائن ObjectInstance برمجياً

### الطريقة 1: عبر ExpressionEvaluator (الطريقة العادية)

هذا ما يحدث عند تنفيذ `صنف(...)` في `visitNewExpr` — ملف `expression_evaluator_oop.cpp`:

```cpp
// 1. الحصول على ClassType المسجل
auto *classManager = Data::ClassManager::getInstance();
ClassType *classType = classManager->getClass("اسم_الصنف");

// 2. إنشاء ObjectInstance بمعرّف فريد
size_t objId = generateObjectId();
auto objectInstance = std::make_shared<ObjectInstance>(classType, objId);

// 3. تهيئة الحقول (بما فيها الموروثة)
ClassType *currentClass = classType;
while (currentClass) {
    for (const auto &field : currentClass->fields) {
        if (!field.isStatic)
            objectInstance->fields[field.name] = field.defaultValue.clone();
    }
    currentClass = currentClass->getBaseClass();
}

// 4. استدعاء الباني (إن وُجد)
if (classType->constructor) {
    // ... تنفيذ جسم الباني ...
}

// 5. تحويل الكائن إلى Value
objectInstance->markConstructed();
Value result(objectInstance);  // Value يحمل shared_ptr<ObjectInstance>
```

### الطريقة 2: عبر ObjectManager

```cpp
ObjectInstance* obj = ObjectManager::getInstance()->createObject("اسم_الصنف");
```

هذا يبحث عن الصنف في `ClassManager`، يستدعي `classType->createInstance()`، ويسجل الكائن.

## 3. تسجيل صنف مدمج (Builtin Class)

### الوضع الحالي

**لا يوجد `registerBuiltinClass()` مخصص.** الأصناف تُسجَّل عادة من Parser عبر `StatementExecutor` عند تنفيذ تعريف صنف في كود ص.

### كيفية تسجيل صنف من C++ برمجياً

يمكنك إنشاء `ClassType` يدوياً وتسجيله:

```cpp
#include "class_manager.h"
#include "class_type.h"

// 1. إنشاء الصنف
auto cls = std::make_unique<ClassType>("نقطة");

// 2. إضافة حقول
cls->addField(ClassField{
    .name = "س",
    .type = DataType::INTEGER,
    .visibility = Visibility::PUBLIC,
    .defaultValue = Value(0)
});
cls->addField(ClassField{
    .name = "ص",
    .type = DataType::INTEGER,
    .visibility = Visibility::PUBLIC,
    .defaultValue = Value(0)
});

// 3. إضافة دوال (methods)
// يتطلب AST node للجسم — أو يمكن تسجيل builtin method

// 4. تسجيل الصنف
ClassManager::getInstance()->registerClass(std::move(cls));

// الآن يمكن لكود ص استخدام: نقطة()
```

### ملاحظات مهمة

- `ClassManager` هو Singleton — `ClassManager::getInstance()`
- `registerClass()` تأخذ `std::unique_ptr<ClassType>` أو `ClassType*` (raw pointer — يُنقل الملكية)
- إذا كان الاسم مستخدماً مسبقاً، تُرجع `false`
- بعد التسجيل، يمكن لكود ص استخدام `اسم_الصنف(...)` تلقائياً

## 4. Method Dispatch على ObjectInstance

### مسار التنفيذ في `visitMethodCallExpr`

ملف: `interpreter_new/src/visitors/expression_evaluator_oop.cpp` (سطر ~608)

```
كائن.منهج(معاملات)
    │
    ├─ تقييم الكائن (node.object->accept)
    │
    ├─ تحديد النوع:
    │   ├─ نص = اسم صنف؟ → استدعاء ثابت (static call)
    │   ├─ مصفوفة؟ → 30+ منهج مدمج (اضف، رتب، شريحة...)
    │   ├─ خريطة؟ → مناهج خرائط مدمجة
    │   ├─ نص عادي؟ → مناهج نصية مدمجة
    │   ├─ كائن OBJECT (ObjectInstance)؟ → بحث المنهج في ClassType
    │   └─ MAP قديم بـ __class__؟ → توافق عكسي
    │
    ├─ البحث عن المنهج: classType->findMethod(methodName)
    │   └─ يبحث في السلسلة الهرمية (الصنف الحالي ← الأب ← الجد...)
    │
    ├─ فحص الوصول: checkMemberAccess(visibility)
    │
    ├─ إنشاء نطاق جديد + ربط:
    │   ├─ "هذا" / "this" ← الكائن الحالي
    │   ├─ حقول الكائن (كمتغيرات محلية)
    │   └─ المعاملات (تتغلب على الحقول عند تطابق الأسماء)
    │
    ├─ تنفيذ جسم المنهج
    │
    └─ تحديث حقول الكائن بالقيم المعدّلة
```

### المناهج المدمجة على المصفوفات

المفسر يعالج مناهج المصفوفات مباشرة في `visitMethodCallExpr` دون الحاجة لتعريف صنف:

| المنهج | الوصف |
|--------|-------|
| `الطول()` / `length()` | حجم المصفوفة |
| `اضف(عنصر)` / `push()` | إضافة عنصر |
| `احذف_اخير()` / `pop()` | حذف وإرجاع الأخير |
| `رتب()` / `sort()` | ترتيب |
| `شريحة(بداية، نهاية)` / `slice()` | استخراج جزء |
| `خريطة(دالة)` / `map()` | تحويل كل عنصر |
| `رشح(دالة)` / `filter()` | تصفية |
| `اختزل(دالة، قاعدة)` / `reduce()` | تجميع |
| وأكثر من 30 منهجاً آخر... | |

## 5. ربط SDL2 والرسوميات

### الملفات الرئيسية

| الملف | الدور |
|------|------|
| `features/graphics/third_party/SDL2-2.28.5/` | مكتبة SDL2 المضمنة |
| `features/graphics/third_party/SDL2_ttf-2.20.2/` | SDL2_ttf للخطوط |
| `interpreter_new/src/ui/ui_bridge.cpp` | الجسر بين المفسر و SDL2 |
| `interpreter_new/src/ui/ui_bridge_events.cpp` | معالجة أحداث SDL2 (تحت `#ifdef SAD_UI_USE_SDL2`) |
| `interpreter_new/src/ui/ui_core_builtins.cpp` | تسجيل `تشغيل_تطبيق()` و `runApp()` |
| `interpreter_new/src/ui/ui_audio_builtins.cpp` | دوال الصوت |
| `features/graphics/stdlib/رسومات/` | مكتبة الرسوميات بلغة ص (واجهات، عناصر، تخطيطات) |

### كيف تعمل واجهة SDL2

1. **الدوال المدمجة** (`تشغيل_تطبيق`، `انتقل`...) مسجلة في `ui_core_builtins.cpp`
2. **UIBridge** يربط بين كائنات ص و SDL2 window/renderer
3. **SDL2** مشروط بـ `#ifdef SAD_UI_USE_SDL2` — يُفعَّل وقت البناء
4. **مكتبة ص** في `features/graphics/stdlib/رسومات/` تعمل فوق الدوال المدمجة (لا تستدعي SDL مباشرة)

### مسار الاستدعاء

```
كود ص: تشغيل_تطبيق(نص("مرحبا"))
    → builtin: run_app_fn (C++)
        → UIBridge::run(rootWidget, interpreter)
            → SDL_CreateWindow() + SDL_CreateRenderer()
            → حلقة الأحداث (SDL_PollEvent)
            → رسم العناصر
```

## ملاحظات عامة

- **`Value`** (`shared/types/include/value.h`) هو النوع الموحد — `std::variant` يحمل int, double, string, array, map, `shared_ptr<ObjectInstance>`, الخ.
- **`ObjectInstance`** يحمل `fields` كـ `std::unordered_map<std::string, Value>` + مؤشر لـ `ClassType`.
- **`ClassType`** يحمل الحقول والدوال والباني ومعلومات الوراثة.
- **هناك طريقتان لتمثيل الكائنات:** OBJECT الحقيقي (`shared_ptr<ObjectInstance>`) و MAP القديم بمفتاح `__class__` — كلاهما مدعوم للتوافق العكسي.
