> **التاريخ:** 2025  
> **الغرض:** تشخيص دقيق للمكونات المكررة في مشروع لغة ص مع خطة توحيد عملية  
> **المنهج:** فحص CMake files وتتبع الاستخدام الفعلي (من يربط ماذا)

---

## النتيجة العامة

| المكون المُدعى تكراره | الواقع | التصنيف |
|----------------------|--------|---------|
| `interpreter_new/` vs `interpreter/` | `interpreter/` **غير موجود** | ❌ لا تكرار — فقط لاحقة مضللة |

## القسم الأول: الآلات الافتراضية (VMs)

### VM1 — `vm/` (الجذر) ✅ نشطة

```
vm/
├─ CMakeLists.txt          → يُعرّف مكتبة sad_vm
├─ include/ (7 headers)
└─ src/ (4 .cpp, ~195 KB)
   ├─ sad_vm_opcodes.cpp
   ├─ sad_vm_compiler.cpp  (61 KB — AST → bytecode)
   ├─ sad_vm_executor.cpp  (75 KB — execution loop)
   └─ sad_jit.cpp          (41 KB — JIT tier)
```

**من يستخدمها:**
- `sad` (المفسر الرئيسي) ← في `cmake/executables.cmake`
- `test_vm_compiler_comprehensive`
- `test_jit_comprehensive`

**الحالة:** 🟢 **نشطة ومربوطة بالمفسر** — هذه هي الـ VM الرسمية.

---

### VM2 — `compiler_new/src/bytecode/` ⚠️ جزئية

```
compiler_new/src/bytecode/
├─ bytecode.cpp, opcodes.cpp, magic.cpp
├─ emitter.cpp, emitter_optimize.cpp
├─ encoder.cpp, decoder.cpp
├─ constant_pool.cpp, symbol_table.cpp
├─ validator.cpp, version.cpp
(11 ملفات، ~246 KB)
```

**من يستخدمها:**
- `compiler_new/CMakeLists.txt` يشمل 3 ملفات فقط: `emitter.cpp`, `bytecode.cpp`, `validator.cpp`
- `vm/CMakeLists.txt` يشمل `opcodes.cpp`
- **8 من 11 ملفاً غير مستخدمة** (`decoder.cpp`, `encoder.cpp`, `emitter_optimize.cpp`, `magic.cpp`, `constant_pool.cpp`, `symbol_table.cpp`, `version.cpp`, `bytecode.cpp` جزئياً)

**الحالة:** 🟡 **نصف ميت** — المشروع يعرف أن Stack-VM مستقل ولا يستخدم معظمه.

---

### VM3 — `runtime_new/src/vm/` ❌ ميتة كلياً

```
runtime_new/src/vm/
├─ vm.cpp           (31 KB)
├─ vm_helpers.cpp   (28 KB)
├─ vm_opcodes.cpp   (20 KB)
└─ vm_gc.cpp        (23 KB — generational tri-color GC)
```

**من يستخدمها:**
- هدف `sad_rt_vm` مُعرَّف في `runtime_new/CMakeLists.txt`
- **لا يوجد `target_link_libraries` لأي هدف آخر مع `sad_rt_vm`**

**الحالة:** 🔴 **كود ميت تماماً** — ~100 KB من الكود يُترجم في البناء ولكن لا يُستدعى من أي مكان.

## القسم الثاني: Garbage Collectors

### GC1 — `runtime_new/src/memory/gc.cpp` ❌ ميت

- هدف `sad_rt_memory` مُعرَّف في `runtime_new/CMakeLists.txt`
- **لا يوجد `target_link_libraries` مع `sad_rt_memory`**
- **كود ميت**

### GC2 — `runtime_new/src/vm/vm_gc.cpp` ❌ ميت

- داخل `sad_rt_vm` الميت أصلاً
- **كود ميت**

### الحقيقة المهمة

**المفسر الحقيقي في `interpreter_new/` لا يستخدم أياً من هذين الـ GCs!** يعتمد على `std::shared_ptr` للكائنات (refcount ضمني). لا يوجد GC **يعمل فعلاً** في المشروع.

| القرار | المنطق |
|---------|---------|
| **احذف الاثنين** | مجرد تجارب تصميمية بلا دمج |
| أو | أبقِ واحداً واربطه فعلياً بـ VM1 إذا كان GC هدفاً مستقبلياً |

## القسم الثالث: WASM — 14 ملف في 4 مسارات!

### الخريطة الحقيقية

#### الموقع 1: `compiler_new/src/backend/` — backend LLVM
```
wasm_codegen.cpp         (16 KB)   — مولّد LLVM IR → WASM
wasm_ast_visitor.cpp     (29 KB)   — زائر AST
wasm_bindgen.cpp         (18 KB)   — ربط Rust-style
wasm_optimizer.cpp       (20 KB)   — تحسينات WASM
```

#### الموقع 2: `compiler_new/src/backend/wasm_direct/` — مولّد مباشر
```

wasm_emitter.cpp           (23 KB)

```

#### الموقع 3: `compiler_new/src/backend/targets/`
```

```

#### الموقع 4: `compiler_new/src/targets/`
```
wasm.cpp                  (23 KB)   — ❓ مكرر مع wasm32_target.cpp؟
```

#### الموقع 5: `tools/wasm/`
```
sad_wasm.cpp              (9 KB)    — مفسر متصفح (Emscripten)
wasm_builtins.cpp         (8 KB)    — Builtins للمتصفح
```

#### الموقع 6: `tests/integration/web/test_wasm_output.cpp` — اختبار

### التشخيص

**3 مسارات توليد مختلفة لنفس الهدف (WASM):**
1. LLVM → WASM عبر `backend/wasm_codegen.cpp`
2. AST → WASM مباشرة عبر `backend/wasm_direct/`
3. ❓ `targets/wasm.cpp` (غير واضح علاقته بالاثنين)

**القرار المقترح:**
- اختر مساراً واحداً رسمياً (LLVM أو مباشر)
- ضع الآخر في `archived/` مع تعليق يوضح سبب الإبقاء
- وحّد `targets/wasm.cpp` مع `backend/targets/wasm32_target.cpp` أو احذف أحدهما

## القسم الخامس: خطة التوحيد المقترحة

### الإصلاح 1 — إزالة اللاحقة `_new` المضللة (صغير، يوم عمل)
- `interpreter_new/` → `interpreter/`
- `runtime_new/` → `runtime/`
- `compiler_new/` → `compiler/`
- تحديث جميع CMake files وincludes
- تحديث الوثائق

**التأثير:** زيادة الوضوح للمساهمين الجدد. **المخاطرة:** صغيرة (تغيير أسماء فقط).

### الإصلاح 2 — أرشفة `runtime/` الميت (متوسط، يومان)
خيار أ: **الحذف النهائي**
- حذف جميع الأهداف غير المربوطة من `runtime_new/CMakeLists.txt`
- حذف الملفات المقابلة

خيار ب: **الأرشفة**
- نقل `runtime_new/src/vm/`, `runtime_new/src/memory/`, `runtime_new/src/abi/`, `runtime_new/src/ffi/`, `runtime_new/src/exception/`, `runtime_new/src/sandbox/`, `runtime_new/src/thread/`, `runtime_new/src/panic/`, `runtime_new/src/ui/`, `runtime_new/src/freestanding/` إلى `archived/runtime_experiments/`
- إبقاء `runtime_new/src/` (أو ما يحتوي `sad_rt_runtime` الحقيقي)
- توثيق السبب في `archived/README.md`

**التوصية:** خيار ب — أرشفة. الكود ليس سيئاً، فقط غير مدمج. يمكن إحياؤه لاحقاً.

### الإصلاح 3 — تقليص `compiler_new/src/bytecode/` (صغير، يوم)
- احتفظ فقط بـ `emitter.cpp`, `bytecode.cpp`, `validator.cpp`, `opcodes.cpp` (المستخدمة)
- أرشف الـ 7 المتبقية (`decoder.cpp`, `encoder.cpp`, `emitter_optimize.cpp`, `magic.cpp`, `constant_pool.cpp`, `symbol_table.cpp`, `version.cpp`)

### الإصلاح 4 — توحيد WASM (كبير، أسبوع)
القرار الاستراتيجي يحتاج:
1. هل نريد مسار LLVM→WASM أم AST→WASM المباشر؟
2. الخيار الأفضل: **اختر LLVM→WASM** (`wasm_codegen.cpp`) — لأن LLVM يعالج التحسينات والسجلات
3. أرشف `wasm_direct/` بالكامل (نحو 133 KB)
4. احذف التكرار بين `targets/wasm.cpp` و `backend/targets/wasm32_target.cpp`

### الإصلاح 5 — حذف الـ GCs الميتة (صغير، ساعتان)
- احذف `runtime_new/src/memory/gc.cpp` + header
- احذف `runtime_new/src/vm/vm_gc.cpp` + header (مع VM3)
- ملاحظة في `docs/`: "لغة ص لا تستخدم GC حالياً — تعتمد على ملكية + refcount"

## الخلاصة الصادقة

**"التكرار" في المشروع أسوأ مما يبدو من جانب، وأفضل من جانب آخر:**

### الجانب الأفضل:
- لا توجد مجلدات قديمة مهجورة (`interpreter/`, `runtime/`, `compiler/` لا توجد)
- المفسر الرئيسي (VM1) نشط ويعمل

### الجانب الأسوأ:
- **~27 ملف في `runtime_new/` كود ميت** (~300 KB)
- **14 ملف WASM موزع على 6 مسارات** — مقلق جداً
- **GCs تجريبية لا تستخدم أبداً**
- **نصف bytecode/ غير مستخدم**

### التوصية النهائية:
**ابدأ بالإصلاح 2 (أرشفة runtime_new الميت)** — المكسب فوري والمخاطر منخفضة. الباقي يمكن جدولته تدريجياً.
