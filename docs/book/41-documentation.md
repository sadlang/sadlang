# الفصل الحادي والأربعون: التوثيق والتعليق (Documentation Practices)

## مقدمة نظرية

**التوثيق الجيد** هو الذي يُجيب أسئلة المستخدم والمطور بدون أن يضطر لقراءة الكود. الكود يُخبرك _كيف_، التوثيق يُخبرك _لماذا_.

| نوع التوثيق | الجمهور | المكان |
|------------|---------|--------|
| **تعليق سطري** | المطور | داخل الكود |
| **تعليق توثيقي** | مستخدم API | قبل الدالة/الصنف |
| **ملف README** | أي شخص | جذر المشروع |
| **دليل المستخدم** | المستخدم النهائي | مجلد docs/ |
| **مرجع API** | المطور | مُولّد تلقائياً |

## 1. تعليقات الكود

### تعليقات جيدة (لماذا)

```sad
# التعليقات الجيدة تشرح السبب، لا الكيف

# ✗ تعليق سيء — يكرر ما يقوله الكود
متغير عداد = 0   # تعيين العداد للصفر

# ✓ تعليق جيد — يشرح السبب
متغير عداد = 0   # يبدأ من صفر لأن المصفوفة تبدأ من 0

# ✗ تعليق سيء
# التحقق من أن العمر أكبر من 18
إذا (العمر > 18)

# ✓ تعليق جيد
# السن القانوني للتسجيل حسب نظام الجهة المختصة
إذا (العمر > 18)
```

### تعليقات الكتلة

```sad
#*
   خوارزمية ترتيب الدمج (Merge Sort)
   التعقيد: O(n log n) في كل الحالات
   الذاكرة: O(n) إضافية

   اخترنا هذه الخوارزمية بدلاً من الترتيب السريع
   لأن البيانات تأتي شبه مرتبة من قاعدة البيانات،
   والدمج يُحافظ على ترتيب العناصر المتساوية (stable)
*#
دالة ترتيب_دمج(قائمة)
   # ...
نهاية
```

## 2. التعليقات التوثيقية

لغة ص تدعم تعليقات توثيقية خاصة بصيغة `##` أو `#** ... **#`:

```sad
## تحسب المسافة بين نقطتين في المستوى
## المعاملات:
##   س1، ص1 — إحداثيات النقطة الأولى
##   س2، ص2 — إحداثيات النقطة الثانية
## الإرجاع: المسافة (عشري)
## مثال:
##   مسافة(0، 0، 3، 4)  → 5.0
دالة مسافة(س1، ص1، س2، ص2)
   متغير فرق_س = س2 - س1
   متغير فرق_ص = ص2 - ص1
   ارجع جذر(فرق_س ** 2 + فرق_ص ** 2)
نهاية

#**
   صنف يمثل حساباً بنكياً

   يدعم الإيداع والسحب مع حماية من السحب الزائد.
   الرصيد لا يمكن أن يصبح سالباً.

   مثال:
      متغير حساب = جديد حساب_بنكي("أحمد"، 1000)
      حساب.أودع(500)
      حساب.اسحب(200)
      اطبع_سطر(حساب.الرصيد())  # 1300
**#
صنف حساب_بنكي
   خاص متغير _الاسم
   خاص متغير _الرصيد

   ## ينشئ حساباً بنكياً جديداً
   ## المعاملات:
   ##   اسم — اسم صاحب الحساب
   ##   رصيد — الرصيد الابتدائي (افتراضي: 0)
   باني(اسم، رصيد)
      _الاسم = اسم
      _الرصيد = رصيد
   نهاية

   ## يُضيف مبلغاً إلى الرصيد
   ## يرمي خطأ إذا كان المبلغ سالباً
   دالة أودع(مبلغ)
      إذا (مبلغ <= 0)
         ارمي "المبلغ يجب أن يكون موجباً"
      نهاية
      _الرصيد = _الرصيد + مبلغ
   نهاية

   ## يسحب مبلغاً من الرصيد
   ## يرمي خطأ إذا كان الرصيد غير كافٍ
   دالة اسحب(مبلغ)
      إذا (مبلغ > _الرصيد)
         ارمي "رصيد غير كافٍ"
      نهاية
      _الرصيد = _الرصيد - مبلغ
   نهاية

   دالة الرصيد()
      ارجع _الرصيد
   نهاية
نهاية
```

## 3. ملف README

```markdown
# 📊 نظام إدارة المكتبة

نظام متكامل لإدارة الكتب والأعضاء والاستعارات، مكتوب بلغة ص.

## المتطلبات
- لغة ص v1.0+
- sad-pkg (مدير الحزم)

## التثبيت
```
sad-pkg تثبيت
```

## التشغيل
```
sad رئيسي.ص
```

## الميزات
- ✅ إضافة وحذف الكتب
- ✅ تسجيل الأعضاء
- ✅ نظام استعارة وإرجاع
- ✅ بحث متقدم
- 🔄 تقارير إحصائية (قيد التطوير)

## بنية المشروع
```
مكتبة/
├── رئيسي.ص           # نقطة الدخول
├── نماذج/
│   ├── كتاب.ص        # صنف الكتاب
│   └── عضو.ص         # صنف العضو
├── خدمات/
│   └── استعارة.ص      # منطق الاستعارة
└── اختبارات/
    └── اختبار_كتاب.ص  # اختبارات
```

## المساهمة
اقرأ CONTRIBUTING.md للتفاصيل.

## الرخصة
MIT
```

## 4. أنماط التوثيق

### توثيق الوحدات

```sad
#**
   وحدة: رياضيات/هندسة

   تحتوي دوال حساب المساحات والمحيطات
   للأشكال الهندسية الأساسية.

   الأشكال المدعومة:
   - الدائرة (مساحة، محيط)
   - المستطيل (مساحة، محيط)
   - المثلث (مساحة)

   الإصدار: 1.2.0
   المؤلف: فريق الرياضيات
**#
```

### توثيق التعدادات

```sad
## أنواع أشكال الطلب في النظام
## كل حالة تمثل مرحلة مختلفة في دورة حياة الطلب
تعداد حالة_الطلب
   ## تم إنشاء الطلب ولم يُعالج بعد
   جديد

   ## جاري المعالجة من قبل الموظف
   قيد_المعالجة

   ## تم شحن الطلب
   مشحون

   ## تم التوصيل للعميل
   مُكتمل

   ## ألغاه العميل أو النظام
   ملغي
نهاية
```

## 5. قواعد التوثيق الذهبية

| القاعدة | المثال |
|---------|--------|
| وثّق **لماذا** لا **كيف** | `# حد 100 بسبب قيود API` |
| وثّق **العقد** لا **التنفيذ** | المعاملات، القيم المرجعة، الأخطاء |
| حدّث التوثيق مع الكود | توثيق قديم أسوأ من بدونه |
| استخدم أمثلة عملية | مثال واحد > 100 سطر شرح |
| اكتب للقارئ لا لنفسك | افترض القارئ لا يعرف السياق |

## خلاصة

| الأداة | الاستخدام |
|--------|-----------|
| `#` | تعليق سطري — لماذا فعلت هذا |
| `#* *#` | تعليق كتلة — خوارزمية/سياق |
| `##` | توثيق API — معاملات وأمثلة |
| `#** **#` | توثيق وحدة/صنف كامل |
| README.md | نظرة عامة + تعليمات |

## تمارين

1. وثّق 3 دوال من مشروع سابق باستخدام `##` مع أمثلة.
2. اكتب ملف README.md كاملاً لمشروع آلة حاسبة.
3. حوّل كوداً بدون تعليقات إلى كود موثق جيداً.
4. اكتب دليل مستخدم (5 صفحات) لتطبيق قائمة مهام.
