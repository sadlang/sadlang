# الفصل الثاني والأربعون: المساهمة في المشاريع مفتوحة المصدر (Contributing to OSS)

## مقدمة نظرية

**المصدر المفتوح** (Open Source) يعني أن كود البرنامج متاح للجميع للقراءة والتعديل والمشاركة. المساهمة فيه تُحسّن مهاراتك وتبني سمعتك وتُفيد المجتمع.

| المفهوم | الوصف |
|---------|-------|
| **المستودع** (Repository) | مكان تخزين الكود (GitHub، GitLab) |
| **الإصدار** (Fork) | نسخة خاصة بك من المشروع |
| **طلب دمج** (Pull Request) | طلب لدمج تعديلاتك في المشروع |
| **قضية** (Issue) | بلاغ عن خطأ أو طلب ميزة |
| **الرخصة** (License) | شروط استخدام الكود |

---

## 1. البدء: أول مساهمة

### الخطوات الأساسية

```
① اختر مشروعاً                    ← ابحث عن "good first issue"
② اقرأ CONTRIBUTING.md            ← قواعد المشروع
③ انسخ (Fork) المستودع             ← نسخة خاصة بك
④ استنسخ (Clone) محلياً            ← نسخة على جهازك
⑤ أنشئ فرعاً (Branch)             ← فرع لتعديلاتك
⑥ عدّل واختبر                     ← الكود والاختبارات
⑦ أرسل (Commit + Push)            ← ارفع التعديلات
⑧ افتح طلب دمج (PR)              ← اطلب المراجعة
⑨ عالج الملاحظات                  ← حسّن حسب المراجعة
⑩ يُدمج!                         ← مبروك 🎉
```

## 2. المساهمة في لغة ص

لغة ص مشروع مفتوح المصدر. إليك كيف تساهم:

### بنية المشروع

```

├── shared/            # المحلل المعجمي والنحوي والأنواع
├── interpreter_new/   # المفسر الشجري
├── compiler_new/      # المترجم (SIR → LLVM)
├── tools/             # LSP، المنسق، مدير الحزم
├── stdlib/            # المكتبة القياسية
├── tests/             # الاختبارات
├── docs/              # التوثيق
└── examples/          # أمثلة
```

### أنواع المساهمات


## 3. كتابة طلب دمج جيد

### عنوان واضح

```
✗ "إصلاح خطأ"
✗ "تحديث"
✓ "إصلاح خطأ في المحلل النحوي: عدم التعرف على 'طابق' بدون أقواس"
✓ "إضافة دعم العمليات البتية (AND, OR, XOR) في المفسر"
```

### وصف شامل

```markdown
## الوصف
إصلاح خطأ في المحلل النحوي (#234) حيث كانت كلمة `طابق`
تتطلب أقواساً حول التعبير، رغم أن المواصفات تسمح بدونها.

## التغييرات
- `shared/parser/src/parser_match.cpp`: إزالة فحص القوس الإجباري
- `tests/comprehensive/test_match.ص`: إضافة 3 حالات اختبار

## الاختبار
```
cmake --build build --config Debug --target comprehensive_tests
ctest --test-dir build -R Comprehensive
```
جميع الاختبارات تمر (903/903).

## لقطات الشاشة
(إن وجد)
```

## 4. مراجعة الكود (Code Review)

### كمُراجع

```
✓ افهم السياق أولاً — اقرأ Issue المرتبطة
✓ جرّب الكود محلياً قبل الموافقة
✓ اقترح تحسينات بلطف: "ماذا لو..."، "هل فكرت في..."
✓ ميّز بين الضروري والاختياري
✓ وافق عندما يكون الكود جيداً — لا تنتظر الكمال

✗ لا تهاجم الشخص — انقد الكود
✗ لا تطلب تغييرات أسلوبية بلا سبب تقني
✗ لا تؤخر المراجعة — الوقت ثمين
```

### كمساهم

```
✓ اقبل الملاحظات بصدر رحب
✓ اسأل إذا لم تفهم الملاحظة
✓ عدّل بسرعة — المراجع ينتظر
✓ اشكر المراجع على وقته

✗ لا تجادل في الأسلوب — اتبع معايير المشروع
✗ لا تأخذ الملاحظات شخصياً
```

## 5. إنشاء مشروع مفتوح المصدر

```markdown
# الملفات الضرورية:

README.md              # ما هو المشروع؟ كيف أستخدمه؟
LICENSE                # ما الرخصة؟ (MIT, Apache, GPL)
CONTRIBUTING.md        # كيف أساهم؟
CODE_OF_CONDUCT.md     # قواعد السلوك
CHANGELOG.md           # سجل التغييرات
.gitignore             # ملفات لا تُرفع (build/, .env)
```

### ملف CONTRIBUTING.md نموذجي

```markdown
# المساهمة في [اسم المشروع]

## كيف تساهم
1. انسخ (Fork) المستودع
2. أنشئ فرعاً: `git checkout -b ميزة/وصف-قصير`
3. طبّق تعديلاتك مع اختبارات
4. تأكد من مرور الاختبارات: `sad اختبارات/`
5. افتح طلب دمج

## معايير الكود
- استخدم `sad-fmt` لتنسيق الكود
- كل دالة عامة يجب أن توثّق بـ `##`
- كل ميزة جديدة تحتاج اختبار

## الإبلاغ عن الأخطاء
استخدم قالب Issue واملأ:
- الإصدار المستخدم
- خطوات إعادة الإنتاج
- السلوك المتوقع vs الفعلي
```

## 6. الرخص الشائعة

| الرخصة | الميزة | القيد |
|--------|--------|-------|
| **MIT** | بسيطة جداً، افعل ما تشاء | اذكر المؤلف |
| **Apache 2.0** | مثل MIT + حماية براءات | اذكر التغييرات |
| **GPL v3** | مفتوح دائماً | المشتق يجب أن يكون GPL |
| **BSD** | مشابهة لـ MIT | اذكر المؤلف |
| **Unlicense** | ملكية عامة | بدون قيود |

## خلاصة

| الخطوة | النصيحة |
|--------|---------|
| الأولى | ابدأ بتوثيق أو إصلاح صغير |
| التواصل | اسأل قبل أن تكتب كوداً كبيراً |
| الجودة | اختبر، نسّق، وثّق |
| المراجعة | اقبل الملاحظات واتعلم منها |
| الاستمرار | ساهم بانتظام وابنِ سمعتك |

## تمارين

1. ابحث عن 3 مشاريع مفتوحة بـ "good first issue" واختر واحداً.
2. اكتب ملف CONTRIBUTING.md لمشروع شخصي.
3. افتح Issue في مستودع لغة ص بتحسين تقترحه.
4. ساهم بإصلاح أو تحسين في أي مشروع مفتوح وشارك رابط PR.
