# ❌ [مُبطَل] لا توجد علة استيراد — كان تشخيصاً خاطئاً

## التصحيح النهائي (2026-06-11، GR-01)
**الاستيراد يعمل تماماً. لا علة إطلاقاً.** التتبّع أثبت:
```
[DBG-IMPORT] fullModuleName='رياضيات' isBuiltin=1
[DBG-IMPORT] loadModule returned=1      ← نجح التحميل
لوغ(2.718) → 0.999896                    ← الدالة تعمل!
```
**السبب الجذري للوهم:** اختباراتي استخدمت **أسماء دوال خاطئة** (`لوغاريتم` بدل الاسم المُسجَّل
`لوغ` = `Bm::LOG`؛ كذلك `استيفاء_خطي`/`مجموع`). الأسماء الصحيحة (القصيرة الموحَّدة) تعمل بعد
الاستيراد. هذا **التشخيص الخاطئ الثاني** بعد «علة arity» (التي كانت module-gating سليماً).

**الإصلاح الحقيقي** الذي جعل الدوال المُحوّلة لـctx قابلة للإرسال = `hasNativeImplementation`
(PR #31). مع الأسماء الصحيحة + الاستيراد، **كل شيء يعمل**.

## [أرشيف] الادّعاء الخاطئ الأصلي
> ~~`استورد <وحدة-مضمنة>` لا يُحمّل الوحدة~~ — **خاطئ، أُبطِل أعلاه.**

## الملخّص
استيراد وحدة مضمنة مُبوّبة (مثل `استورد رياضيات`) **لا يُسجّل دوالها فعلياً**، فتبقى كل دوال
الوحدة (math/maps/kernel/assertions/async...) **غير قابلة للوصول** — تُرفع `SEM004` عند استدعائها.

## إعادة الإنتاج (قاطعة)
```sad
استورد رياضيات
اطبع_سطر(استيفاء_خطي(0، 10، 0.5))
```
**المتوقَّع:** يطبع `5`.
**الفعلي:**
```
❌ error [SEM004]: الدالة 'استيفاء_خطي' غير معرفة بعدد معاملات 3
    💡 جرّب: استورد رياضيات        ← يقترح الاستيراد الذي نُفِّذ بالفعل!
```
التلميح يقترح **نفس الاستيراد المُنفَّذ** → دليل قاطع أن الاستيراد لم يُحمّل الوحدة.

## النطاق / الأثر
- **كل** الدوال المُبوّبة عبر `registerModule` غير قابلة للوصول للمستخدم.
- الصيغة موثّقة وصحيحة (`builtin_registry.cpp:855`: «استورد رياضيات — دوال رياضية»).

## الآلية (من تتبّع الكود)
1. `استورد X` → `statement_executor_modules.cpp:384` → `isBuiltinModule(getFullModuleName())`.
2. إن طابق → `loadModule(name)` (`:387`) → `registrar(*interpreter_)` (`builtin_registry.cpp:115`).
3. `registerBuiltinModules()` يُستدعى (`:865`) و`setInterpreter` يُضبَط (`:864`) → modules_ مُعبّأة.

## الجذر المرجَّح (يحتاج تأكيداً)
أحد:
- **تباين الاسم:** `node.getFullModuleName()` ≠ الاسم المُسجَّل «رياضيات» (ترميز/مسار/تطبيع) →
  `isBuiltinModule` يُرجع false → يسقط لمسار وحدة-ملف صامت (لا خطأ، لا تحميل).
- **singleton/دورة حياة:** `interpreter_` على `BuiltinModuleRegistry::getInstance()` يشير لمفسّر
  غير المُستخدَم وقت الاستدعاء → `loadModule` يُرجع false (`:101` `!interpreter_`).

## خطوات الإصلاح المقترحة
1. أضِف أثراً (log) في `loadModule` و`isBuiltinModule` لمعرفة قيمة الاسم الفعلية ونتيجة المطابقة.
2. قارن `getFullModuleName()` بالاسم المُسجَّل بايتاً ببايت.
3. تحقّق من تطابق singleton + توقيت `setInterpreter` مقابل وقت الاستيراد.

## ملاحظة (العلاقة بـ EM-CPP)
ترحيل أخطاء الدوال المضمنة (EM-CPP، PRs #19-#24) **صحيح بنيوياً** ومُتحقَّق آلياً، لكن حراساته
على كود **غير قابل للوصول حالياً** بسبب هذه العلة. إصلاح هذه العلة يجعل الحراسات (و`[RUN037]`
باسم الدالة) قابلة للوصول والاختبار السلوكي.
