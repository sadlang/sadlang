7. **التوافق الخلفي** (CW-24): إضافة enum/token/AST مسموحة، تغيير معنى موجود ممنوع.

## 2. تفصيل البنود

### P0 — اتّساق الأرقام والتوثيق (🔴 مصداقية، ساعة)
- **الكود**: صحّح تعليق الترويسة [sad_type_system.h:16,55-56](../../../../shared/types/include/sad_type_system.h#L55) من «34 قيمة» إلى «49 قيمة».
- **التوثيق**: تمّ تصحيح [ARCHITECTURE_TYPE_SYSTEM.md](./ARCHITECTURE_TYPE_SYSTEM.md) (هذه الجولة)؛ زامِن النسخة المكرّرة `docs/توثيقات_تطوير_اللغة/توثيقات_الانظمة/`.
- **قبول**: لا رقم متضارب بين الكود والوثيقتين.

### P1 — Null متمايز عن Void (🔴، 1–2 يوم)
- **الوضع**: لا قيمة `SadTypeKind::Null`؛ `LITERAL_NULL → Value()` = Void ([expression_evaluator_core.cpp:278](../../../../interpreter/src/visitors/expression_evaluator_core.cpp#L278)).
- **قرار معماري مطلوب**: هل `لاشيء` نوع مستقلّ `Null` أم حالة من `Optional`؟ (الموصى: `Null` بدائي مستقلّ يتوافق مع نظام Optional لاحقًا).
- **الخطوات**:
  1. أضف `Null` إلى enum (يصير 50 قيمة) + معالجته في `SadPrimitiveType`/السجلّ.
  2. `getTypeName()` يُرجع «لاشيء» لـ Null (راجع `value.cpp:1462`).
  3. حدّث جسر التحويل + التأكيدات في `builtin_module_assertions.cpp:533`.
  4. اختبار: `نوع(لاشيء)` == «لاشيء»، و`لاشيء == لاشيء` صحيح، وفصل `لاشيء` عن قيمة فارغة.
- **قبول**: إثبات حيّ `نوع(لاشيء)`→«لاشيء»؛ اختبارات Null تمرّ.

### P2 — توحيد المدقّق الدلالي (🟠، 3–5 أيام)
- **الوضع**: [type_checker.cpp](../../../../shared/semantic/src/semantic/type_checker.cpp) يستعمل `DataType` ×18 مقابل `SadTypeKind` ×3.
- **الخطوات**: رحّل مواضع `DataType` تدريجيًّا إلى `SadTypeKind` عبر الجسر، موضعًا بموضع مع اختبار بعد كل دفعة (لا دفعة واحدة كبيرة).
- **قبول**: نسبة `SadTypeKind` ترتفع، اختبارات الدلالات خضراء، لا انحدار سلوكي.

### P2.5 — ترحيل `DataType` ثم **حذف دوال الجسر** (🔴 معماري) — مُقسَّمة a/b

> **تقسيم بعد نقد أميليا (ع-6):** القصّة الواحدة (23 ملفًّا + حذف + إثبات حيّ) غير واقعية كـL واحد، فقُسِّمت إلى:
> - **P2.5a** (ترحيل الـAST/المحلّل، L) → [S-TS-P2.5a](../stories/STORY-TS-P2.5a-migrate-ast-datatype.md)
> - **P2.5b** (حذف دوال DataType من الجسر، M) → [S-TS-P2.5b](../stories/STORY-TS-P2.5b-delete-bridge.md)

**لماذا هذا البند هو جوهر «الاستبدال الكامل»:**
الجسر (`type_bridge`) ليس ضرورة معمارية — هو سقالة انتقالية تربط النواة الجديدة (`SadTypeKind`) بـAST قديم يخزّن النوع كـ`DataType`. فقدانه للأنواع المتقدّمة (`SadTypeKind`→**ValueType**: `Optional → Void`, `Result → Void` في [type_bridge.cpp:118-121](../../../../shared/types/src/type_bridge.cpp#L118)) ليس عِلّة تُرقَّع بل **عَرَض**: النوع الهدف أفقر تعبيرًا. الحلّ: إكمال استبدال `DataType` ثم حذف **دوال DataType** من الجسر.

**تصحيح مهمّ (ع-6): الجسر ليس كله DataType.** `type_bridge.cpp` ثلاثة أقسام:
- **DataType (يُحذف في P2.5b):** `toDataType:188`, `fromDataType:235`, `sadTypeToDataType:290`, `sadTypeFromDataType:299`.
- **ValueType (يبقى):** `toValueType:55`, `fromValueType:160`, `sadTypeToValueType:277` — مستهلَك في الـruntime.
- **runtime (يبقى):** `inferSadType:308`, `isValueCompatible:379`.

**الوضع الفعلي:**
- `enum class DataType` في [data_types.h:26](../../../../shared/types/include/data_types.h#L26).
- مغروس في عقد الـAST: [ast_node.h:191](../../../../shared/ast/include/ast_node.h#L191) `getDataType()`، و[declarations.h:57,237,280,716,911,964](../../../../shared/ast/include/declarations.h#L57).
- مستعمَل في **23 ملفًّا** (12 ast + 8 parser + 3 semantic) — تحقّق `grep -rl`. (أميليا قالت 24؛ الفعلي 23.)

**ترتيب مع P3/P4**: نفّذ P2.5a→P2.5b **قبل** P3/P4 — فبعد حذف دوال DataType تُمرَّر الأنواع المتقدّمة عبر الـAST دون أن تُسقَط إلى Void، فيصبح توصيلها (P4) وتطبيق Result (P3) ذا معنى.

**قبول (مُوزَّع على a/b):**
- (a) `grep -c DataType` في `shared/ast`+`shared/parser` = 0.
- (b) دوال DataType الأربع محذوفة من الجسر؛ أقسام ValueType/runtime **سليمة**؛ `data_types.h` محذوف إن صار بلا مستهلك.
- بناء `sad-run` + المترجم = 0، كل الاختبارات خضراء، لا انحدار سلوكي.
- إثبات حيّ: نوع متقدّم (Optional) يعبر المصدر→AST→تنفيذ دون فقدان هويّته.

### P3 — Result: من enum ميت إلى تطبيق (🟠، 2–4 أيام)
- **الوضع**: `Result` في enum بلا `SadResultType` ولا `makeResult`؛ الجسر يُسقطه إلى Void.
- **الخطوات**: أنشئ `SadResultType` (على نسق `SadOptionalType`) + `makeResult` في السجلّ + منطق `isAssignableTo` + توصيل دلالي.
- **قبول**: بناء + اختبار وحدة لـ`Result<T,E>` (نجاح/خطأ).

### P4 — توصيل Optional/Future/Generator (🟡، 5–8 أيام)
- **الوضع**: أصناف موجودة (`SadOptionalType`/`SadFutureType`/`SadGeneratorType`) + دوال `make*` لكن **بلا استخدام** في المفسّر/الدلالات/codegen.
- **الخطوات لكل نوع**: بناؤه عند نقطة الإنشاء في المفسّر + تحقّق دلالي + (للمترجم) ربط codegen.
- **قبول**: كل نوع يُبنى ويُتحقّق منه ويُختبر حيًّا.

### P5 — suite اختبارات نوعية حقيقي (🟠، 2–3 أيام)
- **الوضع**: `tests/safety/` غير موجود؛ ملف وحيد مؤرشف `tests/_archive/safety/type_safety_regression.ص`.
- **الخطوات**: أحيِ الملف المؤرشف ضمن بنية الطبقات الثلاث الحالية (`tests/unit` أو `tests/behavior`)، وسّعه لتغطية البدائيات + Null + كل نوع متقدّم يُكمَل، واربطه بـCI.
- **قبول**: suite مُشغَّل في CI بأرقام حقيقية قابلة للاستشهاد.

### P6 — تدقيق وتصنيف enum (🟢، 1 يوم)
> **تصحيح بعد نقد أميليا (ع-2):** القيم التي ظُنّت «ميتة» **مُستهلَكة فعليًّا**: `Vector` مُطبَّق SIMD (22 موضعًا: `compiler/.../builtins_simd.cpp`, `mem_store.cpp:542`)؛ `Comprehension` (7)، `Color`/`Widget`/`Window`/`Event` (4 لكلٍّ) لها مستهلكون. لا قيمة ميتة مؤكّدة حاليًّا.
- **النطاق المصحّح**: تدقيق توثيقي — إثبات استهلاك كل قيمة، ووسم غير المكتمل `// مخطّط — غير مطبّق` **دون إزالة** ما لم يُثبَت صفر مستهلك.
- **قبول**: كل قيمة مصنّفة بالدليل؛ لا إزالة بلا إثبات موت + بناء أخضر؛ جدول التصنيف في المعمارية محدّث.

### P7 — interning للمركّبة (🟢، 2–3 أيام)
- **الوضع**: المركّبة `make_shared` جديدة كل مرّة → مقارنة المؤشر `==` غير صحيحة.
- **الخطوات**: cache بنيوي في `SadTypeRegistry` للأنواع المركّبة (مفتاح = توقيع بنيوي)، أو استبدال مقارنة المؤشر بمقارنة بنيوية موثّقة.
- **قبول**: `getArrayType(int) == getArrayType(int)` صحيح، اختبار يثبته.
