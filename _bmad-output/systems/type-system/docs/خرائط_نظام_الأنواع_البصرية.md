# خرائط نظام الأنواع البصرية — لغة ص

> **الغرض:** فهمٌ كاملٌ لنظام الأنواع الحاليّ ومساره عبر الكود، بمخططات بصرية غنيّة.
> كل مخطط يصف **الواقع الموجود** كما هو في الكود. (Mermaid — يُعرَض في VS Code/GitHub.)

---

## 1. الصورة الكبرى: من مصدر الحقيقة إلى المحرّكين

`SadTypeKind` يُولَّد من `types.yaml` ويُستهلَك في المفسّر **والمترجم** معًا — مصدرٌ واحد.

```mermaid
flowchart TD
    YAML["📄 language-truth/types.yaml<br/>(مصدر الحقيقة: kind, word, typeof_ar, category)"]
    GEN["⚙️ scripts/codegen/gen_types.py"]
    HDR["🧬 shared/types/generated/sad_type_kind_generated.h<br/>enum SadTypeKind (52 قيمة) + sadTypeKindArabicName()"]
    API["🧩 shared/types/include/sad_type_system.h<br/>SadType · SadTypeRegistry · isAssignableTo · make*"]
    VAL["📦 shared/types/Value<br/>type_ + sadType_"]

    YAML -->|"توليد وقت البناء"| GEN --> HDR
    HDR --> API
    API --> VAL

    VAL --> INT["🌳 المفسّر (sad-run)<br/>تنفيذ فوري"]
    VAL --> COMP["🏭 المترجم (sadc)<br/>SIR → LLVM IR → تنفيذي"]

    style YAML fill:#fde68a,stroke:#b45309,color:#000
    style HDR fill:#bbf7d0,stroke:#15803d,color:#000
    style INT fill:#bfdbfe,stroke:#1d4ed8,color:#000
    style COMP fill:#ddd6fe,stroke:#6d28d9,color:#000
```

> 🔑 لإضافة نوع: عدّل `types.yaml` ثم أعد التوليد. الملفات تحت `generated/` لا تُحرَّر يدويًّا.

## 2. مسار الكود: من نصّ `.ص` إلى التنفيذ

أين «يعيش» النوع في كل مرحلة من خط الأنابيب:

```mermaid
flowchart LR
    SRC["📜 مصدر .ص"] --> LEX["🔤 LexerCore<br/>Token + Position"]
    LEX --> PARSE["🌲 ParserCore"]
    PARSE --> AST["🧱 AST<br/>كل عقدة: getTypeKind() → SadTypeKind"]

    AST --> INT["🌳 InterpreterCore"]
    AST --> SIRB["🏗️ SIRBuilder"]

    subgraph المفسّر [" المفسّر — تنفيذ فوري "]
        INT --> VALR["📦 Value<br/>type_ + sadType_"]
        VALR --> EXEC["▶️ تنفيذ + نوع()"]
    end

    subgraph المترجم [" المترجم — توليد تنفيذيّ "]
        SIRB --> OPT["🔧 SIROptimizer"]
        OPT --> LLVM["⚙️ LLVMCodeGen<br/>mapSIRType(SadTypeKind) → LLVM type"]
        LLVM --> EXE["📦 تنفيذيّ"]
    end

    style SRC fill:#fef3c7,stroke:#b45309,color:#000
    style AST fill:#bbf7d0,stroke:#15803d,color:#000
    style VALR fill:#bfdbfe,stroke:#1d4ed8,color:#000
    style LLVM fill:#ddd6fe,stroke:#6d28d9,color:#000
```

> المحرّكان يقرآن **نفس** `SadTypeKind`، فيتطابق سلوك الأنواع (مثل `نوع()`) بينهما.

## 3. القيمة `Value`: تمثيلان للنوع

`Value` يحمل تمثيلًا مبسَّطًا لوقت التشغيل (`type_`) وتمثيلًا غنيًّا موحَّدًا (`sadType_`).

```mermaid
flowchart TD
    V["📦 Value"]
    V --> T1["type_ : ValueType<br/>(تمثيل مبسَّط)"]
    V --> T2["sadType_ : SadTypePtr<br/>(النوع الموحَّد الغنيّ)"]

    T1 --> U1["isObject() · isInteger() · التخزين الفعليّ · إرسال الطرق"]
    T2 --> U2["getKind() → SadTypeKind · Optional/Result/Future · isAssignableTo"]

    K["🔎 getKind() = getSadType()->getKind()"]
    T2 --> K
    K --> TYPEOF["نوع() · المدقّق · التضييق"]

    note["مثال Future/Generator/Widget:<br/>type_=OBJECT (لإرسال الطرق)<br/>بينما getKind()=النوع الحقيقيّ"]
    V -.-> note

    style V fill:#bfdbfe,stroke:#1d4ed8,color:#000
    style K fill:#fde68a,stroke:#b45309,color:#000
    style note fill:#f1f5f9,stroke:#64748b,color:#000
```

| الحقل | يُجيب على | يُستخدم في |
|------|----------|-----------|
| `type_` (ValueType) | «كيف أُخزَّن وأُرسِل الطرق؟» | `isObject()`, التخزين، الإرسال |
| `sadType_` (SadTypePtr) | «ما نوعي الحقيقيّ؟» | `getKind()`, `نوع()`, المدقّق، الإسناد |

## 6. `SadTypeRegistry`: التجميع والمصانع

سجلٌّ واحد يحتفظ بمفردات الأنواع البدائية (singletons) ويجمّع (intern) المركّبة.

```mermaid
flowchart TD
    REG["🗃️ SadTypeRegistry::instance()"]
    REG --> SINGLE["مفردات مخزَّنة<br/>getVoid · getNull · getInteger<br/>getFloat · getBoolean · getString<br/>getAny · getNever · getUnknown"]
    REG --> BYKIND["getByKind(SadTypeKind) → SadTypePtr"]
    REG --> MAKE["مصانع المركّبة<br/>makeOptional · makeResult<br/>makeArray · makeFuture · makeMap"]
    REG --> INTERN["intern(type)<br/>توحيد المثيلات المتماثلة"]

    MAKE --> INTERN
    INTERN --> CACHE["♻️ مثيل واحد لكل نوع متماثل<br/>(مقارنة بالهوية + ذاكرة أقلّ)"]

    style REG fill:#fde68a,stroke:#b45309,color:#000

```

## 7. تدفّق `نوع()` — اسمٌ من مصدرٍ واحد

`نوع(قيمة)` يقرأ `getKind()` ثم يترجمه عبر `typeof_ar` المُولَّد — فيتطابق في المحرّكين.

```mermaid
sequenceDiagram
    participant P as برنامج ص
    participant TO as type_of (builtins)
    participant V as Value
    participant G as sadTypeKindArabicName
    participant Y as typeof_ar (من types.yaml)

    P->>TO: نوع(القيمة)
    TO->>V: getKind()
    V-->>TO: SadTypeKind (مثلاً Class)
    TO->>G: sadTypeKindArabicName(kind)
    G->>Y: ابحث عن typeof_ar للنوع
    Y-->>G: «كائن»
    G-->>TO: «كائن»
    TO-->>P: «كائن»
    Note over TO,Y: نفس المسار في المفسّر والمترجم ⇒ تطابق مزدوج
```

أمثلة فعليّة: `نوع(42)`→«رقم» · `نوع("ن")`→«نص» · `نوع(لاشيء)`→«عدم» · `نوع(مستقبل())`→«مستقبل» · `نوع(زر())`→«كائن».

## 8. تدفّق null والاختياريّ (Null-safety الأساسيّ)

```mermaid
flowchart TD
    LIT["القيمة الحرفية: لاشيء"] --> NULL["SadTypeKind::Null<br/>(متمايز عن Void)"]
    DECL["تصريح نوع: رقم؟ / رقم?"] --> OPT["SadTypeKind::Optional<br/>(InnerType = Integer)"]

    NULL --> ASSIGN{"isAssignableTo؟"}
    ASSIGN -->|"Null <: T?"| OK["✅ يُسنَد للاختياريّ"]
    ASSIGN -->|"Null <: T (غير اختياريّ)"| WARN["⚠️ حارس P9: «اجعله اختياريًّا: نوع؟»"]

    OPT --> OPS["عوامل الوصول الآمن"]
    OPS --> Q1["?. / ؟.  (سلسلة آمنة)"]
    OPS --> Q2["?? / ؟؟  (اندماج: بديلٌ عند العدم)"]

    NULL --> CG["codegen المترجم:<br/>تمثيل i64 (حارس) · mapSIRType(Null)→i64<br/>نوع(لاشيء)=«عدم» مزدوج"]

    style NULL fill:#fecaca,stroke:#b91c1c,color:#000
    style OPT fill:#bbf7d0,stroke:#15803d,color:#000
    style WARN fill:#fde68a,stroke:#b45309,color:#000
```

> التضييق المتقدّم (smart-cast) و`!!` جزءٌ من **نظام null-safety المستقلّ** (`_bmad-output/systems/null-safety/`).

| أُريد أن… | الملف |
|-----------|-------|
| أُضيف/أُعدّل نوعًا | `language-truth/types.yaml` ثم `gen_types.py` |
| أُضيف منطق إسناد/تباين | `shared/types/include/sad_type_system.h` (`isAssignableTo`) |
