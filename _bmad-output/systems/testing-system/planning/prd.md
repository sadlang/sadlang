# PRD — نظام الاختبارات الموحّد للغة ص

## 1. ملخص تنفيذي

اختبارات لغة ص اليوم مبعثرة على **أكثر من 50 مجلداً** تحت `tests/` بتسميات
متداخلة ومكرّرة (`parser` + `parser_tests`، `oop` + `oop_tests`، `stdlib` +
`stdlib_tests`، `sad_tests` + `sad_examples` + `quick`...)، ما يجعل تغطية أقسام
اللغة غير قابلة للتدقيق ويخالف GR-01. يقترح هذا النظام بنية **ثلاث طبقات** (وحدة /
سلوك / نظام)، يجعل العمود الفقري محرّك التنفيذ المزدوج الناضج في
`tests/dual_execution/` (مفسر + مترجم، ADR-03)، ويربط كل قسم من أقسام اللغة الـ12
بملف تغطية `COVERAGE.md` قابل للتدقيق — مع خطة ترحيل تدريجية بلا حذف (أرشفة لا محو،
GR-04).

## 2. المشكلة

### 2.1. الواقع الحالي

- 50+ مجلداً تحت `tests/` (جرد فعلي): `async, backends, bare_metal, benchmark,
  benchmarks, builtin_errors, compat, compiler, compiler_features, compiler_rules,
  comprehensive, data_tests, dual_execution, fuzzing, generics, grammar, hub,
  integration, interpreter_tests, jit, lexer_tests, low_level, lsp, modules,
  network, oop, oop_tests, ownership, parser, parser_tests, performance, pkg,
  quick, regression, safety, sad_examples, sad_tests, spec_rules, stage1, stdlib,
  stdlib_tests, stress, type_system, unit, توثيق ...`.
- المجلد المنظَّم الوحيد هو `tests/dual_execution/`: فيه `features/NN_قسم/` +
  `config.yaml` بمستويات `P0→full` + `runner.py` يقارن المفسر والمترجم.
- لكنه يحوي داخله أرشيفاً قديماً مكرّراً (`core/, oop/, match/, advanced/`) مع
  `features/`.

### 2.2. الفجوة

| الفجوة | الأثر |
|---|---|
| تكرار مجلدات لنفس الغرض | لا يُعرف أين «المصدر الموثوق» لاختبار ميزة |
| لا تغطية قابلة للتدقيق لكل قسم لغوي | يخالف GR-01 — لا دليل على اكتمال التغطية |
| مشغّلات متعددة متفرقة | لا أمر موحّد لتشغيل «كل الاختبارات» في CI |
| أرشيف مدفون داخل المجلد النشط | تكرار وبطء وتشويش |

## 3. الأهداف

| الهدف | المقياس | الأولوية |
|---|---|---|
| G1 — توحيد الطبقات | كل اختبار في واحدة من 3 طبقات فقط | P0 |
| G2 — تغطية قابلة للتدقيق | `COVERAGE.md` لكل قسم من أقسام اللغة الـ12 | P0 |
| G3 — مشغّل واحد موحّد | `tests/runner.py --level <L>` يشمل الطبقات الثلاث | P0 |
| G4 — صفر فقدان اختبار | كل اختبار قديم مُرحَّل أو مؤرشف موثَّق (GR-04) | P0 |
| G5 — ربط CI | P0=commit، P1=PR، P2=nightly، full=release | P1 |

## 4. غير الأهداف (Non-Goals)

- كتابة اختبارات جديدة لميزات غير مغطّاة (هذا عمل لاحق بعد جرد الفجوات).
- تغيير محرّك `runner.py` نفسه جوهرياً — نُرقّيه لا نعيد كتابته.
- لمس بنية البناء (`cmake/`) إلا في القصة الأخيرة (ربط CI).
- حذف أي اختبار قديم (يُؤرشف فقط حتى يُتأكد من التغطية).

## 5. المستخدمون المستهدفون

- **مطوّرو لغة ص** (تعديل C++ للمفسر/المترجم) — يحتاجون `--level P0` ثم القسم ثم `P1`.
- **CI/CD** — يحتاج أمراً موحّداً لكل مستوى.
- **مراجعو الحوكمة** — يحتاجون `COVERAGE.md` كدليل تدقيق GR-01.

## 7. المتطلبات غير الوظيفية (NFR)

| NFR# | الوصف | المقياس |
|---|---|---|
| NFR-01 | سرعة الدخان P0 | < 30 ثانية على محطة عمل |
| NFR-02 | بلا تراجع أثناء الترحيل | `runner.py --level full` أخضر بعد كل دمج |
| NFR-03 | توثيق ثنائي اللغة | كل `README/COVERAGE` بالعربية (تعليقات موسّعة) |
| NFR-04 | تتبّع git | كل ملف منقول يبقى متتبَّعاً (نقل لا حذف+إنشاء) |

## 8. الافتراضات والقيود

- محرّك `tests/dual_execution/runner.py` يعمل ويُختبر المفسر `sad-run.exe`
  والمترجم `sadc.exe` كما في `config.yaml`.
- لا حذف لأي اختبار قبل إثبات تغطيته (قيد حوكمة GR-04).
- البناء يتطلب `-DBUILD_TESTS=ON`؛ اختبارات الطبقة 1 ترتبط بـ `sad_core`.

## 9. مقاييس النجاح

1. عدد مجلدات `tests/` الجذرية ينخفض من 50+ إلى ≤ 6 (الطبقات الثلاث + `_archive` + ملفات مشتركة).
2. كل قسم من أقسام اللغة الـ12 له `COVERAGE.md` غير فارغ.
3. أمر واحد `runner.py --level full` يشغّل كل شيء بلا تراجع.
4. جرد فجوات موثَّق يحدّد ما ينقص لكل قسم.

## 10. المخاطر والتخفيف

| الخطر | الفئة | الدرجة | التخفيف |
|---|---|---|---|
| **عدم حتمية خرج التزامن/العشري يكسر المقارنة الحرفية** | TECH | **9** | وضع تطبيع + `@nondeterministic` (FR-09، ADR-004) |
| التنفيذ المزدوج (E2E) عمود لكل شيء حتى منطق قابل للوحدة | TECH | 6 | دفع parser/types/lexer إلى `unit/` (ADR-004) |
| أولوية حسب اتساع القسم لا المخاطرة | TECH | 6 | اشتقاق المستويات من درجة المخاطر (FR-10/FR-11) |
| فقدان اختبار أثناء الدمج | OPS | 4 | أرشفة لا حذف + `full` بعد كل دمج (NFR-02) |
| الأساس المرجعي مجهول (`0%` غير مُقاس) | OPS | 4 | قياس baseline فعلي في TEST-001 (FR-08، GR-01) |
| رفرفة الاختبارات الجديدة | TECH | 4 | burn-in 5× + بوّابة جودة (FR-13) |

| مسارات عربية على ويندوز | TECH | 2 | `runner.py` يهيّئ UTF-8 مسبقاً (موجود) |
