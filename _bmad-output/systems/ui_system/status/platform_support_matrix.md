## 3. تفاوت العمق (Depth) لا التغطية (Coverage)

التغطية على مستوى **إنشاء العنصر** كاملة (15/15) في المنصات الأربع. لكن **عمق التنفيذ**
يتفاوت — وهذا سبب تصنيف أندرويد «جزئياً» في `implementation_status.md`:

```
   التغطية (هل العنصر معروف؟)          العمق (كم خاصية/حالة مدعومة؟)
   ┌──────────────────────────┐        ┌──────────────────────────────┐
   │ Desktop  ████████████ 15 │        │ Desktop  ██████████ عميق      │
   │ Web      ████████████ 15 │        │ Web      ██████████ عميق      │
   │ iOS      ████████████ 15 │        │ iOS      █████████  عميق      │
   │ Android  ████████████ 15 │        │ Android  █████      أقل عمقاً  │
   └──────────────────────────┘        └──────────────────────────────┘
```

| المعيار | Desktop | Web | iOS | Android |
|---------|---------|-----|-----|---------|
| تغطية الـ15 (إنشاء) | 15/15 | 15/15 | 15/15 | 15/15 |
| حجم الباطن (سطر) | 6669 | 4082 | 2752 | 903 |
| الخصائص المدعومة | واسعة | واسعة | واسعة | محدودة¹ |
| بعض العناصر placeholder | لا | لا | لا | نعم² |

¹ `SadViewFactory` يدعم: text, fontSize, color, padding, backgroundColor, alignment,
spacing, elevation, bold/italic, checked, value, opacity, visible (قائمة محدودة).
² أندرويد يستخدم `createPlaceholder` لبعض العناصر المتقدمة (مثل منتقي التاريخ/اللون).

## 4. ملاحظات مهمة (GR-01)

1. **التغطية ≠ الصحة الوظيفية النهائية:** المصفوفة تثبت أن كل باطن «يعرف» الـ15، لكن
   التحقق الوظيفي الكامل يتطلب بناء كل منصة وتشغيل أمثلة عليها (لم يُنفَّذ هنا).
2. **حاجز المفسر↔UI قبل أي عرض:** حتى مع تغطية الباطن 15/15، لا تظهر واجهة فعلية حتى
   يُصلَح جسر المفسر↔UI (`نوع()` = «مجهول»، `جديد <واجهة>` يفشل — انظر
   [`implementation_status.md`](implementation_status.md) §3.5 و [EPIC-UI-W15](../epics/EPIC-UI-W15-interpreter-compiler.md)).
3. **أندرويد «جزئي» بسبب العمق لا التغطية:** يلزم تدقيق عمق الخصائص لكل عنصر (مهمة P1).
