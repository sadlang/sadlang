> **التزام GR-01:** لا يُذكر «منفّذ» إلا بدليل (ملف + عدد أسطر). الأرقام من `wc -l`
> بتاريخ 2026-06-08. هذا **ليس** تقرير اختبار — لم يُبنَ المشروع ولم تُشغَّل اختبارات؛

## 3.5 نتائج التحقّق الوظيفي (P0 — 2026-06-08)

بُني المفسر (`cmake --build build --config Debug --target sad`) وشُغّل
`tests/integration/test_event_system.ص`. **النتيجة: التحليل النحوي يعمل، لكن تكامل
التنفيذ ناقص.**

| الاختبار | النتيجة | التفسير |
|----------|---------|---------|
| تحليل `=>` و`لامدا` للأحداث | ✅ نجح | المحلل يقبل الصيغ الثلاث |
| تحليل حاويات متداخلة بأحداث | ✅ نجح | شجرة الأبناء تُبنى |
| `نوع(زر(...)) == "object"` | ❌ فشل | يرجع `"مجهول"` لا `"object"` |
| `نوع(حقل_نص(...).عند_التغيير(...))` | ❌ فشل | نفس السبب |
| `جديد نموذج_أحداث()` لمكوّن `واجهة_تصريحية` | ❌ خطأ دلالي SEM001 | «متغير غير معرّف: جديد» — المكوّن غير مسجّل كنوع قابل للإنشاء |

**الأدلة (مخرجات فعلية):**
```
النوع: مجهول                    ← نوع(زر("اختبار"))
النوع بعد المعدّل: مجهول         ← نوع(زر(...).عند_النقر(لامدا...))
❌ error [SEM001]: ...:132:15   متغير غير معرّف: جديد
   132 │ متغير نموذج = جديد نموذج_أحداث()
```

**الاستنتاج الجذري:** طبقة المحلل النحوي (Parser) مكتملة، لكن:
1. تعبيرات العناصر (`زر(...)`) تُقيّم في المفسر إلى قيمة بنوع `"مجهول"` بدل كائن واجهة حقيقي.
2. مكوّنات `واجهة_تصريحية` غير مربوطة بالطبقة الدلالية كأنواع قابلة للإنشاء عبر `جديد`.

هذا يؤكد ملاحظة §"المنهجية": **حجم الكود الكبير ≠ تكامل وظيفي**. الباطن موجود (آلاف الأسطر)
لكن جسر «المفسر ↔ شجرة UI» غير مكتمل.

## 4. الفجوات والمخاطر

1. **🔴 جسر المفسر↔UI ناقص (مؤكَّد وظيفياً):** تعبيرات العناصر تُقيَّم لنوع `"مجهول"`،
   ومكوّنات `واجهة_تصريحية` لا تُنشأ بـ `جديد` (خطأ SEM001). أهم فجوة.
2. **أندرويد ناقص العمق لا التغطية:** يغطي الـ15 إنشاءً (`SadViewFactory` 87 case)، لكن
   عمق الخصائص أقل من باقي المنصات — انظر [`platform_support_matrix.md`](platform_support_matrix.md).
3. **أمثلة قديمة محذوفة:** أُزيلت من `examples/`؛ يلزم كتابة أمثلة جديدة بالصيغة المعتمدة.
4. **ADRs 03–06:** مذكورة ضمنياً في الكود دون نص صريح — غير موثّقة (GR-01).

## 4.5 تصحيح حوكميّ (2026-06-18) — فجوتا P0 أُعيد تقييمهما بالتتبّع

> **GR-04 / GR-01:** التتبّع بأثر طباعة (لا قراءة كود فقط) صحّح ادّعاءين سابقين:

1. **P0-1 «نوع()=مجهول/أي»** ✅ **مُصلَح** (STORY-UI-W15-01، PR sadlang/s-programming-language#62):
   الجذر في وسم قيمة الكائن `Value::Value(ObjectPtr)` (`shared/types/src/value.cpp:217`،
   كان `getAny()`). أُصلِح ليَسِم `Class` ⇒ `نوع(زر())`/`نوع(نقطة(5))`=«كائن» (تكافؤ مع المترجم).

2. **P0-2 «واجهة لا تُنشأ» — إنذار كاذب + قرار كلمة مفتاحية:** التتبّع أثبت أنّ المكوّن **يُسجَّل
   ويُنشأ** فعلًا؛ سبب الوهم في التقريرين السابقين:
   - تقرير 2026-06-15 استعمل `واجهة` — وكانت آنذاك **اسمًا بديلًا لـ`سمة`/trait** لا للـUI
     (كلمة الـUI كانت `واجهة_تصريحية`)، فـ`واجهة عداد` كان يُحلَّل كـtrait ولا يُستدعى `parseUIDeclaration`
     (مؤكَّد بأثر التحليل: لم يُطبَع لـ`واجهة`، وطُبِع لـ`واجهة_تصريحية`).
   - تقرير 2026-06-08 استعمل `جديد <واجهة>` — و**`جديد` البادئة غير مدعومة عمومًا** (النداء `X()` هو الصيغة).
   - **القرار (2026-06-18):** اعتُمدت **`واجهة` ككلمة مفتاحية وحيدة لتعريف مكوّن UI** (`KEYWORD_UI_DECL`)،
     وأُزيل المرادف `واجهة_تصريحية` (قاعدة الكلمة الواحدة — لا مرادفات)، ونُقلت `واجهة` من أسماء `سمة`
     البديلة (الذي يبقى `سمة` وحده). تعديل مدفوع بالبيانات في `language-truth/keywords.yaml:149`.
   - **الدليل (تشغيل فعليّ):** `واجهة عداد {@حالة عدد=5; دالة بناء()...}` ثم `عداد()` ⇒
     `نوع()`=«كائن» و`ع.عدد`=5. اختبار: `tests/behavior/grammar_gaps/كائني/012_ui_decl_instantiation.ص`.

   **أثر على «الحاجز الحرج»:** ادّعاء ROADMAP أنّ «لا تظهر أيّ واجهة حتى يُصلَح جسر المفسّر↔UI»
   مبالَغ فيه — جسر الإنشاء يعمل لـ`واجهة`. الفجوة المتبقّية الفعليّة: دعم المترجم (W15-04).

3. **W15-02 (إنشاء المكوّن) — ✅ DONE (2026-06-18):** عاملة بالكامل بعد P0-1 + قرار `واجهة`.
   AC-1..AC-5 جميعها ✓ (إنشاء، `نوع=كائن`، تهيئة @حالة، دوال قابلة للاستدعاء، وراثة `يرث`).
   الدليل: اختبارا السلوك 012 (إنشاء + قراءة @حالة) و013 (دوال + وراثة).

4. **W15-03 (تفاعلية @حالة) — ✅ DONE (2026-06-18) + إنذار كاذب آخر:** خلافًا لوصف الستوري،
   `UIStateManager` **موصول بالفعل** بمسار تعيين الحقول (`members_assign.cpp:309` → `setField`
   → `onFieldChanged_` → `onStateFieldChanged` → `scheduleRebuild` → `flush`). الناقص كان
   **تغطية اختبارية** فقط — أُضيف `tests/unit/comprehensive/test_ui_reactive_state.cpp`
   (6/6 ينجح: AC-1 تسجيل، AC-2/5 إطلاق+flush، AC-3 batching، AC-4 تصفية الحقول العادية،
   + لا-تغيير، + فصل المراقب). **تنبيه بناء:** `interpreter_test_stubs.cpp` يُبطل دوال
   `UIStateManager`؛ رُبط الاختبار بـ`sad_core` بدون البدائل.

5. **W15-04 (دعم المترجم عبر SIR) — ✅ جزئيًّا DONE (2026-06-19):** كان المترجم يتخطّى
   عقد `UIDeclarationNode` بصمت (دوال الزائر فارغة في `ASTVisitorBase`)، فلا يُنتج صنفًا.
   الإصلاح: **Phase 0** في `SIRBuilder::buildModule` (`sir_builder_module.cpp`) يخفض كل
   `UIDeclarationNode` على المستوى الأعلى إلى `ClassDecl` مكافئ في مكانه (`@حالة`→حقول،
   الدوال→طُرق، `يرث`→صنف أب)، فتتولّاها مراحل بناء الأصناف القائمة (1.3/1.35/2A) —
   إعادة استخدام منطق الأصناف (CW-19/CW-20) كما في `visitUIDeclaration` بالمفسّر.
   - **AC-1 (لا فشل لعقدة غير مدعومة) ✓** و**AC-4 (تركيب الصنف المكافئ) ✓** — مُثبَتان عبر
     اختبار الوحدة `tests/unit/comprehensive/test_ui_sir_lowering.cpp` (9/9): يظهر في وحدة
     SIR صنف `عداد` بحقل `@حالة` `عدد` وطريقة `عداد.زد`، و`عداد_مزدوج` يحفظ `يرث عداد`.
   - **المتبقّي (موثَّق، خارج هذه الزيادة):** AC-2 (`UIWidgetExprNode`→نداء `بناء`)، AC-3
     (`UIModifierNode`→ضبط خاصية)، AC-5 (`UIConditionalNode`/`UILoopNode`→تحكّم)، AC-6
     (تكافؤ شجرة المفسّر↔المترجم)، ومكتبة UI زمن التشغيل + اختبار من طرف لطرف. **حاجز بيئيّ:**
     لا يُمكن ربط `sadc` في تهيئة Debug (خطأ بيئة LLVM)، فالتحقّق E2E غير متاح هنا؛ الزيادة
     مُختبَرة على مستوى الواجهة الأمامية (sad_frontend يُبنى ويُختبَر في Debug).
