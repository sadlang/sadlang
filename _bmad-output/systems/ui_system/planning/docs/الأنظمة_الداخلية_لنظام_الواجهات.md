## 1. نظام إدارة الحالة (State + Signal)

تفاعلية دقيقة (Fine-Grained Reactivity — ADR-UI-10): `Signal<T>` حاوية قيمة تُخطر مراقبيها
تلقائياً عند التغيير. تعيش الإشارة في خيط اللغة وتُقرأ/تُكتب منه فقط.

```
   @حالة عداد = 0                      متغير عادي عدد = 0
        │                                   │
        ▼                                   ▼
   Signal<عدد>  ◄── observer مسجّل      قيمة في الذاكرة فقط
        │                                   │
   عداد = 5                             عدد = 5
        │                                   │
        ▼                                   ▼
   signal.set(5) ──► يُخطر المراقبين    ❌ لا أحد يُخطَر
        │
        ▼
   UIStateManager.scheduleRebuild()
        │  (batching: يدمج عدة تغييرات في إطار واحد)
        ▼
   الإطار التالي: بناء() ──► Reconciler ──► رسم الفرق فقط
```

**الخلاصة:** `@حالة` = إشارة مُراقَبة تقود إعادة البناء؛ `متغير` = قيمة صامتة.
(انظر الشرح الكامل في إجابة «لماذا @حالة».)

## 2. نظام المطابقة (Reconciler — Virtual DOM)

بدل إعادة بناء الشجرة كاملة عند كل تغيير، يقارن المُوفّق الشجرة القديمة بالجديدة وينتج
«رقعاً» (Patches) موضعية فقط — على نمط React.

```
   الشجرة القديمة            الشجرة الجديدة
        │                         │
        └──────────┬──────────────┘
                   ▼
              diff()  ◄── خوارزمية المقارنة:
                   │      • نوع مختلف        → REPLACE
                   │      • خاصية تغيّرت     → UPDATE_PROPS
                   │      • معالج حدث جديد   → UPDATE_EVENTS
                   │      • أبناء (بالمفاتيح)→ INSERT/REMOVE/REORDER
                   ▼
              DiffResult (قائمة رقع)
                   │
                   ▼
              patch() ──► الشجرة الحية (مُحدّثة موضعياً فقط)

   المكاسب:  ✅ أداء (لا إعادة تخطيط كامل)
             ✅ حفظ التمرير/التركيز/التحريكات
             ✅ ذاكرة (لا إعادة إنشاء عقد لم تتغيّر)
```

## 3. نظام التوجيه الهجين (Hybrid Routing)

كل عنصر يمكن عرضه أصلياً (مكوّن المنصة) أو على Canvas (رسم مباشر). النظام يختار تلقائياً.

```
                  عنصر واجهة (Widget)
                         │
                         ▼
                ┌─── hybrid_routing ───┐
                │  هل يحتاج تخصيصاً     │
                │  بصرياً معقّداً؟       │
                └──────────┬───────────┘
                  لا       │       نعم
            ┌──────────────┴──────────────┐
            ▼                             ▼
      ┌──────────┐                  ┌──────────┐
      │  Native  │                  │  Canvas  │
      │ مكوّن أصلي│                  │ SDL2/GL  │
      │ (أداء +  │                  │ (مرونة + │
      │  إتاحة)  │                  │  تحكم)   │
      └──────────┘                  └──────────┘

   مثال:  زر بسيط → Native        |   زر بتدرّج/ظل مخصّص → Canvas
```

## 4. محرك التخطيط (Layout — Flexbox + RTL)

يحسب الموقع والأبعاد النهائية لكل عنصر بعد بناء شجرة IR. خوارزمية Flexbox مبسّطة بمرحلتين.

```
   شجرة IR + الأنماط
        │
        ▼
   ┌─ المرحلة 1: القياس (Measure) ─┐    من الأبناء ◄── للأعلى
   │ كل حاوية تحسب حجمها من أبنائها │    (bottom-up)
   └────────────┬──────────────────┘
                ▼
   ┌─ المرحلة 2: الترتيب (Arrange) ─┐   من الجذر ◄── للأسفل
   │ توزيع المواقع على المحاور        │   (top-down)
   │   • المحور الرئيسي (main axis)   │
   │   • المحور الثانوي (cross axis)  │
   └────────────┬──────────────────┘
                ▼
   مواقع وأبعاد نهائية (x, y, w, h) لكل عنصر

   ⬅️ دعم RTL تلقائي: المحور الرئيسي للصف يبدأ من اليمين
```

## 5. محرك الأنيميشن (Animation Engine)

```
   قيمة بداية ──────────────────────► قيمة نهاية
        │         منحنى التسهيل           │
        │   ┌────────────────────────┐    │
        └──►│ خطي · تسارع · تباطؤ ·   │◄───┘
            │ نابض (spring)          │
            └────────────────────────┘
                       │
        ┌──────────────┼──────────────┐
        ▼              ▼              ▼
   خصائص رقمية      ألوان        متسلسل/متزامن
   (عرض/شفافية)   (تدرّج سلس)   (sequence/parallel)
```
يدعم: تحريك الخصائص الرقمية والألوان، منحنيات تسهيل متعددة، وتسلسل/تزامن الحركات.

## 6. نظام الإيماءات (Gesture Arena)

```
   لمسة المستخدم
        │
        ▼
   ┌─ ساحة الإيماءات (Gesture Arena) ─┐
   │ عدة مُتعرّفات تتنافس على اللمسة:   │
   │   نقر · سحب · ضغط مطول · تحويم    │
   │            ▼ حل التعارض            │
   │   الفائز بالأولوية يلتقط الإيماءة  │
   └───────────────┬───────────────────┘
                   ▼
            معالج الحدث (=> / كتلة / لامدا)
```
يدعم: ساحة إيماءات لحل التعارضات، إيماءات مخصّصة عبر أنماط، أولويات قابلة للتخصيص.
معالجات الإدخال: `mouse_processor.h`, `keyboard_processor.h`, `touch_processor.h`.

## 7. نظام التركيز (Focus Tree)

```
   شجرة تركيز هرمية
        │
        ├── نطاق تركيز (Scope)
        │       ├── عنصر A  ◄── Tab
        │       └── عنصر B
        │
        └── مصيدة تركيز (Trap) ◄── للحوارات/القوائم (يمنع الخروج بـ Tab)

   ميزات: تركيز تلقائي (Autofocus) · حلقة مؤشر بصري (Focus Ring)
```

## 8. أنظمة مساندة

```
┌─ فيزياء التمرير (scroll_physics) ─┐  ┌─ طابور الأوامر (command_queue) ──┐
│ تمرير بالسرعة + قصور ذاتي         │  │ مخازن مزدوجة (double buffering)   │
│ (velocity + inertia)             │  │ بين خيط اللغة وخيط الرسم          │
└──────────────────────────────────┘  └──────────────────────────────────┘

┌─ ذاكرة الصور (image_cache) ──────┐  ┌─ السمات (theme) ─────────────────┐
│ تخزين مؤقت لتفادي إعادة التحميل   │  │ ألوان/أنماط مركزية (.أزرق...)    │
└──────────────────────────────────┘  └──────────────────────────────────┘
```

## 9. كيف تتعاون الأنظمة؟ (دورة إطار واحدة)

```
   تغيّر @حالة
        │
        ▼
   [State/Signal] ──► [UIStateManager] يجدول إعادة بناء (batching)
        │
        ▼
   بناء() ──► شجرة UINode جديدة
        │
        ▼
   [IRBuilder] + [Hybrid Routing] ──► شجرة IR (أصلي/Canvas لكل عنصر)
        │
        ▼
   [Reconciler] يقارن القديم/الجديد ──► رقع موضعية
        │
        ▼
   [Layout] يحسب المواقع (Flexbox+RTL) ──► [Animation] يطبّق الحركات
        │
        ▼
   [Command Queue] ──► الباطن (SDL2/HTML/SwiftUI/JNI) ──► الشاشة
        ▲
        │
   [Gesture]/[Focus] يلتقطان إدخال المستخدم ──► يُطلقان أحداثاً ──► تغيّر @حالة ↺
```
