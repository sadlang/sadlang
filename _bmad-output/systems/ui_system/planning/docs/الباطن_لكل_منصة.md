## 0. المبدأ المشترك: نقطة الانطلاق واحدة

كل المنصات تبدأ من **نفس شجرة IR المحايدة** (`sad_ui/core/ir.h`). الفرق فقط في الباطن
(Backend) الذي يترجم IR إلى تقنية المنصة:

```
                     SadUI IR (محايد تماماً)
                            │
        ┌───────────┬───────┴───────┬────────────┐
        ▼           ▼               ▼            ▼
   ┌─────────┐ ┌─────────┐    ┌──────────┐ ┌──────────┐
   │ Desktop │ │   Web   │    │   iOS    │ │ Android  │
   │ عرض حي  │ │ توليد   │    │ توليد    │ │ بناء حي  │
   │ (Render)│ │ (Codegen)│   │ (Codegen)│ │ (Build)  │
   └─────────┘ └─────────┘    └──────────┘ └──────────┘

   نمطان مختلفان:
   • عرض حي (Renderer):  يرسم مباشرة في وقت التشغيل   → Desktop, Android
   • توليد كود (Codegen): يُنتج كوداً مصدرياً للمنصة   → Web, iOS
```

| المنصة | النمط | التقنية | الأسطر | الحالة |
|--------|------|---------|--------|--------|
| سطح المكتب | عرض حي | SDL2 + SDL_ttf + OpenGL | 6669 | ✅ منفّذ |
| الويب | توليد كود | HTML5 + CSS3 + JS | 4082 | ✅ منفّذ |
| iOS | توليد كود | SwiftUI + Metal/UIKit | 2752 | ✅ منفّذ |
| أندرويد | بناء حي | JNI → Android Views | 903 | 🟡 جزئي |

## 1. سطح المكتب — SDL2 (عرض حي)

يرسم العناصر مباشرة في نافذة حقيقية وقت التشغيل. يُفعّل بالماكرو `SAD_UI_USE_SDL2`.

```
   شجرة IR
      │
      ▼
   ┌─ renderer.cpp (2207) ─────────────────────┐
   │  يمشي على الشجرة ويرسم كل عقدة:           │
   │   • مستطيلات → SDL_RenderFillRect          │
   │   • نصوص     → SDL_ttf                     │
   │   • صور      → SDL_RenderCopy              │
   └───────────────────┬───────────────────────┘
                        │
   ┌────────────────────┼─────────────────────┐
   ▼                    ▼                       ▼
window.cpp(2255)  renderer_draw(712)   renderer_canvas(400)
حلقة الأحداث       رسم منخفض المستوى    لوحة الرسم المخصصة
والنافذة
                        │
                        ▼
                  text_editing(555)  ← تحرير النص التفاعلي
                  system_bridge(540) ← صوت/مستشعرات
                        │
                        ▼
                   🖥️ نافذة على الشاشة
```

**السمة المميزة:** الوحيد الذي يعرض **حياً وقت التشغيل** على المكتب (لا توليد كود). حلقة
الأحداث في `window.cpp` تلتقط الإدخال وتُغذّي أنظمة الإيماءات/التركيز.

## 2. الويب — HTML/CSS/JS (توليد كود)

يحوّل شجرة IR إلى صفحة ويب كاملة. `html_codegen.cpp` هو المنسّق الذي يوزّع العمل:

```
   شجرة IR
      │
      ▼
   html_codegen.cpp (121) ── المنسّق الرئيسي
      │
      ├──► html_css_codegen (457)         → generateBaseCSS()
      ├──► html_element_codegen (567)     → generateElement() للعناصر الأساسية
      ├──► html_element_advanced (637)    → عناصر متقدمة + تنقل
      ├──► html_style_codegen (286)       → أنماط مضمّنة
      └──► html_script_codegen (417)      → JS تفاعلي (أحداث/حالة)
      │
      ▼
   web_renderer.cpp (1017) + system_bridge (580)
      │
      ▼
   📄 ملف HTML كامل (بنية + تنسيق + تفاعل)
```

**السمة المميزة:** يفصل البنية (HTML) عن التنسيق (CSS) عن السلوك (JS) — كل في مولّد مستقل
(التزام CW-03 فصل الاهتمامات).

## 3. iOS — SwiftUI (توليد كود)

`SwiftUICodegen::generate(IRModule)` يحوّل IR إلى كود SwiftUI تصريحي:

```
   شجرة IR (IRModule)
      │
      ▼
   swiftui_codegen.cpp (1645)
      │   generate(module):
      │     عمود  → VStack { }
      │     صف    → HStack { }
      │     رصة   → ZStack { }
      │     نص    → Text(...)
      │     زر    → Button(...) { }
      │   + المعدّلات → .modifier()
      ▼
   كود SwiftUI (.swift)
      │
      └──► ios_renderer.mm (664)  ← عارض أصلي Objective-C++ (Metal/UIKit)
           system_bridge.cpp (443) ← جسر النظام
      │
      ▼
   📱 واجهة SwiftUI على iOS
```

**تصحيح مهم:** هذا الباطن **منفّذ جوهرياً** (2752 سطر) — وليس هيكلاً كما ادّعت تقارير سابقة.

## 4. أندرويد — JNI → Views أصلية (بناء حي)

لا JSON ولا WebView — بناء Views أصلية مباشرة عبر JNI:

```
   شجرة IR (C++)
      │
      ▼
   native_ui_builder.cpp (198)
      │  يمشي على الشجرة (MAX_DEPTH=50 لمنع التعاود)
      │  لكل عقدة → استدعاء JNI
      ▼
   ┌─── حدود JNI (C++ ⇄ Java) ───┐
      │
      ▼
   SadViewFactory.java
      │  ينشئ View أصلية لكل عقدة
      │  خصائص مدعومة: text, fontSize, color, padding,
      │  backgroundColor, alignment, spacing, elevation,
      │  bold/italic, checked, value, opacity, visible
      ▼
   SadEngine.java + MainActivity.java
      │
      ▼
   🤖 واجهة Android أصلية

   دعم C++: sad_app_main(323) · sad_android_runtime(275) ·
            sad_android_bridge(70) · native_ui_storage(37)
   البناء: build_apk.ps1
```

**سبب التصنيف «جزئي»:** الحجم أصغر بكثير (903 مقابل 2752–6669)، وقائمة خصائص
`SadViewFactory` محدودة — يلزم تدقيق تغطية العناصر الأولية الـ15 (مهمة P1).

## 5. مقارنة الباطن الأربعة

```
                Desktop    Web       iOS       Android
              ┌─────────┬─────────┬─────────┬─────────┐
   النمط      │ عرض حي  │ توليد   │ توليد   │ بناء حي │
   التقنية    │ SDL2    │ HTML/CSS│ SwiftUI │ JNI/Views│
   التوقيت    │ تشغيل   │ ترجمة   │ ترجمة   │ تشغيل   │
   المخرج     │ بكسلات  │ ملف ويب │ كود سويفت│ Views   │
   الأسطر     │ 6669    │ 4082    │ 2752    │ 903     │
   الحالة     │ ✅      │ ✅      │ ✅      │ 🟡      │
              └─────────┴─────────┴─────────┴─────────┘
```

| المعيار | عرض حي (Desktop/Android) | توليد كود (Web/iOS) |
|---------|--------------------------|----------------------|
| متى يحدث؟ | وقت التشغيل | وقت الترجمة |
| المخرج | عرض مباشر | ملف مصدري للمنصة |
| التفاعلية | عبر حلقة أحداث داخلية | عبر كود المنصة المولّد |
| الاعتماد | مكتبة وقت تشغيل | سلسلة أدوات المنصة |

## 6. أين يقع الباطن في الطبقات؟

```
   L2 النواة المحايدة  ──►  IR + Layout + Reconciler  (لا يعرف أي منصة)
         │
         ▼
   L1 الباطن (هذا الملف)  ──►  يترجم IR إلى تقنية المنصة
         │
         ▼
   L0 العتاد/نظام التشغيل  ──►  شاشة · إدخال · GPU
```

إضافة منصة جديدة = كتابة باطن L1 جديد فقط، **دون لمس النواة L2** (مبدأ العزل — STRATEGY §2).
