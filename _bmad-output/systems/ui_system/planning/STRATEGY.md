# استراتيجية نظام الواجهات والرسومات (SadUI)

> وثيقة استراتيجية عُليا لنظام الرسومات في لغة ص. للتفاصيل التقنية:
> [`docs/نظام_الواجهات_الرسومي_ص.md`](docs/نظام_الواجهات_الرسومي_ص.md).
> لحالة التنفيذ المؤكَّدة وظيفياً: [`../status/implementation_status.md`](../status/implementation_status.md).

---

## 1. لماذا هذا النظام؟ (الرؤية والمبرّر)

```
┌────────────────────────────────────────────────────────────────────┐
│  المشكلة: لغة برمجة عربية بلا واجهات = لغة تعليمية محدودة الأثر     │
│                                                                      │
│  الرؤية:  أول نظام واجهات عربي تصريحي، يُكتب مرة ويعمل على          │
│           سطح المكتب + الويب + الجوال — بهوية عربية أصيلة (RTL)     │
└────────────────────────────────────────────────────────────────────┘
```

| الدافع | الشرح |
|--------|-------|
| **تمكين عربي حقيقي** | كتابة واجهات بكلمات عربية (`عمود`، `زر`، `@حالة`) لا ترجمة سطحية |
| **منصة واحدة، عدة أهداف** | تقليل تكلفة بناء التطبيقات: كود واحد → مكتب/ويب/جوال |
| **اتساق مع اللغة** | كتل `نهاية`، لا أقواس `{}` — نفس فلسفة لغة ص بالكامل |
| **RTL أصلي** | اتجاه يمين→يسار افتراضي (حشوة_بداية/نهاية واعية للاتجاه) |
| **تعبيرية مُثبَتة** | 15 عنصراً أولياً تُبنى منها البقية — دليل على قوة اللغة نفسها (ADR-UI-02) |

## 2. طبقات النظام (Architecture Layers)

```
        ╔══════════════════════════════════════════════════════════╗
        ║  L5 — المستهلكون: كود ص (.ص) يكتبه مطوّر التطبيقات         ║
        ╠══════════════════════════════════════════════════════════╣
        ║  L4 — الواجهة اللغوية (Surface Syntax)                     ║
        ║       واجهة_تصريحية · @حالة · سلسلة معدّلات · اعرض         ║
        ║       📁 shared/lexer · shared/parser/src/ui              ║
        ╠══════════════════════════════════════════════════════════╣
        ║  L3 — النموذج الدلالي (Semantic Model)                     ║
        ║       UINode · UIWidgetExprNode · UIStateDecl · أحداث     ║
        ║       📁 shared/ast · interpreter/src/ui (الجسر)          ║
        ║       ⚠️ فجوة مؤكَّدة: التقييم يرجع «مجهول» (status §3.5)   ║
        ╠══════════════════════════════════════════════════════════╣
        ║  L2 — النواة المحايدة (Platform-Neutral Core)             ║
        ║       IR · IRBuilder · hybrid_routing · layout(Flexbox)   ║
        ║       state · reconciler · theme · gesture · animation    ║
        ║       📁 sad_ui/core  (28 ملف · 10790 سطر)               ║
        ╠══════════════════════════════════════════════════════════╣
        ║  L1 — الباطن لكل منصة (Platform Backends)                  ║
        ║   ┌──────────┬──────────┬──────────┬──────────┐          ║
        ║   │ Desktop  │   Web    │   iOS    │ Android  │          ║
        ║   │ SDL2+GL  │ HTML/CSS │ SwiftUI  │ JNI Views│          ║
        ║   │ ✅6669   │ ✅4082   │ ✅2752   │ 🟡903    │          ║
        ║   └──────────┴──────────┴──────────┴──────────┘          ║
        ╠══════════════════════════════════════════════════════════╣
        ║  L0 — العتاد/نظام التشغيل (Screen · Input · GPU)          ║
        ╚══════════════════════════════════════════════════════════╝

        التدفق:  L5 يكتب → L4 يحلّل → L3 يبني نموذجاً → L2 يوحّد ويوجّه →
                 L1 يرسم/يولّد → L0 يعرض على الشاشة
```

**مبدأ العزل:** كل طبقة تعتمد فقط على التي تحتها (CW-02). النواة L2 محايدة تماماً —
لا تعرف SDL2 ولا HTML؛ الباطن L1 هو من يترجم IR إلى تقنية المنصة.

## 3. المستهلكون (Consumers)

```
                        ┌──────────────────┐
                        │   نظام SadUI     │
                        └────────┬─────────┘
         ┌──────────────┬────────┼────────┬──────────────┐
         ▼              ▼        ▼        ▼              ▼
   مطوّر تطبيقات    أداة LSP   المترجم   منصّات      أدوات التعليم
   (كود .ص)        (تلوين/    sadc      النشر       والأمثلة
                    إكمال)   (تحويل)    (apk/web)
```

| المستهلك | كيف يستهلك النظام | نقطة الربط |
|----------|-------------------|------------|
| **مطوّر التطبيقات** | يكتب `واجهة_تصريحية` بكلمات عربية | L4 (الصيغة) |
| **خادم LSP** | تلوين `واجهة_تصريحية`/`اعرض` كسياقيتين، إكمال العناصر الـ15 | `tools/lsp` + `semantic_tokens_provider` |
| **المفسر `sad`** | تقييم تعبيرات العناصر وبناء الشجرة | `interpreter/src/ui` |
| **المترجم `sadc`** | تحويل شجرة UI عبر IR إلى هدف أصلي | L2→L1 |
| **منصّات النشر** | `build_apk.ps1` (أندرويد)، مولّد HTML (ويب) | L1 |

## 4. تكامل النظام مع أنظمة لغة ص الأخرى

```
   ┌─────────────────┐        أنواع العناصر،        ┌──────────────────┐
   │  نظام الأنواع    │◄───── @حالة: نوع ───────────►│   نظام SadUI     │
   │  type-system     │        التحقق من القيم        │                  │
   └─────────────────┘                                └────────┬─────────┘
                                                               │
   ┌─────────────────┐    SEM001 «جديد غير معرّف»،             │
   │  نظام الأخطاء    │◄─── أخطاء نحوية ثنائية اللغة ───────────┤
   │  error-messages  │     data/language/error_messages.yaml   │
   └─────────────────┘                                          │
                                                               │
   ┌─────────────────┐    دوال العناصر مُسجَّلة كـ                │
   │ الدوال المدمجة   │◄─── BuiltinFunction (نص، زر...)  ───────┤
   │ builtin-functions│     interpreter/src/ui/widget_builtins   │
   └─────────────────┘                                          │
                                                               │
   ┌─────────────────┐    هذا التوثيق نفسه + المخططات،          │
   │ التوثيق الحي     │◄─── planning/docs/ (التوثيق الرسومي) ────┘
   │ living-docs      │
   └─────────────────┘
```

| النظام | طبيعة التكامل | الحالة |
|--------|---------------|--------|
| **نظام الأنواع** (`type-system`) | `@حالة اسم: نوع` يستخدم أنواع اللغة (`عدد`، `نص`...)؛ يجب تسجيل `واجهة_تصريحية` كنوع قابل لـ `جديد` | 🔴 ناقص (فجوة status §3.5) |
| **نظام الأخطاء** (`error-messages`) | أخطاء UI نحوية ثنائية اللغة + SEM001 من `error_messages.yaml` | ✅ يعمل (شوهد فعلياً) |
| **الدوال المدمجة** (`builtin-functions`) | العناصر مُسجَّلة كدوال مدمجة عبر `BuiltinModuleRegistry` | ✅ مسجّلة (التقييم ناقص) |
| **التوثيق الحي** (`living-documentation`) | التوثيق + المخططات هنا تُغذّي المصدر المُعتمد | ✅ هذه الوثيقة |
| **النواة المشتركة** (`shared`) | يعيد استخدام Lexer/Parser/AST/Value — لا مكدّس منفصل | ✅ |
| **التزامن** (goroutines) | الأحداث قد تُطلق مهامّ خفيفة (`أطلق`) — تكامل مستقبلي | 🔵 مخطّط |

## 5. المبادئ الاستراتيجية الحاكمة

1. **نواة صغيرة، أطراف غنية:** 15 عنصراً أولياً فقط؛ الباقي يُبنى تركيبياً (ADR-UI-02).
2. **الهجين الذكي:** كل عنصر يُوجَّه لأنسب آلية (أصلي/Canvas) لكل منصة.
3. **محايدة الطبقة:** النواة لا تعرف أي تقنية منصة — العزل التام يسمح بإضافة منصات دون لمس النواة.
4. **اتساق لغوي مطلق:** نفس `إذا/لكل/نهاية` داخل الواجهة وخارجها (ADR-UI-01).
5. **التحقق بالأدلة لا بالحجم:** «منفّذ» تعني «نجح وظيفياً»، لا «يوجد كود» (GR-01).

## 6. المخاطر والخارطة الاستراتيجية

| المخاطرة | الأثر | التخفيف |
|----------|------|---------|
| 🔴 جسر المفسر↔UI ناقص | لا تطبيقات حية رغم وجود الباطن | أولوية P0 — إصلاح التقييم والتسجيل |
| تباين الباطن (أندرويد 903 مقابل iOS 2752) | تجربة غير متسقة عبر المنصات | تدقيق تغطية العناصر الـ15 لكل منصة |
| العناصر المُهملة الـ55+ | كسر مستقبلي عند v2.0 | مكتبة `واجهة_تصريحية` جاهزة قبل الإزالة |
| لا أمثلة محدّثة | صعوبة التبنّي | كتابة أمثلة بالصيغة المعتمدة |

**الخارطة:** `إصلاح الجسر (P0)` → `أمثلة + تدقيق أندرويد (P1)` → `مكتبة العناصر المركّبة (P2)` → `إعلان v2.0 + إزالة المُهمل (P3)`.
