# STORY-UI-W15-02 — تسجيل `واجهة_تصريحية` كصنف قابل لـ `جديد`

## القصة
بصفتي مطوّر تطبيقات، أريد إنشاء كائن من مكوّن `واجهة_تصريحية` عبر `جديد المكوّن()`،
حتى أربط حالته وأستدعي دوال البناء عليه (مثل أي صنف).

## السياق التقني (من الكود)
- `parseUIDeclaration` ينتج `UIDeclarationNode` بحقول: `name`, `parentName`, `stateDecls`, `methods`.
- المفسر **لا يسجّل** `UIDeclarationNode` في سجل الأصناف، لذا `جديد المكوّن()` يفشل بـ
  «متغير غير معرّف: جديد» (SEM001) — **الدليل:** `test_event_system.ص:132`.
- منطق إنشاء الأصناف موجود في `statement_executor_oop.cpp`.

## معايير القبول
- AC-1: `متغير م = جديد مكوّن()` لمكوّن `واجهة_تصريحية نموذج_أحداث` ينجح دون SEM001.
- AC-2: `نوع(م) == "object"`.
- AC-3: حقول `@حالة` تُهيّأ بقيمها الابتدائية (`@حالة عداد = 0` → `م.عداد == 0`).
- AC-4: دوال المكوّن قابلة للاستدعاء (`م.عند_زيادة()` تعمل وتعدّل الحقل).
- AC-5: الوراثة `يرث أب` تُحترم (المكوّن يرث حقول/دوال الأب).

## المهام/المهام الفرعية
- [ ] T1: عند تنفيذ `UIDeclarationNode`، تسجيله في سجل الأصناف كـ ClassDeclaration معادل.
  - [ ] تحويل `stateDecls` (@حالة) إلى حقول، و`methods` إلى دوال الصنف.
  - [ ] اختبار: `جديد نموذج_أحداث()` لا يرمي SEM001.
- [ ] T2: تهيئة حقول `@حالة` بقيمها الابتدائية في الباني الضمني.
  - [ ] اختبار: `م.عداد == 0` بعد الإنشاء.
- [ ] T3: ربط دوال المكوّن (بما فيها `بناء()`) كدوال صنف قابلة للاستدعاء.
  - [ ] اختبار: `م.عند_زيادة()` ثم `م.عداد == 1`.
- [ ] T4: دعم الوراثة `يرث` (إعادة استخدام آلية وراثة الأصناف القائمة).
  - [ ] اختبار: مكوّن يرث من آخر يصل لحقول الأب.
- [ ] T5: تشغيل `test_event_system.ص` (قسم «واجهات مع @حالة») والتأكد من المرور.
