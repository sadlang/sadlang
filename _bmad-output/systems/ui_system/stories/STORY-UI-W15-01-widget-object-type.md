# STORY-UI-W15-01 — تصنيف WidgetBuilder ككائن في `نوع()`

## القصة
بصفتي مطوّر تطبيقات بلغة ص، أريد أن يُرجع `نوع(زر("x"))` القيمة `"object"` (لا `"مجهول"`)،
حتى أتمكن من التحقق من نوع العناصر والتعامل معها كقيم من الدرجة الأولى.

## السياق التقني (من الكود)
- `WidgetBuilder` يرث `Data::ObjectInstance` بِـ `CLASS_NAME` وهمي (`widget_builder.h:251`).
- الدالة المدمجة `نوع()` تصنّف القيمة بناءً على `ValueType`/`getClassName`؛ حالياً
  `WidgetBuilder` يسقط في فرع «مجهول» بدل «object».
- **الدليل:** `نوع(زر("اختبار"))` → `"مجهول"` (تحقق وظيفي 2026-06-08).

## معايير القبول
- AC-1: `نوع(زر("x")) == "object"` يعود `صحيح`.
- AC-2: `نوع(عمود)` و`نوع(حقل_نص("h"))` ترجع `"object"` أيضاً.
- AC-3: `نوع()` لكائن صنف عادي (`جديد نقطة()`) يبقى `"object"` دون تغيير (لا تراجع).
- AC-4: `نوع()` للأنواع البدائية (رقم/نص/منطقي/مصفوفة) لا يتأثر.

## المهام/المهام الفرعية

  (`value.cpp:217`) كان يضبط `sadType_=reg().getAny()` ⇒ Any لكل كائن.
- [x] T2: ~~عبر `isWidgetBuilder()` في طبقة `نوع()`~~ — **عُولج جذريًّا أعمق** (انظر القرار أدناه):
  وسم الكائن بنوعه الصنفيّ `getOrCreateClass(getClassName())` ⇒ `getKind()=Class` ⇒ «كائن».
  - [x] تحقّق: `نوع(زر("ز"))=«كائن»` و`نوع(عمود(نص_عنصر("ن")))=«كائن»` (تشغيل فعليّ).
- [x] T3: العناصر تُصنّف ككائن — العنصر (`WidgetBuilder`/`ObjectInstance`) يمرّ بنفس المنشئ،
  فكلّ عنصر يُنشأ يُرجع «كائن» (تحقّق: زر + عمود؛ والباقي نفس المسار).
- [x] T4: عدم تراجع — تحقّق تفاضليّ شامل عبر **1523 اختبار behavior** (مفسّري مقابل الأساس،

  `نوع(5)=رقم`، `نوع("ن")=نص`، `نوع(صحيح)=منطقي`، `نوع([1])=مصفوفة`. والأصناف العادية:
  `نوع(نقطة(5))=كائن` (كان «أي» — هذا جوهر الإصلاح، يطابق المترجم).

  المستقلّة — خارج نطاق W15-01.

## ملاحظات + قرار النهج
- **انحراف مُبرَّر عن «طبقة نوع()»:** اقترحت الستوري الإصلاح في طبقة `نوع()` عبر `isWidgetBuilder`
  (بناءً على تحليل ساكن ظنّ المشكلة خاصّة بـ`WidgetBuilder`). لكنّ تقرير التشغيل (2026-06-15)
  أثبت أنّ **كلّ كائن** متأثّر (`نقطة(5)`=«أي» أيضًا)، وأنّ **المترجم يُرجع «كائن»** (المرجع
  الصحيح). فالجذر (BF-04) في **وسم القيمة** (`value.cpp:217`) لا في `نوع()`. إصلاحه هناك يحقّق
  تكافؤ المفسّر=المترجم لكلّ الكائنات (عناصر + أصناف)، ويتجنّب ترقيع موضع الاستعمال (BF-09/BF-10).
- لم يُكسر `getClassName()` (يُستعمل كقراءة فقط لتحديد اسم النوع).
- استُخدم نظام الأنواع الموحَّد حصرًا (`SadType`/`getOrCreateClass`) — **لا `DataType`** (محذوف).
