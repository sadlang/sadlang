## 🗳️ القرار 1 — استراتيجية الـ `id`

### الخيارات المطروحة

| # | الاستراتيجية | المثال | تعديل YAML؟ | المخاطر |
|---|---------------|--------|----|--------|
| **A** | اشتقاق من `TokenType` enum | `KEYWORD_IF` → `"keyword.if"` | لا | يكسر إذا تغيّر اسم enum |
| **B** | حقل `id` صريح في YAML | `id: "kw.if"` (يدوي) | نعم — لكل 91 إدخال | عمل يدوي + خطر تكرار |
| **C** | مزيج: اشتقاق تلقائي + override اختياري في YAML | افتراضي اشتقاق، يمكن override بـ `id: "..."` | اختياري (90 بدون، 1 بـ override) | تعقيد بسيط في الكود |

---

### 🏛️ رأي المعماري

> **اختياري: C (المزيج).**
>
> **الحجج:**
> 1. **CW-24 (التوافقية الخلفية):** الـ `id` يجب أن يكون **مستقراً للأبد**. اشتقاقه من `TokenType` يربطه بـ enum داخلي قابل للتغيير. الاسم العربي `"دالة"` لن يتغيّر، لكن `KEYWORD_FUNCTION` قد يُعاد تسميته.
> 2. **مبدأ المسؤولية الواحدة (CW-01):** الـ `id` هو **عقد عام للمستهلك الخارجي** (الموقع، الـ IDE). لا يجب أن يكون مرتبطاً بأسماء C++ داخلية.
> 3. **الخيار C يجمع الأفضل:** افتراض ذكي (لا عمل يدوي للـ 90 كلمة) + بوابة تخصيص مستقبلية (إذا اضطرنا لتغيير enum، نضيف override بدون كسر العقد الخارجي).
>
> **اعتراض على A:** "TokenType مستقر" افتراض غير محقق. تاريخياً، أعيدت تسمية `KEYWORD_INTERFACE` → `KEYWORD_TRAIT` في v4.1. سيحدث ثانية.
>
> **اعتراض على B:** عمل يدوي لـ 91 كلمة = خطر أخطاء + DRY violation (الاسم العربي وحده يكفي لتوليد id).

### 🧪 رأي ضامن الجودة

> **اختياري: A (الاشتقاق).**
>
> **الحجج:**
> 1. **قابلية الاختبار:** الاشتقاق دالة pure — `f(TokenType, KeywordCategory) → string`. اختبار وحدة واحد يغطي كل الـ 91 حالة + الحالات المستقبلية تلقائياً.
> 2. **Idempotency مضمونة:** لا حالة مخفية، لا مدخلات متعددة، نتيجة حتمية.
> 3. **اكتشاف التراجع تلقائي:** إذا تغيّر `TokenType`، تتغيّر الـ ids → snapshot tests تكسر فوراً → نقاش جماعي قبل المرور.
>
> **اعتراض على B:** الإدخال اليدوي = حقل جديد قابل للتلوّث (مسافات، typos)، يحتاج validation script.
>
> **اعتراض على C:** يضاعف مساحة الاختبار (default + override path)، تعقيد بدون منفعة فورية.
>
> **تنازل:** أقبل C إذا توفّرت **اختبارات golden snapshot** تكشف أي تغيّر تلقائياً.

### ⚙️ رأي المنفّذ

> **اختياري: A (الاشتقاق).**
>
> **الحجج:**
> 1. **التكلفة:** A = دالة 30 سطراً + اختبار. B = تعديل 91 سطر YAML + توليد + اختبار. C = A + كود override + تخطيط للتداخل.
> 2. **DRY (CW-19):** المعلومات اللازمة للـ id موجودة بالفعل في `(category, english)` — لا داعي لكتابتها مجدداً.
> 3. **YAGNI:** لا يوجد طلب فعلي لتجاوز افتراض الاشتقاق. أضِف C عند الحاجة الأولى الفعلية.
>
> **تنازل:** أقبل C إذا أصرّ المعماري، لكن أرفض B قطعاً.

### ✅ القرار النهائي للقرار 1

**المعتمد: A (الاشتقاق) + ضمانات قوية**
- **المنطق:** الاشتقاق التلقائي من `(category, english)` بدلاً من `TokenType` لزيادة الاستقرار.
- **الصيغة:**
  - `reserved` → `"keyword." + english.toLowerCase()` (مثال: `"keyword.if"`, `"keyword.function"`)
  - `operator` → `"operator." + english.toLowerCase()` (مثال: `"operator.and"`)
  - `contextual` → `"contextual." + english.toLowerCase()` (مثال: `"contextual.async"`)
  - `builtin_type` → `"type." + english.toLowerCase()` (مثال: `"type.integer"`)
- **التغيير عن الاقتراح الأصلي:** الاشتقاق من `english` (مستقر معجمياً) **وليس** من `TokenType` (قابل لإعادة التسمية).
- **التزامات:**
  1. snapshot test في `tests/sadinfo/golden/keyword_ids.json` يحوي قائمة كل الـ 91 id.
  2. توثيق صريح في `tools/sadinfo/README.md`: "ids مستقرة إلى الأبد منذ schema 1.1.0".
  3. TODO في Story 1.6: إضافة آلية override + `published-keyword-ids-v1.json` registry.

**التصويت:** 🏛️ ✅ (تنازل عن C) | 🧪 ✅ | ⚙️ ✅

## 📋 مراجعة الخطة — كل وكيل يقدّم 3 ملاحظات

### 🏛️ ملاحظات المعماري

1. **🚨 تناقض في المخطط:** الخطة تذكر `kSchemaVersion` = `"1.1.0"`، لكن لا تحدّث `tool` version. **توصية:** ارفع `kToolVersion` من `"0.1.0"` إلى `"0.2.0"` (إصدار ثانوي = ميزات backward-compatible).
2. **🚨 معالجة `--lang en`:** الخطة تقول "يبقي english"، لكن لا تذكر ماذا يحدث بـ `word` (العربي). **توصية:** `--lang en` يبقي **كليهما** لأن `word` هو المفتاح الأساسي وليس "ترجمة عربية". صحّح AC-B3.
3. **🚨 `since: "1.0"` غير صحيح تاريخياً:** بعض الكلمات مثل `أجّل` و`اختر` (goroutines) أُضيفت في v3.x. **توصية:** افتراضي `"unspecified"` (أو حذف الحقل تماماً) حتى نضيف بيانات حقيقية في YAML v4.2.

### 🧪 ملاحظات ضامن الجودة

1. **🚨 ترتيب الـ JSON keys:** الخطة تذكر "إخراج بترتيب YAML"، لكن لا تحدد ترتيب **الحقول داخل كل entry**. **توصية:** ترتيب صريح: `id, word, english, category, tokenType, emittedByLexer, since, aliases, roles`. اختبار snapshot يفرضه.
2. **🚨 لا اختبار للأخطاء:** الخطة تذكر "exit=2 لقيمة `--lang` خاطئة"، لكن لا اختبار يفحص ذلك. **توصية:** `tests/sadinfo/test_dump_keywords_errors.cpp` يغطّي 5 حالات خطأ على الأقل.
3. **🚨 `--filter` بدون `=`:** ماذا يحدث لـ `--filter category` (بدون قيمة)؟ الخطة لا تذكر. **توصية:** خطأ exit=2 مع رسالة واضحة "missing value for filter key 'category'".

### ⚙️ ملاحظات المنفّذ

1. **🚨 تكلفة yaml-cpp:** المستخدم اختار `yaml-cpp`، لكن الخطة قدّرت 45 دقيقة لـ "كاتب YAML داخلي". الواقع: إضافة yaml-cpp إلى cmake + linking + اختبار = ~1 ساعة + احتمال مشاكل بناء على Windows. **توصية:** زيادة التقدير إلى 1.5 ساعة + خطة fallback إن فشل البناء.
2. **🚨 إعادة استخدام الكود:** Task 6 يضيف 5 شعب (`--by-category`, `--minimal`, `--lang`, format, filter) في `dump_keywords.cpp`. **توصية:** استخراج كل تحويل إلى دالة pure منفصلة في `keyword_transforms.cpp` لاتباع CW-19 (DRY) و CW-23 (قابلية الاختبار).
3. **🚨 stdout vs stderr:** الخطة تخلط بينهما. **توصية:** stdout = JSON/YAML فقط (machine-parseable). stderr = تحذيرات + أخطاء + معلومات.

## 🆕 اكتشاف جديد — `--include-deprecated` ليس بلا أثر

### الواقع
ملف `data/language/keywords.yaml` يحوي صراحة:
```yaml
# ── مهجور / Deprecated ──
- { word: "اعطِ", tokenType: KEYWORD_GIVE_DEPRECATED, english: give_deprecated }
```

### الأثر على الخطة
- **AC جديد B6:** بدون `--include-deprecated` → يُحذف `KEYWORD_GIVE_DEPRECATED` من المخرجات (90 entry).
- **AC جديد B7:** مع `--include-deprecated` → يُضمَّن (91 entry).
- **AC جديد C4:** entries مُهمَلة تحوي حقل إضافي `"deprecated": true`.
- **اكتشاف اللغة:** الكلمات التي اسم tokenType ينتهي بـ `_DEPRECATED` تُعتبر deprecated.

### تعديل اشتقاق الـ id
- `KEYWORD_GIVE_DEPRECATED` → `"contextual.give"` (نحذف لاحقة `_deprecated` من english أيضاً).
- **توصية الجودة:** اختبار صريح يفحص هذه الحالة.
