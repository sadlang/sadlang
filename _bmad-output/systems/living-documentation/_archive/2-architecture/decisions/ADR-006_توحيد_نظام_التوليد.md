## 1. السياق (Context)

### 1.1. الوضع الحالي

نظام «الأسماء القانونية للدوال المدمجة وطرق الأنواع» في لغة ص يقع حالياً في **ثلاثة جزر معزولة**:

| الملف | عدد العناصر | الحالة | المصدر |
|---|---|---|---|
| `shared/builtins/include/builtin_registry.h` | 552 ثابت في 32 namespace | **يدوي** | لا مصدر — مكتوب يدوياً |
| `shared/builtins/include/module_definitions.h` | 10 modules + aliases | **يدوي** | لا مصدر — مكتوب يدوياً |
| `shared/builtins/include/builtin_categories.h` | 2 enums (Category, CompilerStrategy) | **يدوي** | يبقى يدوياً (schema) |
| `shared/builtins/generated/type_methods_generated.h` | 80 طريقة × 7 أنواع | **مولَّد** | `data/language/type_methods.yaml` |
| `shared/builtins/generated/keywords_generated.h` | كلمات محجوزة | **مولَّد** | `data/language/keywords.yaml` |

### 1.2. المولِّدات الموجودة

- `scripts/codegen/gen_keywords.py` (273 سطر) — منعزل.
- `scripts/codegen/gen_type_methods.py` (490 سطر) — منعزل.

كل منهما يكرر:
- منطق قراءة YAML.
- منطق التحقق من schema.
- منطق `write_if_changed` (deterministic build).
- منطق `cpp_string_literal()` (UTF-8 escape).
- منطق توليد `inline constexpr std::string_view` constants.
- منطق توليد namespaces بترتيب ثابت.

### 1.3. المشاكل المعمارية

| المشكلة | القاعدة المنتهكة | التأثير |
|---|---|---|
| 552 اسم في `builtin_registry.h` غير مرتبطة بمصدر بيانات (SoT) | CW-04 (التناسق البنيوي) | تعديل اسم → بحث يدوي في 9+ ملفات |
| ازدواجية الأسماء بين registry و YAML stdlib | CW-19 (DRY) | تغيير canonical → drift بين المفسر والوثائق |
| `gen_keywords.py` و `gen_type_methods.py` يكرران ~200 سطر كل واحد | CW-19 (DRY) | تغيير منطق emit → تكرار في n مولِّد |
| لا يوجد orchestrator واحد يربط المولِّدات | CW-02 (تسلسل الطبقات) | ترتيب التوليد غير واضح في CMake |
| لا schema موحَّد لتعريف "feed" — كل مولِّد يخترع schema منفصل | CW-21 (واجهات واضحة) | إضافة مولِّد جديد = نسخ-لصق |
| فحص edge cases (تكرار، canonical UTF-8، shadda) مكرر في كل مولِّد | BF-27 (قاعدة الثلاثة) | فحص ينقصه في مولِّد = ثغرة |

### 1.4. الدافع المباشر

أثناء UTM-3.3d (registry-driven dispatch لـ concurrency)، اكتُشف:

1. أضفنا طبقة `EnglishNames` المولَّدة → اتضح أنها **زائدة عن الحاجة** لأن `Names::TARGET::NAME` (canonical Arabic) تحقق نفس فوائد typo-safety + SoT-driven دون indirection.
2. القاعدة المستخلصة: **«أي طبقة codegen يجب أن تقدم فائدة لا تقدمها الأبسط الموجودة»**.
3. تطبيق هذه القاعدة على المنظومة كلها يكشف العكس: لدينا **552 ثابت** في `builtin_registry.h` بلا أي طبقة codegen أصلاً، بينما 80 طريقة فقط في `type_methods` مغطاة بـ codegen كامل.

التناقض واضح: الأكبر يدوي والأصغر مولَّد — هذا انتهاك CW-04.

### 2.2. المبادئ الموجِّهة

1. **مصدر حقيقة وحيد**: لا يوجد اسم قانوني (`std::string_view`) في `shared/builtins/include/` بدون مصدر YAML.
2. **توحيد الأدوات**: جميع المولِّدات تستعمل نفس `_lib/loader.py + emit.py + validator.py`. لا تكرار منطق.
3. **orchestrator واحد**: CMake لا يعرف عن المولِّدات الفردية — يستدعي `gen_all.py` فقط.
4. **API ثابت**: `Names::Core::PRINT`, `Names::Concurrency::CHANNEL` تبقى متوفرة بنفس التوقيع. الترحيل **داخلي 100%** (CW-24).
5. **بناء deterministic**: `write_if_changed` في كل output → CMake لا يعيد build إلا عند تغيير حقيقي.
6. **schema للجميع**: كل feed له JSON Schema، يُفحص في كل مولِّد قبل توليد أي سطر C++.
7. **تقسيم modular**: لا feed أكبر من ~100 سطر YAML — التقسيم بحسب namespace الحالي.
8. **حواجز معمارية**: `gen_all.py` يفحص أن `shared/builtins/include/` لا يحوي `inline constexpr std::string_view` يدوي (ما عدا `builtin_categories.h` الذي يبقى enum-only).

```python
# scripts/codegen/_lib/emit.py

import hashlib
from pathlib import Path

def cpp_string_literal(s: str) -> str:
    """يُحوِّل سلسلة Python إلى \"...\" آمنة في C++ (UTF-8 escape)."""
    out = ['"']
    for ch in s:
        if ch == '"':   out.append('\\"')
        elif ch == '\\': out.append('\\\\')
        elif 32 <= ord(ch) < 127: out.append(ch)
        else:
            for b in ch.encode('utf-8'):
                out.append(f'\\x{b:02X}')
    out.append('"')
    return ''.join(out)

def emit_namespace(name: str, body: str, indent: int = 0) -> str:
    pad = ' ' * indent
    return f'{pad}namespace {name}\n{pad}{{\n{body}\n{pad}}}\n'

def emit_constant(name: str, value: str, type: str = 'std::string_view', indent: int = 12) -> str:
    pad = ' ' * indent
    return f'{pad}inline constexpr {type} {name} = {cpp_string_literal(value)};\n'

def emit_lookup_table(name: str, entries: list[tuple[str, str]], key_type='std::string_view', val_type='std::string_view') -> str:
    """ينتج std::array<std::pair<...>, N>."""
    ...

def write_if_changed(path: Path, content: str) -> bool:
    """يكتب الملف فقط إذا تغيَّر محتواه. يُرجع True إن تغيَّر."""
    new_hash = hashlib.sha256(content.encode('utf-8')).hexdigest()
    if path.exists():
        old_hash = hashlib.sha256(path.read_bytes()).hexdigest()
        if old_hash == new_hash:
            return False
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(content, encoding='utf-8', newline='\n')
    return True
```

```python
import unicodedata

SHADDA = '\u0651'

def validate_canonical_utf8(name: str, context: str = ''):
    """يفحص أن الاسم NFC، بدون shadda، بدون ZWJ/ZWNJ."""
    if SHADDA in name:
        raise ValueError(f'{context}: الاسم "{name}" يحوي شدَّة (U+0651) — ممنوع')
    nfc = unicodedata.normalize('NFC', name)
    if nfc != name:
        raise ValueError(f'{context}: الاسم "{name}" ليس NFC')
```

### 3.7. مواصفات `gen_all.py`

```python
# scripts/codegen/gen_all.py

import sys
from pathlib import Path
from _lib.loader import load_all
from _lib.validator import (
    validate_canonical_utf8,
    validate_no_duplicates_global,
    validate_module_references,
    validate_no_keyword_collision,
)

def main(repo_root: Path, quiet: bool = False) -> int:
    # 1) تحميل كل شيء
    index, feeds = load_all(repo_root)

    # 2) validations عامة
    builtins_feeds = {fid: f for fid, f in feeds.items() if fid.startswith('builtins.')}
    validate_no_duplicates_global(builtins_feeds)
    validate_module_references(builtins_feeds, feeds['modules'])
    validate_no_keyword_collision(builtins_feeds, feeds['keywords'])
    for fid, f in feeds.items():
        for item in f.data.get('functions', f.data.get('methods', [])):
            validate_canonical_utf8(item['canonical'], context=fid)

    # 3) تشغيل المولِّدات بالترتيب
    from gen_keywords      import generate as gen_kw
    from gen_modules       import generate as gen_mod
    from gen_type_methods  import generate as gen_tm
    from gen_builtins      import generate as gen_bi

    changed = []
    changed += gen_kw(feeds['keywords'], repo_root)
    changed += gen_mod(feeds['modules'], repo_root)
    changed += gen_tm(feeds['type_methods'], repo_root)
    changed += gen_bi(builtins_feeds, feeds['modules'], repo_root)

    # 4) فحص الحراس
    enforce_guards(index.guards, repo_root)

    if not quiet:
        print(f'[gen_all] feeds={len(feeds)} outputs_changed={len(changed)}')
    return 0

def enforce_guards(guards, repo_root):
    """يفحص أن لا ملف يدوي في shared/builtins/include/ يحوي
    inline constexpr std::string_view (ما عدا الاستثناءات)."""
    forbidden = guards.get('forbidden_manual_constants', {})
    for path_str in forbidden.get('paths', []):
        for h in (repo_root / path_str).glob('*.h'):
            if str(h.relative_to(repo_root)).replace('\\', '/') in forbidden.get('exclude', []):
                continue
            if 'inline constexpr std::string_view' in h.read_text(encoding='utf-8'):
                raise SystemExit(f'GUARD: ثابت يدوي في {h} — يجب أن يكون مولَّداً')

if __name__ == '__main__':
    sys.exit(main(Path(__file__).resolve().parents[2]))
```

## 5. ضمانات (Guarantees)

### 5.1. التوافق العكسي (CW-24)

- جميع الـ symbols العامة تبقى كما هي:
  - `Sad::Builtins::Names::Core::PRINT` → نفس النوع `std::string_view`، نفس القيمة `"اطبع"`.
  - `Sad::Builtins::ModuleId::MATH` → نفس القيمة `1`.
  - `Sad::Builtins::resolveModuleId("رياضيات")` → نفس السلوك.
- الاختلاف الوحيد: الملف الذي يحوي التعريف.
  - قبل: `shared/builtins/include/builtin_registry.h` (يدوي).
  - بعد: `shared/builtins/generated/builtin_names_generated.h` (مولَّد).
- `builtin_registry.h` يبقى كـ aggregator header يعمل `#include` للملفات المولَّدة → users لا يلاحظون تغييراً.

### 5.2. أمان البناء (Build Safety)

- `write_if_changed`: ملف `.h` لا يُكتب إلا عند تغيير حقيقي → CMake لا يعيد compile دون داعي.
- `enforce_guards`: محاولة إضافة ثابت يدوي في `shared/builtins/include/` → فشل البناء فوراً.
- schema validation: تعديل YAML بشكل خاطئ → فشل codegen قبل أي C++ compile.

### 5.3. الأداء (Performance)

- جميع الثوابت تبقى `inline constexpr std::string_view` → نفس الـ ABI، نفس الـ binary size.
- جداول البحث تستعمل `std::array<std::pair<...>, N>` constexpr → linear search مقبول لأن N صغير (≤ 600 عنصر، استدعاء واحد عند initialization).
- بدائل: إذا أصبح bottleneck، يمكن لاحقاً توليد perfect hash (`gperf`-style) داخل `emit.py` دون تغيير API.

### 5.4. Idempotency و Determinism

- ترتيب feeds في `index.yaml` ثابت.
- ترتيب functions داخل كل YAML ثابت (لا sort غير مقصود).
- `cpp_string_literal()` بايت-deterministic لنفس المدخل.
- نفس commit → نفس output bytes تماماً.

## 7. البدائل المرفوضة (Rejected Alternatives)

### بديل أ: إبقاء `builtin_registry.h` يدوي، توليد فقط ما هو موجود
**رفض:** يكرّس انتهاك CW-04 و CW-19. النمو من 552 إلى 1000+ مع توسع المكتبات سيُضخّم المشكلة.

### بديل ب: مولِّد واحد ضخم `gen_everything.py` بلا `_lib`
**رفض:** ينتهك CW-01 (مسؤولية واحدة) و CW-21 (واجهات واضحة). صعب الصيانة والاختبار.

### بديل ج: استعمال C++ template metaprogramming بدلاً من codegen
**رفض:** أسماء عربية في templates → unreadable + compile time صاروخي + لا يحل مشكلة SoT.

### بديل د: نقل البيانات إلى JSON بدل YAML
**رفض:** YAML أوضح للقراءة البشرية + تعليقات + الأدوات الموجودة (gen_keywords/type_methods) تستعمل YAML.

### بديل هـ: إبقاء طبقة `EnglishNames` لكن تطبيقها على builtin_registry أيضاً
**رفض:** هذا ما تم رفضه أصلاً في UTM-3.3d-fix2 — `Names::*` (canonical Arabic) يقدم نفس فوائد typo-safety + SoT دون أي indirection.

## 8. معايير القبول (Acceptance Criteria)

1. **صفر** ثابت `inline constexpr std::string_view` يدوي في `shared/builtins/include/` (ما عدا `builtin_categories.h` الذي يحوي enums فقط).

### 10.11. مثال — درس مولَّد من YAML

```yaml
lesson:

  order: 4
  estimated_minutes: 15
  prerequisites: [basics.variables, basics.loops]

        code: |

              ارجع أ + ب
          نهاية
          اطبع_سطر(جمع(3، 5))
        expected_output: "8"
        runnable: true                     # يُشغَّل في CI ويُتحقق من الإخراج
```

### 10.12. ضمانات التوافق بين التوثيق واللغة (5 فحوصات صارمة)

`_lib/docs_validator.py` يفشل البناء عند أي عدم توافق:

| # | الفحص | الفشل عند |
|---|---|---|
| 1 | كل `references.keywords` موجودة في `keywords.yaml` | حذف كلمة من اللغة دون تحديث الدروس |
| 2 | كل `references.builtins` موجودة في `builtins/*.yaml` | حذف/إعادة تسمية دالة دون تحديث |
| 3 | كل `references.type_methods` موجودة في `type_methods.yaml` | تغيير اسم طريقة |
| 4 | كل `references.modules` موجودة في `modules.yaml` | تغيير اسم وحدة |
| 5 | كل `example.runnable: true` يُشغَّل ويطابق `expected_output` | تغيير دلالة دالة دون تحديث المثال |

**النتيجة:** إذا حذف مطوِّر كلمة `دالة` من `keywords.yaml` → كل الدروس التي تذكرها تفشل في البناء فوراً → **مستحيل** أن يتقادم التوثيق.

### 10.13. الحارس المعاكس — كل ميزة في اللغة لها توثيق

`enforce_docs_coverage` يفشل إذا أُضيفت دالة عامة (`visibility: public`) في YAML بدون أن تُذكر في أي درس/دليل/صفحة مرجع. كل دالة جديدة تُضاف للغة → المطوِّر **مُجبَر** على توثيقها قبل دمج التغيير.

```python
def enforce_docs_coverage(language_feeds, docs_feeds):
    """يفشل إذا دالة عامة بلا أي توثيق."""
    documented = set()
    for ds in docs_feeds.values():
        refs = ds.data.get('lesson', ds.data.get('guide', ds.data.get('concept', {}))).get('references', {})
        for kind in ('builtins', 'keywords', 'type_methods', 'modules'):
            documented.update(refs.get(kind, []))

    for fid, feed in language_feeds.items():
        if not fid.startswith('builtins.'):
            continue
        for fn in feed.data['functions']:
            if fn.get('visibility', 'public') == 'public' and fn['canonical'] not in documented:
                raise SystemExit(
                    f"DOCS-COVERAGE: الدالة '{fn['canonical']}' في {fid} "
                    f"بلا توثيق — أضف صفحة مرجع أو اذكرها في درس."
                )
```

### 10.15. الفائدة الإجمالية (لماذا هذا الجهد يستحق)

- **صفر drift:** تغيير في اللغة → الموقع يُحدَّث في نفس البناء.
- **استحالة التقادم:** البناء يفشل إذا الدرس يذكر ميزة محذوفة، أو ميزة جديدة بلا توثيق.
- **أمثلة محققة:** كل مثال `runnable` في كل درس يُشغَّل في CI — لا أمثلة معطوبة.
- **إجبار المطوِّر:** PR يضيف دالة بدون توثيق → فشل CI تلقائي → المطوِّر مُلزَم بكتابة YAML الدرس.
- **ثنائية اللغة مستقبلاً:** YAML يحوي حقول عربية وإنجليزية → نسختان من الموقع تلقائياً (UTM-6.14).
- **روابط متبادلة:** `see_also` و `prerequisites` في YAML → روابط Markdown تلقائية بين الدروس.
