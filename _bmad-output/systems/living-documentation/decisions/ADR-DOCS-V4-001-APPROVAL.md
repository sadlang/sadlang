# ADR-DOCS-V4-001 — اعتماد استراتيجية V4

## السياق (Context)

- المُنطلق: نظام "Living Documentation V3" كان يُحاول أن يكون **طبقة هَندسية مَركزية فوق `shared/`** تَتحكَّم بكل الأدوات (LSP، Website، Formatter، Compiler). هذا أَنتج Coupling مَرتفع جداً ومسؤولية ضَبابية.
- بعد سلسلة مُحادثات (2026-06-04) مع المالك، تَبلوَرَت **رؤية V4** التي تُضيِّق النطاق:
  > "نحن نَهتم باللغة نفسها فقط… كل فريق أداة هو المسؤول أن يكون توثيقه صحيحاً ولسنا نحن… لا علاقة لنا كيف تَستخدم الأدوات مصدر الحقيقة أو أين ستَحفظ ملفاتها."

## القرار (Decision)

**نَعتمد رسمياً `_bmad-output/systems/living-documentation/STRATEGY.md` بالإصدار V4** على الفور (`status: APPROVED`)، بالشروط التَفصيلية التالية:

### 1. النطاق المُلزِم (يَخرج عنه أي عمل = خَرق)

| داخل النطاق ✅ | خارج النطاق ❌ |
|---|---|
| الكلمات المفتاحية (~74 = 40 محجوزة + 25 سياقية + 9 أنواع مدمجة) | كيف يَعرض LSP الكلمات |
| التَوجيهات (`@حجم` …) | كيف يُنسِّق Formatter الكود |
| الدوال المضمنة (~25) | كيف يُولِّد Website صفحات |
| العَوامل والأنواع المدمجة | تَخزين أو موقع وثائق الأدوات |
| قواعد القَواعد (Grammar) | جودة الترجمة في وثائق الأدوات |
| رسائل الأخطاء + اقتراحات الإصلاح | Snippets أو Templates أو Tutorials |
| وحدات stdlib (الأسماء + الـ API) | شرح الفلسفة، الدُروس، التَمارين |
| إصدار الإطلاق (`since`) لكل كيان | أي محتوى تَعليمي |

### 2. المُنتَجات المُسلَّمة من Truth (و لا غَيرها)

1. **`language-truth/`** — جذر مُنفصِل عن `tools/`, `website/`, `shared/`
2. **YAML خام** مُهيكَل عبر JSON Schema لكل فئة
3. **`libsadlangtruth`** (C++ Library): واجهة `getKeyword`, `getDirective`, `getBuiltin`, `getOperator`, `getType`, `getError`, `getAllKeywords`, …
4. **`sadlang-info`** (CLI): `list keywords`, `show KW-FUNC-001`, `search "دالة"`, `stats`
5. **4 اختبارات إلزامية**: Schema، Language Match، Unique IDs، Required Fields

### 3. ما لا نَفعله (و لا نَقبل ضَغطاً لفعله)

- ❌ لا نَكتب أو نُراجع وثائق LSP / Formatter / Website
- ❌ لا نُحدِّد كيف تُخزِّن أي أداة وثائقها (مَكان، صيغة، تَنسيق)
- ❌ لا نَفرض "Consumer Compliance" على الأدوات
- ❌ لا نُولِّد Snippets أو Tutorials أو محتوى تَعليمي
- ❌ لا نَدمج Truth مع طبقات أخرى في نفس النظام

### 4. القَواعد غير القابلة للتَفاوض (ND-V4-1 إلى ND-V4-8)

تَنطبق كاملةً من [STRATEGY.md §7](../STRATEGY.md). أي تعارض مع هذه القَواعد يُرفض تلقائياً.

### 5. حُدود المسؤولية (Boundary)

```
┌─────────────────────────────────────────────────────────────┐
│  مسؤوليتنا (Language Team)                                 │
│  ───────────────────────────────────────                   │
│  • language-truth/*.yaml                                    │
│  • libsadlangtruth (C++)                                    │
│  • sadlang-info (CLI)                                       │
│  • 4 اختبارات: schema, language-match, ids, required       │
│  • سياسة التَغيير (PR لكل تَعديل YAML)                       │
└─────────────────────────────────────────────────────────────┘
                            │
                            │ يَستهلك (read-only)
                            ▼
┌─────────────────────────────────────────────────────────────┐
│  مسؤولية فِرَق الأدوات (مَنفصلة تماماً)                       │
│  ───────────────────────────────────────                   │

│  • Website Team: كيف يَبني صفحات وأين                       │
│  • Formatter Team: كيف يَتعامل مع التَنسيق                  │
```

## البَدائل المَرفوضة (Alternatives Rejected)

| البديل | لماذا رُفِض |
|---|---|
| **V3** (طبقة مَركزية تَتحكَّم بالأدوات) | Coupling عالي، نَجعل أنفسنا BFS Bottleneck، صعوبة التَوسُّع |
| **V4-DRAFT-1** (قسمان: Truth + Tool Docs مع تَخزين موصوف) | يَفرض على الأدوات كيف تُخزِّن وثائقها — يَتجاوز نطاقنا |
| **لا Truth مُستقل** (كل أداة تَكتب ما تَحتاج) | يُكرِّر التَعريفات، يَحدث Drift، لا مَصدر موحَّد |

## النَتائج (Consequences)

### إيجابية ✅

- مسؤولية واضحة، لا تَتداخل مع أي فريق آخر
- صَغير القاعدة → سريع التَطوير + سَهل المُراجعة
- اختبار "Truth = Lexer" يَكشف أي drift فوراً
- Coupling صفر مع `tools/` و `website/`
- يُمكن إعادة استخدام Truth لاحقاً من لُغات أُخرى (Rust binding، Python wrapper…)

### سَلبية / تَكلفة ⚠️

- يَحتاج كل فريق أداة بناء طبقته الخاصة فوق Truth (لا حلول جاهزة)
- التَوثيق التَعليمي (تَمارين، Snippets) لا يَأتي مَعنا — يَجب إن أراد المالك إنشاء "Education Team" مَنفصل
- Truth يَحتاج CI صارم (4 اختبارات) لضَمان عدم الانحراف

### مَخاطر (Risks)

| المُخاطرة | الاحتمال | التَأثير | التَخفيف |
|---|:---:|:---:|---|
| فريق أداة يَتجاهل Truth ويَكتب حقائق لُغوية مُكرَّرة | متوسط | عالي | اختبار "no-hardcoded-language-facts" في CI كل أداة (اختياري — قرارهم) |
| Truth يَتأخَّر عن إضافة كلمة جديدة في Lexer | منخفض | عالي | اختبار Language-Match يَفشل في CI → block PR |
| ID Collision بين فِرَق مُختلفة | منخفض | متوسط | اختبار Unique IDs + Naming Convention في README |
