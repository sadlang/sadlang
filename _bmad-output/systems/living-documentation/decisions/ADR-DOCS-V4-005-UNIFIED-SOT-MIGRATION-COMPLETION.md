# ADR-DOCS-V4-005 — تأكيد المصدر الموحَّد وخطة إكمال الهجرة

## السياق (Context)

عند توثيق نظام الأخطاء في مهارة `sad-lang-dev`، تبيّن وجود **ثلاث بنى YAML للأخطاء لا تتطابق**:

| # | البنية | الموقع | الغرض | الحالة |
|---|--------|--------|------|--------|
| ١ | متداخلة (`title/brief/fix_hint/detailed`، `code: LEX_INVALID_CHARACTER`) | `data/language/error_messages.yaml` (V4) + منسوخة في `language-truth/errors/*.yaml` | كتالوج **رسائل** وقت التشغيل → `gen_error_messages.py` → C++ | **نشطة** |
| ٢ | مسطّحة (`message_ar/message_en`، `code: LEX_0001`، `schema_version: 5.0`) | `language-truth/_schemas/error.schema.json` | الصيغة **المُطبَّعة المستهدفة** لـ V5 | **مُصمَّمة، غير مُطبَّقة** (الملفات الفعلية ما زالت بالبنية ١) |
| ٣ | كيانات (`kind/name/severity/owners`، `code: E0001`) | `data/_schemas/error.schema.json` (v1) + `errors/<id>/_index.yaml` | **كتالوج بيانات `sadinfo`** (تصفّح/أدوات/i18n) | نظام موازٍ |

هذا أثار سؤال المالك المعماري: **مصدر حقيقة موحَّد للبيئة كلها، أم مصدر لكل أداة؟**

## القرار (Decision)

**القرار محسوم سلفاً ويُعاد تأكيده هنا: مصدر حقيقة موحَّد واحد (`language-truth/`).**

استناداً إلى `ADR-DOCS-V4-002` (authority: SoT — «المرجع الأوحد») و`ADR-DOCS-V4-003`
(Codegen Integration) و`language-truth/README` («كل الأدوات يجب أن تستهلك من هذا المجلد»):

1. **`language-truth/` هو المصدر الموحَّد الوحيد** لكل بيانات لغة ص.
2. **كل أداة تستهلك إسقاطاً مُولَّداً** من هذا المصدر — لا مصدراً يدوياً خاصاً بها:
   - المترجم/المفسر ← C++ Generated (`shared/*/generated/`)
   - LSP ← جداول مُولَّدة
   - الموقع/التوثيق ← docs مُولَّدة
   - **sadinfo ← كتالوج مُولَّد** (إسقاط، لا مصدر يدوي موازٍ)
3. **الأنظمة الثلاثة ليست تصاميم متنافسة — هي دَيْن هجرة:** البنية ١ = V4 يُتقاعَد؛ البنية ٢ =
   الهدف الموحَّد؛ البنية ٣ = تتحوّل إلى إسقاط مُولَّد من الموحَّد.
4. **(حُسِم 2026-06-09 — ق-فرعي-2):** **sadinfo إسقاط مُولَّد من `language-truth/`، وليس مصدراً.**
   أساس الحسم: استشارة PM (John) — اتجاه التوليد يحدّد المصدر؛ `language-truth/` يولّد كتالوج
   sadinfo، بينما sadinfo لا يستطيع توليد كتالوج C++ التنفيذي (قوالب + placeholders + `ErrorCode`).
   اعتماد sadinfo مصدراً = قلب التبعية (تصيير اللغة مُشتقّة من بيانات تصفّح). الحقول الغنية
   (`owners`/`severity`/i18n/summary) **تُضاف إلى `language-truth/` أو overlay** ثم يُولَّد sadinfo منها.

### لماذا الموحَّد لا «لكل أداة»؟

| موحَّد (المُعتمَد) | لكل أداة مصدرها (مرفوض) |
|---|---|
| تغيير واحد يتموّج آلياً لكل الأدوات | صيانة متعددة + تباعد حتمي (هو الألم الحالي) |
| اتساق مضمون بين اللغة/الموقع/LSP | تناقضات دائمة (`LEX_INVALID_CHARACTER` ضد `E0001` ضد `message_ar`) |
| نقطة تحقّق/حوكمة واحدة | لا ضمان اتساق |

التشتّت الحالي (3 بنى متناقضة) هو **عَرَض هجرة ناقصة**، لا دليل على فشل النموذج الموحَّد.

## نطاق الهجرة: كل نطاقات YAML (لا الأخطاء وحدها)

التوحيد إلى `language-truth/` يشمل **كل بيانات اللغة** — ليس الأخطاء فقط. مصفوفة الحالة الفعلية
(دليل: `cmake/codegen.cmake` + `shared/*/generated/` + `scripts/codegen/gen_all.py`، 2026-06-09):

> **تحديث لقطة الحالة (2026-06-10، بعد إغلاق EM-V5-1..4):** كل النطاقات الـ13 صارت **مربوطة آلياً
> في CMake** عبر دالة `sad_add_codegen` + هدف `sad_all_codegen` (مربوط بـ`sad_shared`، idempotent
> عبر stamp). المصفوفة أدناه تعكس **الحالة قبل التنفيذ (2026-06-09)** للرجوع التاريخي.

| النطاق | مصدر V5 | مخرَج مُولَّد | مربوط CMake (قبل) | مربوط CMake (الآن ✅) |
|--------|:------:|:------------:|:--:|:--:|
| keywords | ✓ | ✓ | ✅ | ✅ |
| builtins (registry) | ✓ | ✓ | ✅ | ✅ |
| errors | ✓ | ✓ (V5، EM-V5-1) | ❌ | ✅ `sad_error_messages_codegen` |
| sadinfo (إسقاط) | — | ✓ (EM-V5-2) | — | ✅ `sad_sadinfo_errors_codegen` |
| operators/directives/types/type_methods/patterns/grammar/oop/expr_constructs/modules/stdlib | ✓ | ✓ | ❌ baseline يدوي | ✅ عبر `sad_add_codegen` (EM-V5-4) |

**الخلاصة (محدَّثة):** **اكتمل توحيد التوليد** — كل النطاقات تُولَّد آلياً وقت البناء من
`language-truth/`، وV4 (`data/language/error_messages.yaml`) حُذف (EM-V5-3). ق-فرعي-3 مُنفَّذ.
