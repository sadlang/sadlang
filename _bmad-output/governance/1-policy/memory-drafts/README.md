# مسودات الذاكرة (Memory Drafts)

> **الوكلاء يكتبون هنا — PM فقط يدمج في `/memories/repo/`.**

## السبب

ذاكرة المشروع (`/memories/repo/`) مصدر حقيقة دائم يُحمَّل تلقائياً في كل جلسة. أي خطأ فيها يُضلّل كل الوكلاء. لذا:
- **الوكلاء:** يكتبون اقتراح ذاكرة هنا بصيغة draft
- **PM:** يراجع، يحرّر، يدمج في `/memories/repo/` (أو يرفض)

## بنية الـ draft

كل draft ملف منفصل بالاسم: `<topic>.draft.md`

```markdown
# <عنوان الذاكرة المقترحة>

**المقترح:** Alpha | Beta | Gamma  
**التاريخ:** YYYY-MM-DD (من `Get-Date`)  
**المهمة المرتبطة:** TASK-XXX  
**الفئة:** [debugging | pattern | gotcha | convention | architecture]  
**الهدف من الذاكرة:** سطر واحد — لماذا هذا يستحق ذاكرة دائمة؟

---

## المحتوى المقترح

<النص النهائي المقترح للذاكرة — قصير ومركّز كقاعدة CW>

---

## دليل/مرجع

- ملفات/أسطر تدعم هذا الدرس: [path](path#L10)
- مهمة/خطأ/PR مرتبط: TASK-XXX, PR #N
```

## دورة الحياة

1. وكيل ينشئ `<topic>.draft.md` هنا.
2. وكيل يذكر في `TASK-XXX.state.md`: "أضفت memory draft: `<topic>`".
3. PM يراجع أسبوعياً (يوم الأحد):
   - **يدمج:** ينقل المحتوى إلى `/memories/repo/<name>.md` ويحذف الـ draft.
   - **يعدّل ثم يدمج:** يعيد كتابة draft بنفسه ثم يدمج.
   - **يرفض:** يضيف سطر سبب في الـ draft ويتركه 30 يوماً ثم يحذف.

## ممنوع

- الوكلاء لا يكتبون مباشرة في `/memories/repo/` (أي تعديل هناك ينقضه PM).
- لا drafts بدون TASK مرتبط.
