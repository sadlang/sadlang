## الملخص التنفيذي

### رؤية المشروع

إضافة VS Code للغة ص هي أول IDE عربي متكامل — من الكلمات المفتاحية العربية إلى رسائل الخطأ الودية. الرؤية: جعل أحمد (مبتدئ 16 سنة) يكتب أول برنامج ناجح بالعربية خلال 10 دقائق من التثبيت. المشروع brownfield (v2.1.0, 24,800+ سطر TypeScript) يدعم 4 بروتوكولات (LSP, DAP, SSH, REST).

### المستخدمون المستهدفون

| الشخصية | المستوى | الهدف | الأولوية |
|---------|---------|-------|----------|
| **أحمد** | مبتدئ (16 سنة) | كتابة أول برنامج بالعربية | 🔴 القصوى |
| **عمر** | متوسط (مطور ويب) | بناء أداة حقيقية | 🟠 عالية |
| **منى** | محترفة (5 سنوات) | مشروع إنتاجي | 🟡 متوسطة |
| **أ. خالد** | معلم حاسب | تدريس 30 طالب | 🟡 متوسطة |
| **سارة** | مساهمة نظام بيئي | نشر حزم | 🔵 مستقبلية |

### تحديات التصميم الرئيسية

1. **RTL داخل VS Code** — محرر Monaco لا يدعم RTL أصلاً. الحل: "جزر RTL ذكية" (WebView panels, Hover widgets, Diagnostics, Status bar) بدلاً من قلب الواجهة بالكامل. RTL ليست مشكلة تقنية فحسب — هي **لحظة فخر** يجب تصميمها كتجربة عاطفية.

2. **جمهور واسع (8 سنوات - محترف)** — بدلاً من طبقات تدريجية معقدة أو toggle صريح:
   - **تكيّف ضمني بالسلوك** — مراقبة أنماط الاستخدام (سرعة الكتابة، نوع الأخطاء، الميزات المُستخدمة) لتعديل مستوى الواجهة تلقائياً
   - **MVP: وضعان (مبتدئ/متقدم)** كنقطة بداية عملية، مع تحول تلقائي بناءً على إشارات واضحة

3. **Onboarding خلال 10 دقائق** — اللحظة الفارقة. MVP: ملف واحد مفتوح + تعليق عربي + زر "شغّل" أخضر. Walkthrough API محدود لـ RTL → يُستبدل بـ Quick Pick خفيف، ثم WebView تفاعلي لاحقاً.

4. **Error Humanizer** — ليس مجرد ترجمة بل **رفيق متعاطف** يتعلم مع المستخدم. Pipeline معماري: `Compiler Error → Parser → Classifier → Arabic Template → Suggestion Engine → UI Layer`. Module مستقل يُخرج structured data، والـ UI تقرر العرض.

### فرص التصميم

1. **أول IDE عربي بلا منافس** — فرصة لوضع المعيار العالمي لتجربة برمجة عربية
2. **Error Humanizer كميزة تنافسية** — الفرق بين "أداة برمجة" و"رفيق تعلم" — يبني ولاءً
3. **التعليم داخل IDE إنتاجي** — بدلاً من بيئة تعليمية منفصلة محدودة
4. **مايكرو-لحظات احتفال** — عند أول `دالة` ناجحة، أول compilation بدون أخطاء — ملاحظات ذكية رقيقة تبني الثقة
5. **Classroom Lite (مستقبلي)** — extension point يُصمم الآن، يُنفذ لاحقاً

### قرارات التصميم المفتوحة

| القرار | الخيارات | التوصية |
|--------|----------|---------|
| مستوى المستخدم | طبقات / toggle / تكيّف ضمني | وضعان كـ MVP → تكيّف ضمني لاحقاً |
| نبرة Error Humanizer | معلم / رفيق / محايد | رفيق متعاطف (تجنب علاقة السلطة) |
| Onboarding | Walkthrough API / Quick Pick / WebView | Quick Pick كـ MVP → WebView لاحقاً |
| التحقق من المستخدمين | بناء مباشر / مقابلات أولاً | 5 مقابلات سريعة (20 دقيقة) قبل MVP |

## تجربة المستخدم الأساسية

### التجربة المُعرِّفة

الفعل الأساسي: **كتابة كود عربي → تشغيل → رؤية النتيجة**. هذا هو الـ core loop الذي يجب أن يكون سلساً تماماً. كل عنصر في الواجهة يخدم هذا التدفق أو يبتعد عن الطريق.

الهدف الأول: أحمد يكتب `اطبع("مرحباً بالعالم")` ويرى النتيجة خلال 10 دقائق من التثبيت.

### استراتيجية المنصة

| الجانب | القرار |
|--------|--------|
| المنصة | VS Code Desktop (Windows/macOS/Linux) |
| التفاعل | Keyboard-first مع دعم RTL |
| الاتصال | Offline-first — كل الأساسيات بدون إنترنت |
| السحابة | Cloud execution كـ enhancement اختياري |
| التوافق | VS Code ≥ 1.85، لا تعارض مع الإضافات الشائعة |

### التفاعلات بلا جهد

1. **فتح ملف `.ص`** → RTL تلقائي فوري (صفر إعدادات)
2. **كتابة كود** → IntelliSense عربي + snippets جاهزة
3. **تشغيل** → ضغطة زر واحدة أو F5 → النتيجة خلال ثانيتين
4. **خطأ** → رسالة عربية فورية + اقتراح حل بنبرة رفيق متعاطف
5. **التعلم** → دروس مدمجة تفتح في السياق الصحيح

### لحظات النجاح الحرجة

| اللحظة | الشعور | التوقيت |
|--------|--------|---------|
| أول `اطبع("مرحباً")` ناجح | "أنا مبرمج!" | < 10 دقائق |
| أول رسالة خطأ عربية تحل المشكلة | "الأداة تفهمني" | أول جلسة |
| رؤية الكود يتدفق من اليمين | "هذا يشبهني" | أول فتح ملف |
| أول دالة مخصصة تعمل | "أقدر أبني أي شيء" | أول أسبوع |

### مبادئ التجربة

| المبدأ | التطبيق |
|--------|---------|
| **عربي أولاً** | كل ما يراه المستخدم عربي — أوامر، أخطاء، توثيق |
| **صفر إعدادات** | يعمل فوراً — RTL، تلوين، snippets — بدون ضبط |
| **رفيق لا معلم** | الأداة تساعد بتعاطف، لا تُحاضر ولا تُصنّف |
| **بسيط ثم عميق** | واجهة بسيطة تكشف عمقها مع النمو |
| **الفشل آمن** | كل خطأ فرصة تعلم — لا رسائل مرعبة |

## الاستجابة العاطفية المرغوبة

### الأهداف العاطفية الأساسية

1. **"هذا مكاني"** — المبرمج العربي يشعر لأول مرة أن بيئة البرمجة صُنعت له
2. **"أقدر"** — الثقة التي يبنيها النجاح المتكرر، خصوصاً للمبتدئ
3. **"الأداة معي"** — الإحساس بالمرافقة لا بالوحدة

### خريطة الرحلة العاطفية

| المرحلة | الشعور المستهدف | المراد تجنبه | آلية التصميم |
|---------|----------------|-------------|-------------|
| التثبيت | فضول + ترحيب | رهبة | شاشة ترحيب عربية دافئة |
| أول فتح ملف | فخر (RTL!) + ألفة | غرابة | RTL تلقائي + ملف ترحيبي |
| أول كتابة كود | حماس + ثقة | ارتباك | IntelliSense عربي + snippets |
| أول تشغيل ناجح | إنجاز + بهجة | — | مايكرو-احتفال رقيق |
| أول خطأ | فهم + أمان | إحباط / خوف | Error Humanizer بنبرة رفيق |
| العودة اليوم التالي | ألفة + تقدم | نسيان | استعادة السياق تلقائياً |
| بعد أسبوع | انتماء + نمو | ملل | اكتشاف ميزات تدريجياً |

### المشاعر الدقيقة

| المطلوبة | المرفوضة | السياق |
|---------|---------|--------|
| ثقة | ارتباك | كتابة الكود — الإكمال الذكي يعزز |
| أمان | خوف | حدوث خطأ — رسالة ودية |
| فخر | إحراج | استخدام العربية — الأداة تحتفي |
| إنجاز | إحباط | إكمال مهمة — تأكيد إيجابي |
| انتماء | عزلة | رؤية المجتمع — "لست وحدي" |

### التأثير على التصميم

| الشعور | قرار التصميم |
|--------|-------------|
| "هذا مكاني" | كل نص مرئي بالعربية. لا إنجليزية في الواجهة الأساسية |
| "أقدر" | كل خطوة ناجحة بتأكيد إيجابي (✓ خفيف، لون أخضر) |
| "الأداة معي" | Error Humanizer بالعامية الواضحة + اقتراح الحل |
| "أنا أنمو" | ميزات جديدة تظهر عندما يكون جاهزاً |
| "الخطأ عادي" | ألوان هادئة للأخطاء + أيقونات ودية |

### مبادئ التصميم العاطفي

1. **الاحتفاء أولاً** — لحظات النجاح تُلاحَظ (مايكرو-احتفالات)
2. **الفشل طبيعي** — الأخطاء فرص تعلم لا إخفاقات
3. **الهوية العربية فخر** — RTL والعربية هي الوضع الافتراضي
4. **الصمت الذكي** — لا إشعارات مزعجة، الأداة تتكلم عند الحاجة فقط
5. **التقدم المرئي** — المستخدم يرى نموه

## تحليل أنماط UX والإلهام

### المنتجات المُلهمة

| المنتج | ما نتعلمه | ما نتجنبه |
|--------|----------|----------|
| **Replit** | Feedback loop قصير جداً — اكتب وشغّل فوراً | تعقيد الإعدادات |
| **GitHub Copilot** | Inline suggestions هادئة (ghost text) — لا تقاطع التدفق | اقتراحات مفرطة |
| **VS Code** | Command Palette + Walkthrough API + Extension marketplace | Onboarding معقد |
| **Duolingo** | مايكرو-احتفال واحد عند أول نجاح + فشل آمن | Gamification مفرط |
| **Linear** | واجهة نظيفة بدون ضوضاء — إلهام لصفحة الإعدادات | — |

### الأنماط القابلة للنقل

| النمط | المصدر | التطبيق |
|-------|--------|---------|
| Build First, Learn Later | Replit/Scratch | ملف ترحيبي جاهز للتشغيل فوراً |
| Inline Suggestions | Copilot | اقتراحات الإصلاح تظهر inline بهدوء |
| Command Palette بالعربية | VS Code | جميع الأوامر عبر لوحة الأوامر |
| احتفال واحد فقط | Duolingo | عند أول `اطبع("مرحبا")` ناجح + طلب تقييم بلطف |
| واجهة نظيفة | Linear | صفحة الإعدادات بدون ضوضاء |

### أنماط يجب تجنبها

| ضد-النمط | السبب |
|---------|-------|
| Modal dialogs للأخطاء | تقاطع التدفق وتُخيف المبتدئ |
| إعدادات إجبارية قبل البدء | تقتل "الـ 10 دقائق الأولى" |
| Gamification ظاهر (نقاط، مستويات) | المحترف يكرهه |
| RTL قسري على كل الواجهة | يكسر توقعات VS Code |
| رسائل خطأ حمراء صارخة | تولّد خوفاً عند المبتدئ |
| Tooltips متتالية (جولات منتج) | المستخدم يغلقها بدون قراءة |
| Empty states بدون فعل | كل شاشة فارغة تحتاج زر فعل |
| ترجمة حرفية لمصطلحات إنجليزية | الكلمة العربية يجب أن تكون مفهومة بذاتها |

### استراتيجية الإلهام

**المعادلة**: آلية Copilot (اقتراحات هادئة) + فلسفة Replit (شغّل فوراً) + نظافة Linear (لا ضوضاء)

**أولويات من منظور الأعمال** (مدخلات John PM):
1. **اكتشاف Marketplace**: README جذاب بصرياً + GIF متحرك 3 ثوانٍ يُظهر الإضافة تعمل
2. **Activation خلال دقيقة**: الكود يعمل فوراً — هذا أهم من أي تصميم
3. **استقرار = تقييم عالي**: لا أحد يعطي 5 نجوم لتصميم يتعطّل
4. **طلب تقييم**: عند أول تشغيل ناجح (اللحظة السعيدة الوحيدة)

## أساس نظام التصميم

### اختيار النظام: VS Code Design Language

إضافة VS Code تعمل داخل VS Code — نظام التصميم مُحدد تلقائياً. نستخدم مكونات VS Code الأصلية + WebView UI Toolkit للمكونات المخصصة.

### مبررات الاختيار

1. **إلزام تقني** — الإضافة تعيش داخل VS Code
2. **اتساق مع المنظومة** — المستخدم لا يشعر بانفصال عن بيئته
3. **سمات تلقائية** — تتبع dark/light/high contrast بدون جهد
4. **مكتبة رسمية** — `@vscode/webview-ui-toolkit` مدعومة من Microsoft

### خريطة المكونات

| المكوّن | التقنية |
|---------|---------|
| المحرر (Monaco) | TextMate grammars + Semantic tokens + Decorations |
| الأشجار (Explorer, Packages) | VS Code TreeView API |
| الإشعارات والأخطاء | VS Code Notification API + Diagnostic API |
| الإعدادات | VS Code Settings API (contributes.configuration) |
| Tutorial WebViews | `@vscode/webview-ui-toolkit` + CSS RTL مخصص |
| Error Humanizer | Inline Diagnostics + Custom Hover Provider |
| لوحة الأوامر | Command Palette (مدمج) |
| الحالة | Status Bar API |

### استراتيجية التخصيص

**عناصر RTL المخصصة:**
- CSS `direction: rtl` في WebViews فقط
- خطوط عربية (Noto Naskh Arabic / Cairo) داخل WebViews
- Decorations للمحرر لدعم النص العربي

**رموز التصميم (Design Tokens):**
- تتبع `--vscode-*` CSS variables تلقائياً
- لا حاجة لنظام ألوان مستقل
- 3 سمات مدمجة (FR28) = color themes بتنسيق VS Code القياسي

### نهج التنفيذ

- **المكونات الأصلية أولاً** — TreeView, QuickPick, StatusBar, Notifications
- **WebView فقط عند الضرورة** — Tutorial, Marketplace browser, Welcome page
- **CSS scoping** — تخصيصات RTL معزولة داخل WebView ولا تؤثر على VS Code

## التجربة المُعرِّفة

### الجوهر

> **"برمجت بلغتي، واشتغل"**

هذه ليست مجرد ميزة — هي **هوية جديدة يكتسبها المستخدم**. ما سيقوله أحمد لصديقه: "في إضافة تخليك تبرمج بالعربي!"

**الآلية** (Core Loop): اكتب بالعربية → شغّل بضغطة → افهم الخطأ فوراً
**الشعور**: "هذا مكاني" — أول مرة بيئة برمجة صُنعت لي

### النموذج الذهني حسب المستوى

| المستوى | التوقع | التشبيه |
|---------|--------|---------|
| مبتدئ | أكتب → أضغط زر → أرى نتيجة | آلة حاسبة |
| متوسط | أكتب → الأداة تساعدني → أشغّل → أصحح | Word مع spell-check |
| محترف | أكتب بسرعة → أصحح بسرعة → أنشر | VS Code العادي |

### معايير النجاح (SLAs)

| المعيار | القيمة | الواقعية التقنية |
|---------|--------|-----------------|
| من الفتح لأول تشغيل | < 60 ثانية | ✅ Extension ~500ms + Compiler ~3s + 52s للمستخدم |
| من الخطأ للفهم | < 5 ثوانٍ | يعتمد على جودة Error Humanizer |
| من الفهم للإصلاح | < 30 ثانية | الاقتراح واضح + inline |
| IntelliSense | < 100ms | ✅ LSP محلي |

### ما يحدث تلقائياً (صفر تدخل)

1. RTL يتفعل عند فتح `.ص`
2. IntelliSense يعمل فوراً
3. رسائل الخطأ تُترجم تلقائياً
4. ملف ترحيبي يفتح عند أول استخدام

### ما يجب ألا يحدث أبداً

1. رسالة خطأ إنجليزية بدون ترجمة
2. شاشة فارغة بدون إرشاد
3. طلب إعدادات قبل أول تشغيل
4. Crash أو تجمد

## الأساس البصري

### الألوان

الإضافة ترث سمة VS Code تلقائياً عبر `--vscode-*` CSS variables. ثلاث سمات مدمجة (FR28):
- **ليلة الصحراء** (Dark) — الافتراضية، ألوان دافئة هادئة
- **شروق** (Light) — للاستخدام النهاري
- **عالي التباين** (High Contrast) — إمكانية وصول

**ألوان الدلالات المخصصة (WebViews فقط):**

| الدلالة | اللون | السبب |
|---------|-------|-------|
| نجاح | أخضر هادئ `#4CAF50` | تشغيل ناجح، احتفال |
| خطأ | برتقالي دافئ `#FF9800` | ليس أحمر! — "الفشل آمن" |
| معلومات | أزرق هادئ `#42A5F5` | تلميحات، دروس |
| تحذير | أصفر مخفف `#FFC107` | تحذيرات Diagnostics |

### الخطوط

| السياق | الخط | السبب |
|--------|------|-------|
| المحرر | خط المستخدم الحالي | لا نغيّر إعداداته |
| WebViews عربي | Cairo | حديث، واضح، مجاني |
| WebViews fallback | Noto Naskh Arabic → system | تغطية Unicode |
| كود في WebViews | Cascadia Code | متوافق مع VS Code |

### التباعد

- يتبع `--vscode-*` spacing variables
- WebViews: نظام 4px grid
- padding عربي: 16px (أكبر من الإنجليزي لراحة القراءة)

### التخطيط

| العنصر | الاتجاه | التقنية |
|--------|---------|---------|
| المحرر | Monaco (لا تغيير) | TextMate + Semantic |
| Sidebar panels | LTR (كـ VS Code) | TreeView API |
| WebViews | RTL | CSS `direction: rtl` + Grid/Flexbox |
| StatusBar | RTL لعناصرنا فقط | StatusBar API |

### المبرر

- **الغمر عند الاكتشاف** — Welcome, Tutorial, Marketplace هي لحظات لا تتكرر كثيراً وتحتاج انطباعاً قوياً
- **الحد الأدنى عند العمل** — المحرر، Error Humanizer، IntelliSense تُستخدم كل ثانية — السرعة والبساطة أولاً

## رحلات المستخدم التفصيلية

### رحلة أحمد (المبتدئ) — MVP-0

```
تثبيت الإضافة من Marketplace
→ VS Code يُعاد تشغيله
→ Welcome WebView يفتح (شعار + "ابدأ مشروعك الأول")
→ يضغط "ابدأ" → يُنشأ `مرحبا.ص` مع كود جاهز
→ يرى RTL تلقائي + تلوين عربي ← لحظة فخر "هذا يشبهني"
→ يضغط ▶️ (زر أخضر في Editor Title)
→ يرى "مرحباً بالعالم" في Output ← لحظة "أنا مبرمج!"
→ 🎉 مايكرو-احتفال + طلب تقييم بلطف
→ يعدّل الكود → يخطئ
→ Error Humanizer يشرح بالعربية + يقترح الحل ← "الأداة تفهمني"
→ يصلح → يشغّل → نجاح ← ثقة متنامية
→ يبدأ الدرس التالي (walkthrough مدمج)
```

### رحلة عمر (المتوسط) — MVP-1

```
يفتح مشروع موجود → IntelliSense يعمل فوراً
→ يكتب دالة → Snippets عربية تظهر
→ يضع breakpoint → يشغّل Debugger (DAP)
→ يفحص المتغيرات بالعربية
→ يتصل بالخادم السحابي → يشغّل عن بُعد
→ يستورد مكتبة من sila-hub
```

### رحلة منى (المحترفة) — MVP-2

```
تنشئ مشروع من قالب (Scaffolding)
→ تكتب كود معقد → محلل ثابت يحذّر
→ تطبّق إصلاحات سريعة
→ تصفح Marketplace → تنشر حزمة
→ تدير إصدارات الحزم
```

## استراتيجية المكونات

### خريطة المكونات (مُحدّثة بعد نقاش الوكلاء)

| المكوّن | النوع | الأولوية | ملاحظة |
|---------|-------|----------|--------|
| **Welcome + Tutorial** | WebView واحد متعدد الصفحات | MVP-0 | مدمجان لتقليل bundle size ~35% |
| **Run Button** | Editor Title Action (VS Code API) | MVP-0 | خفيف وأصلي |
| **Error Humanizer Hover** | Custom HoverProvider | MVP-0 | أولوية تصميمية عالية |
| **Arabic TreeView Labels** | VS Code TreeView API | MVP-0 | اختبار طول التسميات |
| **Settings** | contributes.configuration | MVP-0 | لا يحتاج كود |
| **Marketplace Browser** | WebView مخصص | MVP-1 | مؤجل — لا يخدم المستخدم الأول |
| **Debug Variables** | VS Code DAP | MVP-1 | API أصلي |

### قرارات معمارية للمكونات

1. **دمج WebViews**: Welcome + Tutorial في WebView واحد (SPA مع routing داخلي)
2. **Lazy Activation**: استخدام `onView` و `onCommand` events — لا تسجيل دفعة واحدة
3. **Message Passing**: contract واضح بين Extension Host و WebView (schema مُختبَر)
4. **Tutorial بديل**: دراسة `contributes.walkthroughs` كبديل أخف إذا كان يدعم RTL

## إمكانية الوصول والتوافق

### RTL والعربية

| المتطلب | التطبيق |
|---------|---------|
| NFR12 — RTL كامل | `direction: rtl` في جميع WebViews + عناصر عربية |
| NFR13 — Bidi | Unicode bidi algorithm + `unicode-bidi: embed` |
| جزر RTL ذكية | المحرر والأشجار تبقى LTR (نمط VS Code)، WebViews RTL |

### إمكانية الوصول العامة

| المتطلب | التطبيق |
|---------|---------|
| NFR14 — لوحة الأوامر | كل أمر مسجّل في Command Palette بالعربية |
| NFR15 — قارئ الشاشة | `aria-label` عربي على كل عنصر تفاعلي في WebViews |
| عالي التباين | سمة مدمجة + اختبار WCAG AA |
| حجم الخط | يتبع إعدادات VS Code — لا نغيّره |
| لوحة المفاتيح | كل عنصر تفاعلي قابل للوصول بـ Tab + Enter |

## الخلاصة

وثيقة UX مكتملة تغطي 14 خطوة من سير العمل التصميمي. الوثيقة تُعرّف:

- **التجربة المُعرِّفة**: "برمجت بلغتي، واشتغل"
- **5 مبادئ تجربة**: عربي أولاً، صفر إعدادات، رفيق لا معلم، بسيط ثم عميق، الفشل آمن
- **اتجاه هجين**: غمر في الاكتشاف + حد أدنى في العمل
- **7 مكونات مخصصة** موزعة على MVP-0 و MVP-1
- **استراتيجية اختبار** واضحة للمكونات المخصصة
- **إمكانية وصول** شاملة (RTL, Bidi, قارئ شاشة, عالي تباين)

**القرارات الرئيسية المتخذة بمشاركة الوكلاء:**
- دمج Welcome + Tutorial في WebView واحد (Winston)
- Error Humanizer بنبرة "رفيق" لا "معلم" (Maya)
- احتفال واحد فقط ثم صمت + طلب تقييم (Sally + John)
- أولوية Marketplace Discovery: README + GIF متحرك (John)
- تكيّف ضمني بالسلوك كهدف بعيد، وضعان كـ MVP (الجميع)
